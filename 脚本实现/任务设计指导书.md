# 任务设计指导书 v1.0

> **文档性质**：任务文件编写规范与设计约束  ｜  **适用范围**：所有 `tasks/` 下的任务（日常/常驻/活动/特殊）

---

## 一、概述

每个游戏任务在系统中经历以下生命周期：

```
┌─ ① 创建 ──────────────────────────────────────────────────────┐
│  UI「任务管理」→ 新建 → 选择分类/任务类型 → 自动生成 .py 模板    │
│  模板包含：统一属性声明 + 三阶段结构桩 + 占位 import            │
└────────────────────────────────────────────────────────────────┘
                              ↓
┌─ ② 编辑 ──────────────────────────────────────────────────────┐
│  在生成的 .py 中：                                             │
│    · 引用需要的通用模块（battle_loop / select_team / ...）      │
│    · 编写特化步骤（副本专属逻辑）                                │
│    · 按 TaskGraph 编排执行顺序                                  │
│    · 有战斗 → 声明 uses_battle = True                          │
│    · 需阵容 → 声明 uses_team = True / uses_soul = True          │
└────────────────────────────────────────────────────────────────┘
                              ↓
┌─ ③ 配置 ──────────────────────────────────────────────────────┐
│  UI 根据模块声明动态显示配置区域：                               │
│    · 时间调度参数（必配） — 所有任务                             │
│    · 每日轮次（必配） — 今天调度几轮（equivalent to YAML        │
│      execution_rule，控制 Scheduler 重新入队次数）              │
│    · 每轮循环次数 — 有 loop 区时显示（任务体内的 BattleLoop      │
│      循环数，与"每日轮次"是不同概念）                           │
│    · 阵容ID — 声明 uses_team 时显示                             │
│    · 御魂预设 — 声明 uses_soul 时显示                           │
│    · 体力门槛 — 声明 uses_stamina 时显示                        │
└────────────────────────────────────────────────────────────────┘
                              ↓
┌─ ④ 调度 ──────────────────────────────────────────────────────┐
│  Scheduler 扫描 tasks.yaml → 计算 next_run_time                │
│  → 到期 → build_schedule() → 加入优先队列                       │
│  → ScriptWorker 弹出 → 动态 import → 执行                       │
└────────────────────────────────────────────────────────────────┘
```

**核心原则：任务文件自描述。** 任务通过模块级变量声明自身能力，UI 据此渲染配置表单，无需手动维护配置文件与代码的一致性。

## 二、任务统一属性

每个任务 `.py` 文件的**模块级**必须声明以下属性。这些属性被 `TaskManager` 解析，供 UI 面板展示。

### 2.1 必选属性

| 属性 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `display_name` | `str` | 任务显示名（中文） | `"御魂副本-八岐大蛇"` |
| `description` | `str` | 一句话功能说明 | `"自动刷御魂八岐大蛇第十层"` |
| `task_type` | `str` | `"battle"`（战斗任务）或 `"event_task"`（事件任务） | `"battle"` |

### 2.2 模块声明（决定 UI 配置区）

| 属性 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `uses_battle` | `bool` | `False` | 是否包含战斗 → UI 显示阵容/御魂配置 |
| `uses_team` | `bool` | `False` | 是否需要在战斗前调整阵容 |
| `uses_soul` | `bool` | `False` | 是否需要配置御魂方案 |
| `uses_stamina` | `bool` | `False` | 是否需要体力检查 |
| `loop_count` | `int` | `1` | 默认循环次数（UI 可覆盖） |
| `timeout` | `int` | `300` | 任务总超时（秒） |

### 2.3 完整属性声明示例

```python
"""御魂副本-八岐大蛇第十层"""
display_name = "御魂副本-八岐大蛇"
description = "自动刷御魂八岐大蛇第十层，含阵容切换和御魂调整"
task_type = "battle"

uses_battle = True
uses_team = True
uses_soul = True
uses_stamina = True
loop_count = 10
timeout = 900
```

## 三、任务文件标准结构

### 3.1 标准模板

```python
"""
{display_name}

{description}
"""

# ==================== ① 模块声明（必填） ====================
display_name = "任务显示名"
description = "一行功能说明"
task_type = "event_task"          # "battle" 或 "event_task"

# 能力声明（按需启用）
uses_battle = False
uses_team = False
uses_soul = False
uses_stamina = False
loop_count = 1
timeout = 300

# ==================== ② 导入依赖 ====================
from tasks.base.task_step import TaskStep, StepResult
from tasks.base.task_context import TaskContext
from tasks.base.task_graph import TaskGraph

# 通用模块（按需引用）
from tasks.common.close_popup     import ClosePopup
from tasks.common.return_hall     import ReturnHall
# from tasks.common.battle_loop    import BattleLoop      # uses_battle=True 时引入
# from tasks.common.select_team    import SelectTeam      # uses_team=True 时引入
# from tasks.common.check_stamina  import CheckStamina    # uses_stamina=True 时引入

# ==================== ③ 特化步骤（副本专属逻辑） ====================
class EnterDungeon(TaskStep):
    """进入副本"""
    name = "enter_dungeon"
    timeout = 30

    def execute(self, context: TaskContext) -> StepResult:
        exe = context.executor
        # 点击副本入口
        exe.click_image("副本/按钮-八岐大蛇")
        exe.click_image("副本/按钮-第十层")
        return StepResult.success("已进入副本")


class SetupSouls(TaskStep):
    """配置御魂（特化步骤示例）"""
    name = "soul_setup"
    timeout = 60

    def execute(self, context: TaskContext) -> StepResult:
        soul_config = context.task_config.get("soul_setup", {})
        # TODO: 实现御魂配置逻辑
        return StepResult.success("御魂已配置")

# ==================== ④ 构建 TaskGraph ====================
def build_graph(context: TaskContext) -> TaskGraph:
    """组装任务步骤图。"""
    g = TaskGraph("my_task")

    # SETUP 阶段（执行一次）
    g.add_step("close_popup", ClosePopup())
    g.add_step("enter",       EnterDungeon())

    if context.task_config.get("uses_soul"):
        g.add_step("soul_setup", SetupSouls())

    # LOOP 阶段（循环 N 次）
    g.add_step("battle",      BattleLoop(
        times=context.task_config.get("loop_count", 1)
    ))

    # TEARDOWN 阶段（执行一次）
    g.add_step("go_home",     ReturnHall())

    # 连线
    g.set_entry("close_popup")
    g.add_edge("close_popup", "enter")
    g.add_edge("enter",       "soul_setup")
    g.add_edge("soul_setup",  "battle")
    g.add_edge("battle",      "go_home")

    g.set_error_branch("go_home")
    return g


# ==================== ⑤ 入口类（框架约定） ====================
class MyTask(TaskStep):
    """任务入口。框架通过此类找到任务并执行。"""
    name = "my_task"
    display_name = display_name
    description = description
    timeout = timeout

    def execute(self, context: TaskContext) -> StepResult:
        graph = build_graph(context)
        success = graph.run(context)
        return (
            StepResult.success("任务完成")
            if success else StepResult.fail("任务执行失败")
        )
```

### 3.2 结构要点

| 区域 | 用途 | 执行次数 |
|------|------|---------|
| **SETUP** | 关弹窗→进入页面→调整阵容→设置御魂 | 1 次 |
| **LOOP** | 检查体力→发起战斗→等待结算→领奖 | N 次（`loop_count`） |
| **TEARDOWN** | 返回庭院 / 错误恢复 | 1 次 |

> **关键约束**：LOOP 区只放"可重复执行"的通用/特化模块。阵容调整、御魂设置等一次性操作必须放在 SETUP 区。

```

│ 每日轮次: [10]  ← 今天 Scheduler 调度几轮 │
│ 🔄 每轮循环: [1] ← 每轮内 BattleLoop 次数 │
│ 执行方式: [次数 ▼] ← count=按轮次, time=按时长 │
│                                          │
│ ── ⚔ 战斗配置 ──（uses_battle=True 出现）│

│ 失败容忍: [3] 次                         │
│                                          │
│ ── 🍃 体力配置 ──（uses_stamina=True）   │
│ 体力门槛: [6]                            │
│                                          │
│ 下次执行: [2026-07-21 08:00]             │
│ 优先级:   [10]                           │
│             [💾 保存配置]                 │
└─────────────────────────────────────────┘
```

> **"每日轮次"≠"每轮循环"**：  
> - **每日轮次** (YAML `execution_rule.value`)：今天 Scheduler 将这个任务放入队列多少次。每次放进去 → ScriptWorker 执行 → 任务体内 BattleLoop 循环 N 次。  
> - **每轮循环** (Python `loop_count`)：任务体内的 `BattleLoop(times=N)` 战斗次数。一轮可能包含多场战斗。  
> - 举例：每日轮次=3, 每轮循环=10 → 今天调度 3 轮，每轮打 10 场，总共 30 场。

### 4.3 联动实现原理

```
TaskManager._parse_file(filepath)
    │
    ├── 提取 display_name, description, task_type
    ├── 提取 uses_battle, uses_team, uses_soul, uses_stamina
    ├── 提取 loop_count, timeout
    └── 构造 TaskModule（携带所有声明）

UI._on_game_task_clicked(task_module)
    │
    ├── task_module.uses_battle → 显示战斗配置区
    ├── task_module.uses_team   → 显示阵容下拉
    ├── task_module.loop_count  → 显示循环次数输入
    └── ...以此类推
```

## 五、时间调度配置（所有任务必配）

### 5.1 调度字段

每个任务在 `tasks.yaml` 中的配置：

```yaml
special:
  - name: orochi_soul_10       # 文件名（不含 .py）
    enabled: true               # 是否启用
    priority: 5                 # 优先级（1最高，数字越大越低）
    repeat:                     # ⏱ 时间规则
      type: daily               # once/daily/weekly/monthly_start/interval_days/interval_hours/expire_at/special
      time_start: "08:00"       # 每日/每周开始时间
      time_end: "23:59"         # 每日/每周结束时间
      max_daily: 50             # 每日最大执行次数（可选）
    execution_rule:             # 📊 执行规则
      mode: count               # count（按次数）/ time（按时长）
      value: 10                 # 次数或分钟数
```

### 5.2 八种重复规则

| 类型 | 说明 | 必填字段 |
|------|------|---------|
| `daily` | 每日执行 | `time_start`, `time_end` |
| `weekly` | 每周指定日 | `weekdays`, `time_start`, `time_end` |
| `monthly_start` | 每月初 | `time_start`, `time_end` |
| `interval_days` | 隔 N 天 | `days` |
| `interval_hours` | 隔 N 小时 | `hours` |
| `once` | 单次 | `at`（ISO时间） |
| `expire_at` | 依赖外部失效 | `window` |
| `special` | 活动窗口 | `window: {date_start, date_end}` |

## 六、循环体设计约束

> **关键说明**：指导书中的"三阶段模型"（SETUP → LOOP → TEARDOWN）是一个**概念模型**。
> 实际实现中，**TaskGraph 不支持循环边**——`add_edge()` 创建的是单向边，`run()` 遍历时不会自动回到 LOOP 区起点。
> 循环是由 **BattleLoop(times=N)** 步骤内部通过 `for i in range(times)` 实现的，对 TaskGraph 而言是一个不透明的黑盒步骤。
> 这并不影响三阶段模型作为设计规范的有效性——只要编写任务的人理解：循环是步骤内部的事，TaskGraph 只负责步骤间的**线性编排**。

### 6.1 正确示例 ✅

```
SETUP:  体力检查 → 进入副本 → 调整阵容 → 设御魂
         ↓
LOOP:   发起战斗 → 等待结束 → 结算领奖   ← 循环 N 次
         ↓
TEARDOWN: 返回庭院
```

### 6.2 错误示例 ❌

```
LOOP:   进入副本 → 调整阵容 → 设御魂 → 战斗 → 结算
        ↑____ 阵容调整每次循环都执行，浪费 30s+ ____↑
```

### 6.3 循环次数配置

```python
# ❌ 硬编码 — 不推荐
battle = BattleLoop(times=10)

# ✅ 从配置读取 — 推荐，UI 可调
loop_count = context.task_config.get("loop_count", 10)
battle = BattleLoop(times=loop_count)
```

## 八、特化步骤编写规范

### 8.1 命名约定

| 规则 | 示例 |
|------|------|
| 类名用动宾结构 | `EnterDungeon`, `SetupSouls`, `SelectBuff` |
| `name` 用小写下划线 | `"enter_dungeon"`, `"soul_setup"` |
| `timeout` 合理估计 | 简单点击 15s，战斗等待 180s，御魂配置 60s |

### 8.2 特化步骤骨架

```python
class EnterDungeon(TaskStep):
    """进入副本 — 点击副本入口 → 选择层数 → 确认"""
    name = "enter_dungeon"
    is_generic = False     # 特化模块
    timeout = 30

    def execute(self, context: TaskContext) -> StepResult:
        exe = context.executor
        rec = context.recognizer

        # ① 点击副本入口按钮
        if not exe.click_image("副本/按钮-八岐大蛇", timeout=5):
            return StepResult.fail("未找到副本入口")

        # ② 选择层数
        layer = context.task_config.get("layer", 10)
        if not exe.click_image(f"副本/按钮-第{layer}层", timeout=3):
            return StepResult.fail(f"未找到第{layer}层按钮")

        # ③ 确认进入
        exe.click_if_exists("common/ui/confirm_btn")

        return StepResult.success(f"已进入副本第{layer}层", layer=layer)
```

### 8.3 错误处理

```python
def execute(self, context: TaskContext) -> StepResult:
    try:
        result = exe.click_image("xxx", timeout=5)
        if not result:
            return StepResult.retry("未找到目标，重试")
        return StepResult.success()
    except Exception as e:
        context.log(f"[{self.name}] 异常: {e}")
        return StepResult.fail(str(e))
```

## 十、任务文件检查清单

在 UI 中保存任务配置之前，确认以下项目：

### 代码级

- [ ] 模块声明完整（`display_name`, `description`, `task_type`）
- [ ] 能力声明按需设置（`uses_battle`, `uses_team`, `uses_soul`, `uses_stamina`）
- [ ] 有 `class XxxTask(TaskStep)` 入口类，`name` 与文件名一致
- [ ] 入口类覆写 `execute(context)` → 内部调用 `build_graph(context).run(context)`
- [ ] 特化步骤放在 LOOP 外（SETUP 或 TEARDOWN）
- [ ] 循环次数从 `context.task_config.get("loop_count")` 读取（不硬编码）
- [ ] 所有 `click_image` 的素材名与 `assets/` 实际文件对应
- [ ] `timeout` 设置合理（不设 0 即无限等待）

### 配置级

- [ ] `repeat.type` 选择正确
- [ ] `time_start` / `time_end` 格式为 `HH:MM`
- [ ] `execution_rule.mode` 与 `value` 匹配
- [ ] 启用开关 `enabled: true`
- [ ] 优先级设置合理（同类任务不要全设同一个值）
- [ ] `next_run_time` 在合理范围内（自动计算或手动覆盖）

### 素材级

- [ ] 任务用到的所有图片已放入 `assets/` 对应子目录
- [ ] 素材命名遵循 `{场景}/{类型}-{名称}.png` 约定

| 循环次数硬编码在代码中 | 改循环次数需要改 .py 文件，不能 UI 调 | 🟡 中 |
| `BattleLoop` 只等待不发起 | 没有通用的"发起战斗"模块（`StartBattle`） | 🟡 中 |
| 无御魂配置通用模块 | 每次需要御魂都得写特化步骤 | 🟢 低 |
| 体力 OCR 未实现 | `CheckStamina` 是空壳 | 🟢 低 |

### 建议实现顺序

1. **TaskManager 扩展解析 `uses_*`** → `_parse_file()` 增加对这些变量的提取
2. **新建任务模板** → `NewTaskDialog` 生成带完整骨架的 .py
3. **UI 动态配置区** → `_on_game_task_clicked()` 根据 `uses_*` 显示/隐藏字段
4. **`StartBattle` 通用模块** → 发起战斗的通用步骤
5. **`SetupSouls` 通用模块** → 御魂配置通用步骤
