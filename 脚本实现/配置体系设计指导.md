# 配置体系设计指导 v1.0

> **文档性质**：所有配置文件的字段定义、读写规则、层级关系  ｜  **配套**：06-配置管理中心 / 05-时间调度模块

---

## 一、配置文件全景

```
config/
├── global.yaml          ← 全局运行参数
├── tasks.yaml           ← 任务编排（调度+执行规则）
├── accounts.yaml        ← 账号管理
├── coords/              ← 坐标配置（按场景）
│   ├── courtyard.json
│   ├── login.json
│   └── teams/
└── runtime/
    └── task_state.json  ← 运行时状态持久化（自动维护）
```

**配置文件与模块的对应关系**：

| 配置文件 | 负责模块 | 读/写 |
|---------|---------|:--:|
| `global.yaml` | 06-配置管理 / 所有模块 | 启动时读，UI 可写 |
| `tasks.yaml` | 06-配置管理 → 05-时间调度 | 启动时读，UI 可写 |
| `accounts.yaml` | 06-配置管理 → 15-账号管理 | 启动时读，UI 可写 |
| `coords/*.json` | 06-配置管理 → 14-执行器 | 启动时读 |
| `task_state.json` | 05-时间调度（TaskStateStore） | 自动读写（原子写盘） |

## 二、global.yaml — 全局运行参数

```yaml
# ── ADB 连接 ──
adb:
  device_id: "127.0.0.1:16384"   # ADB 设备地址
  path: "C:/.../adb.exe"          # ADB 可执行文件路径
  port: 16384                     # ADB 端口

# ── 屏幕 ──
screen:
  width: 1280                     # 模拟器宽度（像素）
  height: 720                     # 模拟器高度（像素）
  dpi: 240                        # DPI（预留）

# ── 应用 ──
app:
  package: "com.netease.onmyoji.wyzymnqsd_cps"  # 阴阳师包名
  activity: "com.netease.onmyoji.Launcher"       # 启动 Activity

# ── 模拟器 ──
emulator:
  type: "mumu"                    # ldplayer / mumu / nox
  path: ""                        # 自定义模拟器路径（空=自动检测）
  auto_launch: true               # 是否自动启动模拟器

# ── 图像识别 ──
recognize:
  threshold: 0.8                  # 默认匹配置信度（0~1）
  grayscale: true                 # 是否灰度匹配
  method: "template"              # 匹配方法

# ── 防封号 ──
anti_detect:
  click_offset_radius: 12         # 点击偏移半径（像素）
  delay_jitter: 0.6               # 延迟抖动（秒）
  min_interval: 0.8               # 最小操作间隔（秒）
  long_pause_prob: 0.05           # 走神概率（0~1）
  max_daily_actions: 2000         # 每日最大操作次数
  max_daily_runtime: 8            # 每日最大运行时长（小时）

# ── 运行模式 ──
run:
  log_level: "INFO"               # 日志级别：DEBUG / INFO / WARNING / ERROR
  mode: "background"              # 运行模式
  screenshot_on_error: true       # 异常时自动截图

# ── 调度 ──
schedule:
  reset_at: "00:00"               # 每日重置时间
```

### 2.1 ConfigManager 访问方式

```python
from core.config_manager import ConfigManager
config = ConfigManager()

# 点分路径读取
config.get("adb.port")                    # → 16384
config.get("screen.width")                # → 1280
config.get("recognize.threshold")         # → 0.8
config.get("anti_detect.max_daily_actions") # → 2000

# 带默认值（键不存在时返回默认值）
config.get("recognize.method", "template")  # → "template"
config.get("screen.dpi", 240)               # → 240

# 读取整段
config.get_section("anti_detect")
# → {"click_offset_radius": 12, "delay_jitter": 0.6, ...}

# 写入（立即原子写盘）
config.set("adb.port", 5555)
```

## 三、tasks.yaml — 任务编排配置

```yaml
# 任务按分类组织
daily: []
permanent: []
event: []
special:
  - name: "soul_10"              # 任务名 = 文件名（不含 .py）
    enabled: true                 # 是否启用
    priority: 5                   # 优先级（1~99，数值越小越优先）

    repeat:                       # ⏱ 重复规则（8 种类型）
      type: "daily"
      time_start: "08:00"         # HH:MM
      time_end: "23:59"           # HH:MM
      max_daily: 50               # 每日上限（可选）

    execution_rule:               # 📊 执行规则
      mode: "count"               # "count"（按轮次）/ "time"（按时长，分钟）
      value: 10                   # 轮次数 或 分钟数

# 默认调度顺序
default_order:
  - daily
  - permanent
  - special
  - event
```

### 3.1 重复规则字段速查

| type | 必填字段 | 说明 |
|------|---------|------|
| `daily` | `time_start`, `time_end` | 每日指定时间段内执行 |
| `weekly` | `weekdays`, `time_start`, `time_end` | 每周指定星期几 |
| `monthly_start` | `time_start`, `time_end` | 每月初 |
| `interval_days` | `days` | 每隔 N 天 |
| `interval_hours` | `hours` | 每隔 N 小时 |
| `once` | `at`（ISO 时间字符串） | 指定时刻执行一次 |
| `expire_at` | 无（依赖外部上报） | 外部失效时间 |
| `special` | `window: {date_start, date_end}` | 活动日期范围 |

### 3.2 执行规则说明

| mode | value 含义 | 举例 |
|------|-----------|------|
| `count` | 今天 Scheduler 将此任务放入队列多少次 | `value: 3` → 今天调度 3 轮 |
| `time` | 今天累计执行多少分钟 | `value: 120` → 今天最多执行 120 分钟 |

### 3.3 ConfigManager 任务配置访问

```python
# 获取单个任务的完整配置（合并 tasks.yaml + coords/*.json）
config.get_task_config("soul_10")
# → {"name": "soul_10", "repeat": {...}, "execution_rule": {...}, ...}

# 获取整个 tasks.yaml
config.get_tasks_config()
# → {"daily": [...], "permanent": [...], "special": [...], ...}
```

## 六、task_state.json — 运行时状态（自动维护）

```json
{
  "_version": 1,
  "_updated_at": "2026-07-20T22:30:00",
  "tasks": {
    "soul_10": {
      "last_run_time": "2026-07-20T08:05:00",
      "last_success": true,
      "next_run_time": "2026-07-21T08:00:00",
      "success_count": 45,
      "today_count": 5,
      "fail_streak": 0,
      "expire_at": null
    }
  }
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `next_run_time` | ISO 字符串 | 下次执行时间（null=无限制） |
| `last_run_time` | ISO 字符串 | 上次执行时间 |
| `last_success` | bool | 上次是否成功 |
| `success_count` | int | 历史成功总次数 |
| `today_count` | int | 今日已执行次数（00:00 重置） |
| `fail_streak` | int | 连续失败次数（成功后归零） |
| `expire_at` | ISO 字符串 / null | 外部失效时间 |

**原子写盘**：`TaskStateStore.save()` 使用 `tempfile.mkstemp() + shutil.move()` 实现——先写临时文件，再原子替换。崩溃不会损坏数据。

**注意**：此文件由 `Scheduler` 自动维护，**不要手动编辑**。

## 七、配置校验

```python
from core.config_schema import ConfigSchema

# 启动时自动校验
errors = ConfigSchema.validate(config.get)
if errors:
    for e in errors:
        print(f"⚠ 配置校验失败: {e}")
```

校验字段示例（来自 `config_schema.py`）：

| 校验项 | 规则 |
|--------|------|
| `adb.port` | 类型=int, 范围 1024~65535 |
| `screen.width` | 类型=int, 最小值 640 |
| `recognize.threshold` | 类型=float, 范围 0.1~1.0 |
| `anti_detect.click_offset_radius` | 类型=int, 范围 0~100 |
| `anti_detect.max_daily_runtime` | 类型=int, 范围 1~24 |
| `run.log_level` | 枚举: DEBUG/INFO/WARNING/ERROR |

## 八、配置修改流程

```
UI 中修改配置
  → ConfigManager.set(key_path, value)
    → 更新内存缓存
    → 原子写盘（临时文件→替换）
    → 发布 config_changed 事件（预留）
    → 相关模块感知变化
```

**任务配置修改的特例**（`tasks.yaml`）：

```
UI「游戏任务」面板
  → _on_save_task_config()
    → 收集表单数据 → 构建配置字典
    → 更新 tasks.yaml
    → Scheduler.update_next_run() → 重新计算 next_run_time
    → Scheduler.build_schedule() → 发布 SCHEDULE_UPDATED
```

## 九、三级配置覆盖

读取配置时按优先级查找（高→低）：

1. **task 级**：`tasks.{category}.{task}.{key}` — 单任务专属
2. **account 级**：`accounts.{account}.{key}` — 某账号专属
3. **global 级**：`global.{key}` — 全局默认

`ConfigManager.get()` 自动按此优先级查找，取最先匹配到的值。
