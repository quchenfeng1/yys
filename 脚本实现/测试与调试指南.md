## 一、内置终端诊断

启动后，右侧面板的「🖥 终端」标签实时显示所有 `print()` 输出和异常 traceback。这是主要的运行时诊断窗口。

### 1.1 终端颜色编码

| 颜色 | 含义 | 来源 |
|:--:|------|------|
| 🟢 绿 | INFO 级别日志 | `logger.info()` / `[INFO]` |
| 🟠 橙 | WARNING 级别日志 | `logger.warning()` / `[WARNING]` |
| 🔴 红 | ERROR 级别日志 + 异常 | `logger.error()` / Traceback |
| ⚪ 灰 | DEBUG 级别日志 | `logger.debug()` / `[DEBUG]` |

### 1.2 日志级别筛选

在「📋 日志」标签页中，可筛选显示级别：
- **DEBUG**：全部日志（含模板匹配详情、防封参数等）
- **INFO**（默认）：正常运行日志
- **WARNING**：只显示警告和错误
- **ERROR**：只显示错误

**调试建议**：排查识图问题时，切换到 DEBUG 级别查看每次模板匹配的置信度。

## 二、模拟任务测试

### 2.1 使用 test_list（60 秒模拟运行）

`tasks/special/test_list.py` 是一个无需游戏环境的纯模拟任务：

```python
# 配置：启用 test_list → 执行规则=按次数,1次 → 启动脚本
# 预期：终端输出每 5 秒一次进度，60 秒后完成
# 用途：验证调度循环、任务队列 UI、日志输出是否正常
```

### 2.2 使用 test_verify（最小任务）

`tasks/special/test_verify.py` 是 new_task 模板生成的标准五段骨架任务：

```
仅执行 ClosePopup → ReturnHall，验证 TaskGraph 基本运作
```

### 2.3 创建一次性调试任务

```
1. 在「任务管理」→「特殊任务」→ 新建 → 类型选"事件任务"
2. 编辑 .py 文件 → 只放你想测试的一两个步骤
3. 配置：repeat=once, 执行规则=按次数,1次
4. 启动脚本 → 观察终端输出
```

## 三、素材匹配调试

### 3.1 检查素材清单

```bash
# 列出所有已加载素材（按分区）
python tools/asset_helper.py --list

# 树形展示目录结构
python tools/asset_helper.py --tree

# 检查素材文件完整性
python tools/asset_helper.py --check
```

### 3.2 确认素材能被识别

在任务步骤中使用低阈值 + DEBUG 日志：

```python
def execute(self, context):
    rec = context.recognizer
    # 降低阈值测试
    result = rec.find("主界面/按钮-目标按钮", threshold=0.6)
    if result:
        context.log(f"找到！位置={result.center}, 置信度={result.confidence:.3f}")
    else:
        context.log("未找到，可能原因：素材不匹配、分辨率不一致、画面未加载")
```

### 3.3 常见识图问题

| 现象 | 排查步骤 |
|------|---------|
| 始终找不到 | ① 确认模拟器分辨率=1280×720 ② 确认素材已放入正确分区 ③ 用 `--list` 确认素材索引名 |
| 偶尔找不到 | 检查阈值是否太高，降至 0.7 测试 |
| 找错位置 | 素材区域不够独特，扩大裁剪范围或换特征 |
| 置信度低 | 游戏画面有半透明叠加、动画效果，选更稳定的特征 |

## 四、调度时间验证

### 4.1 检查下次执行时间

在「游戏任务」面板中点击任务行，查看"下次执行"字段。该值来自 `task_state.json` 的 `next_run_time`。

### 4.2 手动推进

- 将 `next_run_time` 改为当前时间之前
- 点击「保存配置」
- `Scheduler.build_schedule()` 检测到期 → 任务入队

### 4.3 查看调度队列

任务队列面板（「全局控制」视图）显示当前 Scheduler 的完整日程表，包括：
- 当前执行中的任务（大卡片 + 进度条）
- 即将执行的任务（小方块，按优先级排列）

## 五、异常截图分析

当 `run.screenshot_on_error: true` 时，异常发生时的游戏画面自动保存到 `logs/snapshots/`。

文件命名格式：`{时间戳}_{任务名}_{步骤名}.png`

可用于分析：
- 异常时游戏处于什么画面
- 识图为什么失败（对比素材和实际截图）

## 七、调试清单

按此顺序逐项排查，能定位 90% 的问题：

```
□ 1. Python 版本 ≥ 3.10？
□ 2. 依赖包全部安装？（pip list 检查 opencv / pyqt5 / yaml / loguru）
□ 3. 模拟器分辨率 = 1280×720？
□ 4. ADB 能连接？（终端无 "DeviceConnectError"）
□ 5. 游戏已启动且在主界面？（终端无 "LoginFailedError"）
□ 6. 素材文件存在？（python tools/asset_helper.py --list）
□ 7. 任务 enabled: true？（tasks.yaml）
□ 8. next_run_time 已到？（任务队列面板确认）
□ 9. 重复规则类型正确？（daily/weekly/once/...）
□ 10. 日志级别切到 DEBUG 查看详细匹配信息
```

## 八、快速复现测试流程

```
1. 配置 test_list 任务（模拟运行，不依赖游戏）
2. 启用 + 执行规则=1次 + repeat=once
3. 启动 → 观察日志终端输出
   ✅ 看到 "[test_list] 测试文件运行 60s / 60s" → 调度循环正常
   ✅ 看到 "测试完成" → 任务执行正常
   ✅ UI 任务队列刷新 → 事件通信正常

4. 如果 test_list 通过，再配置 test_verify 任务
5. 如果 test_verify 通过，调度循环 + TaskGraph 均正常
6. 然后部署真实游戏任务
```
