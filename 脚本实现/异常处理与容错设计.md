## 一、异常层次结构

```
ScriptError（脚本基础异常）
├── DeviceConnectError       ← 设备连接失败
├── RecognizeError           ← 图像识别失败
│   └── SceneNotFoundError   ← 场景未找到
├── LoginFailedError         ← 登录流程失败
├── AntiBanRiskError         ← 触发防封风险限制
├── ConfigError              ← 配置错误
├── TeamNotFoundError        ← 阵容预设未找到
├── MitamaNotMatchError      ← 御魂不匹配
└── TeamLockFailedError      ← 锁定阵容失败
```

所有自定义异常继承自 `ScriptError`，上层可统一 `except ScriptError` 捕获。

## 二、StepResult 四种状态（任务步骤级容错）

```python
@dataclass
class StepResult:
    status: str    # "success" / "fail" / "skip" / "retry"
    next_step: Optional[str] = None
    data: dict = field(default_factory=dict)
    message: str = ""
```

| 状态 | 含义 | TaskGraph 行为 | 何时使用 |
|------|------|---------------|---------|
| `success` | 步骤成功 | 沿默认边前进到下一步 | 正常完成 |
| `fail` | 步骤失败 | 走 error 分支 → ErrorReturn → 跳过任务 | 不可恢复的错误 |
| `skip` | 跳过 | 按条件边跳转到指定步骤 | 体力不足跳过、条件不满足 |
| `retry` | 重试 | 重新执行当前步骤 | 临时故障（可恢复） |

### 使用示例

```python
class CheckStamina(TaskStep):
    def execute(self, context):
        required = context.task_config.get("stamina_required", 0)
        current = self._ocr_stamina(context)  # OCR 读取当前体力
        if current < required:
            return StepResult.skip("体力不足，跳过任务")
        return StepResult.success("体力充足")

class EnterDungeon(TaskStep):
    def execute(self, context):
        if not context.executor.click_image("副本/入口", timeout=5):
            return StepResult.retry("未找到入口，重试")  # 可能是加载延迟
        return StepResult.success()
```

## 三、TaskGraph 错误恢复路径

每个 `TaskGraph` 通过 `set_error_branch()` 设置全局错误分支。任意步骤返回 `fail` 时自动跳转到错误分支：

```
正常路径:  setup → enter → battle → claim → go_home
错误路径:  任意步骤失败 → error_return → (skip/abort)
```

```python
g = TaskGraph("my_task")
g.set_error_branch("error_recovery")  # 失败统一走这里

g.add_step("error_recovery", ErrorReturn())
# ErrorReturn.execute(): 反复点返回直到庭院 → 返回 StepResult.skip
```

**错误分支的 Safe Harbor 原则**：错误恢复步骤本身要尽量简单可靠，不应再次失败。`ErrorReturn` 只做"点返回按钮 + 检测庭院"这种高成功率操作。

## 四、Scheduler 失败冷却机制（调度级容错）

任务执行失败后，`Scheduler.mark_done(task_name, success=False)` 触发递增冷却：

```python
# scheduler.py 内部逻辑
def mark_done(self, task_name, success):
    if success:
        # 成功：推进 next_run_time，fail_streak 归零
        self._store.update(task_name, fail_streak=0)
        self._advance_next_run(task_name)
    else:
        # 失败：添加递增冷却（5→10→15→...→60 分钟）
        fail_count = self._store.get(task_name).fail_streak + 1
        cooldown = min(fail_count * 5, 60)  # 最多冷却 60 分钟
        next_retry = datetime.now() + timedelta(minutes=cooldown)
        self._store.update(task_name,
                          fail_streak=fail_count,
                          next_run_time=next_retry)
    self._store.save()  # 原子写盘
```

| 连续失败次数 | 冷却时间 |
|:--:|:--:|
| 1 | 5 分钟 |
| 2 | 10 分钟 |
| 3 | 15 分钟 |
| ... | ... |
| 12+ | 60 分钟（上限） |

**设计意图**：避免死循环反复执行一个必然失败的任务（如素材缺失、游戏维护）。冷却递增给用户留出修复时间窗口，成功后 `fail_streak` 自动归零。

## 五、ScriptWorker 调度循环异常保护（09-运行控制中心）

```python
def _run_schedule_loop(self):
    _consecutive_errors = 0
    while not self.is_stopped():
        try:
            # ... 正常的调度+执行流程 ...
            _consecutive_errors = 0  # 成功则归零
        except Exception as e:
            _consecutive_errors += 1
            self.log(f"调度循环异常: {e}", "ERROR")
            if _consecutive_errors > 10:
                self.log("连续异常过多，停止调度循环", "ERROR")
                break
            time.sleep(3)
```

**保护层次**：

| 层次 | 机制 | 触发条件 |
|------|------|---------|
| 步骤级 | StepResult.fail → error 分支 | 单步失败 |
| 任务级 | try/except 包裹 step.execute() | 任务代码崩溃 |
| 调度级 | 连续异常计数器 → 10 次自动停止 | 调度循环本身异常 |
| 调度级 | Scheduler fail_streak 冷却 | 任务反复失败 |

## 六、设备断连处理

```
设备连接断开
  → ADBClient 抛 DeviceConnectError
  → ScriptWorker 捕获
  → 发布 CONNECTION_LOST 事件
  → UI StatusBar 显示"未连接"（红色）
  → 调度循环暂停（预留）
  → 用户可手动停止 / 等待重连
```

当前实现中，连接失败后 ScriptWorker 不会自动重连，需要用户介入。自动重连是未来增强方向。

## 九、容错设计原则总结

| 原则 | 实现 |
|------|------|
| **步骤原子性** | 步骤内部不中断，步骤边界检查停止信号 |
| **失败有兜底** | TaskGraph error 分支 → ErrorReturn → 回到庭院 |
| **失败不推进** | mark_done(success=False) 不推进 next_run_time |
| **递增冷却** | fail_streak × 5min，最多 60min，防止死循环 |
| **连续异常熔断** | ScriptWorker 连续 10 次异常自动退出 |
| **数据不丢失** | task_state.json 原子写盘，崩溃可恢复 |
| **运行有上限** | 每日操作次数 + 运行时长的防封号硬限 |
| **异常可追溯** | 日志 + 异常截图 + 事件历史 |
