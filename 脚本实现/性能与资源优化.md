> **文档性质**：长时间运行的资源管理、性能调优、磁盘空间控制  ｜  **配套**：部署与环境配置指南

## 一、内存优化

### 1.1 素材缓存

`Recognizer` 启动时将 `assets/` 下所有 PNG 预加载为灰度图缓存到内存中。

| 素材数量 | 单张大小 (1280×720区域) | 内存占用（灰度） |
|:--:|:--:|:--:|
| 20 张 | ~30KB | ~0.6 MB |
| 50 张 | ~30KB | ~1.5 MB |
| 100 张 | ~30KB | ~3.0 MB |
| 200 张 | ~30KB | ~6.0 MB |

**优化建议**：
- 素材裁剪尽量小（只保留特征区域），减少内存
- 不需要的素材及时从 `assets/` 删除
- 灰度图比彩色图节省 2/3 内存

### 1.2 截图缓存

每次 `Recognizer.find()` 调用都会触发一次 ADB 截图（~3MB BGR 全屏）。频繁识图时可能产生大量临时图像对象。

**优化建议**：
- `wait_any()` 内置轮询间隔（默认 0.5s），不要用 `while True: find()` 手动轮询
- `click_if_exists()` 不会截图（只检查缓存中上一次 `find()` 的结果），优先使用

## 二、CPU 优化

### 2.1 调度循环休眠

```python
while not self.is_stopped():
    task_name = scheduler.get_next_task()
    if not task_name:
        time.sleep(5)   # ← 无任务时休眠 5 秒，避免 CPU 空转
        continue
```

### 2.2 模板匹配开销

`cv2.matchTemplate()` 是全图扫描，在 1280×720 图像上单次耗时约 5~20ms。100 张素材轮询一次约 0.5~2 秒。

**优化建议**：
- 使用 `region` 参数限定搜索范围（如只看屏幕下半部分）
- 先匹配粗特征（大图），再匹配细特征（小图）
- 使用灰度匹配（`grayscale: true`）— 已默认开启

### 2.3 事件循环

Qt 事件循环 + QThread 分离确保 UI 线程不被阻塞。ScriptWorker 在工作线程中运行，不影响 UI 响应。

### 2.4 事件总线性能

| 优化点 | 实现 | 效果 |
|-------|------|------|
| 异步分发 | publish 入队即返回 | 发布者线程不等待 handler |
| 去重合并 | 短时间相同事件合并 | 防止事件风暴 |
| handler 超时 | 5 秒超时自动中断 | 防止慢 handler 阻塞后续事件 |
| 批量广播 | `set_states()` 合并多次更新为一次事件 | 减少 UI 刷新次数 |

### 2.5 调度循环自适应休眠

无到期任务时，休眠时间随空闲时长自适应增加（2 秒 → 5 秒 → 10 秒），一旦有新任务到期立即恢复。既避免 CPU 空转，又保证任务到期后及时响应。

## 三、磁盘优化

### 3.1 日志轮转

`loguru` 默认支持日志轮转。在 `global.yaml` 中配置：

```yaml
run:
  log_level: "INFO"
  # 日志保留天数（loguru 内置支持）
  # rotation: "10 MB"     # 单文件 10MB 后轮转
  # retention: "7 days"    # 保留 7 天
```

### 3.2 异常截图清理

异常截图保存在 `logs/snapshots/`，长时间运行可能积累大量文件。

```bash
# 手动清理 7 天前的截图
# Windows PowerShell:
Get-ChildItem logs/snapshots/*.png | Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-7) } | Remove-Item
```

### 3.3 task_state.json

单个文件 < 10KB，即使有 100 个任务也不会超过 100KB。该文件每次 `mark_done()` 都会原子写盘，但频率很低（每任务执行完一次），不影响性能。

### 3.4 磁盘占用预估

| 资源 | 预估占用 |
|------|:--:|
| 项目代码 | ~5 MB |
| 素材（100 张） | ~3 MB |
| 日志（7 天） | ~50 MB |
| 异常截图（累积） | 按需清理 |
| **合计** | **~60 MB** |

## 四、模拟器性能

### 4.1 分辨率影响

1280×720（默认）是性价比最高的分辨率：
- 比 1920×1080 少 60% 像素 → 模板匹配快 2~3 倍
- 素材在 720p 下足够清晰，不影响识别精度

### 4.2 帧率设置

模拟器帧率建议设置为 30fps（节省 CPU），不需要 60fps。

### 4.3 多开资源

每个额外模拟器实例约占用：
- 1~2 GB 内存
- 2~4 个 CPU 核心

2 个实例建议 16GB 内存 + 6 核 CPU。

## 五、长时间运行注意事项

### 5.1 内存泄漏检查点

| 检查项 | 正常范围 |
|--------|:--:|
| Python 进程内存 | < 500 MB |
| 运行 8 小时后内存 | 较启动时增长 < 100 MB |
| QThread 数量 | ≤ 3（主线程 + EventBus 分发 + ScriptWorker） |

### 5.2 定时重启建议

```
推荐策略：每天 00:00 Scheduler 自动重置计数器
如果连续运行 > 24h，建议手动重启一次以释放潜在内存碎片
```

### 5.3 监控指标

通过终端日志关注：
- 单次 `click_image` 耗时（正常 < 1s）
- 单次 `wait_any` 轮询次数（正常 1~5 次）
- `cv2.matchTemplate` 匹配耗时（正常 5~20ms）

如果发现异常增长，可能是内存不足或素材缓存膨胀。
