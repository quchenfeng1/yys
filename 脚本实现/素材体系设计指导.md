## 一、素材目录结构

```
assets/
├── 主界面/         ← 庭院场景 + 主界面UI按钮
├── 探索/           ← 探索地图、副本入口
├── 召唤/           ← 召唤界面
├── 商城/           ← 商城/商店界面
├── 战斗/           ← 战斗UI通用元素（挑战、胜利、失败）
├── 阴阳寮/         ← 寮相关界面（结界、道馆、麒麟）
├── 活动/           ← 限时活动界面
├── 通用/           ← 跨场景通用按钮（关闭、确认、返回）
└── 阵容/           ← 阵容预设标记图
```

**9 个分区说明**（来自 `core/image_manager.py` 的 `SCENE_SECTIONS`）：

| 分区 | 图标 | 场景描述 | 典型素材 |
|------|:--:|------|---------|
| 主界面 | 🏠 | 庭院、主界面入口 | 庭院标志、探索入口、町中入口、签到入口 |
| 探索 | 🗺 | 探索地图内副本入口 | 御魂入口、觉醒入口、秘闻入口、章节选择 |
| 召唤 | ✨ | 召唤界面 | 召唤按钮、十连按钮、跳过动画 |
| 商城 | 🛒 | 商城/商店 | 商城入口、购买按钮、每日免费礼包 |
| 战斗 | ⚔ | 战斗界面通用元素 | 挑战按钮、胜利标志、失败标志、准备按钮 |
| 阴阳寮 | 🏯 | 阴阳寮 | 寮入口、结界突破、道馆、麒麟 |
| 活动 | 🎪 | 限时活动 | 活动Banner、活动入口、活动兑换 |
| 通用 | 🔧 | 跨场景通用按钮 | 关闭按钮、确认按钮、返回按钮 |
| 阵容 | 👥 | 阵容预设 | 阵容验证图、御魂配置图 |

## 二、素材命名规范

### 2.1 格式

```
{分区}/{类型}-{名称}.png
```

| 组成部分 | 说明 | 示例 |
|---------|------|------|
| 分区 | 9 个分区名之一 | `主界面` / `战斗` / `通用` |
| 类型 | `识别`（场景标志）/ `按钮`（可点击目标）/ `标志`（状态） | `按钮` |
| 名称 | 简短中文描述 | `挑战` / `确定` / `胜利` |

### 2.2 命名示例

| 素材用途 | 正确命名 | 错误命名 |
|---------|---------|---------|
| 庭院中点击探索入口 | `主界面/按钮-探索入口.png` | `explore_btn.png` |
| 副本中点击挑战 | `战斗/按钮-挑战.png` | `challenge.png` |
| 检测胜利画面 | `战斗/标志-胜利.png` | `win.png` |
| 通用关闭按钮 | `通用/按钮-关闭.png` | `close.png` |
| 确认庭院场景 | `主界面/识别-庭院标志.png` | `courtyard_main.png` |
| 式神录入口 | `主界面/按钮-打开式神录.png` | `shikigami.png` |

### 2.3 代码中引用

```python
# 素材路径是 assets/ 下的相对路径（去 .png 扩展名，用 / 分隔）
# assets/主界面/按钮-探索入口.png  →  "主界面/按钮-探索入口"
# assets/战斗/按钮-挑战.png       →  "战斗/按钮-挑战"
# assets/通用/按钮-关闭.png       →  "通用/按钮-关闭"

executor.click_image("主界面/按钮-探索入口")
recognizer.find("战斗/标志-胜利")
recognizer.wait_any(["战斗/标志-胜利", "战斗/标志-失败"], timeout=180)
recognizer.exists("主界面/识别-庭院标志", threshold=0.7)
```

## 三、素材索引机制

`Recognizer` 启动时扫描 `assets/` 下所有 `.png` 文件，按**去掉扩展名的相对路径**建立内存索引：

```
assets/
├── 主界面/
│   ├── 识别-个人名片.png       →  索引: "主界面/识别-个人名片"
│   ├── 按钮-打开底部菜单.png   →  索引: "主界面/按钮-打开底部菜单"
│   └── 按钮-打开式神录.png     →  索引: "主界面/按钮-打开式神录"
├── 战斗/
│   ├── 按钮-挑战.png          →  索引: "战斗/按钮-挑战"
│   └── 标志-胜利.png          →  索引: "战斗/标志-胜利"
└── 通用/
    ├── 按钮-关闭.png          →  索引: "通用/按钮-关闭"
    └── 按钮-确定.png          →  索引: "通用/按钮-确定"
```

启动时 `Recognizer._load_templates()` 预加载全部素材到内存（灰度图），后续匹配直接使用缓存，无需磁盘 IO。

## 四、素材采集规范

### 4.1 截图要求

| 要求 | 说明 |
|------|------|
| 分辨率 | 必须与脚本配置一致（默认 `1280×720`） |
| 格式 | PNG（无损） |
| 裁剪 | 只保留目标按钮/标志的**最小完整区域**，不含背景 |
| 特征 | 选取**唯一且稳定**的视觉特征（不受文字变化影响的部分） |

### 4.2 采集流程

```
1. 模拟器运行游戏 → 到达目标页面
2. 使用模拟器截图功能（或 ADB screenshot）
3. 用图片编辑工具裁剪出目标按钮/标志
4. 保存为 PNG，放入 assets/{分区}/ 对应目录
5. 在 UI「图片配置」面板中确认素材已加载
```

### 4.3 素材质量检查

```bash
# 使用 tools/asset_helper.py 检查素材状态
python tools/asset_helper.py --list      # 列出所有素材（按分区）
python tools/asset_helper.py --tree      # 树形展示目录结构
python tools/asset_helper.py --check     # 校验所有素材能否被读取
python tools/asset_helper.py --missing   # 对比代码引用找出缺失素材
```

## 五、识别参数

### 5.1 全局参数（`global.yaml`）

```yaml
recognize:
  threshold: 0.8      # 默认匹配置信度阈值（0~1）
  grayscale: true     # 是否灰度匹配（推荐 true，速度更快）
  method: template    # 匹配方法（当前仅支持 template）
```

### 5.2 阈值调节

| 场景 | 建议阈值 | 原因 |
|------|:--:|------|
| 高对比度按钮（白底黑字） | 0.85~0.95 | 特征清晰，误匹配风险低 |
| 场景标志（带背景纹理） | 0.65~0.80 | 背景可能有微小变化 |
| 弹窗关闭按钮（通用） | 0.75~0.85 | 可能有多处相似按钮 |
| 战斗中动态元素 | 0.60~0.75 | 动画效果导致变化 |

**原则**：阈值越高，误识别率越低，但漏识别率越高。调试阶段可降低到 0.6 确保能找到，正式运行调回 0.8。

### 5.3 代码中覆盖阈值

```python
# 对特定素材使用不同于全局默认的阈值
executor.click_image("战斗/按钮-挑战", threshold=0.75)

# exists() 用于判断"是否在某个场景"，阈值可宽松
recognizer.exists("主界面/识别-庭院标志", threshold=0.7)

# wait() 用于等待页面加载，阈值可适中
recognizer.wait("战斗/标志-胜利", timeout=180, threshold=0.8)
```

## 六、模板匹配原理

```
截图 (1280×720 全屏)
  → 灰度转换（cv2.cvtColor → GRAY）
  → cv2.matchTemplate(截图, 模板, TM_CCOEFF_NORMED)
  → 得分矩阵（每个像素位置都有一个 0~1 的匹配分）
  → 找最高分位置
  → 分数 ≥ threshold → 返回 MatchResult(中心坐标, 置信度)
  → 分数 < threshold → 返回 None（未找到）
```

**MatchResult** 结构：
```python
@dataclass
class MatchResult:
    name: str          # 模板名
    center: tuple      # 中心坐标 (x, y)
    topleft: tuple     # 左上角 (x, y)
    size: tuple        # (w, h)
    confidence: float  # 置信度 0~1
```

## 七、素材管理面板

在 UI 中点击「图片配置」→ 选择分区，可进行：

| 操作 | 功能 |
|------|------|
| 查看 | 缩略图 + 名称 + 备注 + 尺寸 |
| 添加 | 从本地选择 PNG → 自动复制到对应分区目录 |
| 编辑 | 修改备注和所属分区 |
| 删除 | 从磁盘移除文件 |
| 预览 | 真实尺寸弹窗查看 |

素材变更后自动更新 `Recognizer` 的模板缓存（通过 `ImageManager` 触发事件）。

## 八、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 始终找不到素材 | 分辨率不匹配 | 确认模拟器分辨率 = `screen.width × screen.height` |
| 偶尔找不到 | 阈值太高 | 降低到 0.7，或在 `click_image` 中单独指定 |
| 找错位置 | 模板不够独特 | 扩大裁剪范围，包含更多唯一特征 |
| 索引名写错 | 使用了 Windows 反斜杠 | 统一用正斜杠 `/`，如 `"主界面/按钮-探索入口"` |
| 新素材不生效 | 缓存未刷新 | 重启脚本或重新初始化 Recognizer |
| 中文路径读取失败 | cv2.imread 不支持中文 | Recognizer 已内置 PIL 桥接，无需担心 |
