## 一、目的与作用

**一句话定位**：脚本任务的文件级生命周期管理器。扫描 tasks/ 目录发现所有游戏任务和通用模块，解析 Python 源码提取元数据，提供创建、删除、打开编辑功能。

**与 04-任务模块 的区别**：
- **04-任务模块**：运行时执行任务的引擎（TaskStep / TaskGraph / 通用模块）
- **13-任务管理模块**：开发时的任务文件管理（扫描/创建/删除/打开编辑）

**核心职责**：
1. **任务发现**：扫描 tasks/ 下四类目录的全部任务文件
2. **通用模块发现**：扫描 tasks/common/ 目录的通用模块
3. **元数据解析**：从 Python 文件中提取显示名、功能描述、分类
4. **新建任务**：在指定分类下生成 Python 骨架文件
5. **删除任务**：安全删除（重命名而非物理删除）
6. **打开编辑**：用系统默认程序打开 .py 文件

## 三、运行逻辑

### 3.1 任务发现流程

```
scan_all()
  → 递归扫描 daily/ / permanent/ / event/ / special/ 四个目录
  → 对每个 .py 文件提取元数据（display_name / description / docstring）
  → 扫描 common/ 目录提取通用模块元数据
  → 缓存到内存
  → 返回全量列表
```

### 3.2 元数据提取规则

从 Python 文件中按优先级提取：`display_name` 类属性（最高优先）> `description` 类属性 > 模块级 docstring 第一行（fallback）。

**提取方式**：使用 `ast` 模块（抽象语法树）安全解析源码，提取类级别的字符串赋值语句。不执行也不导入 .py 文件，避免运行不可信代码。不使用正则表达式，防止被字符串内的注释或多行文本干扰。

### 3.3 新建任务

在指定分类目录下生成 Python 骨架文件，包含完整的类结构：类名、name 属性、display_name 属性、description 属性、execute() 方法默认实现、模块级 docstring。

### 3.4 删除与恢复任务

**删除**：不物理删除文件，而是重命名为 `.deleted` 后缀，保留文件内容以便恢复。

**恢复**：`restore_task(task_name)` 将 `.deleted` 文件重命名回 `.py`，恢复任务到可用状态。

## 四、重点功能

### 4.1 自动扫描发现

新增任务文件放入 tasks/ 对应目录后自动被发现，无需手动注册或修改配置文件。

### 4.2 元数据自动提取

从 Python 源码自动提取显示名和描述，无需额外编写元数据文件。

### 4.3 安全删除

重命名而非删除，防止误操作导致代码丢失。

## 五、实现思路

### 5.1 模块结构

```
core/
└── task_manager.py       ← 任务管理器（纯数据层，不依赖 PyQt5）
```

### 5.2 核心数据结构和类型签名

**TaskMeta（任务元数据）**：
```
@dataclass
class TaskMeta:
    filepath: str         # 文件绝对路径
    name: str             # 文件名（不含 .py，如 "soul_12"）
    display_name: str     # 显示名（如 "御魂12层"）
    description: str      # 功能描述
    category: str         # 分类（daily/permanent/event/special/common）
    module_name: str      # Python 模块名（如 "tasks.daily.soul_12"）
```

### 5.3 核心方法定义

**TaskManager（任务文件管理器）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `scan_all() -> list[TaskMeta]` | 🔓 公开 | `TaskManager` | 扫描全部任务和通用模块。清除并重建 `_cache` |
| `get_all_tasks() -> list[TaskMeta]` | 🔓 公开 | `TaskManager` | 获取全部游戏任务列表（从 `_cache` 读取） |
| `get_tasks_by_category(cat) -> list[TaskMeta]` | 🔓 公开 | `TaskManager` | 按分类获取任务列表（从 `_cache` 过滤） |
| `get_generic_modules() -> list[TaskMeta]` | 🔓 公开 | `TaskManager` | 获取通用模块列表（从 `_cache` 读取） |
| `find_by_name(name) -> TaskMeta \| None` | 🔓 公开 | `TaskManager` | 按文件名查找任务，未找到返回 `None`（已在 5.2 节正确标注） |
| `open_file(task_name_or_path) -> None` | 🔓 公开 | `TaskManager` | 用默认程序打开 .py 文件。参数为文件名或文件路径 |
| `new_task(category, name, display) -> str` | 🔓 公开 | `TaskManager` | 新建任务骨架，返回文件路径 |
| `delete_task(task_name) -> None` | 🔓 公开 | `TaskManager` | 安全删除任务（重命名为 .deleted） |
| `restore_task(task_name) -> None` | 🔓 公开 | `TaskManager` | 恢复已删除任务（将 .deleted 重命名回 .py） |
| `get_category_stats() -> dict[str, int]` | 🔓 公开 | `TaskManager` | 获取各分类的任务数量统计（分类名 → 数量） |
| `find_missing_assets() -> list[str]` | 🔓 公开 | `TaskManager` | 遍历 tasks/ 下所有 .py 文件，正则匹配 `click_image("xxx")` 等模板引用名，与 assets/ 目录对比，返回缺失的素材名列表 |

### 5.4 核心流程

**任务发现流程**：
```
scan_all()
  → 递归扫描 daily/ / permanent/ / event/ / special/ 四个目录
  → 对每个 .py 文件提取元数据（display_name / description / docstring）
  → 扫描 common/ 目录提取通用模块元数据
  → 缓存到 _cache
  → 返回全量列表
```

**新建任务流程**：
```
new_task("daily", "soul_12", "御魂12层")
  → 在 tasks/daily/ 下生成 soul_12.py 骨架文件
  → 包含类结构：类名、name/display_name/description 属性、execute() 默认实现
  → 返回文件路径
```

### 5.5 关键设计

- **纯数据层**：不依赖 UI 框架，可在命令行和 UI 中通用
- **元数据缓存**：避免重复扫描
- **新建任务模板**：保证代码风格一致
- **安全删除**：重命名而非物理删除，防止误操作
