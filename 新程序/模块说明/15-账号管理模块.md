## 一、目的与作用

**一句话定位**：账号配置与生命周期管理。加载 accounts.yaml，管理主号和小号的配置信息，处理账号切换，过滤各账号可执行的任务范围。

**为什么需要这个模块**：

脚本支持多模拟器多开，每个模拟器绑定一个游戏账号。不同账号有不同的角色和任务范围：

- **主号（main）**：执行所有任务（日常+副本+活动）
- **小号（sub1/sub2/...）**：只执行产出类任务（permanent 副本）

这些逻辑散落在各模块中会导致紧耦合。账号管理模块统一管理账号信息，其他模块通过查询接口获取当前账号配置。

**核心职责**：
1. **账号配置加载**：加载 accounts.yaml，解析主号和小号配置
2. **账号切换**：切换当前操作账号，通知连接模块切换设备
3. **角色管理**：区分主号/小号角色，提供角色判断接口
4. **任务范围过滤**：根据当前账号角色，返回可执行的任务列表
5. **多开协调**：管理多开账号列表，提供切换目标
6. **组队协调**：管理主号与小号之间的组队关系，提供组队伙伴查询和协调操作

**设计原则**：
- **单一数据源**：所有账号信息从 accounts.yaml 加载，本模块统一管理
- **切换即通知**：账号切换时通过事件总线通知相关模块（连接模块切换设备、状态管理更新当前账号）

## 三、运行逻辑

### 3.1 账号切换流程

```
切换账号到 "sub1"
  → 1. 从 _accounts 中查找 "sub1" 的配置
  → 2. 未找到 → 返回 False，记录错误日志
  → 3. 调 _connection.switch_device("sub1的device_id") → 切换模拟器连接
  → 4. 连接失败 → 尝试重新连接原设备（`_connection.switch_device(old_device_id)`），返回 False
  → 5. 更新 _current_id = "sub1"
  → 6. 更新状态管理：current_account = "sub1", account_role = "sub"
  → 7. 发布 account_switched 事件（含 account_id, role）
  → 8. 通知调度模块刷新日程表（任务范围变化）
  → 9. 返回 True
```

### 3.2 任务范围过滤

```
获取当前账号可执行的任务列表
  → 1. 查当前账号的 task_scope（如 ["daily", "permanent"]）
  → 2. 从全部任务中筛选出分类在 task_scope 内的任务
  → 3. 返回过滤后的列表
```

主号默认所有任务可执行，小号仅可执行 permanent 类任务。

### 3.3 多开遍历模式

脚本支持"遍历所有账号"模式：

```
1. 从主号开始执行
2. 主号所有任务完成后 → 切换到 sub1
3. sub1 任务完成后 → 切换到 sub2
4. 所有账号完成后 → 回到主号等待下一轮
```

由运行控制中心驱动，账号管理模块提供账号列表和切换接口。

### 3.4 组队协调流程

当主号执行需要组队的战斗任务时，自动协调小号参与：

```
主号战斗任务开始前 → 检查任务是否需要组队（task_config.teaming）
  │
  ├── 需要组队：
  │     → 获取同 group 的小号列表（get_teaming_partners）
  │     → 对小号逐一执行：
  │         ① 切换到小号（switch_to sub1）
  │         ② 等待加载 → 检测庭院/组队界面
  │         ③ 执行组队加入操作（接受邀请 / 申请入队）
  │         ④ 切换回主号
  │     → 主号发起组队（创建队伍 / 邀请）
  │     → 进入战斗
  │
  └── 不需要组队：正常执行
```

组队协调由 **09-运行控制中心** 驱动，**15-账号管理模块** 提供账号查询和切换支持，具体的组队操作由 **04-任务执行引擎** 的通用模块实现。

## 四、重点功能

### 4.1 角色区分

主号和小号执行不同的任务范围，小号不执行日常任务（签到、悬赏等），只产出资源。

### 4.2 切换联动

账号切换时自动通知连接模块切换模拟器、通知状态管理更新、通知调度模块刷新任务范围。一次切换，多模块联动。

### 4.3 配置驱动

所有账号信息通过 accounts.yaml 配置，新增账号无需改代码。

## 五、实现思路

### 5.1 模块结构

```
core/
└── account_manager.py    ← 账号管理主入口
```

### 5.2 核心数据结构和类型签名

**TeamAction（组队协调动作枚举）**：
```
class TeamAction:
    ACCEPT_INVITE = "accept_invite"   # 接受组队邀请
    APPLY_TEAM = "apply_team"         # 申请入队
    LEAVE_TEAM = "leave_team"         # 离开队伍
    PREPARE_JOIN = "prepare_join"     # 前置准备（打开组队界面等）
```

> `coordinate_action(account_id, action, params)` 的 `action` 参数取值同上。执行流程：切换账号 → 更新 `sub_account_status` → 发布 `coordinate_action` 事件（携带有 `account_id`, `action`, `params`）→ **09-运行控制中心** 订阅后通过 Executor 执行实际识图/点击。本模块**不直接执行游戏内操作**，仅切换账号 + 更新状态 + 发布事件。

### 5.3 核心方法定义

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `load_accounts() -> None` | 🔓 公开 | `AccountManager` | 从 accounts.yaml 加载全部账号配置。由 **16-应用启动引导** 在初始化时调用 |
| `switch_to(account_id) -> bool` | 🔓 公开 | `AccountManager` | 切换到指定账号（含设备切换） |
| `get_current() -> AccountInfo \| None` | 🔓 公开 | `AccountManager` | 获取当前账号信息 |
| `get_task_scope() -> list[str]` | 🔓 公开 | `AccountManager` | 获取当前账号可执行的任务分类 |
| `get_all_accounts() -> list[AccountInfo]` | 🔓 公开 | `AccountManager` | 获取全部账号列表 |
| `is_main() -> bool` | 🔓 公开 | `AccountManager` | 当前是否主号 |
| `switch_next() -> bool` | 🔓 公开 | `AccountManager` | 按 accounts.yaml 中 sub_accounts 列表顺序遍历。当前为 main → 切到第一个 sub；当前为最后一个 sub → 返回 False（无更多账号）。返回 False 后调用方（09-运行控制中心）应自行调用 `switch_to("main")` 回到主号，而非继续调用 switch_next |
| `get_teaming_partners(group) -> list[AccountInfo]` | 🔓 公开 | `AccountManager` | 获取指定分组中可用的组队小号列表 |
| `prepare_teaming(task_name) -> dict[str, bool]` | 🔓 公开 | `AccountManager` | 为指定任务准备组队：依次唤醒小号、完成前置操作。返回 `{account_id: 是否就绪}` 字典，调用方根据可用小号数量决定是否继续组队。某个小号唤醒失败时（连接断开/游戏未登录）对应值为 False，不影响其他小号 |
| `coordinate_action(account_id, action, params) -> bool` | 🔓 公开 | `AccountManager` | 在指定账号上执行协调操作（如"接受邀请"、"申请入队"） |

### 5.4 核心流程

**账号切换流程**：
```
switch_to("sub1")
  → 从 _accounts 查找 "sub1" 配置
  → 未找到 → 返回 False，记录错误日志
  → 调 01-设备连接模块.switch_device(device_id) → 切换模拟器连接
  → 连接失败 → 回退原账号，返回 False
  → 更新 _current_id = "sub1"
  → 更新 07-运行时状态管理：current_account = "sub1", account_role = "sub"
  → 发布 account_switched 事件到 08-事件通信总线
  → 通知 05-时间调度模块 刷新日程表（任务范围变化）
  → 返回 True
```

### 5.5 关键设计

- **切换即通知**：`switch_to()` 内部发布 `account_switched` 事件，相关模块订阅后自行响应
- **设备解耦**：账号管理通过事件总线通知切换，不直接持有连接模块引用
- **配置驱动**：task_scope 在 accounts.yaml 中配置，灵活控制各账号执行范围

### 6.2 对外部模块的调用

| 被调用方 | 调用方式 | 说明 |
|---------|---------|------|
| **06-配置管理中心** | 读配置 | 读取 accounts.yaml 账号配置 |
| **01-设备连接模块** | 调用 | 切换账号时调 `switch_device()` 切换模拟器 |
