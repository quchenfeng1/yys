# 01-设备连接模块（Device Connection Module）

> **类型**：核心运行层  ｜  **对应说明书**：ADBClient 5.1 + EmulatorManager  ｜  **对应用户模块**：#8 连接模块

---

## 一、目的与作用

**一句话定位**：封装模拟器ADB连接与底层设备操作，对上层完全屏蔽ADB命令细节，统一连接错误的抛出口。是整套系统最底层的"手和眼"。

**核心职责**：
1. **连接管理**：建立/断开/检测ADB连接，支持多模拟器多开（每个账号绑定独立端口）
2. **设备操作**：截图、点击、滑动、按键、文本输入——最底层的硬件操作
3. **状态监控**：心跳检测连接是否存活，断线时通过事件总线广播
4. **自动重连**：断线后按退避策略尝试恢复连接，期间暂停设备操作
5. **错误出口**：所有连接相关异常从此模块抛出（按错误类型分层，非单一异常）

**设计原则**：
- 最底层的执行器，不包含任何业务逻辑
- 截图返回原始图像数据，不做识别（识别归识图模块）
- 点击只接受坐标参数，不做防封号偏移（防封号归安全模块）
- 严格只读模拟器设置，禁止修改模拟器系统配置

## 二、模块属性与依赖

### 2.1 依赖注入（外部模块引用）

| 属性名 | 类型 | 作用域 | 作用 |
|--------|------|--------|------|
| `_config` | `ConfigManager` | 🔒 私有 | 读取 adb 路径、端口、设备ID等配置 |
| `_event_bus` | `EventBus` | 🔒 私有 | 发布 connection_lost / connection_restored / connection_error |
| `_state_manager` | `StateManager` | 🔒 私有 | 更新 connection_status、active_device_id |

### 2.2 对外暴露属性（其他模块可读取）

通过状态管理模块或直接查询接口读取。

| 属性名 | 类型 | 作用域 | 说明 |
|--------|------|--------|------|
| `connection_status` | `ConnectionState` | 📖 只读对外 | 连接状态：connected / disconnected / reconnecting |
| `active_device_id` | `str \| None` | 📖 只读对外（@property） | 当前操作的设备ID（如 `127.0.0.1:16384`） |
| `screen_size` | `tuple[int, int]` | 📖 只读对外 | 模拟器屏幕分辨率 (width, height)，通过 `get_screen_size()` 获取 |

### 2.3 内部私有属性

| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_device_pool` | `dict[str, ADBClient]` | 设备连接池：device_id → ADBClient 映射，管理多设备连接 |
| `_pool_lock` | `Lock` | 保护 `_device_pool` 和 `_active_device` 的线程安全锁。所有对设备池的读写必须先获取此锁 |
| `_active_device` | `ADBClient \| None` | 当前正在操作的 ADBClient 实例。受 `_pool_lock` 保护 |
| `_heartbeat_thread` | `Thread \| None` | 后台心跳检测线程引用（守护线程） |
| `_reconnect_thread` | `Thread \| None` | 当前活跃的重连临时线程引用（守护线程）。断线后由 `ConnectionManager` 创建，重连完成或超时后置 `None` |
| `_quality_records` | `dict[str, deque[float]]` | 各操作延迟记录：操作名 → 最近100次耗时（毫秒）。`deque` 线程安全地追加，无需额外加锁 |
| `_conn_pause_event` | `Event` | 连接暂停信号：重连期间设置此事件，screenshot/click 等操作在调用前检查并等待 |
| `_adb_timeout` | `float` | ADB 命令超时秒数（默认 15 秒）。所有 `subprocess.run()` 调用均携带此超时参数 |

## 三、运行逻辑

### 3.1 连接生命周期

```
建立连接：检测ADB路径 → 连接设备 → 验证连通性 → 获取屏幕信息 → 记录活动设备
                                                    失败 → 抛出连接异常

断开连接：停止心跳 → 设置 _conn_pause_event（阻止新操作）
         → 获取 _pool_lock → 断开ADB会话 → 清理设备池 → 释放锁 → 更新连接状态

切换设备：获取 _pool_lock → 保存当前设备上下文
         → 从连接池查找目标设备
         ├── 有 → 切换 _active_device 引用
         └── 无 → 新建连接 → 加入设备池 → 切换引用
         → 释放锁
```

> **线程安全规则**：
> - `_device_pool` 和 `_active_device` 的所有读写必须持有 `_pool_lock`
> - `screenshot()` / `click()` 等操作开始时先获取锁，读取 `_active_device`，释放锁后再执行命令
> - 心跳重连时同样先获取锁再替换 `_active_device`
> - 获取锁的超时设为 3 秒，避免死锁
> - **锁释放后的竞态说明**：ADB 命令通过 `subprocess.run()` 异步执行，无法在子进程运行期间持有锁。
>   释放锁到命令实际执行之间存在微小的竞态窗口（微秒级）。在此期间心跳可能切换 `_active_device`，
>   导致命令发往了错误的设备。但因 ADB 命令包含 `-s serial` 参数，命令目标由 serial 决定而非
>   `_active_device`，连接池切换只会影响下次读取。因此**此竞态窗口不会导致数据损坏或崩溃**，
>   最坏情况是命令执行失败，由超时和重试机制兜底。

### 3.2 连接暂停与恢复机制（防止操作与重连冲突）

设备操作在执行前必须检查当前连接状态：

```
screenshot() / click(x, y) / swipe(...) 等操作入口
  → 检查 _conn_pause_event 是否被设置
  ├── 已设置（重连中）→ 等待 _conn_pause_event（超时 10 秒）
  │     ├── 等待期间重连完成（event 被清除）→ 继续执行
  │     └── 超时 → 抛出 DeviceReconnectingError
  └── 未设置 → 正常执行操作
```

> **暂停触发时机**：心跳检测到断线时设置 `_conn_pause_event`，同时通知 `ConnectionManager` 启动独立临时线程执行退避重连。
> **恢复时机**：重连成功或全部重试失败后由临时线程清除 `_conn_pause_event`。
> **为何不由心跳直接管理**：避免心跳线程被耗时的退避重连循环阻塞，确保其能快速响应 `stop()` 信号。
> **目的**：防止在 `_active_device = None` 期间调用设备操作导致 `AttributeError`。

### 3.3 心跳检测

后台线程定期（默认30秒）执行连通性检测。心线程**仅负责检测**，发现断线后通过事件总线通知 `ConnectionManager` 启动重连，自身不执行耗时的重连尝试。

```
心跳线程定期唤醒（默认30秒）
  → 执行 adb shell echo ok 连通性检查（timeout=5s）
  ├── 成功 → 继续等待下一周期
  └── 失败 → 发布 connection_lost 事件
            → 设置 _conn_pause_event（暂停所有设备操作）
            → 返回等待下一周期（不阻塞于重连）
```

> **连通性检测命令**：使用 `adb shell echo ok`（轻量，约 50ms），避免使用 `adb get-state`（较慢）。
> **线程协作**：心跳线程仅在设置 `_conn_pause_event` 时短暂操作，不持有 `_pool_lock`。
> **轻量化目的**：心跳线程保持轻量可快速响应 `stop()` 信号，避免因长时间重连阻塞导致无法退出。

`ConnectionManager` 收到 `connection_lost` 事件后（或其内部调度逻辑检测到断线状态），启动独立的重连流程。重连在一个**临时后台线程**中执行，与心跳周期完全解耦：

```
重连流程（在独立临时线程中执行）
  → 按退避策略尝试重连（1s→2s→4s→8s→16s，最多5次）
     每次重试：
       获取 _pool_lock（超时 3s）
         → 调用 ADBClient.reconnect() 执行单次连接尝试
         ├── 成功 → 更新 _active_device → 发布 connection_restored
         │        → 退出重试循环
         └── 失败 → 释放 _pool_lock
                  → 等待下次退避（含 ±20% 随机抖动）
     全部失败 → 发布 connection_error
  → 清除 _conn_pause_event（恢复设备操作）
  → 线程结束
```

> **退避含随机抖动**：每次退避间隔加入 ±20% 随机抖动，避免固定间隔模式。
> **临时线程为守护线程**：确保程序退出时不会被重连线程阻塞。
> **与旧设计的区别**：原方案中心跳线程自身执行重连，断线后心线程会阻塞在退避循环中长达约31秒（1+2+4+8+16），期间无法响应 `stop_heartbeat()` 的 `join()` 超时信号。新方案将检测与恢复分离后，心跳线程始终轻量，重连线程可独立被中断。

### 3.4 多开切换

维护多设备连接池，AccountManager 切换账号时调用切换设备接口。切换操作受 `_pool_lock` 保护：

```
switch_device(target_id)
  → 获取 _pool_lock
  → 保存当前 device_id 到临时变量
  → 从 _device_pool 查找 target_id
  ├── 存在 → 将 _active_device 指向目标 ADBClient
  └── 不存在 → adb connect target_id
              → 创建新 ADBClient → 加入 _device_pool
              → 将 _active_device 指向新实例
  → 更新状态管理中的 active_device_id
  → 释放 _pool_lock
  → 返回 True/False
```

> **ADB 连接模型的说明**：ADB 的"连接"实际是验证设备可达性并记录 serial number。`_device_pool` 中存储的 `ADBClient` 实例主要保存设备序列号、ADB 路径等配置信息，而非持久的 TCP 连接。每次 ADB 命令（截图/点击）都独立创建子进程执行。池化的意义在于**避免重复验证**和**快速切换**，而非复用连接。

### 3.5 连接质量监控

记录每次截图/点击/滑动的响应延迟，保留最近100次历史数据。使用 `deque` 确保线程安全的尾部追加和自动淘汰：

```
screenshot() / click() / swipe() 执行完毕后
  → 计算操作耗时（毫秒）
  → _quality_records["screenshot"].append(elapsed_ms)  ← deque 自动淘汰旧数据
  → 若 deque 长度 > 100 → 自动从左侧弹出（deque 的 maxlen 参数）
  → 计算平均延迟
  → 平均延迟 > 2000ms → 发布 connection_quality_warning 事件
  → 综合延迟、成功率、心跳等指标计算连接健康度（0-100分）
  → 健康度 < 50 → 主动触发重连
```

> **`deque` 优势**：`collections.deque(maxlen=100)` 的 `append()` 是线程安全的原子操作，
> 且自动保留最近100条记录，无需手动维护索引。

## 四、重点功能

### 4.1 分层异常体系

所有连接异常基于 `DeviceError` 基类，按错误类型分层：

| 异常类 | 触发场景 | 可恢复性 |
|--------|---------|---------|
| `DeviceError` | 所有设备异常的基类 | — |
| `DeviceConfigError` | ADB 未找到、路径配置错误 | 需用户修复配置 |
| `DeviceNotFoundError` | 设备 ID 无法连接（adb connect 失败） | 可能恢复 |
| `DeviceOfflineError` | 设备曾在线但已断开（adb devices 显示 offline） | 可重试 |
| `DeviceTimeoutError` | ADB 命令执行超时（超过 `_adb_timeout`） | 可重试 |
| `DeviceReconnectingError` | 操作发起时设备正在重连 | 等待后重试 |
| `DeviceScreenshotError` | 截图返回空/损坏数据 | 可重试 |
| `DevicePermissionError` | ADB 权限不足 | 需用户修复 |

上层模块（14-执行器）可根据异常类型决定恢复策略：`DeviceTimeoutError` → 自动重试；`DeviceConfigError` → 通知用户停止运行。

### 4.2 连接暂停机制（防操作冲突）

重连期间通过 `_conn_pause_event` 暂停所有设备操作：
- 心跳检测到断线 → 设置 event → 操作等待或快速失败
- 重连成功/失败 → 清除 event → 操作恢复正常
- 操作等待超时（10秒）→ 抛出 `DeviceReconnectingError`
- 避免 `_active_device = None` 期间的 AttributeError 崩溃

### 4.3 截图优化与容错

使用 `adb exec-out screencap -p` 直接输出二进制流，避免文件IO开销。同时增加容错：
- 二进制流解析为 OpenCV 图像后检查是否为 `None`
- 解析失败自动重试 1 次
- 仍失败抛出 `DeviceScreenshotError`
- 所有 ADB 命令带超时参数（默认 15 秒）

> **内存与性能说明**：一张 1080p 截图的 PNG 原始数据约 200~500KB，
> 解码为 OpenCV 的 BGRA `np.ndarray` 后约 8MB（1920×1080×4 字节）。
> 在轮询等待（如 `wait_any`）场景下，每轮截图都会产生新的数组分配，
> Python GC 会自动回收旧数组，不会造成内存泄漏。但若每秒截图多次，
> 频繁的内存分配可能触发 GC 抖动。优化方案（可选实现）：
> - 在 `ADBClient` 层对截图做 JPEG 压缩（质量 85%）减小带宽
> - 识别模块的 `_screenshot_cache` 在同一任务步骤内复用截图，减少 ADB 调用
> - 降低截图分辨率：`adb shell wm size 720x1280` 再截图（需注意修改回原始分辨率）

**截图缓存策略**：`screenshot()` 方法可增加可选参数 `use_cache=False`。当为 `True` 时：
- 若上次截图时间在 0.5 秒内，直接返回缓存的上一次截图 `np.ndarray`
- 超过 0.5 秒或缓存为空，执行新截图并更新缓存
- 适用于同一任务步骤内多次 `find()` 操作复用同一帧，减少 ADB 调用

**截图质量可配置**：在高频率轮询场景下，可增加配置参数 `screenshot_quality`：
- `normal`（默认）：原始 `screencap -p`，最高质量
- `fast`：JPEG 压缩（质量 85%），带宽减少 60~80%，适合特征搜索场景
- `low_res`：临时降低截图分辨率（如 720p），内存占用降至约 3MB，需注意截图后恢复分辨率

### 4.4 自动重连与退避

断线后自动尝试重连，每次间隔递增（1s→2s→4s→8s→16s），最多5次。每次间隔加入 ±20% 随机抖动。重连期间设置 `_conn_pause_event` 暂停操作。通过事件总线通知各模块，运行控制模块可据此暂停调度。

> **检测与恢复分离**：心跳线程仅检测连通性，发现断线后通过事件通知 `ConnectionManager` 启动独立的重连临时线程。心跳线程自身不执行重连，始终保持轻量响应。这种设计避免了原方案中心跳线程被退避循环长期阻塞（最多约31秒）的问题，确保 `stop()` 信号能及时中断。

### 4.5 连接池（配置缓存）

设备连接池实质是**设备配置缓存**而非持久连接池。`ADBClient` 实例保存设备序列号、ADB 路径等配置，切换设备时避免重复验证。预热在 AccountManager 初始化时触发，提前验证所有已配置设备的连通性。

## 五、实现思路

### 5.1 模块结构

```
device/
├── connection.py        ← ConnectionManager 连接模块主入口（线程安全，含暂停机制）
├── adb_client.py        ← ADBClient ADB 命令封装层（子进程管理 + 超时 + 输出解析）
│                           每个实例绑定一个设备 serial，不同设备不同实例。
│                           截图/点击/滑动等原始 ADB 命令在此实现为实例方法。
│                           所有命令统一经过 `run()` 方法发出，由该方法负责：
│                           子进程创建、超时控制（`subprocess.run(timeout=...)`）、
│                           返回码检查、异常转换（将 subprocess 异常转为 DeviceError 子类）。
│                           ConnectionManager 依赖此类的实例执行设备操作，自身不直接调用 subprocess。
├── emulator.py          ← EmulatorDetector 模拟器自动发现
│                           职责：检测本机安装的模拟器类型、定位 ADB 可执行文件路径、
│                           枚举多开实例的 ADB 端口号。不管理连接生命周期。
│                           核心方法：
│                           - `detect_all() -> list[DeviceInfo]`：扫描本机返回所有可用的
│                             模拟器设备信息（类型、serial、adb_path、分辨率）
│                           - `get_adb_path() -> str`：按优先级返回 ADB 路径
│                             （MuMu 自带 → 蓝叠自带 → 系统 PATH）
│                           - `enumerate_ports(emulator_type) -> list[int]`：根据模拟器类型
│                             返回多开端口列表（MuMu 基址 16384 每开 +1）
│                           平台差异：macOS 下 MuMu 的 ADB 位于
│                           `/Applications/MuMu.app/Contents/MacOS/tools/adb`；
│                           Windows 下位于
│                           `C:\Program Files\MuMu\emulator\nemu\EmulatorShell\adb.exe`
└── heartbeat.py         ← HeartbeatMonitor 心跳检测子线程（连通性检查+发布事件+暂停信号）。**不包含重连逻辑**——重连由 ConnectionManager 在独立临时线程中执行
```

### 5.2 核心数据结构：ADBClient

`ADBClient` 是 `adb_client.py` 中定义的类，封装了针对**单个设备**的所有 ADB 命令。

**属性**：

| 属性名 | 类型 | 说明 |
|--------|------|------|
| `serial` | `str` | 设备序列号（如 `127.0.0.1:16384` 或 `emulator-5554`） |
| `adb_path` | `str` | adb 可执行文件路径（由 EmulatorDetector 提供） |
| `platform` | `str` | 模拟器类型标识（`mumu` / `bluestacks` / `ldplayer` / `generic`），用于兼容差异 |
| `screenshot_timeout` | `float` | 截图命令超时（默认 15s） |
| `input_timeout` | `float` | 输入命令超时（默认 10s） |

**核心方法**：

| 方法签名 | 可见性 | 作用 |
|---------|--------|------|
| `build_cmd(args) -> list[str]` | 🔒 私有 | 构造完整的 ADB 命令列表：`[adb_path, "-s", serial, *args]` |
| `run(args, timeout) -> subprocess.CompletedProcess` | 🔒 私有 | 执行 ADB 命令。调用 `subprocess.run(self.build_cmd(args), timeout=timeout, capture_output=True)`。超时抛 `DeviceTimeoutError`，返回码非零抛对应异常 |
| `screencap() -> bytes` | 🔓 公开 | 执行 `adb -s serial exec-out screencap -p`，返回原始 PNG 字节流 |
| `tap(x, y) -> None` | 🔓 公开 | 执行 `adb -s serial shell input tap x y` |
| `swipe(x1,y1,x2,y2,duration_ms) -> None` | 🔓 公开 | 执行 `adb -s serial shell input swipe x1 y1 x2 y2 duration` |
| `keyevent(key) -> None` | 🔓 公开 | 执行 `adb -s serial shell input keyevent KEYCODE_xxx` |
| `text(text) -> None` | 🔓 公开 | 执行 `adb -s serial shell input text <escaped_text>` |
| `am_start(package, activity) -> bool` | 🔓 公开 | 执行 `adb -s serial shell am start -n package/activity` |
| `foreground_package() -> str \| None` | 🔓 公开 | 尝试获取当前前台包名（dumpsys 方式） |
| `wm_size() -> tuple[int, int]` | 🔓 公开 | 执行 `adb -s serial shell wm size` 解析分辨率 |
| `echo() -> bool` | 🔓 公开 | 执行 `adb -s serial shell echo ok`，用于连通性检查（超时 5s） |
| `connect() -> bool` | 🔓 公开 | 执行 `adb connect serial`，用于首次连接设备 |

> **设计要点**：
> - `run()` 是所有命令的统一入口，封装了子进程创建、超时控制、返回码检查、异常转换
> - `ConnectionManager` 不直接调用 `subprocess`，而是委托 `ADBClient.run()`，保持职责单一
> - 不同平台的差异通过 `platform` 字段在 `EmulatorDetector` 中确定，`ADBClient` 不需要感知差异

### 5.3 核心方法定义

**ConnectionManager（连接模块主入口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `connect(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | 建立连接，未指定则连接默认设备。获取 `_pool_lock` 后执行 ADB 验证 |
| `disconnect(device_id=None) -> None` | 🔓 公开 | `ConnectionManager` | 断开指定设备连接。停止心跳、设暂停事件、加锁清理。`device_id` 为 None 时断开当前设备 |
| `is_connected(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | 检测连接状态（执行 `adb -s serial shell echo ok`，超时 5s） |
| `switch_device(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | 切换操作目标设备。获取 `_pool_lock`，从池中查找/新建，切换引用 |
| `screenshot() -> np.ndarray` | 🔓 公开 | `ConnectionManager` | 截图。先检查 `_conn_pause_event`（等待超时抛异常），获取 `_pool_lock` 读 `_active_device`，释放锁后执行 `adb exec-out screencap -p`（超时 15s），`cv2.imdecode` 转 numpy，失败重试 1 次 |
| `click(x, y) -> None` | 🔓 公开 | `ConnectionManager` | 坐标点击。先检查暂停事件，获取锁读设备，释放锁后执行 `adb shell input tap x y`（超时 10s） |
| `swipe(x1,y1,x2,y2,duration) -> None` | 🔓 公开 | `ConnectionManager` | 滑动操作。先检查暂停事件，获取锁读设备，释放锁后执行 `adb shell input swipe x1 y1 x2 y2 duration`（超时 15s） |
| `input_key(key) -> None` | 🔓 公开 | `ConnectionManager` | 模拟按键输入。先检查暂停事件，获取锁读设备，释放锁后执行 `adb shell input keyevent KEYCODE_xxx`（超时 5s） |
| `input_text(text) -> None` | 🔓 公开 | `ConnectionManager` | 输入文本字符串。内部处理 shell 特殊字符转义（空格→`%s`，`$`→`\\$` 等），执行 `adb shell input text <escaped_text>`（超时 10s）。用于登录时输入账号密码 |
| `get_screen_size() -> tuple` | 🔓 公开 | `ConnectionManager` | 获取屏幕分辨率。执行 `adb shell wm size` 解析宽高，抛出 `DeviceConfigError` 若无法获取（仅读取，不修改） |
| `launch_app(package, activity) -> bool` | 🔓 公开 | `ConnectionManager` | 启动 App。执行 `adb shell am start -n package/activity`（超时 15s），验证进程是否启动 |
| `is_app_foreground(package) -> str` | 🔓 公开 | `ConnectionManager` | 判断 App 的运行状态。返回枚举值：`FOREGROUND`（前台运行）、`BACKGROUND`（后台存活）、`NOT_RUNNING`（未运行）。优先使用 `adb shell dumpsys activity activities | grep mResumedActivity` 解析前台包名；若 dumpsys 格式不匹配则回退 `adb shell pidof <package>`（此时仅能区分 `NOT_RUNNING` 与 `RUNNING`，将存活状态标记为 `RUNNING`——调用方需注意此语义差异，自行决定是否接受模糊判断） |

| `reconnect(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | **单次**连接尝试。执行 `adb connect device_id` + `adb shell echo ok` 验证，成功则更新 `_active_device`。退避重试逻辑由上层（心调度或临时线程）编排，本方法仅做一次尝试。不操作 `_conn_pause_event` |

**HeartbeatMonitor（心跳检测）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `start(interval, conn_manager) -> None` | 🔓 公开 | `HeartbeatMonitor` | 启动心跳检测线程。保存 `ConnectionManager` 引用，检测到断线时发布 `connection_lost` 事件并设置 `_conn_pause_event`；**不执行重连**（重连由独立临时线程处理） |
| `stop() -> None` | 🔓 公开 | `HeartbeatMonitor` | 停止心跳检测。设置 `_stop_event` 退出标志，`join(timeout=5)` 等待线程退出；若超时则记录警告（线程可能卡在 ADB 命令中），将线程引用置 `None` 后返回（不阻塞程序退出） |

### 5.4 核心流程

**截图流程**（含暂停检查、锁保护、容错和超时）：
```
screenshot()
  → 检查 _conn_pause_event 是否设置
  │   ├── 是（重连中）→ 等待最多 10 秒
  │   │     ├── 等待期间重连完成（event 被清除）→ 继续
  │   │     └── 超时 → 抛出 DeviceReconnectingError
  │   └── 否 → 继续
  → 获取 _pool_lock（超时 3s，否则抛异常）
  → 读取 _active_device（若为 None → 释放锁 → 抛 DeviceOfflineError）
  → 释放 _pool_lock
  → 委托 ADBClient 执行 adb exec-out screencap -p（subprocess.run，timeout=15s）
  → 超时 → 抛 DeviceTimeoutError
  → cv2.imdecode 解析为 np.ndarray
  → 解析结果为 None → 重试 1 次
  │     ├── 重试成功 → 继续
  │     └── 重试失败 → 抛 DeviceScreenshotError
  → 记录耗时到 _quality_records["screenshot"].append(ms)
  → 返回图像数据
```

**点击流程**（含暂停检查和锁保护）：
```
click(x, y)
  → 检查 _conn_pause_event（等待最多 10s）
  → 获取 _pool_lock（超时 3s）
  → 读取 _active_device（若为 None 则抛 DeviceOfflineError）
  → 释放 _pool_lock
  → 执行 adb shell input tap x y（subprocess.run，timeout=10s）
  → 超时 → 抛 DeviceTimeoutError
  → 记录耗时到 _quality_records["click"].append(ms)
  → 返回
```

**文本输入流程**：
```
input_text(text)
  → 检查 _conn_pause_event（等待最多 10s）
  → 获取 _pool_lock（超时 3s）→ 读取 _active_device → 释放锁
  → 对 text 做 shell 转义处理：
      空格 → %s
      $   → \$（shell 变量前缀）
      "   → \"
      \   → \\
      &   → \&
      `   → \`
      !   → \!
  → 执行 adb shell input text <escaped_text>（subprocess.run，timeout=10s）
  → 超时 → 抛 DeviceTimeoutError
  → 记录耗时到 _quality_records["input_text"].append(ms)
  → 返回
```

**连接检测流程**（检测与重连分离）：
```
[心跳线程] 定期执行（默认30秒）
  → 执行 adb shell echo ok 连通性检查（timeout=5s）
  ├── 成功 → 等待下一周期
  └── 失败 → 发布 connection_lost 事件
            → 设置 _conn_pause_event（暂停设备操作）
            → 返回等待下一周期（不阻塞）

[独立临时线程] 由 ConnectionManager 在收到断线信号后启动
  → 按退避策略尝试重连（1s→2s→4s→8s→16s，最多5次）
     每次重试：
       获取 _pool_lock（超时 3s）
       → 调 ADBClient.reconnect() 单次连接尝试
         ├── 成功 → 更新 _active_device
         │        → 发布 connection_restored
         │        → 退出重试循环
         └── 失败 → 释放 _pool_lock
                  → 等待下次退避（含 ±20% 随机抖动）
     全部失败 → 发布 connection_error
  → 清除 _conn_pause_event（恢复设备操作）
  → 临时线程结束
```

### 5.5 关键设计

- **只读模拟器**：严格遵守用户权限边界，禁止 `wm size` / `wm density` 等写操作
- **ADB 路径自动检测**：MuMu 自带 adb 优先，找不到则 fallback 到系统 PATH
  - macOS: `/Applications/MuMu.app/Contents/MacOS/tools/adb` → 系统 PATH
  - Windows: `C:\Program Files\MuMu\emulator\nemu\EmulatorShell\adb.exe` → 系统 PATH
  - 多开端口：基址 16384，每开 +1（16385, 16386, ...）
- **截图优化**：使用 `adb exec-out screencap -p` 直接输出二进制流，避免文件 IO
- **异常分层**：`DeviceError` 基类 + 具体子类，上层按类型决定恢复策略
- **命令超时**：所有 ADB 子进程调用携带 `timeout` 参数（默认 15s），防止模拟器卡死导致永久阻塞
- **连接暂停机制**：重连期间通过 `_conn_pause_event` 暂停操作，防止 `NoneType` 崩溃
- **线程安全**：`_pool_lock` 保护设备池，`deque` 确保延迟记录线程安全
- **心跳退避重连**：断线后按指数退避重试，间隔含随机抖动（±20%）
- **设备池本质是配置缓存**：ADB 的"连接"是轻量的设备可达性验证，`_device_pool` 缓存的是设备序列号和路径配置，而非持久 TCP 连接
- **ADBClient 统一命令出口**：所有 ADB 命令经由 `adb_client.py` 的 `run()` 发出，封装子进程管理、超时和异常转换，`ConnectionManager` 不直接调用 subprocess
- **检测与重连分离**：心跳线程仅负责连通性检测，断线后由独立临时线程执行退避重连，避免心跳线程被重连循环阻塞
- **守护线程保证退出**：心跳线程和重连临时线程均设为守护线程，`stop_heartbeat()` 中 `join(timeout=5)` 超时后记录警告并将线程引用置 `None`，不阻塞程序关闭流程
- **孤儿进程限制**：ADB 命令通过 `subprocess.run(timeout=...)` 执行，超时后 `subprocess` 会 `kill()` 子进程；但若 Python 进程自身被强制终止（如 `SIGKILL`），由 `subprocess.Popen` 启动的 ADB 子进程可能成为孤儿进程。此为操作系统级限制，无法在模块内部完全避免。建议部署时配合进程管理器（如 `supervisor`）确保子进程清理
