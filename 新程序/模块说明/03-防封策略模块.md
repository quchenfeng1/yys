# 03-防封策略模块（Anti-Ban Strategy Module）

> **类型**：核心运行层  ｜  **对应说明书**：AntiDetect 5.4 + 第八部分防封号策略  ｜  **对应用户模块**：#7 安全模块

---

## 一、目的与作用

**一句话定位**：防封号策略引擎，为所有操作（点击/滑动/等待/节奏）生成拟人化随机参数，覆盖全操作链路，模拟人类操作行为。

**核心职责**：
1. **点击安全**：随机偏移坐标、贝塞尔曲线鼠标轨迹，避免固定落点
2. **滑动安全**：随机滑动时长、起止点微调，避免固定滑动模式
3. **等待安全**：随机延迟抖动（可打断），避免固定间隔被检测
4. **节奏安全**：走神暂停概率触发，模拟人类注意力波动（暂停期间保持最低活动防断线）
5. **文本输入安全**：模拟逐字键入的随机间隔，避免一次性粘贴被检测
6. **策略可调**：安全强度参数化，多档可切换，不影响业务代码

**设计原则**：
- **策略注入而非控制**：被 Executor 调用提供随机参数，不主导执行流程
- **全链路覆盖**：点击/滑动/等待/节奏，缺一不可
- **参数化**：所有安全参数从配置读取，支持热调整
- **可禁用**：调试模式下关闭所有安全处理，便于快速测试

| `_drift_lock` | `Lock` | 保护参数漂移的线程安全锁。`_check_drift()` 内部使用双重检查锁定模式，防止多线程并发执行 `_apply_drift()` 导致参数交错修改 |
| `_config_sub_id` | `str \| None` | 配置变更事件的订阅 ID，用于 `config_changed` 时重新加载 `_profile_params` |

## 三、运行逻辑

### 3.1 安全策略注入流程

安全模块不主动执行任何操作，而是被 Executor 调用提供随机参数：

```
14-执行器模块.click_image(template)
  → 02-图像识别模块.find(template) → 得到 MatchResult（含中心坐标+矩形宽高）
  → 03-防封策略模块.random_offset_in_bounds(cx, cy, w, h) → 图标矩形内安全偏移坐标
  → 03-防封策略模块.generate_trajectory(from_x, from_y, to_x, to_y) → 贝塞尔曲线路径点列表
  → 03-防封策略模块.sleep(0.3, 0.2, stop_event) → 可打断随机延迟
  → 03-防封策略模块.maybe_long_pause(stop_event) → 判断是否走神，内部含可打断随机时长
  → 14-执行器模块 将贝塞尔路径发送至 01-设备连接模块（多段 adb swipe 实现）
  → 14-执行器模块 记录结果到 12-日志监控中心
```

> **贝塞尔曲线在 ADB 上的实现说明**：ADB 的 `input tap` 不支持鼠标轨迹。实现方式是将贝塞尔路径的**起止控制点**拟合成**单条** `input swipe` 命令（起点→终点，duration 随机 50~100ms）。浏览器和游戏对 `input swipe` 的轨迹渲染会自动插值出弧线效果，视觉效果等效于贝塞尔曲线。相比多段 swipe（每段 10~15ms，10 段共 100~150ms + 累积延迟），单段方案更轻量且效果已足够。若需更精细的曲线，最多拆 2~3 段（每段覆盖路径的 1/3），总耗时仍控制在 80ms 以内。FAST 和 DEBUG 模式下跳过轨迹生成，直接使用 `input tap`。

### 3.2 随机参数生成规则

| 操作类型 | 随机参数 | 生成策略 |
|---------|---------|---------|
| **点击偏移** | 偏移半径 / 图标边界 | 优先使用 `random_offset_in_bounds` 在图标矩形内随机偏移，确保点击不超出目标边界；回退使用 `random_offset` 基于半径的正态分布偏移（结果钳制在 ±2σ 内） |
| **鼠标轨迹** | 路径点列表 | 贝塞尔曲线插值（4 控制点），每段 10~20px，路径点间距自适应曲线曲率。FAST/DEBUG 模式下跳过 |
| **滑动时长** | 毫秒数 | `random_swipe_duration(base)`：基础时长 ± 随机抖动（抖动范围由行为档案控制） |
| **滑动起止** | 坐标微调 | `random_offset(start_x, start_y, radius)` 微调起止点各一次 |
| **操作间隔** | 秒数 | `random_delay(base, jitter)`：基础延迟 ± 随机抖动。`sleep(base, jitter, stop_event)`：实际执行休眠（可打断） |
| **走神暂停** | 是否触发 + 时长 | `maybe_long_pause(stop_event)`：按概率触发（SAFE=15%），触发后休眠 5~15s（可打断）。休眠期间每隔 3s 检查一次 stop_event，避免无法停止 |
| **文本输入** | 逐字间隔 / 分组批量 | `random_typing_delay()`：模拟人类逐字输入间隔（80~250ms/字），含随机波动和偶尔的"停顿思考"（概率 5%，停顿 1~3s）。**分组策略**：长文本按 3~5 字一组拆分为多次 `adb shell input text` 调用而非逐字发送。例如输入 16 位密码时分 4 组发送，每组后等待随机间隔。总 ADB 调用次数从 N（逐字）降为 ceil(N/4)，大幅减少 IPC 开销 |

### 3.3 行为档案

四档安全强度，可在运行时随时切换。

**档案切换机制**：
```
用户在 UI 面板选择档案
  → 10-参数桥接模块 → 06-配置管理中心.set("global.anti_detect.profile", "safe")
  → 配置持久化 → 发布 config_changed 事件
  → 03-防封策略模块 订阅了 config_changed
      → 重新读取 global.anti_detect 整段配置
      → 更新 _profile_name 和 _profile_params
      → 记录 "档案切换: normal→safe" 审计日志
```

**配置路径**：所有安全参数集中在 `global.anti_detect` 段：
```yaml
global:
  anti_detect:
    profile: "normal"             # 当前档案名
    offset_radius: 10             # 偏移半径（px），SAFE=15 / NORMAL=10 / FAST=5 / DEBUG=0
    jitter_range: 0.5             # 延迟抖动范围（秒）
    pause_probability: 0.08       # 走神概率，NORMAL=8%
    drift_enabled: true           # 是否启用参数渐变
    drift_amplitude: 0.15         # 渐变幅度（±15%）
```

**四档预设**：

| 档案 | 偏移半径 | 延迟抖动 | 走神概率 | 轨迹 | 适用场景 |
|------|---------|---------|---------|------|---------|
| **SAFE** | 15px | 1.0s | 15% | 贝塞尔 | 最安全，长时间挂机 |
| **NORMAL** | 10px | 0.5s | 8% | 贝塞尔 | 平衡，日常使用 |
| **FAST** | 5px | 0.2s | 3% | 跳过 | 快速，短期冲刺 |
| **DEBUG** | 0px | 0s | 0% | 跳过 | 调试，关闭所有安全 |

### 3.4 参数渐变（长时间运行）

每运行一段时间后，行为参数在预设范围内小幅度漂移，避免长时间运行后行为模式固化被检测。

**实现方式**：`AntiDetect` 内部维护 `_check_drift()` 私有方法，依赖档案参数的方法在计算前自动调用它：

```
_check_drift()
  → 检查 time.time() - _last_drift_time >= 3600
  ├── 否 → 直接返回（不漂移）
  └── 是 → 获取 _drift_lock（双重检查锁定）
          → 再次检查 _last_drift_time（防止并发线程已漂移）
          ├── 仍超时 → 执行漂移：
          │     → 读取配置中的 drift_amplitude（默认 ±15%）
          │     → 对每个参数在其基础值 ±amplitude 范围内重新随机
          │         偏移半径 = base × (1 + uniform(-0.15, 0.15))
          │         抖动范围 = base × (1 + uniform(-0.15, 0.15))
          │         走神概率 = base × (1 + uniform(-0.15, 0.15))
          │     → 更新 _profile_params
          │     → 记录 "参数漂移: 偏移半径 10→11.3" 审计日志
          │     → 更新 _last_drift_time = time.time()
          └── 已不超时 → 释放锁 → 返回
```

**调用 `_check_drift()` 的方法**（依赖档案参数，需要漂移感知）：
- `random_offset()`、`random_swipe_duration()`、`random_delay()`、`sleep()` — 偏移半径/抖动范围来自档案参数
- `maybe_long_pause()` — 走神概率来自档案参数
- `random_typing_delay()` — 打字节奏模拟不依赖档案参数，但为统一性也调用

**不调用 `_check_drift()` 的方法**：
- `random_offset_in_bounds()` — 偏移量由目标图标宽高决定，非档案参数
- `generate_trajectory()` — 贝塞尔曲线控制点生成不依赖档案参数（仅根据 FAST/DEBUG 跳过）

> **漂移范围钳制**：所有漂移后的参数不会低于 DEBUG 值（0）或超过 SAFE 值的 120%，确保安全性不越界。
> **幂等设计**：`_check_drift()` 内部通过 `_last_drift_time` 判断是否 ≥3600s，无论被调用多少次，每小时仅执行一次漂移。即使执行器完全忘记调用 `update_drift()`，参数漂移也不会失效。
> **`update_drift()` 保留为显式入口**：`BehaviorProfile.update_drift()` 方法仍对外公开，供执行器在 `click_image()` 前显式调用，但不再是漂移的唯一触发途径。内外部双保险。

## 四、重点功能

### 4.1 全链路拟人化

覆盖点击、滑动、等待、节奏、文本输入五个维度，操作间隔随机抖动、鼠标轨迹贝塞尔曲线、走神暂停模拟注意力波动、逐字键入模拟人类打字节奏，全方位模拟人类操作特征。

### 4.2 可打断安全等待

所有涉及 `time.sleep()` 的方法均接受 `stop_event` 参数。`sleep()` 内部使用 `event.wait(timeout=delay)` 替代裸 `time.sleep()`，当外部设置停止信号时立即返回。走神暂停（5~15s）期间每隔 3s 检查一次，确保最长响应延迟不超过 3 秒。

### 4.3 多档行为档案

四档预设 + 支持自定义，通过配置热重载切换。订阅 `config_changed` 事件自动感知档案变更。DEBUG 模式下关闭所有安全处理，不影响开发效率。

### 4.4 操作审计日志

使用 `deque(maxlen=5000)` 记录每次操作的坐标、时间、类型、耗时等信息。环形缓冲确保内存不膨胀。可通过接口导出分析，用于事后行为审计和操作模式检测。

> **导出安全策略**：`export_log()` 方法在导出日志时先获取 `_audit_log_lock`，执行 `list(_audit_log)` 做**快照拷贝**，释放锁后再处理拷贝数据。避免长时间持锁阻塞正在进行的 `record_action()` 追加操作。

### 4.5 异常体系

| 异常类 | 触发场景 | 说明 |
|--------|---------|------|
| `RunLimitExceeded` | `check_run_limit()` 检测到 `_action_count` 超过配置上限 | 由 14-执行器模块 捕获，通知 09-运行控制中心 停止调度 |
| `ProfileNotFound` | `reload_profile()` 读取的档案名不在预设范围内 | 回退到 NORMAL 档案并记录警告 |

## 五、实现思路

### 5.1 模块结构

```
core/
├── anti_detect.py       ← AntiDetect 安全策略引擎主入口（参数生成 + 可打断等待 + 审计日志）
└── behavior_profile.py  ← BehaviorProfile 行为档案管理（多档安全强度 + 参数渐变 + 配置热重载）
```

> ⚠️ **执行器已拆出**：原本文中的 Executor 已拆分为独立的 **14-执行器模块**。本模块只保留策略引擎，安全策略通过 14-执行器模块 的调用注入。

### 5.2 核心方法定义

**AntiDetect（防封策略引擎）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `_check_drift() -> None` | 🔒 私有 | `AntiDetect` | **惰性兜底检查**。双重检查锁定（`_drift_lock`）：先无锁检查 `_last_drift_time`，若距上次 ≥3600s 则获取锁后二次确认，再执行 `_apply_drift()`。仅依赖档案参数的方法（`random_offset` / `random_delay` / `sleep` / `maybe_long_pause` / `random_typing_delay`）在入口处调用此方法。`random_offset_in_bounds` 和 `generate_trajectory` 不调用（参数来源非档案） |
| `random_offset(cx, cy, radius) -> tuple` | 🔓 公开 | `AntiDetect` | 在中心点周围生成正态分布随机偏移坐标。结果钳制在 ±2σ 内，防止极端值。**入口自动调用 `_check_drift()`** |
| `random_offset_in_bounds(cx, cy, w, h) -> tuple` | 🔓 公开 | `AntiDetect` | 在图标矩形范围内生成均匀分布随机偏移坐标，确保点击不超出图标边界。不调用 `_check_drift()`（偏移量由目标图标宽高决定，非档案参数） |
| `generate_trajectory(from_x, from_y, to_x, to_y, steps) -> list[tuple]` | 🔓 公开 | `AntiDetect` | 生成 4 控制点贝塞尔曲线路径点列表（默认 12 步）。FAST/DEBUG 模式返回空列表（跳过轨迹）。不调用 `_check_drift()`（控制点生成不依赖档案参数） |
| `random_swipe_duration(base_ms) -> int` | 🔓 公开 | `AntiDetect` | 随机滑动时长：`base_ms × uniform(0.8, 1.2)`，返回毫秒数。**入口自动调用 `_check_drift()`** |
| `random_delay(base_sec, jitter_sec) -> float` | 🔓 公开 | `AntiDetect` | 随机延迟时间：`base_sec + uniform(-jitter_sec, jitter_sec)`，返回秒数。不执行休眠，仅计算值。**入口自动调用 `_check_drift()`** |
| `sleep(base_sec, jitter_sec, stop_event) -> bool` | 🔓 公开 | `AntiDetect` | 随机延迟执行。计算 delay = `random_delay(base, jitter)`（钳制 ≥ 0），内部使用 `stop_event.wait(timeout=delay)` 替代 `time.sleep()`。返回 True 表示正常完成等待，False 表示被 stop_event 打断。**入口自动调用 `_check_drift()`** |
| `maybe_long_pause(stop_event) -> bool` | 🔓 公开 | `AntiDetect` | 按概率触发长暂停（SAFE=15%）。走神概率来自档案参数，**入口自动调用 `_check_drift()`**。若触发，执行 5~15s 可打断休眠（分段 wait，每段 3s 检查一次 stop_event） |
| `random_typing_delay() -> float` | 🔓 公开 | `AntiDetect` | 模拟人类逐字输入间隔。基值 80~250ms 均匀随机，5% 概率触发"停顿思考"（额外 +1~3s）。返回秒数。**入口自动调用 `_check_drift()`**（统一性考虑）。**注意**：此延迟在每组字符之间调用，而非逐字调用。14-执行器模块 的 `input_text()` 将长文本按 3~5 字分组，每组发送一次 ADB 命令后调用此方法等待 |
| `check_run_limit() -> None` | 🔓 公开 | `AntiDetect` | 获取 `_action_lock` 后读取 `_action_count`，检查是否超过配置上限（`global.anti_detect.max_actions_per_session`），超限抛出 `RunLimitExceeded`（由 14-执行器模块 捕获，通知 09-运行控制中心 停止调度） |
| `record_action() -> None` | 🔓 公开 | `AntiDetect` | 获取 `_action_lock` 后执行 `_action_count += 1`（保证多线程下计数准确），记录操作到 `_audit_log`（类型、坐标、时间戳）。deque 自动维护 maxlen=5000，无需手动清理 |
| `export_log() -> list[dict]` | 🔓 公开 | `AntiDetect` | 导出操作审计日志。获取 `_audit_log_lock`，执行 `list(_audit_log)` 做快照拷贝，释放锁后返回拷贝列表。避免长时间持锁阻塞 `record_action()` |
| `reload_profile() -> None` | 🔓 公开 | `AntiDetect` | 从配置重新加载 `_profile_params`（由 `config_changed` 事件触发调用）。**切换档案会重置漂移计时器和所有漂移参数**到新档案的预设值：`_last_drift_time = 0`（下次调用任何参数方法时立即触发首次漂移），`_profile_params` 加载为新档案基线。若配置中的档案名不在预设范围内，回退到 NORMAL 并记录警告（抛 `ProfileNotFound` 内部处理，不传播到外部） |

**BehaviorProfile（行为档案管理）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `update_drift(current_time, params) -> dict` | 🔓 公开 | `BehaviorProfile` | 检查距离上次漂移是否 ≥3600s。是则对 params 各参数在 ±drift_amplitude 范围内重新随机，返回更新后的参数字典。漂移结果钳制在 [DEBUG_value, SAFE_value×1.2] 范围内 |
| `load_profile(profile_name) -> dict` | 🔓 公开 | `BehaviorProfile` | 根据档案名从配置加载预设参数。支持 "safe"/"normal"/"fast"/"debug"，配合 `global.anti_detect` 中的自定义覆盖 |

### 5.3 核心流程

**安全参数调用流程**（由 14-执行器模块 驱动，完整链路）：
```
14-执行器模块.click_image("btn")
  │
  ├── 1. 调 02-图像识别模块.find("btn")
  │     → MatchResult(center=(637,598), w=80, h=40, confidence=0.95)
  │
  ├── 2. 调 03-防封策略模块.random_offset_in_bounds(637, 598, 80, 40)
  │     → 图标矩形内安全偏移坐标 (641, 602)
  │
  ├── 3. 调 03-防封策略模块.generate_trajectory(last_x, last_y, 641, 602)
  │     → 返回贝塞尔曲线路径点列表 [(630,590), (635,595), (638,599), (641,602)]
  │     → FAST/DEBUG 模式返回 []（跳过轨迹）
  │
  ├── 4. 调 03-防封策略模块.sleep(0.3, 0.2, stop_event)
  │     → 计算 delay = 0.3 + uniform(-0.2, 0.2) = 0.27s
  │     → stop_event.wait(timeout=0.27)
  │     ├── 正常等待 → 返回 True
  │     └── 被打断 → 返回 False → 终止执行
  │
  ├── 5. 调 03-防封策略模块.maybe_long_pause(stop_event)
  │     → 按概率（NORMAL=8%）决定是否触发
  │     ├── 未触发 → 继续
  │     └── 触发 → 分段休眠（每段 3s 检查 stop_event）
  │           总时长随机 5~15s，可打断
  │
  ├── 6. 执行点击（根据轨迹选择方式）
  │     ├── 轨迹非空 → 调 01-设备连接模块.swipe(起点, 终点, 随机时长 50~100ms)
  │     │              单条 swipe 命令，系统自动插值弧线
  │     └── 轨迹为空 → 调 01-设备连接模块.tap(安全坐标)
  │
  └── 7. 调 03-防封策略模块.record_action()
        → _action_count += 1 → _audit_log.append({...})
```

### 5.4 关键设计

- **策略注入模式**：安全模块不主导执行，而是被调用提供参数，保持各模块职责清晰
- **参数化配置**：所有安全参数从 `global.anti_detect` 段读取，可在 UI 面板实时调整，`config_changed` 事件驱动热重载
- **全链路覆盖**：点击/滑动/等待/节奏/文本输入，五个维度缺一不可
- **可打断等待**：所有 `sleep` 类方法使用 `event.wait(timeout)` 替代 `time.sleep()`，接收 `stop_event` 实现快速停止
- **事件驱动档案切换**：订阅 `config_changed` 事件，感知配置变更后自动重载 `_profile_params`
- **惰性参数漂移**：`_check_drift()` 内聚在 `AntiDetect` 内部，依赖档案参数的方法入口自动调用（`random_offset_in_bounds` 和 `generate_trajectory` 除外）。使用 `_drift_lock` 双重检查锁定，防止多线程并发漂移。幂等设计（每小时仅执行一次），即使执行器完全忘记调用也不会失效。`update_drift()` 保留为外部显式入口，内外双保险
- **档案切换重置漂移**：`reload_profile()` 切换档案时会重置 `_last_drift_time = 0` 并加载新档案基线，漂移参数被丢弃。这是有意行为——新档案从头开始漂移，避免切换后参数越界
- **贝塞尔轨迹 ADB 适配**：单条 `adb swipe` 命令利用系统插值模拟曲线，FAST/DEBUG 模式下跳过。仅需 2~3 段即可模拟复杂曲线
- **环形审计日志**：`deque(maxlen=5000)` 记录操作历史，内存可控且线程安全
- **偏移钳制**：正态分布结果钳制在 ±2σ、矩形偏移限制在边界内、漂移结果钳制在安全范围内，防止极端值

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `random_offset(cx, cy, radius)` | **14-执行器模块** | 正态分布随机偏移（结果钳制在 ±2σ） |
| `random_offset_in_bounds(cx, cy, w, h)` | **14-执行器模块** | 在图标矩形内均匀随机偏移 |
| `generate_trajectory(from_x, from_y, to_x, to_y, steps=12)` | **14-执行器模块** | 贝塞尔曲线路径点列表（FAST/DEBUG 返回空列表） |
| `random_swipe_duration(base_ms)` | **14-执行器模块** | 随机滑动时长（毫秒），base_ms × uniform(0.8, 1.2) |
| `random_delay(base_sec, jitter_sec)` | **14-执行器模块** | 计算随机延迟值（秒），不执行休眠 |
| `sleep(base_sec, jitter_sec, stop_event)` | **14-执行器模块** | 执行可打断随机休眠。返回 True=正常完成 / False=被打断 |
| `maybe_long_pause(stop_event)` | **14-执行器模块** | 概率触发可打断长暂停（5~15s），返回是否触发 |
| `random_typing_delay()` | **14-执行器模块** | 模拟逐字输入间隔（80~250ms/字，5%概率额外停顿）。**配合分组策略**：14-执行器模块 将文本按 3~5 字分组，每组调用一次 ADB 后等待此延迟 |
| `check_run_limit()` | **14-执行器模块** | 检查运行上限，超限抛 `RunLimitExceeded`。由 14-执行器模块 捕获后通知 09-运行控制中心 停止调度 |
| `record_action()` | **14-执行器模块** | 记录操作计数（`_action_lock` 保护）和审计日志 |
| `export_log()` | **14-执行器模块** / **12-日志监控中心** | 导出操作审计日志快照（`_audit_log_lock` 保护，快照拷贝后释放锁） |
