# 模块拼接书

> 本文档展示整个程序从启动到运行的完整模块协作链路，包括模块结构图、启动流程、任务队列搭建、任务执行全链路。帮助开发者理解"所有模块如何拼在一起"。

---

## 一、模块总览

### 1.1 三层架构

程序分为三个层次，共 **16 个模块**：

```
  ┌─────────────────────────────────────────────────────────────────┐
  │                        桥梁表现层                                 │
  │                                                                 │
  │   10-参数桥接模块       11-用户界面模块                             │
  │   (UI↔程序数据绑定)     (PyQt5界面面板)                            │
  └──────────────────────────┬──────────────────────────────────────┘
                             │  事件总线 + 传参桥接
  ┌──────────────────────────▼──────────────────────────────────────┐
  │                        支撑服务层                                 │
  │                                                                 │
  │  06-配置管理中心  07-运行时状态管理  08-事件通信总线                   │
  │  12-日志监控中心    13-任务文件管理  15-账号管理模块                  │
  │  16-应用启动引导                                                  │
  └──────────────────────────┬──────────────────────────────────────┘
                             │  直接调用
  ┌──────────────────────────▼──────────────────────────────────────┐
  │                        核心运行层                                │
  │                                                                 │
  │  01-设备连接模块  02-图像识别模块  03-防封策略模块               │
  │  04-任务执行引擎  05-时间调度模块  09-运行控制中心               │
  │  14-执行器模块                                                    │
  └─────────────────────────────────────────────────────────────────┘
```

### 1.2 模块依赖关系图

箭头方向表示"依赖方向"（A → B 表示 A 依赖 B）：

```
16-应用启动引导 ───→ 所有模块（创建并注入依赖）
      │
      ├──→ 06-配置管理中心（最先初始化，含 _lock 线程安全 + _watcher 热重载）
      ├──→ 08-事件通信总线（第二初始化）
      │
      ├──→ 12-日志监控中心 ──→ 06, 08, 01(可选,异常截图)
      ├──→ 07-运行时状态管理 ──→ 08(event)。内部维护 `_lock`(线程安全)、`_history`(环形缓冲 1000 条)
      ├──→ 10-参数桥接模块 ──→ 06, 07, 08, 05
      │
      ├──→ 01-设备连接模块 ──→ 06, 08, 07
      ├──→ 02-图像识别模块 ──→ 01(截图), 06, 12, 08（含 TriggerWatcher 触发监控子服务）
      ├──→ 03-防封策略模块 ──→ 06(配置), 08(事件订阅/可打断), 12(审计日志)
      │
      ├──→ 14-执行器模块 ──→ 02, 03, 01, 12, 06
      ├──→ 05-时间调度模块 ──→ 06(config), 07(state), 08(event)。内部维护`_lock`(线程安全)、`_timezone`(UTC+8)
      ├──→ 04-任务执行引擎 ──→ 06(config), 08(event), 07(state)。executor/recognizer 由 09 在 execute() 时注入 TaskContext
      ├──→ 13-任务文件管理（无依赖，纯文件操作）
      │
      ├──→ 09-运行控制中心 ──→ 05, 04, 01, 06, 07, 08, 12, 14, 02(含 TriggerWatcher), 03, 15
      ├──→ 15-账号管理模块 ──→ 06, 01, 07, 08, 05
      │
      └──→ 11-用户界面模块 ──→ 10（唯一核心通信通道）, 08（事件驱动刷新）
            │
            └── 10-参数桥接模块 内部桥接至:
                  ├── 06-配置管理中心（UI配置读写）
                  ├── 05-时间调度模块（日程查询/修改）
                  ├── 13-任务文件管理（文件CRUD）
                  ├── 15-账号管理模块（账号切换）
                  └── 09-运行控制中心（启停信号）
```

### 2.2 关闭序列

Qt 主窗口关闭 → `app_stopping` 事件 → 各模块依次停止：

```
Qt 窗口 closeEvent
  │
  ▼
16-应用启动引导.shutdown()
  │  发布 app_stopping 事件 → 08-事件通信总线分发
  │
  ├── 1. 09-运行控制中心 收到 → 若仍在运行则执行停止流程
  │     （同"停止"流程：中断线程 → 停止触发监控 TriggerWatcher.stop() → 保存状态 → 断开连接）
  │
  ├── 2. 05-时间调度模块.save_state()
  │     → 保存调度状态（task_state.json 原子写盘）
  │
  ├── 3. 04-任务执行引擎
  │     → 清理当前执行的任务上下文（中断子线程、释放资源）
  │
  ├── 4. 07-运行时状态管理.reset()
  │     → 清空运行时状态（保留白名单键）
  │
  ├── 5. 13-任务文件管理
  │     → 清空文件缓存（_cache = {}）
  │
  ├── 6. 01-设备连接模块.disconnect()
  │     → 断开设备连接 → 停止心跳 → 清理设备池
  │
  ├── 7. 06-配置管理中心.stop_watcher()
  │     → 停止文件监控线程
  │
  ├── 8. 08-事件通信总线.stop()
  │     → 设置 _stop_event → join 分发线程(timeout=3) → 清空队列
  │     → 停止所有事件分发
  │
  ├── 9. 12-日志监控中心 关闭
  │     → 停止异步日志工作线程
  │
  └── 10. Qt 事件循环退出 → 进程结束
```

## 三、任务队列搭建阶段

### 3.1 用户点击"启动"后的完整链路

```
用户点击 UI 的"启动"按钮
  │
  ▼
10-参数桥接模块 → RunBridge
  │  发布 start_requested 事件
  ▼
08-事件通信总线
  │  分发事件给订阅者
  ▼
09-运行控制中心._on_start()
  │
  ├── 1. 允许性检查
  │     ├── 调 15-账号管理模块.get_current() → 获取当前账号
  │     ├── 调 06-配置管理中心.get() → 读取上限配置
  │     ├── 调 01-设备连接模块.is_connected() → 检查连接
  │     └── 全部通过 → 继续
  │
  ├── 2. 初始化连接
  │     ├── 调 15-账号管理模块.get_current() → 获取当前账号的 device_id
  │     └── 调 01-设备连接模块.connect(device_id)
  │         → 内部验证 ADB 可达性
  │         → 初始化 _pool_lock / _conn_pause_event 等同步原语
  │         → 更新 connection_status = connected
  │
  ├── 3. 加载调度状态
  │     └── 调 05-时间调度模块.load_state()
  │
  ├── 4. 初始化空 FIFO 队列
  │
  ├── 5. 状态置为 running
  │     └── 调 07-运行时状态管理.set_state("run_status", "running")
  │
  ├── 5.5 启动触发监控
  │     └── 调 09 内部 TriggerWatcher.start()
  │           → 收集配置了 repeat.type=trigger 的任务触发模板
  │           → 启动常驻监控线程（截图 → match_any(识别列表)）
  │
  ├── 6. 启动填充线程 _filler_loop()
  │
  └── 7. 启动执行线程 _executor_loop()
```

### 3.2 填充线程：任务队列搭建

填充线程启动后，立即开始构建任务队列：

```
填充线程 _filler_loop() 启动
  │
  └── 循环（间隔2~3秒）：
        │
        ├── 1. 熔断检查（跳过已熔断）
        │
        ├── 2. 允许性检查（上限/连接）
        │
        ├── 3. 调 05-时间调度模块.get_next_task()（内部调 build_schedule()）
        │       │
        │       ├── 扫描所有启用任务
        │       ├── is_due() 三重判据检查
        │       ├── check_times_limit() 次数上限检查
        │       ├── 依赖检查（depends_on）
        │       ├── 调 15-账号管理模块.get_task_scope() 过滤
        │       └── 返回到期任务列表
        │
        │   ⭐ 触发式任务（repeat.type=trigger）入队路径：
        │      TriggerWatcher 命中触发模板
        │        → 发布 trigger_detected 事件
        │        → 05-时间调度模块 订阅 → update_next_run(name, now)
        │        → 该任务立即"到期" → 填充线程下轮 get_next_task() 拾取入队
        │        → 普通时间型任务不受影响（无触发模板则不监控）
        │
        ├── 4. 到期任务列表按 priority 降序排列
        │
        ├── 5. 加锁 → 遍历列表
        │     ├── 未入队 → 加入 FIFO 队列尾部 + 加入已入队集合
        │     └── 已在队列 → 跳过
        │
        ├── 6. 解锁
        │
        ├── 7. 更新 queue_length / queue_contents → 07-状态管理
        │
        ├── 8. 发布 schedule_updated 事件 → 08-事件总线
        │       │
        │       └── 11-用户界面模块.TaskQueuePanel 收到事件
        │             → 重建队列卡片展示
        │
        └── 9. 休眠2~3秒 → 回到开头
```

## 四、任务执行阶段

### 4.1 单次任务执行全链路

当一个任务从队列头部取出后，经过以下完整链路：

```
执行线程出队 → 任务名如 "yuhun（御魂副本）"
  │
  ├── 1. 从已入队集合移除（允许未来重新入队）
```

### 4.2 步骤内的执行器调用细节

每个步骤在执行过程中，会通过 `context.executor` 调用 **14-执行器模块**，进而协调三个底层模块：

```
以 BattleLoop 中的"点击挑战按钮"为例：

context.executor.click_image("common/battle/challenge_btn")
  │
  │  ├── 1. 调 02-图像识别模块.find("challenge_btn", mode=AUTO)
  │     │  （内部流程：检查素材存在 → _cache_lock 检查缓存 → 截图→ 释放锁 → 模板匹配
  │     │    → 多尺度自适应 → 置信度≥threshold? → 返回 OR 回退 OCR（按 _meta.json））
  │     → 返回 MatchResult(center=(637,598), w=80, h=40, confidence=0.95)
  │
  ├── 2. 未找到 → 返回 False（步骤处理失败情况）
  │
  ├── 3. 调 03-防封策略模块.random_offset_in_bounds(637, 598, 80, 40)
  │     → 返回图标矩形内的安全坐标 (641, 602)
  │
  ├── 4. 调 03-防封策略模块.generate_trajectory(last_x, last_y, 641, 602)
  │     → 返回轨迹路径点（起点+终点+2 控制点）
  │     → FAST/DEBUG 模式返回空列表（跳过轨迹）
  │
  ├── 5. 调 03-防封策略模块.sleep(0.3, 0.2, stop_event)
  │     → event.wait(timeout=0.27) 可打断等待
  │     ├── True（正常完成）→ 继续
  │     └── False（被打断）→ 终止操作
  │
  ├── 6. 调 03-防封策略模块.maybe_long_pause(stop_event)
  │     → 按概率触发（NORMAL=8%），触发后分段 3s 检查 stop_event
  │
  ├── 7. 执行点击（根据轨迹选择方式）
  │     ├── 轨迹非空 → 调 01-设备连接模块.swipe(起点, 终点, 随机时长 50~100ms)
  │     │              单条 swipe，系统自动插值弧线
  │     └── 轨迹为空 → 调 01-设备连接模块.click(641, 602)
  │           │
  │           │  进入 01-设备连接模块.click():
  │           │    ├── 检查 _conn_pause_event（重连中？等待最多 10s）
  │           │    ├── 获取 _pool_lock（超时 3s）
  │           │    ├── 读取 _active_device（若为 None 抛 DeviceOfflineError）
  │           │    ├── 释放 _pool_lock
  │           │    ├── 执行 adb shell input tap 641 602（timeout=10s）
  │           │    └── 记录耗时到 _quality_records["click"]
  │           │
  │           └── 返回
  │
  ├── 8. 调 03-防封策略模块.record_action()
  │     → _action_count++ → 审计日志追加
  │
  ├── 9. 更新操作计数 → 执行线程更新到运行控制中心
  │
  └── 10. 返回 True
```

### 4.3 场景检测与弹窗拦截

执行循环中集成了场景检测机制，应对误触和弹窗干扰：

**弹窗扫描（每步执行前）**：
```
09-运行控制中心 执行线程 调 _scan_popups_before_exec()
  → 遍历弹窗模板列表：popup_reward, popup_ad, popup_update, close_btn 等
  → 对每个模板调 14-执行器模块.click_if_exists(name)
      → 匹配到 → 点击关闭 → sleep(1) → 继续扫描
      → 未匹配 → 跳过
  → 全部检查完毕 → 开始执行任务
```

**场景验证（每步执行后）**：
```
09-运行控制中心 执行线程
  → 调 14-执行器模块.ensure_scene(expected_scene)
  → 确认在预期场景 → 继续下一步
  → 不在预期场景
      → 调 14-执行器模块.detect_scene([候选场景模板列表])
      → 匹配到某场景 → 更新 07.last_known_scene
                      → 走该场景对应的恢复路径
      → 未匹配 → 截图保存 → 递增异常计数 → 失败冷却
```

### 4.4 异常场景恢复（完整链路）

当任务步骤执行失败时，自动进入场景恢复流程：

```
步骤失败（click_image假 / ensure_scene超时 / 抛出异常）
  │
  ├── 1. 截图保存 → 12-日志监控中心.capture_on_error()
  │
  ├── 2. 页面分析 → 14-执行器.detect_scene([庭院,探索,御魂,结算,失败,登录,弹窗...])
  │     │
  │     ├── 匹配到已知场景 → 更新 07.last_known_scene
  │     └── 未匹配 → 进入保护模式
  │
  ├── 3. 恢复路径选择
  │     ┌──────────────────────────────────────┐
  │     │ "战斗结算" → click("确认") → 返回   │
  │     │ "战斗失败" → click("退出") → 回庭院  │
  │     │ "登录界面" → 游戏断开 → 终止任务    │
  │     │ "弹窗"     → click("关闭") → 重试   │
  │     │ "庭院/探索" → 重新导航到目标入口     │
  │     └──────────────────────────────────────┘
  │
  ├── 4. 恢复验证 → ensure_scene(目标场景)
  │     ├── 成功 → 继续执行
  │     └── 失败 → _recover_count++
  │           → _recover_count >= 3 → 放弃当前任务（初始执行 + 2 次恢复重试 = 最多 3 次尝试）
  │           → 执行下一个（避免死循环浪费资源）
  │
  └── 5. 保护模式（完全未知）
        ├── 通用退出序列：关弹窗 → 返回键 → 取消 → 回庭院
        ├── 任一成功 → 恢复
        └── 全部失败 → 跳过任务 → 保护资源
```

### 6.2 核心数据流

```
配置数据流：
  06-配置管理中心 ← YAML/JSON 文件
    → 所有模块读取配置

事件数据流：
  任意模块 → 发布事件 → 08-事件通信总线 → 分发给订阅者

状态数据流：
  任意模块 → set_state() → 07-运行时状态管理 → 发布 state_changed
    → UI 订阅 → 自动刷新展示

操作数据流：
  04-任务步骤 → context.executor.click_image()
    → 14-执行器模块 → 02-图像识别(find)
                    → 03-防封策略(random_offset_in_bounds + generate_trajectory + sleep + maybe_long_pause)
                    → 01-设备连接(click)
    → 返回结果给任务步骤

运行时进度数据流：
  04-BattleLoop 每完成1次 → completed++
    → 调 07.set_state("task_runtime_progress", {task: {completed, total}})
    → 用户点击停止 → 09 读取 → 写 task_runtime_progress.json
    → 下次启动 → 09 读 json → 调 07.set_state → 04 读取剩余次数

  02-TriggerWatcher 监控循环（运行期间常驻）
    → 截图 → match_any(trigger_templates 识别列表)
    → 命中模板 A → 发布 trigger_detected(task_name=A对应的任务)
    → 05-时间调度模块 订阅 → update_next_run(A, now)
    → 09-填充线程 get_next_task() 拾取 → 入队 → 执行
    → mark_done(A, True) → trigger 类型 → completed + 清空 next_run
    → 11-已失效区显示"等待下次触发"
    → 下次命中触发模板 → 重新激活
  （手动触发：11-队列面板"手动触发"按钮 → TaskBridge.update_next_run(name, now)，同一链路）
```

### 6.5 性能优化关键设计

| 优化点 | 说明 | 影响模块 |
|-------|------|---------|
| **截图缓存** | 同一任务步骤内复用截图，避免重复 ADB 请求。受 `_cache_lock` 保护 | 02-图像识别模块 |
| **识别结果缓存** | 1 秒 TTL（含时间戳校验），避免轮询时重复模板匹配。受 `_cache_lock` 保护 | 02-图像识别模块 |
| **素材索引** | assets/ 全量加载至内存，含加载校验（跳过损坏文件） | 02-图像识别模块 |
| **OCR 降级状态** | PaddlePaddle 未安装时 `_ocr_ready=False`，OCR 返回 None 不抛异常 | 02-图像识别模块 |
| **点分路径索引缓存** | `get()` 首次遍历后缓存结果，后续 O(1) 读取 | 06-配置管理中心 |
| **批量状态更新** | `set_states()` 合并多次更新为一次 `state_changed` 事件 | 07-运行时状态管理 |
| **事件去重** | 短时间内相同事件自动合并 | 08-事件通信总线 |
| **handler 软超时** | 单 handler 超过 5 秒记录警告日志，但**不中断执行**（Python 无法安全终止正在执行的函数，故采用软超时） | 08-事件通信总线 |
| **自适应休眠** | 无任务时空闲越久休眠越长（2~10秒），减少 CPU 空转 | 09-运行控制中心 |
| **日志预过滤** | level 低于最低级别时直接丢弃，避免对象创建开销 | 12-日志监控中心 |
| **异步日志写入** | 日志放入队列后立即返回，不阻塞业务线程 | 12-日志监控中心 |

```
  │                                              │

  07-状态管理（共享层） ─────── 11-UI 面板          │
```
