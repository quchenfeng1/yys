# 07-运行时状态管理（Runtime State Management）

> **类型**：支撑服务层  ｜  **对应说明书**：（新概念）  ｜  **说明**：解耦新增，统一管理运行时全局状态

---

## 一、目的与作用

**一句话定位**：全局状态管理中心。集中管理脚本运行时所有跨模块共享的状态，通过事件总线广播状态变化，避免模块间紧耦合查询。

**为什么需要这个模块**：

脚本运行中有大量全局状态需要被多个模块共享——当前账号、连接设备、游戏场景、运行状态、执行任务、今日统计等。如果这些状态散落在各模块内部，会导致：
1. **紧耦合**：模块间互相查询状态时需持有对方引用
2. **不一致**：A模块改了状态，B模块不知道
3. **UI难以展示**：UI需要轮询各模块获取状态

**核心职责**：
1. **状态集中存储**：所有全局状态单一数据源
2. **读写接口**：get_state(key) / set_state(key, value)
3. **变化广播**：状态变更时通过事件总线自动通知订阅者
4. **状态快照**：导出当前全部状态快照，用于调试和 UI 刷新

**设计原则**：
- **单一数据源**：全局状态只在此维护，其他模块不自行缓存
- **变化即广播**：set_state 自动发事件，订阅者无需轮询
- **只管运行时态**：配置归配置模块，持久化记录归定时模块，本模块只管理"当前运行态"

### 2.3 内部私有属性

| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_state` | `dict[str, Any]` | 状态字典：key → value 的运行时状态存储。受 `_lock` 保护 |
| `_lock` | `Lock` | 保护 `_state` / `_validators` / `_history` 的线程安全锁。`set_state()` / `set_states()` / `get_snapshot()` / `reset()` 均需获取 |
| `_validators` | `dict[str, callable]` | 状态校验器：key → 校验函数，`set_state()` 写入前调用。校验器通过 `add_validator(key, fn)` 注册 |
| `_history` | `dict[str, deque] \| None` | 变化历史环形缓冲：可选开启，`key → deque(maxlen=1000)`。记录每次变更的 `(timestamp, old_value, new_value)`。启用方式：`set_state("_history_enabled", True)` |

## 三、运行逻辑

### 3.1 状态读写流程（线程安全）

**写状态**：`set_state(key, value)` → 获取 `_lock` → 检查校验器 → 对比旧值 → 若变化则更新 `_state` → 记录 `_history` → 释放锁 → 发布 `state_changed` 事件（**事件发布在锁外，避免持锁调用订阅者 handler**）。

**批量写状态**：`set_states(mapping)` → 获取 `_lock` → 遍历 mapping 逐项校验 → 对比旧值 → 收集所有变化键 → 统一更新 `_state` → 统一记录 `_history` → 释放锁 → 发布一次 `state_changed` 事件（含所有变化键的列表）。

**读状态**：`get_state(key, default)` → 从 `_state` 字典中查找 → 找到返回值，未找到返回 default。**不获取 `_lock`**（Python GIL 保证单次 dict 读取的原子性，但此策略依赖于 CPython 实现细节，非语言规范保证）。>
> **返回值语义**：`get_state()` 返回的值是**瞬间快照**，必须视为**不可变对象**对待：
> - 返回值是内部 `_state` 中该键的内存**引用**，而非拷贝
> - 若值是可变的（list/dict/自定义类实例），其他线程随时可能通过 `set_state()` 替换它，导致调用方持有的引用指向过期对象
> - **禁止**直接修改返回值（如 `get_state("x").append(1)`）——这既不会触发 `state_changed` 事件，还可能因并发写入导致运行时错误
> - 如需修改值，应调 `set_state(key, new_value)`
>
> **`get_states_safe(keys) -> dict`**（可选安全接口）：获取多个键的**加锁浅拷贝**。获取 `_lock` → 逐项 `copy.copy(_state[k])` → 释放锁 → 返回。适用于需遍历列表或读取自定义类实例的场景，调用方获得的是独立副本，不受并发写入影响。注意浅拷贝只拷贝第一层，嵌套可变对象仍需谨慎。
>
> **多键原子读取**：`get_state()` 每次返回单个键的值，多次调用之间若有其他线程写入，可能读到不一致的状态对（如 `current_task` 已变但 `task_progress` 未更新）。需要读取一组相关键的调用方应使用 **`get_snapshot()`** 获取一次性快照，确保多键值来自同一时刻。
> **状态变更守则**：所有状态变更**必须**通过 `set_state()` 或 `set_states()` 进行。禁止通过 `get_state()` 获取可变对象（list/dict）后直接修改——这样不会触发 `state_changed` 事件。`get_state()` 返回的值应视为只读快照，如需修改请调 `set_state()`。
>
> **防御措施**：`set_state()` 内部在更新 `_state[key] = value` 之前，检查新值与旧值是否为**同一个对象引用**（`value is old_value`）。如果是，记录警告日志 `"状态键 '{key}' 的 set_state 收到了与旧值相同的对象引用，可能通过 get_state 直接修改了可变对象"`。这能在开发阶段捕获大部分违规使用，但不影响正常运行。

### 3.2 变化广播机制

每次 `set_state()` 检测到值有变化时，自动通过事件总线发布 `state_changed` 事件。订阅者可针对性订阅特定 key 的变化，无需轮询检查。批量更新时多个键合并为一次事件，减少事件分发开销。

### 3.3 状态校验

设置状态时自动校验值的有效性。校验器通过 `add_validator(key, validator_fn)` 注册。内置校验器示例：
- `run_status` → 检查值是否在 `RunState` 枚举中
- `connection_status` → 检查值是否在 `ConnectionState` 枚举中
非法值拒绝设置并记录警告。

### 3.4 状态快照（深拷贝）

`get_snapshot()` 获取 `_lock` 后执行 `copy.deepcopy(_state)` 返回**完整深拷贝**，可用于：
- 写入日志方便调试
- UI 整体刷新展示
- 异常恢复时保存上下文

> 深拷贝确保调用方修改快照内容不会意外影响全局运行状态。注意深拷贝对大对象的性能影响（当前 ~20 个状态键，拷贝耗时 <1ms）。

### 3.5 状态历史（环形缓冲）

可启用历史记录功能，记录关键状态的每次变更。启用方式：`set_state("_history_enabled", True)`。

- 内部使用 `defaultdict(lambda: deque(maxlen=1000))` 管理每个 key 的历史
- 每次 `set_state()` 检测到值变化时，追加 `(timestamp, old_value, new_value)` 到对应 deque
- 环形缓冲自动淘汰旧数据，最多保留每个 key 最近 1000 条变更

## 四、重点功能

### 4.1 单一数据源

所有全局状态集中管理，其他模块不自行缓存副本，从根本上避免状态不一致问题。

### 4.2 自动广播

状态变化即推送，订阅者实时感知，无需轮询、无需持有发布者引用。

### 4.3 非持久化

运行时状态不写磁盘（重启即重置），与持久化数据分离。需要持久化的数据由对应模块自行管理（如定时模块写 task_state.json）。

### 4.4 快照导出

一键获取全局状态全貌，便于调试、日志记录和 UI 刷新。

### 5.2 核心方法定义

**StateManager（状态管理主入口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `get_state(key, default) -> Any` | 🔓 公开 | `StateManager` | 读取任意全局状态值。不获取 `_lock`（GIL 保证单次 dict 读取原子性，但依赖 CPython 实现细节）。返回值是内部对象的**内存引用**（非拷贝），必须视为只读快照，**禁止直接修改**——修改不会触发 `state_changed`，且可能因并发写入导致运行时错误 |
| `get_states_safe(keys) -> dict` | 🔓 公开 | `StateManager` | 安全获取多个键的**加锁浅拷贝**。获取 `_lock` → 逐项 `copy.copy(_state[k])` → 释放锁 → 返回。适用于需遍历列表、读取自定义类实例等场景，调用方获得独立副本不受并发影响。`keys` 为键名列表，或 None（返回 `_state` 全部键的浅拷贝） |
| `set_state(key, value) -> None` | 🔓 公开 | `StateManager` | 更新状态。获取 `_lock` → 校验器检查 → 对比旧值 → 更新 `_state` → 记录 `_history` → 释放锁 → 发布 `state_changed`（锁外）。写盘失败不修改缓存 |
| `set_states(mapping) -> None` | 🔓 公开 | `StateManager` | 批量更新多个键。获取 `_lock` → 逐项校验 → 收集变化键 → 统一更新 `_state` → 统一记录 `_history` → 释放锁 → 发布一次合并的 `state_changed` |
| `set_current_scene(name) -> None` | 🔓 公开 | `StateManager` | 设置当前场景：写入 `current_scene`（`state_schema.CURRENT_SCENE`）；`name` 非 None 时同步写入 `last_known_scene`（`LAST_KNOWN_SCENE`）。供 07 订阅 `scene_updated` 时内部调用，也供任务/模块主动写入 |
| `get_current_scene() -> str \| None` | 🔓 公开 | `StateManager` | 读取当前场景名（`current_scene`），未设置返回 None |
| `get_last_known_scene() -> str \| None` | 🔓 公开 | `StateManager` | 读取最后已知场景名（`last_known_scene`），供 09-运行控制中心 误触/弹窗后恢复定位 |
| `get_snapshot() -> dict` | 🔓 公开 | `StateManager` | 获取全部状态的深拷贝副本。获取 `_lock` → `copy.deepcopy(_state)` → 释放锁 → 返回。调用方修改副本不影响全局状态 |
| `reset() -> None` | 🔓 公开 | `StateManager` | 重置所有状态为初始值（脚本重启时）。获取 `_lock` → 遍历 `_state`，仅删除不在 `_reset_whitelist` 中的键 → `_history.clear()`（如启用）→ `_validators` 保留 → 释放锁 → 发布专用事件 `state_reset`（所有订阅者收到后应执行全量刷新，而非逐个键更新）。**白名单**：通过 `add_reset_whitelist(key)` 注册，白名单中的键在 `reset()` 时被保留（如系统初始化时注入的模块引用等不应被清空的全局对象） |
| `add_reset_whitelist(key) -> None` | 🔓 公开 | `StateManager` | 将指定键加入重置白名单，`reset()` 时保留该键的值不被清空。在初始化阶段调用（如 16-应用启动引导 注册某些系统级引用） |
| `add_validator(key, validator_fn) -> None` | 🔓 公开 | `StateManager` | 注册状态校验器。`validator_fn(value) -> bool`，返回 False 拒绝设置。在 `_lock` 外调用（初始化时注册，不涉及并发） |
| `subscribe(key, callback) -> str` | 🔓 公开 | `StateManager` | 订阅特定状态的变化。内部将回调注册到 `_subscribers[key]` 列表中，同时订阅 EventBus 的 `state_changed` 事件（全局一次订阅，收到事件后按 `e.data["key"]` 查 `_subscribers` 表分发）。返回订阅 ID 用于取消。**不依赖 EventBus 的 content-based filter**，即使 EventBus 不支持按内容过滤也能正常工作 |

### 5.3 核心流程

**写状态流程**（线程安全 + 锁外发事件）：
```
set_state(key, value)
  → 获取 _lock
  → 检查 key 是否有校验器
  → 有 → 调校验器判断值是否合法
        → 不合法 → 记录告警，拒绝设置 → 释放锁 → 返回
  → 读取旧值 old_value = _state.get(key)
  → 对比 old_value != value
  → 无变化 → 释放锁 → 返回
  → 有变化 → **额外检查**：value is old_value（同一对象引用）？
           → 是 → 记录警告 "可能通过 get_state() 直接修改了可变对象"
           → 更新 _state[key] = value
           → _history 启用？→ deque.append((timestamp, old_value, new_value))
  → 释放 _lock
  → 发布 state_changed(key, old_value, new_value) 到事件总线（锁外执行）
```

> **锁外发事件的原因**：订阅者的 handler 可能反过来调 `get_state()` 或 `set_state()`（读最新状态或更新 UI），如果在锁内发布会导致 handler 尝试获取同一把锁 → 死锁。先释放锁再发事件，handler 可以安全地读取状态。

**读状态流程**（无锁，GIL 保证原子性）：
```
get_state(key, default=None)
  → 在 _state 字典中查找 key（GIL 保证单次查找原子性）
  → 找到 → 返回值（只读快照，不可直接修改）
  → 未找到 → 返回 default
```

**批量写状态流程**（合并事件）：
```
set_states({"run_status": "running", "current_task": "yuhun"})
  → 获取 _lock
  → 遍历 mapping，逐项校验
  → 收集所有 key 的旧值和新值
  → 统一更新 _state（一次性写入所有变化键）
  → 统一记录 _history（如有变更）
  → 释放 _lock
  → 发布一次 state_changed(keys=[...], mapping={key: {old, new}})
    （UI 面板收到一次事件即可一次性刷新多个控件）
```

### 5.4 关键设计

- **键名规范**：通过 `StateKeys` 常量类统一管理 20 个状态键名，避免拼写错误
- **变化即广播**：`set_state` 自动发布 `state_changed` 事件，订阅者无需轮询
- **锁外发事件**：先释放 `_lock` 再发事件，防止订阅者 handler 获取同一锁导致死锁
- **批量合并事件**：`set_states()` 一次锁获取 + 一次事件发布，减少锁竞争和事件分发开销
- **深拷贝快照**：`get_snapshot()` 返回 `copy.deepcopy()`，调用方修改不影响全局状态
- **环形历史**：`deque(maxlen=1000)` 记录变更历史，内存可控
- **状态变更守则**：所有变更必须通过 `set_state()` / `set_states()`，禁止直接修改 `get_state()` 返回的可变对象
- **同引用检测**：`set_state()` 检查新旧值是否为同一对象引用，是则记录警告，辅助开发阶段排查违规使用
- **`reset()` 专用事件**：发布 `state_reset` 而非普通 `state_changed`，UI 收到后执行全量刷新而非逐键更新
- **重置白名单**：`add_reset_whitelist(key)` 注册的键在 `reset()` 时被保留，防止系统级引用被意外清空
- **校验可选**：通过 `add_validator()` 注册校验器，非法值拒绝设置并告警
- **非持久化**：运行时状态不写盘（重启即重置），持久化数据归各自模块
- `reset()` 清空 `_state`（白名单除外）和 `_history`，保留 `_validators`（校验器在模块生命周期内不变）

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `get_state(key)` | 所有模块 | 读取任意全局状态（返回内存引用，禁止直接修改） |
| `get_states_safe(keys)` | 所有模块 | 安全获取多个键的加锁浅拷贝（线程安全） |
| `set_state(key, value)` | 所有模块 | 更新状态，自动广播变化 |
| `get_snapshot()` | UI / 日志 | 获取全部状态快照 |
| `reset()` | 运行控制中心 | 重置所有状态（白名单保留） |
| `subscribe(key, callback)` | 任意模块 | 订阅特定状态变化 |

### 6.2 对外部模块的调用

| 被调用方 | 调用方式 | 说明 |
|---------|---------|------|
| **08-事件通信总线** | 发布事件 | `set_state()` 时自动发布 `state_changed` 事件；`reset()` 时自动发布 `state_reset` 事件 |
