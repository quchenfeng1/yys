# 06-配置管理中心（Configuration Center）

> **类型**：支撑服务层  ｜  **对应说明书**：ConfigManager 5.5  ｜  **对应用户模块**：#5 配置模块

---

## 一、目的与作用

**一句话定位**：配置数据中心。统一加载/管理/持久化所有 YAML/JSON 配置，提供点分路径读写接口，不涉及任何运行逻辑判断。

**核心职责**：
1. **配置加载**：启动时加载 global.yaml / tasks.yaml / accounts.yaml / coords/*.json
2. **统一访问**：提供点分路径读写接口，所有模块统一经由本模块访问配置
3. **持久化**：配置变更后立即原子写盘，重启不丢失
4. **热重载**：支持重新读取配置文件，外部修改后同步
5. **校验**：配置值类型/范围校验，非法值告警但不阻断

**设计原则**：
- **纯数据，不判断**：只读写数据，不做业务判断（那归运行控制模块）
- **单一数据源**：所有模块统一经此模块读取配置，避免不一致
- **原子持久化**：写临时文件 → 替换原文件，避免写盘中断损坏

## 二、模块属性与依赖

### 2.1 依赖注入（外部模块引用）

| 属性名 | 类型 | 作用域 | 作用 |
|--------|------|--------|------|
| `_event_bus` | `EventBus` | 🔒 私有 | 配置变更时发布 `config_changed` 事件 |
| `_monitor` | `Monitor` | 🔒 私有 | 记录配置加载/变更日志 |

### 2.2 对外暴露属性（其他模块可读取）

| 属性名 | 类型 | 作用域 | 说明 |
|--------|------|--------|------|
| `config_version` | `int` | 📖 只读对外 | 当前配置版本号 |

### 2.3 内部私有属性

| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_paths` | `dict[str, str]` | 各配置文件在磁盘上的路径映射。key=配置段名（`global`/`tasks`/`accounts`/`coords`），value=磁盘路径 |
| `_cache` | `dict[str, Any]` | 内存中的完整配置数据副本（嵌套 dict）。受 `_lock` 保护 |
| `_index_cache` | `dict[str, Any]` | 点分路径索引缓存：`"{account_id}.global.adb.port"` → 对应值。键中包含当前账号 ID（如 `"account_A.tasks.yuhun.priority"`），确保账号切换后缓存不会返回旧账号的值。**`set()` 时会删除受影响的索引条目**（匹配所有账号前缀），下次 `get()` 重新计算。账号切换时清空整个 `_index_cache`（通过订阅 `account_switched` 事件）。受 `_lock` 保护 |
| `_lock` | `Lock` | 保护 `_cache` / `_index_cache` / `_paths` 的线程安全锁。`get()` / `set()` / `reload()` / `load()` 均需获取 |
| `_watcher` | `Thread \| None` | 热重载文件监听线程（watchdog polling 模式，每隔 3s 检查文件 mtime）。在 `load()` 中启动，在 `stop_watcher()` 中停止 |
| `_watcher_stop` | `Event` | 热重载线程停止信号。设置此事件后线程退出循环 |
| `_version` | `int` | 配置文件版本号（存储在 `global._version` 中）。用于自动迁移：加载时检测到版本号低于当前程序期望值，则按顺序执行 `v1→v2`、`v2→v3` 等增量迁移函数 |

## 三、运行逻辑

### 3.1 配置加载流程

```
启动时 → 按顺序加载各配置文件
  → 检查版本号，执行自动迁移（如有）
  → 校验配置合法性（类型/范围检查）
  → 建立点分路径索引
  → 初始化文件监听器（热重载）
  → 就绪
```

### 3.2 配置访问流程（含三级覆盖和索引缓存）

```
调用 get("tasks.yuhun.priority")
  → 获取 _lock（保护 _index_cache 和 _cache）
  → 检查 _index_cache["tasks.yuhun.priority"] 是否命中
  ├── 命中 → 释放锁 → 返回缓存值
  └── 未命中 → 查找三级覆盖（优先级从高到低）：
        ① task级: _cache["tasks"]["yuhun"]["priority"] → 找到？
           ├── 是 → 写入 _index_cache → 释放锁 → 返回
           └── 否 → 继续
        ② account级: 检查当前账号的 accounts 段
           ├── 是 → 写入 _index_cache → 释放锁 → 返回
           └── 否 → 继续
        ③ global级: _cache["global"]["adb"]["port"]
           ├── 找到 → 写入 _index_cache → 释放锁 → 返回
           └── 未找到 → 释放锁 → 返回 default
```

### 3.3 配置持久化流程（先写盘 → 再更新缓存，保证一致）

```
调用 set("tasks.yuhun.priority", 5)
  → 获取 _lock（防止并发写入同一文件）
  → 解析 key_path 定位所属配置文件：
      ├── 前缀 "global."     → global.yaml
      ├── 前缀 "tasks."      → tasks.yaml
      ├── 前缀 "accounts."   → accounts.yaml
      ├── 前缀 "coords."     → coords/{scene}.json
      └── 其他               → 抛出 ConfigPathError("无法定位配置段")
  → 读旧值（用于审计日志）
  → 写临时文件 → os.replace 替换原文件
  ├── 成功 → 更新 _cache 中的对应路径
  │        → 删除 _index_cache 中所有以 "tasks.yuhun" 开头的条目
  │           （使受影响的索引失效，下次 get() 重新计算）
  │        → 发布 config_changed(key_path, old_value, new_value)
  ├── 失败 → 不修改 _cache 和 _index_cache
  │        → 抛出异常（上层捕获并记录日志）
  → 释放 _lock
```

> **写盘优先原则**：先写盘、后更新缓存。写盘失败时缓存不变，确保内存与磁盘始终一致。`_index_cache` 只失效不直接更新，因为三级覆盖查找可能涉及多个数据源，下次 `get()` 重新计算最准确。

### 3.4 三级分层覆盖

配置支持三级覆盖（优先级从高到低）：
1. **task级**：`tasks.{category}.{task}.{key}` — 单个任务专属配置
2. **account级**：`accounts.{account}.{key}` — 某个账号专属配置
3. **global级**：`global.{key}` — 全局默认配置

读取时自动按优先级查找（见 3.2 流程），取最先匹配到的值。

## 四、重点功能

### 4.1 点分路径访问

统一使用点分路径访问所有配置，如 `global.adb.port`、`tasks.permanent.yuhun.priority`。不再需要直接操作 yaml/json 数据结构。

### 4.2 任务配置自动合并

`get_task_config(task_name)` 将 tasks.yaml（编排配置）和 coords/{name}.json（坐标配置）合并返回，一次调用获取完整配置。任务条目支持设计书调度字段：`repeat`（含 `on_enter` 启动类型、`trigger` 特殊条件触发类型及 `trigger_templates` 识别列表）、`execution_mode`（`daily`/`per_slot`，替代原 `execution_rule`）、`time_slots`（多时段）、`max_daily`（每日上限）、`total_count`（累计上限）、`time_start/time_end`（单时段）、`active_range` 等。触发式任务（`repeat.type=trigger`）无需时间字段。

**合并策略**：浅合并（第一层 key 合并）。tasks.yaml 和 coords JSON 处于同一层级，同名 key 以 tasks.yaml 完整替换 coords 的同名 key，**不做深层递归合并**。例如 tasks.yaml 定义 `{click_points: {btn1: [100,200]}}` 而 coords 定义 `{click_points: {btn2: [300,400]}}`，结果为 `{click_points: {btn1: [100,200]}}`（coord 的 btn2 被整体替换）。如需保留 coord 中的子配置，应将它们放在不同的顶级 key 下，避免同名冲突。若 coords/{name}.json 不存在，返回 tasks.yaml 中该任务的配置部分。

### 4.3 热重载

配置文件被外部修改后自动重新加载，无需重启程序。也可手动调用 `reload()` 同步。

**实现方式**：使用 `watchdog` 库的 `PollingObserver`（跨平台文件监听，每 3s 轮询文件 mtime）。在 `load()` 中启动，在 `stop_watcher()` 中停止。

**重载行为**：`reload()` 获取 `_lock` → 重新读取所有配置文件 → 重建 `_cache` → 清空 `_index_cache` → 重新 `validate()` → 发布 `config_changed` 事件 → 释放锁。

> **竞态处理**：若用户在热重载触发的同时调用 `set()`，先获得 `_lock` 的一方先执行，另一方等待锁释放后重新读取最新数据，不会互相覆盖。
>
> **重复事件说明**：`set()` 写盘后发布一次 `config_changed`，同时 `os.replace` 触发热重载 watcher 的 mtime 检测，watcher 调用 `reload()` 再发布一次。同一个变更可能触发两次 `config_changed` 事件。**订阅者应是幂等的**——重复收到同一事件的更新不应影响正确性。若需去重，可在 `reload()` 中比较 `_cache` 前后差异，仅在配置实际变化时发布事件。

### 4.4 配置版本迁移

配置文件带版本号（存储在 `global._version`），程序升级后自动检测版本差异并执行增量迁移。

**迁移机制**：
- 加载时检查配置文件中的 `global._version` 与程序期望版本 `CURRENT_VERSION` 的差异
- 按顺序执行 `v_n → v_{n+1}` 迁移函数（每个版本一个函数，存储在 `config_schema.py` 的 `MIGRATIONS` 列表中）
- 迁移函数接收旧配置 dict，返回新配置 dict
- 所有迁移执行完毕后更新 `global._version` 并保存

### 4.5 配置导入导出

支持将全套配置打包为 zip 备份，或从备份恢复。

**导出格式**：`export_config(path)` 创建 zip 文件，包含 `config/` 目录下所有 YAML/JSON 文件的副本，目录结构与源目录一致。

**导入选项**：
- 覆盖模式（`mode="overwrite"`，默认）：用备份文件替换现有配置
- 补充模式（`mode="supplement"`）：仅补充备份中有但现有配置中缺失的文件，不覆盖已有文件
- 导入完成后自动调用 `reload()` 使变更生效

### 4.6 配置变更审计

每次 `set()` 操作自动记录审计日志：

| 审计字段 | 说明 |
|---------|------|
| `timestamp` | 变更时间 |
| `key_path` | 被修改的配置路径 |
| `old_value` | 修改前的值 |
| `new_value` | 修改后的值 |
| `source` | 变更来源（UI/任务/模块名） |

审计日志通过 **12-日志监控中心** 持久化存储，支持按时间/路径/来源检索。用于问题排查和变更回溯。

### 4.7 全局运行时配置

以下全局配置项由 **09-运行控制中心** 读取，控制脚本的运行行为：

| 配置路径 | 类型 | 说明 | 示例 |
|---------|------|------|------|
| `global.run_window` | `list[str]` | 每日运行时段，空则不限制 | `["08:00", "23:00"]` |
| `global.scheduled_start` | `str \| null` | 定时启动时间 | `"06:00"` |
| `global.scheduled_stop` | `str \| null` | 定时停止时间 | `"23:00"` |
| `global.notification` | `dict` | 通知方式配置 | `{desktop: true, sound: false, webhook: null}` |
| `global.teaming` | `dict` | 组队配置（等待超时、重试次数等） | `{wait_timeout: 30, max_retries: 3}` |
| `global.recognize` | `dict` | 识别配置（阈值、OCR 开关、匹配模式） | `{threshold: 0.8, ocr_enabled: true, ocr_lang: "ch", ocr_confidence: 0.6}` |

## 五、实现思路

### 5.1 模块结构

```
core/
├── config_manager.py     ← 配置管理主入口
└── config_schema.py      ← 配置 Schema 定义与校验
```

### 5.2 核心方法定义

**ConfigManager（配置管理中心）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `get(key_path, default) -> Any` | 🔓 公开 | `ConfigManager` | 点分路径读取配置值。获取 `_lock` → 查 `_index_cache` → 三级覆盖查找 → 写入 `_index_cache` → 返回 |
| `set(key_path, value) -> None` | 🔓 公开 | `ConfigManager` | 设置配置值并原子持久化。获取 `_lock` → 按 key 前缀定位文件 → 写临时文件 → os.replace → 更新 `_cache` → 失效 `_index_cache` 受影响条目 → 发事件 → 释放锁。写盘失败不修改缓存 |
| `get_section(section) -> dict` | 🔓 公开 | `ConfigManager` | 读取整个配置段（如 `get_section("global")` 返回 global 下全部配置）。获取 `_lock` 后从 `_cache` 中读取对应子树，返回副本（dict 深拷贝） |
| `get_task_config(name) -> dict` | 🔓 公开 | `ConfigManager` | 读取完整任务配置。获取 `_lock` → 从 `_cache["tasks"]` 查找任务 → 尝试加载 `coords/{name}.json` → 浅合并（tasks 优先）→ **返回深拷贝（`copy.deepcopy`）**，调用者修改返回的 dict 不影响内部缓存 |
| `get_coords(scene) -> dict` | 🔓 公开 | `ConfigManager` | 读取场景坐标。获取 `_lock` → 从 `_cache["coords"]` 查找 `scene` → 返回或 None |
| `reload() -> None` | 🔓 公开 | `ConfigManager` | 手动热重载所有配置。获取 `_lock` → 重新读取所有文件 → 重建 `_cache` → 清空 `_index_cache` → validate() → 发布 config_changed → 释放锁 |
| `load() -> None` | 🔓 公开 | `ConfigManager` | 按固定顺序（global → tasks → accounts → coords）加载所有配置文件。检查版本号执行迁移 → validate() → 建立 `_index_cache` → 启动 `_watcher` 线程 |
| `validate() -> list[str]` | 🔓 公开 | `ConfigManager` | 校验所有配置。遍历 `_cache` 每个值，对照 `config_schema.py` 中的类型/范围/枚举定义检查合法性。返回错误描述列表（空列表表示全部通过） |
| `export_config(path, overwrite=False) -> None` | 🔓 公开 | `ConfigManager` | 导出全套配置为 zip 备份。`path` 为输出路径。获取 `_lock` 后读取所有配置文件的磁盘副本打包 |
| `import_config(path, mode="overwrite") -> None` | 🔓 公开 | `ConfigManager` | 从 zip 备份恢复配置。`mode="overwrite"` 覆盖现有文件，`mode="supplement"` 仅补充缺失文件。完成后自动调 `reload()` |
| `stop_watcher() -> None` | 🔓 公开 | `ConfigManager` | 停止热重载文件监听线程。设置 `_watcher_stop` 事件，`join(timeout=3)` 等待线程退出。关闭时由 16-应用启动引导 调用 |

### 5.3 核心流程

**配置加载流程**（固定顺序 + 版本迁移 + 校验 + 索引 + 热重载）：
```
load()
  → 获取 _lock
  → 按固定顺序加载（global.yaml → tasks.yaml → accounts.yaml → coords/*.json）
  → 检查 _cache["global"]["_version"] 与 CURRENT_VERSION
  ├── 等于 → 无需迁移
  └── 小于 → 依次执行 v_n → v_{n+1} 迁移函数
       → 更新 _version → save_state()
  → validate() 校验合法性（类型/范围检查），错误记录到日志但不阻断
  → 遍历 _cache 建立 _index_cache（仅缓存已读取过的键路径，惰性填充）
  → 启动 _watcher 文件监听线程（watchdog PollingObserver，3s 间隔）
  → 就绪
```

**配置读取流程**（三级覆盖 + 索引缓存）：
```
get("tasks.yuhun.priority")
  → 获取 _lock
  → 检查 _index_cache["tasks.yuhun.priority"]
  ├── 命中 → 释放锁 → 返回
  └── 未命中 → 解析点分路径 ["tasks", "yuhun", "priority"]
       → 三级覆盖查找：
         ① task: _cache["tasks"]["yuhun"]["priority"]
         ② account: _cache["accounts"][当前账号]["priority"]
         ③ global: _cache["global"]["priority"]
       → 找到任一 → 写入 _index_cache → 释放锁 → 返回
       → 全未找到 → 释放锁 → 返回 default
```

**配置写入流程**（先写盘 + 后更新缓存 + 索引失效）：
```
set("tasks.yuhun.priority", 5)
  → 获取 _lock
  → 解析前缀 "tasks." → 定位到 _paths["tasks"]（tasks.yaml）
  → 记录旧值 old = _cache["tasks"]["yuhun"]["priority"]
  → 写临时文件（序列化为 YAML/JSON，保留原文件格式）
  → os.replace 临时文件 → 原文件
  ├── 成功 → 更新 _cache["tasks"]["yuhun"]["priority"] = 5
  │        → 删除 _index_cache 中所有以 "tasks.yuhun" 开头的条目
  │        → 发布 config_changed(key_path="tasks.yuhun.priority", old, new)
  └── 失败（IOError）→ 不修改 _cache 和 _index_cache → 抛出异常
  → 释放 _lock
```

### 5.4 关键设计

- **纯数据职责**：只读写，不判断业务逻辑
- **原子写盘**：写临时文件 → os.replace 替换，崩溃不损坏
- **写盘优先原则**：先写盘、后更新缓存，写盘失败时缓存不变，确保内存与磁盘始终一致
- **索引惰性失效**：`set()` 只删除 `_index_cache` 中受影响的键前缀，不直接更新值，下次 `get()` 通过三级覆盖重新计算。**缓存键含账号 ID**，账号切换时清空 `_index_cache`，防止返回过期值
- **线程安全**：`_lock` 保护 `_cache` / `_index_cache` / `_paths` 的所有读写
- **校验可选**：`validate()` 返回错误列表，非法配置只告警不阻断
- **三级覆盖**：task级 > account级 > global级，自动按优先级查找
- **热重载跨平台**：watchdog PollingObserver（轮询 mtime，3s 间隔），避免平台差异。订阅者应为幂等的——热重载与 `set()` 可能重复发布 `config_changed`
- **YAML 注释限制**：`set()` 使用 `yaml.dump()` 重写文件，会丢失原文件中的所有注释。建议 YAML 注释仅用于开发说明，不作为功能配置
- **资源管理**：`_watcher` 线程在 `stop_watcher()` 中通过 Event 信号停止并 join(timeout=3)

### 6.2 对外部模块的调用

| 被调用方 | 调用方式 | 说明 |
