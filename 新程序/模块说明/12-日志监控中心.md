> **类型**：支撑服务层  ｜  **对应说明书**：Logger 5.6 升级  ｜  **说明**：新增，统一管理可观测性能力>
> **UI 实现状态**：✅ 完整实现。4 个监控子面板（指标/截图/报告/历史）+ LogPanel 双标签均已就位。
> `Monitor.query_logs()` 支持按级别/模块/任务/时间/关键词检索。
> 全局单例 `monitor` 在 `main_window.py` 中初始化。

## 一、目的与作用

**一句话定位**：可观测性中心。统一管理结构化日志、运行指标、异常截图和运行报告，为调试、监控和优化提供数据支撑。

**为什么需要这个模块**：

现有日志只是简单文本输出，缺少结构化记录、运行指标统计、异常自动截图、运行报告生成等能力。如果这些能力散落在各模块中实现，会导致日志逻辑侵入业务代码，格式不一致。

**核心职责**：
1. **结构化日志**：每条日志带模块/级别/任务/步骤/标签，可按维度筛选检索
2. **运行指标收集**：自动统计各任务执行次数/成功率/平均耗时/总耗时
3. **异常自动截图**：出错时自动截图并保存上下文（任务/步骤/配置/调用栈）
4. **运行报告**：每日/每周自动生成运行总结（Markdown格式）
5. **日志事件化**：日志通过事件总线发布，UI日志面板订阅显示
6. **通知推送**：支持桌面通知、声音提示、Webhook，异常/完成/上限时推送

**设计原则**：
- **非侵入式**：其他模块只需简单调用，不感知日志内部实现
- **结构化优先**：所有日志和指标都是结构化数据，文本输出只是其中一种渲染
- **异步写入**：日志写入不阻塞业务线程，通过队列异步落盘
- **可配置级别**：调试时全量记录，生产时精简输出

## 三、运行逻辑

### 3.1 结构化日志流程

```
调用 log(level, message, module, task, step, tags)
  → 级别预过滤：level < 当前配置的最低级别 → 直接丢弃（避免不必要的对象创建）
  → 封装为 LogEntry（含时间戳/级别/消息/模块/任务/步骤/标签）
  → 放入异步日志队列 → 立即返回（不阻塞调用线程）
  → 后台线程从队列取出 LogEntry：
      ├── 写入文本日志文件（loguru渲染）
      ├── 写入结构化日志文件（JSON格式，供检索）
      └── 发布 log_record 事件到事件总线（UI日志面板订阅）
```

### 3.2 运行指标收集流程

```
运行控制模块调用 record_task_start(task_name)
  → 记录任务开始时间

运行控制模块调用 record_task_done(task_name, success, duration)
  → 更新该任务的执行次数、成功/失败计数、总耗时
  → 更新最后执行时间
  → 失败时记录错误信息

查询：get_metrics(task_name) → 返回单个任务统计
      get_all_metrics() → 返回全部任务统计
```

每个任务的统计指标：总执行次数、成功次数、失败次数、成功率、平均耗时、总耗时、最后执行时间。

### 3.3 异常截图流程

```
捕获到异常 → 调用 capture_on_error(task, step, error)
  → 生成文件名 {task}_{step}_{时间戳}
  → 保存截图：try _connection.screenshot() except → 记录警告，截图路径置空
  → 保存上下文 JSON（任务/步骤/错误信息/调用栈/时间，截图路径可为空）
  → 记录错误日志
```

### 3.4 运行报告生成

`generate_daily_report()`：汇总当日所有任务的执行情况、成功率、耗时分布、异常记录、截图索引。
`generate_weekly_report()`：按周汇总，包含趋势分析。

## 四、重点功能

### 4.1 结构化日志

每条日志携带模块、任务、步骤、标签等多维信息，可按任意维度筛选检索。文本和 JSON 双格式写入，兼顾可读性和可检索性。

### 4.2 运行指标自动统计

无需手动记录，运行控制模块每次任务执行时自动上报数据，自动统计各任务的执行次数、成功率、耗时等关键指标。

### 4.3 异常截图自动保存

出错时自动截取现场画面并保存上下文信息，事后可回溯异常现场。截图和上下文按日期归档，UI 查看器可直接浏览。

### 4.4 日志事件化

日志通过事件总线实时推送给 UI 日志面板，无需轮询，无额外延迟。

### 4.5 通知推送

`notify(level, title, message)` 在内部发布 `notify_alert` 事件到事件总线（携带 level/title/message）。UI 订阅后根据 level 执行对应操作：`"success"` 静默通知栏，`"warning"` 声音提示，`"error"` 弹窗提醒。通知方式（桌面弹窗/声音/Webhook）通过配置 `global.log.notify_method` 控制。

## 五、实现思路

### 5.1 模块结构

```
core/
├── monitor.py               ← 监控主入口 Monitor
├── metrics_collector.py     ← 运行指标收集器
├── snapshot_manager.py      ← 异常截图管理器
├── report_generator.py      ← 运行报告生成器
└── logger.py                ← 底层日志引擎（保留loguru）
```

### 5.2 核心数据结构和类型签名

**LogLevel（日志级别枚举）**：
```
# core/monitor.py 或 core/logger.py
class LogLevel:
    DEBUG = "DEBUG"
    INFO = "INFO"
    WARNING = "WARNING"
    ERROR = "ERROR"
```

**LogEntry（结构化日志条目）**：
```
@dataclass
class LogEntry:
    timestamp: float       # 时间戳（time.time()）
    level: str             # 日志级别（DEBUG/INFO/WARNING/ERROR）
    message: str           # 日志消息
    module: str            # 模块名（如 "09-运行控制中心"）
    task: str | None       # 关联任务名（可选）
    step: str | None       # 关联步骤名（可选）
    tags: list[str]        # 标签列表（如 ["error", "connection"]）
```

**TaskStats（任务运行统计）**：
```
@dataclass
class TaskStats:
    total: int             # 总执行次数
    success: int           # 成功次数
    fail: int              # 失败次数
    avg_duration: float    # 平均耗时（秒）
    total_duration: float  # 总耗时（秒）
    last_run: float        # 最后执行时间戳
```

**TaskRecord（任务执行记录）**：
```
@dataclass
class TaskRecord:
    task_name: str         # 任务名
    start_time: float      # 开始时间戳
    duration: float        # 耗时（秒）
    success: bool          # 是否成功
    error: str | None      # 错误信息（失败时）
```

> **日志存储与查询**：结构化日志按日期归档为 JSON 文件（`logs/structured/{YYYY-MM-DD}.jsonl`），每行一条 JSON 格式的 LogEntry。`query_logs()` 读取对应日期的文件逐行解析并过滤。对于桌面自动化脚本场景，单日日志量通常在数百条以内，逐行扫描性能可接受。保留策略：超过 `config.get("global.log.retention_days", 30)` 天的日志文件自动清理。

### 5.4 核心流程

**结构化日志流程**（异步）：
```
调用 log(level, msg, module, task, step, tags)
  → 级别预过滤：level < 当前配置的最低级别 → 直接丢弃
  → 封装为 LogEntry（含时间戳/级别/消息/模块/任务/步骤/标签）
  → 放入 _log_queue → 立即返回（不阻塞调用线程）

后台工作线程：
  while running:
    → 从 _log_queue 取出 LogEntry
    → try:
        → 写入文本日志文件（loguru 渲染）
        → 写入结构化日志文件（JSONL 格式，logs/structured/{YYYY-MM-DD}.jsonl）
        → 发布 log_record 事件到事件总线（UI 日志面板订阅）
      except Exception:
        → 降级为 stderr 输出
        → 尝试直接发布 log_record 事件（让 UI 至少看到错误）
        → 不中断后台线程循环
```

**运行指标收集流程**：
```
record_task_start(name) → 记录任务开始时间
record_task_done(name, success, duration)
  → 更新 _task_stats[name] 的执行次数、成功/失败计数、总耗时
  → 失败时记录错误信息
```

### 5.5 关键设计

- **非侵入式**：其他模块只需调用 monitor.log() / monitor.record_task()，不感知内部实现
- **异步写入**：日志通过队列异步写入，不阻塞业务线程
- **日志检索**：支持按级别/模块/任务/时间/关键词检索历史日志
- **日志事件化**：通过事件总线推送日志，UI 订阅后实时显示
