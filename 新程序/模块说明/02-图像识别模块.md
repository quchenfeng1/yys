# 02-图像识别模块（Image Recognition Module）

> **类型**：核心运行层  ｜  **对应说明书**：Recognizer 5.2  ｜  **对应用户模块**：#6 识图控制模块

---

## 一、目的与作用

**一句话定位**：在截图中定位目标图片，返回匹配位置与置信度。纯识别引擎，不涉及任何操作和安全处理，是系统的"眼睛"。

**核心职责**：
1. **模板匹配**：在截图中查找目标模板图，返回位置+置信度
2. **素材管理**：加载 assets/ 四层分类目录的全部图片，建立内存索引（含加载校验）
3. **区域限定**：支持限定搜索范围，加速识别减少误匹配
4. **等待机制**：轮询等待目标出现，支持超时、多个模板同时等待、外部停止信号打断
5. **OCR文字定位**：识别界面文字位置，应对动态背景界面（含降级策略）
6. **异常统一出口**：所有识别相关异常从此模块抛出（素材不存在、OCR 不可用、模板数据损坏等）
7. **触发监控（TriggerWatcher）**：对触发式任务（`repeat.type=trigger`）的识别列表持续监控，命中后发布 `trigger_detected` 事件，驱动任务自动入队

**设计原则**：
- **纯粹性**：只做"看"，不做"做"（点击归执行模块，安全归安全模块）
- **无副作用**：识别过程不修改任何外部状态，纯函数式调用
- **可独立测试**：给图片+模板→返回结果，不依赖设备连接
- **线程安全**：缓存读写受锁保护，避免多线程场景下数据污染
- **降级优先**：OCR 引擎不可用时静默降级为纯模板匹配，不影响主流程

## 二、模块属性与依赖

### 2.1 依赖注入（外部模块引用）

| 属性名 | 类型 | 作用域 | 作用 |
|--------|------|--------|------|
| `_connection` | `ConnectionManager` | 🔒 私有 | 获取当前截图（调用 screenshot()） |
| `_config` | `ConfigManager` | 🔒 私有 | 读取识别阈值(`global.recognize.threshold`)、素材目录配置、OCR 开关(`global.recognize.ocr_enabled`)、OCR 语言(`global.recognize.ocr_lang`)、OCR 置信度阈值(`global.recognize.ocr_confidence`)、备用 OCR 引擎(`global.recognize.ocr_engine`) |
| `_monitor` | `Monitor` | 🔒 私有 | 记录识别耗时和性能数据 |
| `_event_bus` | `EventBus` | 🔒 私有 | 可选。`wait()`/`wait_any()` 检查 `stop_requested` 事件，实现可打断等待 |

### 2.2 对外暴露属性（其他模块可读取）

通过识别接口返回值获取。

| 属性名 | 类型 | 作用域 | 说明 |
|--------|------|--------|------|
| `match_result` | `MatchResult` | 📖 只读对外 | 匹配结果：模板名、中心坐标、左上角坐标、区域大小、置信度、识别方式(template/ocr/hybrid) |

### 2.3 内部私有属性

| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_asset_cache` | `dict[str, np.ndarray]` | 素材缓存：name → BGR 彩色图（三通道），启动时全量加载。匹配时根据模式动态转灰度（`cv2.cvtColor(..., COLOR_BGR2GRAY)`），保留颜色信息供彩色匹配场景使用。加载时校验 `cv2.imread()` 返回值，无效文件跳过并记录警告 |
| `_result_cache` | `dict[str, tuple[float, float, Any]]` | 识别结果缓存：短时间重复识别。键为模板名或 OCR 缓存键 `("ocr", text, region_hash)`，值为 `(timestamp, confidence, MatchResult或tuple)`。查找时比较当前时间与 timestamp，超过 TTL（默认 1秒）视为过期。OCR 结果复用可避免 50~150ms 的重复推理 |
| `_result_cache_ttl` | `float` | 结果缓存有效期（默认 1.0 秒） |
| `_screenshot_cache` | `np.ndarray \| None` | 截图缓存：同一轮截图复用，避免重复 ADB 请求。受 `_cache_lock` 保护 |
| `_last_frame_time` | `float` | 上一帧截图的时间戳，用于判断截图缓存是否过期 |
| `_screenshot_ttl` | `float` | 截图缓存有效期（默认 0.2 秒）。推荐固定为 `interval × 0.4`（高频期 interval 默认 0.5s → TTL=0.2s），确保每次 `find()` 调用间隔超过 TTL，强制重新截图，做到真正的每轮新画面。超过此时间视为过期，下次 `find()` 自动触发重新截图 |
| `_cache_lock` | `Lock` | 保护 `_screenshot_cache` 和 `_result_cache` 的线程安全锁。`find()` 的缓存读写均需获取此锁，避免多线程场景下扫描线程污染的截图被执行线程误用 |
| `_threshold` | `float` | 默认置信度阈值 0.8 |
| `_latency_records` | `deque[float]` | 每次识别的耗时记录（毫秒），`deque(maxlen=200)` 线程安全追加，用于性能监控 |
| `_asset_dir` | `str` | assets/ 目录路径 |
| `_ocr_engine` | `object \| None` | OCR 引擎实例（惰性初始化，首次调用 `locate_text()` 时创建）。支持 PaddleOCR，若安装失败或导入出错则 `_ocr_ready = False`，所有 OCR 操作返回 `None` 并记录警告 |
| `_ocr_ready` | `bool` | OCR 引擎是否已成功加载。若为 False，`locate_text()` / `locate_any()` 直接返回 `None` 不抛异常 |
| `_init_lock` | `Lock` | 保护 `_init_engine()` 的线程安全锁，防止多线程并发初始化时重复加载 OCR 模型（约 50MB 翻倍）。使用双重检查锁模式 |
| `_ocr_lock` | `Lock` | 串行化 OCR 推理调用的锁。PaddleOCR 的预测接口是否线程安全未经明确保证，使用此锁强制 `_ocr_page()` 串行执行，避免并发崩溃 |

## 三、运行逻辑

### 3.1 识别流程（线程安全）

```
接收识别请求（模板名 + 可选区域 + 阈值 + 模式）
  → 校验：模板名是否存在于 _asset_cache
  ├── 不存在 → 记录 "素材不存在: {name}" 警告 → 返回 None
  └── 存在 → 继续

  → [加锁 _cache_lock] 检查结果缓存
  ├── 命中且未过期（当前时间 - timestamp < _result_cache_ttl）→ 直接返回缓存
  └── 未命中/已过期 → 继续

  → [加锁 _cache_lock] 检查截图缓存
  ├── _screenshot_cache 非 None 且 (time.time() - _last_frame_time) < _screenshot_ttl → 直接使用
  └── 缓存未命中或已过期（超过 _screenshot_ttl）→ 释放 _cache_lock → 调 _connection.screenshot()
       → 检查截图是否为 None 或空
       ├── 无效 → 抛 RecognitionError("截图无效")
       └── 有效 → [加锁 _cache_lock] 更新 _screenshot_cache + _last_frame_time → 释放锁

  → 释放 _cache_lock（模板匹配过程不持锁，避免阻塞其他线程的缓存读取）

  → 检查模板尺寸 ≤ 截图尺寸
  ├── 模板更大 → 抛 RecognitionError("模板({tw}x{th})大于截图({sw}x{sh})")
  └── 通过 → 继续

  → 根据 mode 参数选择识别路径
  ├── 模式B(仅模板) / 模式A(默认)：
  │     → 灰度化处理
  │     → 多尺度循环（依据模板与截图尺寸比动态计算尺度范围）
  │     → 执行 cv2.matchTemplate
  │     → 取最高置信度结果
  │     ├── 置信度 ≥ threshold → 命中
  │     └── 置信度 < threshold → 模式A 且 OCR 可用 → 回退 OCR 定位
  └── 模式C(仅OCR)：
        → 直接调 _ocr_locator.locate_text(name) 或完整页面 OCR 后筛选

  → [加锁 _cache_lock] 写入 _result_cache（含当前时间戳）
  → 记录本次识别耗时到 _latency_records
  → 返回 MatchResult 或 None
```

> **截图缓存线程安全规则**：
> - `_screenshot_cache` 的读写必须持有 `_cache_lock`
> - **TTL 机制**：截图缓存有效期为 `_screenshot_ttl`（默认 0.3~0.5 秒）。超过此时间自动视为过期，下次 `find()` 会重新截图。此机制保证 `wait()` 轮询每次循环都能获取最新画面，避免死循环
> - 多个线程同时调用 `find()` 时，谁先获得锁谁负责更新截图，后续线程在 TTL 内复用缓存
> - 获取新截图后立即释放锁，模板匹配不持锁，减少锁竞争
> - `clear_cache()` 方法强制清空截图和结果缓存，由 14-执行器模块 在步骤边界调用，确保新步骤开始前获取最新画面

### 3.2 等待机制（可打断 + 自适应退避）

`wait(name, timeout, interval, stop_event)` 和 `wait_any(names, timeout, stop_event)`：

```
wait(name, timeout, interval=0.5, stop_event=None)
  → 记录开始时间
  → 循环：
      ├── [检查停止] 若 stop_event 被设置 → 立即返回 None（不等待超时）
      ├── 调 find(name) → 找到则返回结果
      ├── 未找到 → 计算已耗时
      │     ├── 已耗时 > timeout → 返回 None
      │     └── 未超时 → 自适应休眠：
      │           剩余时间 > 10s → sleep(min(interval * 4, 2.0))  ← 后期降低频率（默认 0.5s→2.0s）
      │           剩余时间 ≤ 10s → sleep(interval)                 ← 临近超时恢复频率
      └── 回到循环开始
```

> **自适应退避策略**：等待开始时 interval=0.5s 高频轮询。若等待超过 5 秒仍未匹配到目标，自动将间隔升到 2.0s，减少无意义的截图开销。临近超时时恢复短间隔，确保不遗漏目标短暂出现。
>
> **停止信号**：`stop_event` 参数接收 `threading.Event`，当外部（如 09-运行控制中心）设置此事件时，等待立即返回 None。避免用户点停止后线程仍在 `time.sleep()` 中阻塞。
>
> **停止响应延迟说明**：自适应退避阶段最长睡眠为 2.0 秒（降频期）。在此期间 `stop_event` 的检查被 sleep 阻塞，停止响应最多有 2 秒延迟。对于桌面自动化场景通常可接受，如需更低延迟可将长 sleep 拆分为 0.1 秒循环检查。

### 3.3 素材索引（含加载校验）

启动时递归扫描 assets/ 下全部 PNG 文件，按相对路径（如 `common/battle/challenge_btn`）建立索引，以 BGR 彩色图缓存到内存。运行时查找直接从内存读取，避免磁盘 IO。匹配时根据模式动态转灰度（`cv2.cvtColor(..., COLOR_BGR2GRAY)`），保留颜色信息供彩色匹配场景使用。

**加载流程**：
```
_load_templates()
  → 递归遍历 _asset_dir 下所有 *.png 文件
  → 对每个文件：
      ├── 调 cv2.imread(path, cv2.IMREAD_COLOR) 读取为 BGR 彩色图
      │   ├── 失败（返回 None）→ 记录 "素材加载失败: {path}" 警告 → 跳过该文件
      │   └── 成功 → 存入 _asset_cache
      └── 检查 numpy 数组是否为空（0x0 尺寸）
            ├── 空 → 跳过该文件并记录警告
            └── 非空 → 存入缓存
  → 检查 len(_asset_cache)
      ├── 0 → 记录 "警告: assets/ 目录为空，所有识别将返回 None" ERROR 日志
      └── >0 → 记录 "已加载 N 个素材" INFO 日志
  → 就绪
```

### 3.4 OCR定位

当模板匹配无法应对动态背景界面时，使用 OCR 识别文字位置。作为模板匹配的补充方案，速度较慢但适应性更强。

**引擎选择**：
- 首选 **PaddleOCR** 轻量模型（`ch_PP-OCRv4`），推理延迟约 50~150ms，中文识别准确率 >95%
- 若 PaddlePaddle 未安装或导入失败（ImportError），OCR 功能静默降级：`_ocr_ready = False`，所有 OCR 方法返回 `None`，不影响模板匹配流程
- 配置项 `global.recognize.ocr_engine` 可指定备用引擎（预留扩展）

**文字匹配规则**（`locate_text` / `locate_any`）：
```
locate_text("确认")
  → _ocr_page(region) 对截图区域执行全页 OCR
  → 遍历返回的 OCRResult 列表
  → 对每个结果计算 Levenshtein 编辑距离：
      ├── 编辑距离 ≤ max(1, ceil(len(text)*0.25)) → 视为匹配成功（容忍 OCR 识别误差）
      │    例："确认" (len=2) → 阈值 = max(1, ceil(2×0.25)) = 1
      │      "确认" → "确认" 距离=0 ✓
      │      "确认" → "碓认" 距离=1 ✓（'碓'≠'确'）
      │      "确认" → "确以" 距离=1 ✓（'以'≠'认'）
      │      "确认" → "取消" 距离=2 ✗（正确拒绝，防止误点击）
      └── 编辑距离 > 阈值 → 跳过
  → 返回匹配结果中置信度最高且编辑距离最小的文字块坐标
  → 未匹配到任何结果 → 返回 None
```

> **模糊匹配的必要性**：游戏 UI 中文字可能带有特效（阴影、描边、渐变色），PaddleOCR 对这些字体的识别准确率会下降到 80~90%。严格精确匹配会频繁漏检，Levenshtein 距离容错能显著提高命中率。

### 3.5 双引擎调度策略

识别模块支持三种模式的自动切换，保证识别效率和准确率的平衡。模式通过 `MatchMode` 枚举控制：

| 模式 | 枚举值 | 行为 | 适用场景 |
|------|--------|------|---------|
| **模板优先（默认）** | `AUTO` | 先模板匹配，置信度不足时根据模板元数据决定是否回退 OCR | 大部分场景 |
| **仅模板匹配** | `TEMPLATE_ONLY` | 直接执行 `cv2.matchTemplate`，不调用 OCR | 按钮/图标等静态 UI |
| **仅OCR** | `OCR_ONLY` | 跳过模板匹配，直接执行文字定位 | 动态公告、弹窗文字 |

```
识别请求 → 根据 mode 参数选择路径：

  mode=AUTO:
    ① 模板匹配
    ② 置信度 ≥ threshold → 返回模板结果
    ③ 置信度 < threshold → 检查该模板的元数据（在素材目录的 _meta.json 中定义）
         ├── fallback_to_ocr: true → 调 OcrLocator.locate_text()
         │    匹配成功 → 返回 OCR 结果（method="ocr"）
         │    匹配失败 → 返回 None
         └── fallback_to_ocr: false/未定义 → 返回 None（不回退 OCR）

  mode=TEMPLATE_ONLY:
    ① 模板匹配 → 返回结果或 None

  mode=OCR_ONLY:
    ① 检查 _ocr_ready
         ├── False → 记录 "OCR 不可用" 警告 → 返回 None
         └── True → 调 OcrLocator.locate_text() → 返回结果或 None
```

> **模板元数据机制**：在 `assets/` 各子目录下可放置 `_meta.json` 文件，为每个模板定义识别行为：
> ```json
> {
>   "common/popup/activity_banner": {
>     "fallback_to_ocr": true,
>     "ocr_hint": "活动"
>   },
>   "common/ui/close_btn": {
>     "fallback_to_ocr": false
>   }
> }
> ```
> 若 `_meta.json` 不存在或模板未在其中定义，fallback_to_ocr 默认为 false。此机制取代了之前模糊的"文字线索"概念。

### 3.6 触发监控（TriggerWatcher）

对触发式任务（`repeat.type=trigger`）提供"识别列表 → 自动触发"的常驻监控能力：

```
TriggerWatcher（02 模块内子服务，core/trigger_watcher.py）
  ├─ 构造注入：recognizer（复用模板匹配）+ connection（截图）+ event_bus
  ├─ start():
  │     → 从 05-Scheduler.get_all_tasks() 收集 repeat.type=trigger 的任务
  │     → 构建识别列表 {模板名 → 任务名}（来自 repeat.trigger_templates）
  │     → 启动常驻 daemon 线程
  └─ 监控循环（间隔 1~3s）:
        ├── [检查停止] stop_event 被设置？→ 退出循环
        ├── 对识别列表中每个触发模板调 match_any(识别列表)
        │     → 命中模板 A（属于任务 X）→ 发布 trigger_detected(task_name=X)
        │     → 同一模板同一时刻只触发一次（触发后从本轮列表移除，下轮重新检测）
        ├── 未命中 → 继续
        └── sleep(interval)

  stop():
        → 设置 stop_event → join 监控线程(timeout=3)
```

> **职责边界**：TriggerWatcher 只负责"识别到 → 发布事件"，**不直接修改任何调度状态**
> （不持有 05 引用）。触发动作（`update_next_run(name, now)`）由 05-时间调度模块
> 在订阅 `trigger_detected` 时执行。此设计保持 02 的"无副作用"原则。
>
> **运行生命周期**：由 09-运行控制中心 在构造时内部创建（复用已注入的
> recognizer/connection/event_bus），`_on_start` 时 `start()`、`_on_stop` 时 `stop()`。
> 09 构造函数签名不变。
>
> **多线程截图安全**：TriggerWatcher 作为新增"扫描线程"，截图/识别全部走
> `_cache_lock` + `_screenshot_ttl` 机制，与执行线程的截图缓存隔离，避免互相污染。

## 四、重点功能

### 4.1 模板匹配 + OCR 双引擎

静态界面用 OpenCV 模板匹配（快速高效），动态背景界面用 OCR 定位文字（适应变化）。两者互补，覆盖所有识别场景。OCRS 不可用时静默降级，不影响主流程。

### 4.2 自适应多尺度匹配

根据模板与截图的尺寸比动态计算缩放范围（默认 0.8~1.2，步长 0.05），覆盖不同分辨率下的渲染偏差。取置信度最高的匹配结果。

### 4.3 识别缓存与线程安全

短时间内对同一模板的重复识别结果缓存（默认1秒），避免轮询等待时的重复计算开销。`_cache_lock` 保护截图缓存和结果缓存，防止多线程场景下扫描线程污染的截图被执行线程误用。

### 4.4 区域限定

通过 region 参数限定搜索范围，既加速识别又减少误匹配。

### 4.5 分层异常体系

| 异常类 | 触发场景 | 说明 |
|--------|---------|------|
| `RecognitionError` | 所有识别异常的基类 | — |
| `AssetNotFoundError` | `find()` 传入的模板名在 `_asset_cache` 中不存在 | 检查素材是否缺失 |
| `OCRNotAvailableError` | 调用 `locate_text()` 时 `_ocr_ready = False` | OCR 引擎未加载或导入失败 |
| `AssetCorruptedError` | 素材加载时 `cv2.imread()` 返回 None | 素材文件损坏 |

### 4.6 可打断等待

`wait()` / `wait_any()` 接受 `stop_event` 参数，接收外部停止信号后立即返回 None，避免用户点停止后线程仍在 sleep 中阻塞。

## 五、实现思路

### 5.1 模块结构

```
core/
├── recognizer.py        ← Recognizer 识图主引擎（模板匹配 + 缓存管理 + 线程安全锁）
├── ocr_locator.py       ← OcrLocator OCR文字定位子模块（基于 PaddleOCR，含 Levenshtein 模糊匹配）
└── trigger_watcher.py   ← TriggerWatcher 触发监控子服务（识别列表 → trigger_detected 事件）
```

### 5.2 核心数据结构

**MatchResult（识别匹配结果）**：
```python
@dataclass
class MatchResult:
    template_name: str         # 匹配到的模板名，如 "common/battle/challenge_btn"
    center_x: int              # 匹配区域中心 X 坐标
    center_y: int              # 匹配区域中心 Y 坐标
    x: int                     # 匹配区域左上角 X
    y: int                     # 匹配区域左上角 Y
    width: int                 # 匹配区域宽度
    height: int                # 匹配区域高度
    confidence: float          # 匹配置信度（0.0 ~ 1.0）
    scale: float = 1.0         # 匹配时的缩放比例（多尺度匹配时有效）
    method: str = "template"   # 识别方式："template" / "ocr" / "hybrid"
```

**OCRResult（OCR 识别结果）**：
```python
@dataclass
class OCRResult:
    text: str                  # 识别出的文字内容
    confidence: float          # OCR 置信度（0.0 ~ 1.0）
    x: int                     # 文字区域左上角 X
    y: int                     # 文字区域左上角 Y
    width: int                 # 文字区域宽度
    height: int                # 文字区域高度
```

### 5.3 核心方法定义

**Recognizer（识图主引擎）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `find(name, region, threshold, mode) -> MatchResult \| None` | 🔓 公开 | `Recognizer` | 查找单个模板，返回最佳匹配或 None。mode 为 `MatchMode` 枚举（AUTO/TEMPLATE_ONLY/OCR_ONLY）。可能抛出 `AssetNotFoundError`（模板名不存在）、`RecognitionError`（截图无效或模板>截图） |
| `find_all(name, region, threshold) -> list[MatchResult]` | 🔓 公开 | `Recognizer` | 查找所有匹配位置 |
| `exists(name, threshold) -> bool` | 🔓 公开 | `Recognizer` | 判断目标是否存在（内部调 find，不抛异常） |
| `wait(name, timeout, interval, stop_event) -> MatchResult \| None` | 🔓 公开 | `Recognizer` | 等待模板出现，超时返回 None。`stop_event: Event | None` 接收外部停止信号，设置后立即返回 |
| `wait_any(names, timeout, stop_event) -> tuple[str, MatchResult] \| None` | 🔓 公开 | `Recognizer` | 等待多个模板中任一出现。`stop_event` 同 `wait()` |
| `clear_cache() -> None` | 🔓 公开 | `Recognizer` | 清空 `_screenshot_cache` 和 `_result_cache`（获取 `_cache_lock` 后置 None），由 14-执行器模块在步骤边界调用 |
| `reload() -> None` | 🔓 公开 | `Recognizer` | 重新加载素材（清空 `_asset_cache` 后重新 `_load_templates()`，清空所有缓存） |
| `suggest_template(screenshot) -> str \| None` | 🔓 公开 | `Recognizer` | 将截图与已知模板逐一遍历匹配，返回置信度最高的模板名。O(n) 复杂度，仅在手动收藏场景使用，不用于运行时 |
| `match_any(names, region, threshold) -> list[tuple[str, MatchResult]]` | 🔓 公开 | `Recognizer` | **识别列表批量识别（立即版）**：一次截图（复用现有缓存/锁机制）对列表内所有模板匹配，返回命中集合 `[(模板名, MatchResult), ...]`，未命中返回空列表。供 TriggerWatcher 触发监控使用 |

**TriggerWatcher（触发监控子服务）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `start() -> None` | 🔓 公开 | `TriggerWatcher` | 收集触发式任务识别列表（05.get_all_tasks() 中 repeat.type=trigger 的 trigger_templates）→ 启动常驻监控线程 |
| `stop() -> None` | 🔓 公开 | `TriggerWatcher` | 设置 stop_event → join 监控线程（timeout=3） |
| `_monitor_loop() -> None` | 🔒 私有 | `TriggerWatcher` | 监控循环：间隔 1~3s 截图 → `match_any(识别列表)` → 命中 → 发布 `trigger_detected(task_name)` |

**OcrLocator（OCR文字定位，基于 PaddleOCR）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `locate_text(text, region) -> tuple \| None` | 🔓 公开 | `OcrLocator` | 全页 OCR → 遍历结果 → Levenshtein 模糊匹配（编辑距离 ≤ max(1, ceil(len×0.25))），返回匹配文字块的中心坐标。若 `_ocr_ready` 为 False 则返回 None |
| `locate_any(texts, region) -> tuple[str, tuple] \| None` | 🔓 公开 | `OcrLocator` | 多个候选文字，**只执行一次 `_ocr_page(region)`**，在返回的 OCRResult 列表中一次性筛选出与 texts 中任意一个模糊匹配的结果，避免对每个候选词重复 OCR 推理。返回第一个匹配到的文字名+坐标 |
| `_ocr_page(region) -> list[OCRResult]` | 🔒 私有 | `OcrLocator` | 对截图指定区域执行 OCR 全页识别，返回文字块列表（含文本+置信度+坐标）。含超时机制（默认 5s），超时返回空列表 |
| `_init_engine() -> None` | 🔒 私有 | `OcrLocator` | 惰性初始化 OCR 引擎。使用双重检查锁（`_init_lock`）防止多线程并发初始化时重复加载模型。捕获 ImportError（PaddlePaddle 未安装），设置 `_ocr_ready = False`，不抛异常 |

**MatchMode（识别模式枚举）**：

```python
class MatchMode(Enum):
    AUTO = "auto"              # 模板优先，按元数据决定是否回退 OCR
    TEMPLATE_ONLY = "template" # 仅模板匹配
    OCR_ONLY = "ocr"           # 仅 OCR 文字定位
```

> 注：素材索引功能已内联到 `Recognizer._load_templates()` 中，`AssetIndex` 独立类已取消。

### 5.4 核心流程

**识别流程**（含缓存、锁、校验、多尺度、双引擎）：
```
find(name, region, threshold, mode=AUTO)
  → 检查 name 是否在 _asset_cache 中
  ├── 否 → 日志警告 "素材缺失: {name}" → 返回 None
  └── 是 → 继续

  → 获取 _cache_lock
  → 检查 _result_cache[name] → 命中且未超 TTL？
  ├── 是 → 释放锁 → 返回缓存结果
  └── 否 → 继续

  → 检查 _screenshot_cache 是否有效且 (time.time() - _last_frame_time) < _screenshot_ttl
  ├── 是 → 直接使用
  └── 否（TTL 过期或缓存空）→ 释放 _cache_lock → 调 _connection.screenshot()
         → 截图 None/空？→ 抛 RecognitionError("截图无效")
         → 获取 _cache_lock → 更新 _screenshot_cache + _last_frame_time

  → 释放 _cache_lock（模板匹配不持锁）
  → 检查模板 ≤ 截图？→ 否 → 抛 RecognitionError("模板大于截图")

  → 根据 mode 分发：
      AUTO / TEMPLATE_ONLY:
        → 计算自适应尺度范围（基于模板与截图尺寸比例）
        → 多尺度循环 cv2.matchTemplate
        → 取最高置信度
        ├── 置信度 ≥ threshold → 结果
        └── 置信度 < threshold AND mode=AUTO
              → 检查模板元数据 fallback_to_ocr
              ├── true → 调 OcrLocator.locate_text()
              │         匹配 → 返回 OCR 结果
              │         不匹配 → 返回 None
              └── false → 返回 None

      OCR_ONLY:
        → 检查 _ocr_ready
        ├── false → 日志警告 → 返回 None
        └── true → 调 OcrLocator.locate_text() → 返回结果

  → 获取 _cache_lock → 写入 _result_cache（含时间戳）→ 释放锁
  → 记录耗时到 _latency_records
  → 返回 MatchResult 或 None
```

**等待流程**（含停止信号和自适应退避）：
```
wait(name, timeout=30, interval=0.5, stop_event=None)
  → 校验 name 存在
  → 记录开始时间 start = time.time()
  → 循环：
      ├── [步骤边界] stop_event 被设置？→ 返回 None（立即响应停止）
      ├── 调 find(name)
      │   ├── 命中 → 返回 MatchResult
      │   └── None → 继续
      ├── 计算 elapsed = time.time() - start
      ├── elapsed > timeout？→ 返回 None
      └── 自适应休眠：
            ├── elapsed < 5s → sleep(interval)          ← 高频期（默认 0.5s）
            ├── elapsed < timeout-3 → sleep(min(interval*4, 2.0)) ← 降频期（默认升至 2.0s）
            └── else → sleep(interval)                   ← 临近超时恢复高频
```

### 5.5 关键设计

- **灰度优先（彩色备用）**：`_asset_cache` 存储 BGR 彩色图，匹配时动态转灰度（`cv2.cvtColor`）。颜色敏感场景可直接使用彩色匹配，无需修改缓存结构
- **PIL 读取兼容中文路径**：保留 `_imread_unicode()` 方案处理中文路径
- **索引名=相对路径**：`common/battle/challenge_btn` 对应 `assets/common/battle/challenge_btn.png`
- **无状态设计**：识别过程不修改任何外部状态，纯函数式调用，便于测试
- **OCR 惰性初始化**：PaddleOCR 模型约 50MB，首次调用 `locate_text()` 时加载，不占用启动时间。初始化受 `_init_lock` 双重检查锁保护，防止多线程并发加载
- **OCR 降级策略**：PaddlePaddle 未安装时静默降级，所有 OCR 方法返回 None，不影响模板匹配
- **OCR 串行化**：`_ocr_lock` 强制 OCR 推理串行执行，避免 PaddleOCR 预测接口在多线程并发下可能引发的第三方库崩溃
- **OCR 模糊匹配**：使用 Levenshtein 编辑距离容忍 OCR 识别误差，编辑距离 ≤ max(1, ceil(len×0.25)) 即视为匹配。对 2 字短字符串阈值为 1（仅容忍一字之差），防止"确认"与"取消"等关键按钮的误匹配
- **`_meta.json` 元数据驱动回退**：取代"文字线索"模糊概念，每个模板的 OCR 回退行为在 json 文件中明确定义
- **`_cache_lock` 线程安全**：保护截图缓存和结果缓存，多线程场景下避免数据污染
- **截图缓存 TTL**：`_screenshot_ttl`（默认 0.2 秒，推荐 `interval × 0.4`）确保 `wait()` 轮询每次循环都能获取最新截图，避免因复用旧图导致的死循环。TTL 小于高频期间隔，保证每轮查找都强制刷新截图
- **OCR 结果缓存**：`_result_cache` 扩展支持 OCR 缓存键 `("ocr", text, region_hash)`，避免同一步骤内多次 OCR 同一段文字的重复推理开销
- **`clear_cache()` 公开接口**：供执行器在步骤边界调用，强制清空截图和结果缓存，确保新步骤开始前获取最新画面
- **stop_event 可打断等待**：`wait()`/`wait_any()` 接收外部停止信号，快速响应停止请求（最坏延迟 2 秒，由降频期最长 sleep 决定）
- **自适应等待退避**：前期高频轮询，后期自动降频，减少无意义的截图开销。降频期最长 sleep 2.0s，停止响应最多延迟 2 秒
- **自适应多尺度**：基于模板与截图尺寸比例动态计算尺度范围（0.8~1.2），替代固定三尺度
- **素材加载校验**：加载时检查图片有效性，跳过损坏文件；空目录记录 ERROR 日志
- **异常分层**：`RecognitionError` 基类 + `AssetNotFoundError` / `OCRNotAvailableError` / `AssetCorruptedError`
- **PaddleOCR 可选依赖**：PaddlePaddle 为可选安装，核心模板匹配功能不依赖它
- **TriggerWatcher 无副作用**：命中后只发布 `trigger_detected` 事件，不持有/修改 05 调度状态（保持"识别过程不修改任何外部状态"原则）
- **触发监控复用识别链路**：`match_any` 走与 `find` 相同的缓存/锁/多尺度机制，无独立识别路径
- **触发监控线程安全**：作为新增扫描线程，截图/识别遵守 `_cache_lock` + `_screenshot_ttl` 规则，与执行线程隔离
- **触发防重**：同一模板命中并触发后，本轮识别列表移除该项，下轮重新检测（配合任务执行使图片消失，天然避免反复触发）

### 6.1 外部提供的调用接口

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `find(name, region, threshold, mode)` | **14-执行器模块** / 任务步骤 | 查找单个模板，返回最佳匹配或 None。可能抛 `AssetNotFoundError`（模板不存在）/ `RecognitionError`（截图无效） |
