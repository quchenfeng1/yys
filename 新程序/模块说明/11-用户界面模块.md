## 一、目的与作用

**一句话定位**：用户界面。分解为菜单树、任务列表、日志终端、状态展示等子模块，通过传参模块与程序逻辑交互，UI 自身不含任何业务逻辑。

**核心职责**：
1. **界面展示**：三栏布局（左菜单 / 中任务列表 / 右日志终端），展示配置、任务、日志、状态
2. **用户交互**：接收用户操作（点击/输入/勾选），通过传参模块传递给程序
3. **状态刷新**：订阅事件总线，自动刷新运行状态、任务进度、连接状态
4. **内置终端**：捕获 stdout/stderr 实时显示，替代外部命令行黑窗口
5. **素材管理**：可视化增删改查 assets/ 目录的图片素材

**设计原则**：
- **UI零逻辑**：UI只负责展示和接收输入，所有逻辑通过传参模块交给程序
- **事件驱动刷新**：订阅事件自动更新，不主动轮询程序状态
- **子模块独立**：每个 UI 区域是独立 Widget，可单独开发测试替换
- **菜单与目录对应**：菜单分类与 tasks/ 子目录一一对应，自动生成

## 三、运行逻辑

### 3.1 事件驱动刷新机制

UI 子模块不主动轮询程序状态，而是通过事件总线订阅相关事件自动更新（共 22 种事件）：

- **运行状态变化**：订阅 `state_changed(run_status)` → 更新状态显示文字和颜色。订阅 `state_reset` → 所有只读控件重新加载默认值
- **任务执行**：订阅 `task_started` / `task_done` / `step_done` / `task_skipped` → 更新当前任务和步骤显示、刷新队列卡片
- **运行启停**：订阅 `run_started` / `run_paused` / `run_stopped` / `run_limit_reached` → 更新启停按钮状态和运行状态栏
- **连接状态**：订阅 `connection_lost` / `connection_restored` / `connection_error` / `connection_quality_warning` → 更新连接图标、延迟/丢包警告
- **日程更新**：订阅 `schedule_updated` → 刷新任务队列卡片
- **日志记录**：订阅 `log_record` / `notify_alert` → 追加到日志流显示，提醒弹窗
- **素材和场景**：订阅 `scene_unknown` / `assets_missing` → UI 提示未知场景或缺失素材
- **任务列表**：订阅 `tasks_list_changed` → 重新扫描任务目录并重建任务列表面板
- **启动检查**：订阅 `preflight_complete` → 显示启动自检结果

### 3.2 任务队列展示（TaskQueuePanel）

中间面板的任务队列卡片组件，将定时模块的日程表数据可视化：

**数据流**：`定时模块 build_schedule()` → 过滤+排序 → 存入状态管理 → 发布 `schedule_updated` 事件 → 本面板订阅并重建卡片。

**队列四区**（`TaskQueuePanel`）：
| 分区 | 收纳任务 | 数据来源 |
|------|---------|---------|
| ▶ 正在执行 | 当前执行中的任务（大卡片） | `run.current_task` |
| ⏳ 待执行 | `due` 到期任务 | `Scheduler.get_due_tasks()` |
| 🕐 未开始 | `waiting` 且未到 `next_run_time` | `Scheduler.get_upcoming()` |
| ⚠ 已失效 | `completed`（达上限 / `on_enter` 本轮已完成 / `trigger` 本轮已执行）/ `skipped` / 待配置 | `Scheduler.get_invalid_tasks()` |

**已失效区子类型标注**：
| 子类型 | 标注 | 说明 |
|--------|------|------|
| 已过期 | `[已过期] · 累计 x/y 次已完成` | `total_count` 满 / `active_range` 结束 / `expire_at` 到期 |
| 待配置 | `[待配置] · 尚未配置执行规则` | 任务库有但未配置 / 已停用 |
| 本轮已完成 | **`[本轮已完成] · 下次启动执行`** | `repeat.type=on_enter` 执行完毕，等待下次启动时由 `load_state()` 重新激活 |
| 等待下次触发 | **`[等待下次触发] · 外部触发后重新激活`** | `repeat.type=trigger` 执行完毕，等待手动触发（按钮）或 TriggerWatcher 识图命中触发模板时重新激活 |
| 已跳过 | `[已跳过]` | 熔断（fail_streak / unrecoverable） |

**刷新机制**：

| 触发事件 | 响应行为 |
|---------|---------|
| `schedule_updated` | 重建整个队列卡片列表 |
| `task_started` | 更新当前任务为大卡片（含进度条），队列中移除该任务 |
| `task_done` | 清除当前任务卡片，刷新队列 |

**卡片设计**：

| 属性 | 大卡片（当前任务） | 小卡片（队列任务） |
|------|-------------------|------------------|
| 尺寸 | 自适应宽 × 90px | 120 × 70px |
| 内容 | 名称 + 优先级徽章 + 状态 + 进度条 | 名称 + 优先级 + 预计时间 |
| 交互 | 展示当前执行进度 | 点击可跳转详情（预留） |

**触发式任务展示**（`repeat.type=trigger`，无 `next_run_time`）：
- 未触发时：小卡片显示 **"待触发"**（不显示倒计时时间），卡片带触发图标
- 已触发（`due`）：进入 ⏳ 待执行 区，正常显示
- 已执行完：进入 ⚠ 已失效 区，标注 **`[等待下次触发]`**
- 每张触发式任务卡片提供 **"手动触发"按钮**：点击 → `TaskBridge.update_next_run(name, now)` → 任务立即到期入队（与 TriggerWatcher 识图触发走同一链路）

**优先级色阶**：P1(红) → P2(橙) → P3(黄) → P5(绿) → P10(蓝,默认) → P20(紫) → P99(灰)

### 3.3 内置终端

日志面板的双标签设计：日志标签页展示结构化日志流（带级别筛选/清除/导出），终端标签页以只读方式实时显示 stdout/stderr 输出。采用暗色背景，自动着色（INFO=绿 / WARNING=橙 / ERROR=红 / DEBUG=灰）。

### 3.4 图片素材管理

可视化面板管理 assets/ 目录下的素材图片：
- 左侧 9 个场景分区列表，显示各分区图片数量
- 右侧缩略图 + 名称 + 备注 + 尺寸
- 支持添加（从本地选择PNG自动复制到分区）、编辑备注、预览、删除

### 3.5 任务列表自动生成

任务列表面板自动扫描 tasks/ 的四类子目录，为每个任务生成一行配置控件（启用开关、优先级、执行模式编辑器、倒计时），新增任务无需修改 UI 代码。执行模式编辑器支持：单时段 `time_start/time_end`、多时段 `time_slots`（可增删时段行）、执行模式 `execution_mode`（按天 `daily` / 按时间段 `per_slot`）、启动执行 `repeat.type=on_enter`、特殊条件触发 `repeat.type=trigger`（含触发模板 `trigger_templates` 编辑，无时间字段）、每日上限 `max_daily`。

### 3.6 菜单树结构（8 大类）

左菜单树与 tasks/ 子目录对应，自动生成 8 大类：

| 大类 | 对应目录 | 说明 |
|------|---------|------|
| 📅 日常 | `tasks/daily/` | 每日必做任务（御魂/觉醒/金币妖怪等） |
| ⚔️ 战斗 | `tasks/battle/` | 战斗相关（突破/斗技/道馆等） |
| 🎉 活动 | `tasks/event/` | 限时活动入口（自动扫描活动目录） |
| 📜 永久 | `tasks/permanent/` | 常驻玩法（秘闻/御灵/业原火等） |
| 🔧 特殊 | `tasks/special/` | 特殊功能（抽卡/兑换/新手等） |
| 🛠️ 工具 | `tasks/tools/` | 辅助工具（脚本更新/日志查看等） |
| 👤 小号 | — | 小号配置与管理（账号切换/扫描结果） |
| ⚙️ 设置 | — | 全局配置（连接/防封号/通知/日程） |

### 3.7 底部状态栏（9 项）

底部状态栏展示全局运行状况，从左到右 9 项：

| 序号 | 状态项 | 数据来源 | 说明 |
|:---:|--------|---------|------|
| 1 | 运行状态 | `state_changed(run_status)` | 运行中/已暂停/已停止/异常，带颜色标识 |
| 2 | 当前任务 | `task_started` / `task_done` | 正在执行的任务名 |
| 3 | 连接状态 | `connection_lost/restored` | 已连接/已断开/连接中，带图标 |
| 4 | 连接质量 | `connection_quality_warning` | 正常/延迟高/不稳定（红黄绿指示） |
| 5 | 当前账号 | `state_changed(current_account)` | 当前操作的账号名 |
| 6 | 今日运行时长 | `state_changed(today_run_duration)` | 格式 `HH:MM:SS` |
| 7 | 队列长度 | `schedule_updated` | `N 个任务待执行` |
| 8 | 调度状态 | `state_changed(task_status)` + `schedule_updated` | 展示**当前执行任务**的调度状态（due/waiting/completed/skipped）。若无执行中任务，展示**下一个到期任务**的 `next_run_time` 倒计时 + 任务名 |
| 9 | 沙盒模式 | `state_changed(dry_run_mode)` | 沙盒已开启 / 正常模式 |

### 3.8 UI 自控面板（元控面板）

`ui_settings_panel.py` 是 UI 自身的设置面板，不涉及程序核心配置，仅控制 UI 行为：

- 日志级别筛选（DEBUG/INFO/WARNING/ERROR 切换）
- 日志自动滚动开关
- 终端字体大小调整
- 面板布局重置（恢复 QSplitter 默认比例）
- 暗色/亮色主题切换（预留）
- 面板显隐控制（显示/隐藏特定面板）

### 3.9 执行历史面板

`execution_history.py` 展示历史任务执行记录：

- 每条记录：任务名 + 执行时间 + 耗时 + 结果(成功/失败) + 失败原因
- 按日期分组显示
- 支持按任务名筛选
- 数据来源：`state_changed(execution_history)` 由 **12-日志监控中心** 写入
- 默认保留最近 100 条记录

## 四、重点功能

### 4.1 UI零逻辑

UI 只负责展示和接收输入，不包含任何业务逻辑。所有程序交互通过传参模块中转，UI 不直接调用连接/识图/安全/任务/定时/运行控制等核心模块。

### 4.2 三栏布局

左栏菜单树 + 弹出配置面板，中栏控制栏 + 任务列表 + 队列卡片，右栏日志 + 终端。底部状态栏展示全局运行状况。与现有 GUI 布局一致。

### 4.3 事件驱动

UI 通过订阅事件自动刷新，不轮询程序状态，性能开销小，响应及时。

### 4.4 子模块独立

每个 UI 面板是独立 Widget，可单独开发、测试、替换。新增面板不影响现有布局。

### 5.2 核心方法定义

UI 模块不提供程序调用接口，只通过事件总线被动接收事件刷新界面。

**MainWindow（主窗口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `__init__(param_bridge, event_bus, image_mgr, parent=None)` | 🔓 公开 | `MainWindow` | 构造函数。接收 10-参数桥接模块、08-事件通信总线、ImageManager 等依赖 |
| `init_ui() -> None` | 🔓 公开 | `MainWindow` | 初始化三栏布局（QSplitter 比例 1:3:1）和所有 12 个子面板，调用 ParamBridge.bind_all() |
| `refresh_task_list() -> None` | 🔓 公开 | `MainWindow` | 扫描 tasks/ 目录，通过 TaskBridge.get_task_list() 获取已注册任务，为每个任务生成一行配置控件。初始化时调用一次，后续在以下时机触发刷新：`TaskBridge.new_task()` / `delete_task()` / `open_file()` 完成后发布 `tasks_list_changed` 事件，`MainWindow` 订阅后重新调用此方法 |
| `show() -> None` | 🔓 公开 | `MainWindow` | 显示主窗口并启动事件循环 |

### 5.3 核心流程

**事件驱动刷新流程**：
```
程序模块发布事件（如 task_started、state_changed、log_record 等 22 种事件）
  → 08-事件通信总线 分发事件
  → UI 各面板的订阅 handler 被调用
  → 更新对应控件显示（任务卡片、状态栏、日志流、连接图标等）
  → 无需轮询
```

**用户操作流程**：
```
用户点击"启动"按钮
  → 调用 10-参数桥接模块.request_start()
  → 参数桥接模块发布 start_requested 事件
  → 09-运行控制中心 订阅后执行启动逻辑
  → UI 不直接调用任何核心模块
```

### 5.4 关键设计

- **传参模块桥梁**：UI 不直接碰配置/状态/事件，全经传参模块中转
- **事件驱动刷新**：订阅事件自动更新，不轮询程序状态
- **复用组件**：TaskRow / RepeatEditor / CountdownLabel 等抽到 widgets/ 复用
- **子模块独立**：每个 UI 面板是独立 Widget，可单独开发测试替换

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

UI 模块不对外提供程序调用接口。其他模块通过事件总线发布事件，UI 订阅后自动刷新界面。

### 6.2 对外部模块的调用

| 被调用方 | 调用方式 | 说明 |
|---------|---------|------|
| **10-参数桥接模块** | 调用 | **唯一通信通道**。详见各子桥接器： |
| ↳ `UIBinding` | 调用 | `bind()` / `bind_state()` / `unbind()` / `undo()` / `bind_all()` — 控件↔配置双向绑定 |
| ↳ `RunBridge` | 调用 | `request_start()` / `request_stop()` / `request_pause()` / `request_resume()` — 启停控制 |
| ↳ `TaskBridge` | 调用 | `get_task_list()` / `get_task_detail()` / `get_dependency_graph()` / `list_by_category()` / `update_priority()` / `update_repeat()` / `update_next_run()` / `batch_update()` / `import_calendar()` / `reset_fail_streak()` / `new_task()` / `delete_task()` / `open_file()` |
| ↳ `AccountBridge` | 调用 | `switch_to()` / `get_all_accounts()` — 账号切换与列举 |
| ↳ `ConfigBridge` | 调用 | `get()` / `set()` / `export_config()` / `import_config()` — 通用配置读写与备份 |
| **08-事件通信总线** | 订阅 | 订阅全部 22 种 UI 事件：`state_changed` / `state_reset` / `task_started` / `task_done` / `step_done` / `task_skipped` / `run_started` / `run_paused` / `run_resumed` / `run_stopped` / `run_limit_reached` / `connection_lost` / `connection_restored` / `connection_error` / `connection_quality_warning` / `schedule_updated` / `tasks_list_changed` / `log_record` / `notify_alert` / `scene_unknown` / `assets_missing` / `preflight_complete` |
| **04-任务执行引擎（TaskRegistry）** | 读（间接通过 ParamBridge） | 通过 `TaskBridge.get_task_list()` / `get_task_detail()` / `get_dependency_graph()` 获取任务信息 |
| **05-时间调度模块** | 调用（间接通过 ParamBridge） | 通过 `TaskBridge.update_next_run()` / `import_calendar()` / `reset_fail_streak()` 操作调度 |
| **15-账号管理模块** | 调用（间接通过 ParamBridge） | 通过 `AccountBridge.switch_to()` / `get_all_accounts()` 管理账号 |
| **13-任务文件管理** | 调用（间接通过 ParamBridge） | 通过 `TaskBridge.new_task()` / `delete_task()` / `open_file()` 管理任务文件 |
