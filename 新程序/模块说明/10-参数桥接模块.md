# 10-参数桥接模块（Parameter Bridge Module）

> **类型**：桥梁表现层  ｜  **对应说明书**：（UI↔程序绑定，新形式化层）  ｜  **对应用户模块**：#3 传参模块>
> **集成状态**：✅ 本模块为 UI 与核心层的**唯一标准通信路径**。
> 所有 UI 控件必须通过本模块的桥接接口与程序交互，禁止直接调用核心模块。
> `ui/param_bridge/` 下的 6 个子桥接器（RunBridge/TaskBridge/AccountBridge/ConfigBridge/
> UIBinding/Schemas）已提供完整的绑定能力，`MainWindow` 初始化时调用 `bind_all()` 完成注册。
> 详见 `脚本实现/UI设计思路.md` §十六。
---

## 一、目的与作用

**一句话定位**：UI与程序之间的数据桥梁。内部拆分为"配置数据模型层"（定义参数结构）和"UI数据绑定层"（控件↔配置双向同步），实现 UI 改 → 配置改 → 程序读到新值，程序状态变 → UI 自动更新。

**为什么需要这个模块**：

没有传参模块时，UI 直接操作程序逻辑（按钮调 scheduler.start()、输入框写 config.set()），导致 UI 与程序紧耦合。有了传参模块后，UI 只与传参模块交互，传参模块再与配置模块/运行控制/事件总线交互，UI 和程序完全解耦。

**核心职责**：
1. **参数体系定义**：定义每个任务/模块需要哪些参数的 schema
2. **UI数据绑定**：UI控件与配置数据的双向同步
3. **参数聚合**：一个任务需要多组参数（定时+阵容+副本），负责聚合
4. **校验拦截**：UI输入的参数校验后传给程序，非法值拦截在 UI 层

**设计原则**：
- **UI不碰逻辑**：UI控件只与传参模块交互，不直接调用程序模块
- **双向绑定**：用户编辑 → 配置更新；程序状态变 → UI 自动刷新
- **参数聚合**：一个"运行传参"聚合了启停信号+账号选择+任务范围

## 三、运行逻辑

### 3.1 双向绑定流程

**用户修改控件**：用户勾选/输入/选择 → UIBinding 检测变化 → 校验类型/范围（非法值提示不提交）→ 保存 UndoRecord（config_path + old_value）→ 写入配置模块 set() → 配置持久化 → 发布 config_changed 事件 → 程序读取到新值。

**程序状态变化**：程序模块更新状态 → set_state() → 发布 state_changed 事件 → UIBinding `_on_state_changed` 收到事件 → 通过 `pyqtSignal` 或 `QMetaObject.invokeMethod` 将控件更新投递到 **UI 主线程**执行 → Qt 控件在工作线程中安全更新。

> **跨线程安全**：UIBinding 的 `_bindings` 字典被 UI 线程（bind/bind_state）和事件总线线程（_on_state_changed）同时访问。通过 `_bindings_lock`（`threading.Lock`）保护读写。更关键的是，Qt 控件只能在 UI 主线程操作——`_on_state_changed` 必须通过信号槽机制跨线程投递，不能直接在工作线程中调用 `widget.setText()`。

### 3.2 运行传参流程

UI 启停按钮 → RunBridge 桥接 → 通过事件总线发布控制信号（start_requested / stop_requested / pause_requested / resume_requested）→ 运行控制模块订阅并执行。

### 3.3 任务参数传参流程

UI 任务行控件（启用开关/优先级/执行模式/多时段编辑器）→ TaskBridge 桥接 → 通过 UIBinding 写入配置模块 → 定时模块读取配置进行调度。

### 3.4 校验拦截

所有 UI 输入的参数在绑定层进行类型/范围校验，非法值弹出提示并不提交，确保脏数据不进入程序。

## 四、重点功能

### 4.1 UI零逻辑

UI 控件只与传参模块的数据绑定交互，不直接调用任何程序模块。改 UI 布局不影响程序逻辑，改程序接口不影响 UI 代码。

### 4.2 双向数据绑定

用户编辑控件 → 自动写配置并持久化；程序状态变化 → 自动更新控件显示。无需手动同步。

### 4.3 参数变更回滚

支持撤销上一次配置修改，避免误操作后无法恢复。

**实现方式**：UIBinding 内部维护 `_undo_stack: deque[UndoRecord](maxlen=10)`。每次 `bind()` 检测到用户修改控件时，在调用 `config.set()` 之前保存 `UndoRecord(config_path, old_value, new_value, timestamp)` 入栈。`undo()` 弹出最近一条记录，调用 `config.set(record.config_path, record.old_value)` 恢复旧值。撤销后该记录从栈中移除，不可重做。

> **撤销递归防护**：`undo()` 调用 `config.set()` 本身也会触发绑定层的值保存逻辑，导致产生新的 UndoRecord。为避免此递归，`UIBinding` 维护 `_undo_lock` 标志：`undo()` 执行前设置 `_undo_lock = True`，`config.set()` 的 signal handler 检测到 `_undo_lock` 为 True 时跳过 push 操作。`undo()` 执行完毕后 `_undo_lock = False`。

### 4.4 批量参数编辑

支持批量修改多个任务的同类参数（如一次性修改所有日常任务的执行时间），提升配置效率。

**错误处理策略**：`batch_update(names, key, value)` 逐条执行，失败记录跳过继续，最终返回所有失败的路径列表 `list[str]`。不执行回滚（失败原因通常是权限或 schema 校验不通过，不影响已成功写入的条目）。UI 层收到失败列表后可向用户展示"以下任务修改失败"。

## 五、实现思路

### 5.1 模块结构

```
ui/
├── param_bridge/
│   ├── schemas.py         ← 配置数据模型层（参数 schema 定义）
│   ├── ui_binding.py      ← UI数据绑定层（控件↔配置双向同步）
│   ├── run_bridge.py      ← 运行传参（启停信号桥接）
│   ├── task_bridge.py     ← 任务参数传参（优先级/规则/阵容）
│   ├── account_bridge.py  ← 账号传参
│   └── config_bridge.py   ← 通用配置传参（连接/防封号/日志）
```

### 5.2 核心数据结构和类型签名

**Binding（绑定条目）**：
```
@dataclass
class Binding:
    widget: QWidget           # 绑定的 UI 控件引用
    config_path: str          # 配置点分路径（如 "tasks.daily.enabled"）
    binding_type: str         # 绑定类型："two_way"(双向) / "read_only"(只读状态显示)
    last_value: Any           # 上一次写入的值（用于 undo）
    state_key: str | None     # 状态键（仅 binding_type="read_only" 时有效）
    validator: callable | None # 可选的校验函数 (value) -> bool
```

**ParamSchema（参数 schema 定义）**：
```
@dataclass
class ParamSchema:
    key: str                  # 参数键名
    label: str                # UI 显示标签（如"执行时间"）
    type: type                # 参数类型（str / int / float / bool / list）
    default: Any              # 默认值
    required: bool            # 是否必填
    validator: callable | None # 校验函数 (value) -> bool，不通过则提示不提交
    options: list | None      # 枚举值列表（如下拉框选项），None 表示自由输入
    description: str          # 参数说明文字（用于 tooltip 或帮助面板）
```

**UndoRecord（撤销记录）**：
```
@dataclass
class UndoRecord:
    config_path: str          # 被修改的配置路径
    old_value: Any            # 修改前的值
    new_value: Any            # 修改后的值
    timestamp: float          # 修改时间戳
```

> `schemas.py` 负责定义每个任务/模块所需的参数结构。例如日常任务需要一个 `ParamSchema` 描述其执行时间（`type=time`）、启用状态（`type=bool`）、优先级（`type=int, range=1-5`）等。`schemas.py` 导出一个 `TASK_SCHEMAS: dict[str, ParamSchema]` 字典，UI 初始化时读取生成对应控件。

| `bind_state(widget, state_key) -> None` | 🔓 公开 | `UIBinding` | 将 UI 控件绑定到指定状态键（只读显示）。不生成 UndoRecord |

| `_on_state_changed(event) -> None` | 🔒 私有 | `UIBinding` | 订阅 `state_changed` 事件。通过 `QMetaObject.invokeMethod` 或 `pyqtSignal` 将控件更新任务投递到 UI 主线程执行，确保 Qt 控件不在工作线程中被操作 |

### 5.4 核心流程

**用户修改控件流程**：
```
用户勾选/输入/选择
  → UIBinding 检测变化
  → 校验类型/范围（非法值提示不提交）
  → 保存 UndoRecord(config_path, old_value) 到 _undo_stack
  → 写入配置模块 set()
  → 配置持久化
  → 发布 config_changed 事件
  → 程序读取到新值
```

**运行传参流程**：
```
用户点"启动"按钮
  → RunBridge.request_start()
  → 发布 start_requested 事件到事件总线
  → 09-运行控制中心 订阅后执行启动逻辑
```

**程序状态→UI刷新流程**：
```
程序模块更新状态 → set_state()
  → 发布 state_changed 事件
  → UIBinding 收到事件
  → 自动更新对应控件显示
```

### 5.5 关键设计

- **UI不碰逻辑**：UI 只与传参模块交互，不直接调用程序
- **事件驱动刷新**：只读显示（倒计时/状态）通过订阅事件自动刷新，不轮询
- **校验在UI层**：非法值在绑定层拦截，不传到程序
- **双向绑定**：用户编辑 → 配置更新；程序状态变 → UI 自动刷新
- **跨线程安全**：`_bindings_lock` 保护 `_bindings` 字典；`_on_state_changed` 通过 `pyqtSignal` 投递到 UI 主线程执行控件更新，避免在工作线程操作 Qt 控件
- **撤销机制**：`_undo_stack`（deque maxlen=10）在每次 set() 前保存旧值，`undo()` 弹出恢复。`_undo_lock` 防止 `undo()` 自身的 `config.set()` 产生递归记录
- **Schema 驱动**：所有 UI 控件根据 `ParamSchema` 定义生成（类型/默认值/校验/枚举），保证 UI 与配置结构一致
