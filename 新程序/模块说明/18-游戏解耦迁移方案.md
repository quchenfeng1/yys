## 二、目标目录结构

```
主程序/
  core/                      # 通用核心（不变）
  tasks/
    base/                    # ✅ 框架保留（BaseTask/TaskStep/TaskGraph/TaskResult）
    __init__.py
  games/
    _shared/                 # （可选，后期）跨游戏共享：通用步骤/通用素材/通用检查器
    yys/                     # ← yys 专属（游戏档案）
      profile.yaml           # game_id / 名称 / 素材根 / 任务目录 / 配置路径 / OCR语言 / 坐标模式
      tasks/                 # ← 迁移自 tasks/{daily,event,permanent,special,battle,common}
        daily/ event/ permanent/ special/ battle/ common/ + __init__.py
      assets/                # ← 迁移自 assets/
      tasks.yaml             # ← 迁移自 config/tasks.yaml
      coords/                # ← 迁移自 config/coords/
      visual_tasks/          # ← 新体系：该游戏的可视化任务（节点图 json）
      runtime/               # ← 迁移自 config/runtime/（该游戏调度状态）
  config/
    global.yaml              # ✅ 全局（保留：全局设置 + device）
    accounts.yaml            # ✅ 账号（先全局，跨游戏共享设备/账号）
    cookies/                 # ✅ 空目录（暂保留）
```

## 二.5 迁移边界清单（该放 / 不该放）

**✅ 应放入 `games/yys/`（yys 专属）**：
| 项 | 说明 |
|---|---|
| `assets/` | yys 素材 |
| `tasks/{daily,event,permanent,special,battle,common}/` | yys 游戏任务 + 战斗/组队通用步骤（**过渡存量**：新体系下任务一律可视化生成，代码任务可逐步重建后删除） |
| `tasks.yaml` | yys 任务调度配置 |
| `coords/` | yys 坐标（**预留机制：`load_coords` + `CoordEntry` schema 已实现，但当前空目录、无实际使用**；建议删除或保留空目录） |
| `visual_tasks/` | 新体系：yys 的**可视化任务节点图**（用节点画布构建的脚本 json；与代码任务 .py 并存） |
| `runtime/` | yys 调度运行状态（task_state.json 等）——删游戏=删状态，更干净 |
| `profile.yaml` | 游戏档案（名称/素材根/OCR语言/坐标模式/设备默认） |

**❌ 不放入（全局/核心）**：
| 项 | 说明 |
|---|---|
| `core/` | 执行引擎 |
| `tasks/base/` | 框架（BaseTask/TaskStep） |
| `config/global.yaml` | 全局设置 + device |
| `config/accounts.yaml` | 账号（先全局） |
| `config/cookies/` | 空目录 |

**待定（建议）**：
| 项 | 建议 |
|---|---|
| `accounts.yaml` | **先全局**（同批模拟器/账号跨游戏），后续需要再拆 |
| `config/runtime/` | **迁入 games/yys/runtime/**（每个游戏独立调度状态，删游戏删状态） |
| 跨游戏共享素材/步骤 | 后期 `games/_shared/`（通用关闭/返回按钮、通用检查器） |

**任务形态原则（新体系）**：
- **所有游戏任务 = 可视化节点图**（`games/{game}/visual_tasks/`），理论上不存在非可视化任务。
- **自定义节点（Code/Custom Node）作为扩展点**：遇到可视化难以表达的复杂逻辑
  （如组队协调/多账号协作/特殊算法），可写一个自定义节点注册进节点库，**在画布上照样用**——
  任务仍是节点图，只是底层节点承载代码。
- 现有 `tasks/*.py` 代码任务 = **过渡存量**（迁移到 `games/yys/tasks/` 保持运行），
  可逐步用可视化重建后删除；长期主形态为 `visual_tasks/` + 自定义节点。

## 三、任务代码 import 适配（改动最小方案）

## 四、加载器适配（核心改造）

新增 `core/game_profile.py`：
- `scan_games()`：扫描 `games/` 返回游戏列表（动态菜单数据源）
- `GameProfile.load(game_id)`：读 `profile.yaml`，提供 `tasks_dir/assets_dir/tasks_yaml/coords_dir`
- 默认游戏 `yys`；`current_game` 可切换

适配（把硬编码路径改为 profile 提供）：
| 位置 | 现 | 改 |
|---|---|---|
| `core/bootstrap.py` | `root/config` / `root/tasks` / `root/assets` | 全局=root/config；游戏=GameProfile.yys |
| `core/config_manager.py` | tasks.yaml/coords 在 config/ | tasks.yaml/coords 走游戏 profile（global/accounts 仍全局） |
| `core/task_manager.py` | tasks_dir/assets_dir=root/tasks,assets | games/yys/tasks,assets |
| `tasks/registry.py` | `discover_tasks` 扫 `tasks.{daily,event,permanent,special}` | 扫 `games.yys.tasks.{...}`（参数化游戏） |
| `core/asset_catalog.py` / 设备 | assets_dir=root/assets | games/yys/assets |
