> **类型**：核心运行层  ｜  **对应说明书**：5.3 ｜  **说明**：从03-防封策略模块拆出，独立为操作执行桥接层>

## 一、目的与作用

**一句话定位**：高层操作执行桥接层。封装"识图→安全偏移→设备操作"的完整链路，为任务步骤提供 `click_image()`、`wait_any()` 等语义化操作接口。

**为什么拆出**：

原 03-防封策略模块 中 Executor 仅作为"安全注入点"描述，但实际 `core/executor.py` 代码承担了更多职责：

- 协调识图模块获取坐标
- 调用防封模块生成安全参数
- 委托连接模块执行设备操作
- 提供任务步骤可直接调用的高层 API

将其拆为独立模块，职责更清晰。

**核心职责**：
1. **操作链路编排**：按"识图 → 安全偏移 → 执行"顺序协调三个底层模块
2. **高层操作接口**：提供 `click_image()`、`wait_any()`、`ensure_scene()` 等语义化方法
3. **超时与重试封装**：操作超时自动重试，重试间隔由安全模块控制
4. **全链路记录**：每次操作记录识别结果、安全参数、执行耗时到监控模块
5. **异常转换**：将底层异常（DeviceConnectError、RecognizeError）转换为操作结果

**设计原则**：
- **桥接而非控制**：Executor 不包含业务逻辑，只负责编排调用顺序
- **接口语义化**：对外暴露 `click_image("common/battle/challenge_btn")` 而非 `click(x, y)`
- **可替换底层**：替换识图算法或连接方式不影响 Executor 的上层调用方

## 三、运行逻辑

### 3.1 操作执行链路

每次高层操作（如 `click_image`）的内部流程：

```
调用 click_image("common/battle/challenge_btn", region=(0,0,200,200), timeout=10)
  → 1. 调 recognizer.find("common/battle/challenge_btn", region) → 得到 MatchResult(中心 cx,cy, 矩形 w,h)
  → 2. 未找到且 timeout > 0 → 循环重试：每轮开头调 recognizer.clear_cache() 清除旧截图缓存，确保重新截图（避免因动画/加载未完成导致识别失败），超时返回 False
  → 3. 未找到且 timeout = 0 → 直接返回 False
  → 4. 调 anti_detect.random_offset_in_bounds(cx, cy, w, h) → 图标矩形内安全偏移
  → 5. 调 anti_detect.random_delay() → 随机延迟
  → 6. 调 anti_detect.maybe_long_pause(stop_event) → 判断是否走神（内部含随机时长）
  → 7. 检查 _dry_run.is_set()
      ├── True → 记录 "[沙盒] click_image: btn_name at (safe_x,safe_y)"
      └── False → connection.click(safe_x, safe_y) 实际执行
  → 8. 记录 _last_operation = {template, original_pos, safe_pos, duration_ms, confidence, success, dry_run, timestamp}
  → 9. 记录操作耗时和结果到 _monitor
  → 10. 返回 True / False
```

### 3.2 等待机制

`wait_any(template_names, timeout, interval)`：

```
1. 记录开始时间
2. 循环：
   a. 调 connection.screenshot() 获取当前截图（每轮仅截一次）
   b. 在同一张截图上遍历 template_names，对每个调 recognizer.find()
      （利用 02-图像识别模块 的 _screenshot_cache 机制，避免每识别一个模板就截一次图）
   c. 找到任意一个 → 返回 (模板名, MatchResult, waiting_time) — 其中 `waiting_time` 为从开始等待到找到目标的耗时（秒），由 `time.time() - start_time` 计算，可用于日志记录和性能分析
   d. 未找到 → 调 anti_detect.random_delay(interval) 等待
   e. 检查是否超时 → 超时返回 None
```

### 3.3 场景确保

`ensure_scene(template_name, timeout)` — 确保当前处于指定场景，不在则等待：

```
1. 调 recognizer.wait(template_name, timeout=timeout)
2. 找到 → 返回 True
3. 超时未找到 → 返回 False（调用方走错误恢复）
```

### 3.4 场景感知（probe_scene）

`probe_scene(candidates, timeout)` — 静默感知当前位置（与 `detect_scene` 的区别：未命中**不发布 `scene_unknown`**，用于运行时持续定位而非错误恢复）：

```
1. 遍历 candidates 调 recognizer.exists(name)
2. 命中场景 X → 发布 scene_updated(scene=X) → 返回 X
3. 全部未命中 → 返回 None（不发布 scene_unknown，素材缺失/未配置不阻断）
4. 内部 _last_scene 去重：场景未变化不重复发布
```

`detect_scene` 命中后同样发布 `scene_updated`（场景变化才发布）。`scene_updated` 由 07-运行时状态管理 订阅维护 `current_scene`/`last_known_scene`，11-用户界面 订阅显示当前场景。

## 四、重点功能

### 4.1 一键操作链路

`click_image(template)` 一次调用完成"识图→偏移→轨迹→走神检查→点击→记录"全链路。任务步骤无需关心底层细节。

### 4.2 语义化接口

| 接口 | 说明 | 替代的原始操作 |
|------|------|--------------|
| `click_image(name)` | 找到图片并点击 | `find + offset + click` |
| `wait_any(names)` | 等待多个目标任一出现 | 轮询截图+识别 |
| `ensure_scene(name)` | 确保在某个场景 | 循环 wait |
| `random_sleep(a, b)` | 随机等待一段时间 | `sleep(random.uniform)` |

### 4.3 全链路可观测

每次操作自动记录：原始坐标、安全偏移后坐标、操作耗时、识别置信度、是否走神。数据写入监控模块，可用于事后审计和操作模式分析。

### 4.4 沙盒模式语义

沙盒模式下 `click_image()` 识别成功后直接返回 `True`，不实际执行点击。这是因为沙盒要验证"如果正常运行，这次点击会成功"，识别成功即表示可点击。调用方（任务步骤）根据返回值决定下一步，流程验证的目的已达成。同理，其他操作方法（`swipe`/`input_text`/`input_key`）在沙盒模式下也仅记录日志并返回正常结果，不执行实际操作。

**沙盒模式返回值语义**（所有操作方法一致）：`True` = 目标存在且（非沙盒模式下）操作已执行；`False` = 目标不存在或操作不可执行。此语义在沙盒与非沙盒模式下一致，调用方无需区分模式。

**沙盒模式下的等待加速**：`random_sleep()` / `sleep()` 在检测到 `_dry_run.is_set()` 时直接返回 True，不执行实际休眠。走神检查 `maybe_long_pause()` 同理跳过。此行为使沙盒模式的执行速度接近实时，快速跑通完整流程。

## 五、实现思路

### 5.1 模块结构

```
core/
└── executor.py       ← 执行器主入口（单文件，约200行）
```

### 5.2 核心数据结构和类型签名

**LastOperation（操作记录）**：
```
@dataclass
class LastOperation:
    template: str              # 模板名
    original_pos: tuple        # 原始坐标 (cx, cy)
    safe_pos: tuple            # 安全偏移后坐标 (safe_x, safe_y)
    duration_ms: float         # 操作耗时（毫秒）
    confidence: float          # 识别置信度（0~1）
    success: bool              # 是否成功
    dry_run: bool              # 是否沙盒模式
    timestamp: float           # 时间戳
```

### 5.3 核心方法定义

**Executor**（单类，约200行）：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `click_image(name, region, timeout, stop_event) -> bool` | 🔓 公开 | `Executor` | 识图→偏移→点击全链路。`region` 限制识别区域（可选），`timeout` 控制重试超时（默认 0 即单次尝试）。返回 `True` 表示**成功找到目标且（非沙盒模式下）已完成点击**；返回 `False` 表示目标未找到或操作未执行 |
| `click_point(x, y) -> None` | 🔓 公开 | `Executor` | 直接点击坐标，不经过识图。内部调 `anti_detect.random_offset_in_bounds(cx, cy, 10, 10)` 以 10px 半径做微小偏移（避免每次点击同一像素点）。含 dry_run 检查 |
| `click_if_exists(name, threshold) -> bool` | 🔓 公开 | `Executor` | 存在则点击，不存在则跳过（不等待） |
| `wait_any(names, timeout, interval) -> tuple \| None` | 🔓 公开 | `Executor` | 等待多个模板中任一出现。返回 `(模板名, MatchResult, waiting_time)`，其中 `waiting_time` 为等待耗时（秒），可用于日志和性能分析 |
| `ensure_scene(name, timeout) -> bool` | 🔓 公开 | `Executor` | 确保当前场景为目标场景 |
| `detect_scene(candidates, timeout) -> str \| None` | 🔓 公开 | `Executor` | 遍历候选场景模板，返回最先匹配的场景名。**命中后发布 `scene_updated`（含场景名）**；全部候选未匹配发布 `scene_unknown` |
| `probe_scene(candidates, timeout) -> str \| None` | 🔓 公开 | `Executor` | 静默场景感知：命中返回场景名并发布 `scene_updated`；未命中返回 None（**不发布 `scene_unknown`**）。供场景感知步骤 scene_probe / 运行时定位，素材缺失不阻断 |
| `random_sleep(min_s, max_s, stop_event) -> bool` | 🔓 公开 | `Executor` | 随机等待一段时间（min_s~max_s 秒）。透传 `stop_event` 给 anti_detect.sleep()，实现可打断休眠。返回 True=正常完成 / False=被打断。**沙盒模式下自动跳过等待**：检测 `_dry_run.is_set()` 时直接返回 True（不执行休眠），加速流程验证 |
| `swipe(x1,y1,x2,y2,duration) -> None` | 🔓 公开 | `Executor` | 滑动操作。调 anti_detect.generate_trajectory() 生成贝塞尔路径点，按路径点逐次调用 connection.swipe()（dry_run 跳过） |
| `long_press(x, y, duration) -> None` | 🔓 公开 | `Executor` | 长按操作。通过 ADB 长按手势实现：连续发送 touch-down + wait + touch-up 事件，而非滑动 |
| `input_text(text) -> None` | 🔓 公开 | `Executor` | 输入文本（用于账号密码，含 dry_run 检查） |
| `input_key(key) -> None` | 🔓 公开 | `Executor` | 按键操作（BACK/HOME/MENU，含 dry_run 检查） |
| `get_last_operation() -> dict \| None` | 🔓 公开 | `Executor` | 获取上一次操作详情 |
| `set_dry_run(enabled) -> None` | 🔓 公开 | `Executor` | 设置沙盒模式：True 时不实际执行点击，仅记录操作日志 |
| `is_dry_run() -> bool` | 🔓 公开 | `Executor` | 查询当前是否沙盒模式 |

### 5.4 核心流程

**click_image 完整链路**：
```
click_image(template_name)
  → find 获取 MatchResult（中心 cx,cy + 宽高 w,h）→ 未找到返回 False
  → random_offset_in_bounds(cx, cy, w, h) 图标矩形内安全偏移
  → sleep 随机延迟
  → maybe_long_pause 走神判断（内部含随机时长）
  → 检查 dry_run 标志
      ├── True → 仅记录："[沙盒] 将要点击 (641,602)" → 返回 True
      └── False → connection.click 实际执行
  → 记录耗时和结果到 _monitor
  → 返回 True
```

**swipe 滑动链路**：
```
swipe(x1, y1, x2, y2, duration)
  → 调 anti_detect.generate_trajectory(x1,y1, x2,y2, steps=10) → 得到贝塞尔路径点列表
  → 对每个路径点 (px,py) 做随机微调（anti_detect.random_offset_in_bounds 2px 半径）
  → 检查 _dry_run.is_set()
      ├── True → 记录 "[沙盒] swipe from (x1,y1) to (x2,y2)"
      └── False → 逐点调用 connection.swipe(px, py, px_next, py_next, segment_duration)
  → 记录操作到 _last_operation / _monitor
```

**wait_any 等待链路**：
```
wait_any(names, timeout, interval)
  → 记录开始时间 start = time.time()
  → 循环：
      截图 → 遍历识别 names
      找到任一 → 返回 (模板名, 坐标, time.time() - start)  ← 附带等待耗时
      未找到 → random_delay 等待
      超时 → 返回 None
```

**detect_scene 场景检测链路**：
```
detect_scene(candidates, timeout)
  → 记录开始时间
  → 循环：
      截图 → 遍历 candidates 列表
      找到任一 → 返回该场景名
      未找到 → 短暂等待
      超时 → 返回 None
  → 调用方（09-运行控制中心）根据返回值自行更新 07.current_scene
```

### 5.5 关键设计

- **桥接模式**：Executor 本身不含业务逻辑，只编排三个底层模块的调用顺序
- **全链路记录**：每次操作记录完整上下文，便于问题排查
- **安全透明**：调用方无需关心安全处理，Executor 自动注入防封偏移和走神
- **接口语义化**：`click_image("btn_name")` 替代 `find→offset→click` 三步操作
