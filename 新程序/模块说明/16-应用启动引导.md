# 16-应用启动引导（Application Bootstrap）

> **类型**：入口层  ｜  **对应说明书**：main.py ｜  **说明**：定义模块初始化顺序、依赖注入、启动与关闭流程>
> **实现状态**：✅ `ApplicationBootstrap` 为**唯一启动路径**。`main.py` 调用 `bootstrap.start()` 按 6 层 15 步顺序初始化所有模块、注入依赖、启动 UI。
> 详见 `脚本实现/UI设计思路.md` §二十一。
---

## 一、目的与作用

**一句话定位**：应用程序的入口与组装器。按照正确的依赖顺序初始化所有模块，建立模块间的引用关系，启动 UI，处理优雅关闭。

**为什么需要这个模块**：

目前 16 个模块各自有独立的设计，但缺少一个"总装图"：

- 各模块的初始化顺序是什么？（配置模块必须在其他模块之前初始化）
- 模块间的依赖引用如何注入？（构造函数传递？全局单例？）
- 启动时先加载配置还是先连接设备？
- 关闭时先断开连接还是先保存状态？

应用启动引导模块回答这些问题，是整个程序的**总装蓝图**。

**核心职责**：
1. **初始化顺序编排**：按依赖关系依次初始化所有模块
2. **依赖注入**：将已初始化的模块引用传递给依赖方
3. **启动入口**：初始化完成后显示 UI，进入事件循环
4. **优雅关闭**：接收关闭信号 → 停止运行 → 保存状态 → 断开连接 → 退出
5. **单例管理**：确保每个模块只有一个实例（全局单例）

**设计原则**：
- **依赖顺序明确**：先初始化被依赖方，再初始化依赖方
- **全局单例**：每个模块只有一个实例，通过启动引导统一创建和持有
- **关闭有序**：关闭顺序与初始化顺序相反，保证资源正确释放

## 二、模块属性与依赖

### 2.1 依赖注入（外部模块引用）

启动引导模块不依赖其他业务模块，它是**创建者**而非**使用者**。它持有所有模块的单例引用。

| 属性名 | 类型 | 作用域 | 作用 |
|--------|------|--------|------|
| `_modules` | `dict[str, object]` | 🔒 私有 | 已初始化的模块实例字典，按名称索引 |

### 2.2 对外暴露属性

| 属性名 | 类型 | 作用域 | 说明 |
|--------|------|--------|------|
| `modules` | `dict[str, object]` | 📖 只读对外 | 所有已初始化模块的单例字典，供其他模块按需获取引用 |

### 2.3 内部私有属性

| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_init_order` | `list[str]` | 模块初始化顺序列表 |
| `_shutdown_hooks` | `list[callable]` | 关闭时需执行的回调列表 |

## 三、运行逻辑

### 3.1 模块初始化顺序

依赖关系决定了严格的初始化顺序：

```
第1层：基础设施（无依赖）
  ① 配置管理中心（06-ConfigManager） — 其他模块依赖它读取配置
  ② 事件通信总线（08-EventBus） — 其他模块依赖它通信

第2层：基础服务（依赖配置+事件）
  ③ 日志监控中心（12-Monitor） — 启动日志系统
  ④ 运行时状态管理（07-StateManager）

第3层：核心功能（依赖2层）
  ⑤ 设备连接模块（01-ConnectionManager）
  ⑥ 图像识别模块（02-Recognizer）
  ⑦ 防封策略模块（03-AntiDetect）

第4层：业务编排（依赖3层）
  ⑧ 时间调度模块（05-Scheduler）
  ⑨ 执行器模块（14-Executor） — 依赖 ⑤⑥⑦ + 监控+配置
  ⑩ 任务执行引擎（04-TaskRegistry）
  ⑪ 任务文件管理（13-TaskManager）
  ⑫ 参数桥接模块（10-ParamBridge）
  共 5 个模块，覆盖调度/执行/注册/文件/桥接全部业务编排能力

第5层：账号管理
  ⑬ 账号管理模块（15-AccountManager）— 依赖 05/01/07/08/06（均在第 4 层及之前已初始化）。提前初始化使 09 在构造时可获得已就绪的 AccountManager 引用

第6层：运行控制（依赖5层）
  ⑭ 运行控制中心（09-RunController）— 三线程模型：填充+执行+扫描。此时 15 已就绪，调度循环可直接查询账号信息和任务范围

第7层：用户界面
  ⑮ 用户界面模块（11-MainWindow）
```

### 3.2 启动流程

```
main.py 入口
  → 1. 创建 ApplicationBootstrap 实例
  → 2. 按初始化顺序依次创建各模块实例：

      第1层：基础设施
        ① 初始化配置管理中心（ConfigManager）
          → 加载 global.yaml / tasks.yaml / accounts.yaml
          → 完成配置校验
        ② 初始化事件通信总线（EventBus）
          → 创建全局单例，启动异步分发线程

      第2层：基础服务
        ③ 初始化日志监控中心（Monitor）
          → 传入配置、事件总线、连接（可选，异常截图用），启动日志系统
        ④ 初始化运行时状态管理（StateManager）
          → 传入事件总线，设置初始状态（run_status = stopped）

      第3层：核心功能
        ⑤ 初始化设备连接模块（ConnectionManager）
          → 传入配置、事件总线、状态管理
        ⑥ 初始化图像识别模块（Recognizer）
          → 传入连接、配置、监控、事件总线（可选，用于 wait() 停止信号），加载素材索引
        ⑦ 初始化防封策略模块（AntiDetect）
          → 传入配置、监控、事件总线（订阅 config_changed 档案切换 + stop_requested 打断 sleep）

      第4层：业务编排
        ⑧ 初始化时间调度模块（Scheduler）
          → 传入配置、状态管理、事件总线，加载 task_state.json
        ⑨ 初始化执行器模块（Executor）
          → 传入识别器、防封引擎、连接、监控、配置
        ⑩ 初始化任务执行引擎（TaskRegistry）
          → 扫描 tasks/ 目录 → 自动注册全部任务
        ⑪ 初始化任务文件管理（TaskManager）
          → 准备任务文件 CRUD 能力
        ⑫ 初始化参数桥接模块（ParamBridge）
          → 传入配置、事件总线、状态管理、调度器

      第5层：账号管理
        ⑬ 初始化账号管理模块（AccountManager）
          → 传入配置、连接、状态管理、事件总线、调度器
          → 加载 accounts.yaml 账号列表

      第6层：运行控制
        ⑭ 初始化运行控制中心（RunController）
          → 传入调度器、任务注册、连接、配置、状态管理、事件总线、监控、
            执行器、识别器、防封引擎、**账号管理**
          → 三线程模型：填充(filler) + 执行(executor) + 扫描(scanner)

      第7层：用户界面
        ⑮ 初始化用户界面模块（MainWindow）
          → 传入参数桥接、事件总线、ImageManager（图片管理器）
          → 显示主窗口

  → 3. 启动自检：调 self_check() → 检查 ADB 连通性/素材完整性/配置合法性/依赖完整性
  → 4. 发布 preflight_complete 事件（携带检查结果）
  → 5. 发布 app_started 事件 → 08-事件通信总线分发，通知各模块程序已就绪
  → 6. 注册信号处理（_register_signal_handlers → SIGINT/SIGTERM → shutdown）。注意：Python signal 模块在 Windows 上对 SIGTERM 支持有限，且信号处理器不在 Qt 事件线程中执行。建议组合方案：主窗口 closeEvent 直接调 shutdown()；SIGINT 用 signal.signal(signal.SIGINT, lambda sig, frame: app.quit())，让 Qt 的 aboutToQuit 信号触发清理）
  → 7. 进入 Qt 事件循环（app.exec_()）
```

### 3.3 关闭流程

```
用户关闭窗口 / 系统关闭信号（SIGINT/SIGTERM）
  → 发布 app_stopping 事件 → 08-事件通信总线分发 → 各模块依次停止
  → 1. 停止 09-运行控制中心（stop() → 设置停止标志 → 等待三线程退出）
  → 2. 保存 05-时间调度模块 状态（task_state.json 原子写盘）
  → 3. 04-任务执行引擎 清理当前执行的任务上下文（中断子线程、释放资源）
  → 4. 清除 07-运行时状态管理（reset() → 清空运行时状态，保留白名单键）
  → 5. 13-任务文件管理 清空缓存（_cache = {}）
  → 6. 01-设备连接模块 断开连接（disconnect() → 停止心跳 → 清理设备池）
  → 7. 06-配置管理中心 停止热重载（stop_watcher() → 停止 watchdog 文件监控线程）
  → 8. 08-事件通信总线 停止（stop() → 设置 _stop_event → join 分发线程 timeout=3）
  → 9. 关闭 12-日志监控中心（停止异步日志工作线程）
  → 10. 清空模块字典
  → 11. 退出事件循环 → 进程退出
```

### 3.4 依赖注入方式

所有模块采用**构造函数注入**：每个模块在创建时将其依赖的模块实例通过构造函数传入，而非在模块内部自行创建或查找。注入顺序严格按照初始化顺序：先初始化的模块实例作为参数传入后初始化的模块。

## 四、重点功能

### 4.1 依赖顺序自动推导

按照"被依赖方先初始化"的原则编排顺序。底层模块（配置、事件）最先初始化，上层模块（UI）最后初始化。

### 4.2 全局单例管理

启动引导创建并持有所有模块实例，通过 `modules` 字典对外提供。任何模块需要获取其他模块引用时，通过启动引导获取，避免重复创建。

### 4.3 优雅关闭

关闭顺序与初始化顺序相反：停止运行控制 → 保存调度状态 → 清理任务上下文 → 重置运行时状态 → 清空任务文件缓存 → 断开设备连接 → 停止配置热重载 → 停止事件总线 → 关闭日志 → 清空模块字典 → 退出。保证资源正确释放，状态不丢失，分发线程安全退出。

## 五、实现思路

### 5.1 模块结构

```
core/
└── bootstrap.py          ← 应用启动引导（初始化编排 + 依赖注入 + 关闭管理）

项目根目录/
└── main.py               ← 程序入口，调用 bootstrap.start()
```

### 5.2 核心方法定义

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `start() -> None` | 🔓 公开 | `ApplicationBootstrap` | 按顺序初始化所有模块，启动 UI |
| `shutdown() -> None` | 🔓 公开 | `ApplicationBootstrap` | 优雅关闭：停止运行控制 → 保存调度状态 → 断开设备连接 → 停止事件总线 → 关闭日志 → 退出事件循环 |
| `get(module_name) -> object` | 🔓 公开 | `ApplicationBootstrap` | 按名称获取已初始化的模块实例 |
| `self_check() -> dict` | 🔓 公开 | `ApplicationBootstrap` | 启动前自检：检查 ADB 连通性、素材完整性、配置合法性、依赖完整性。在初始化完成后、UI 显示前调用，返回检查结果并发布 `preflight_complete` 事件。**失败策略**：配置不合法 → 弹窗告警但允许继续（06 有默认值兜底）；ADB 不通 → 弹窗告警但允许继续（用户可手动修复后重连）；素材缺失 → 发布 `assets_missing` 事件，UI 显示缺失列表，不阻断启动；依赖不完整（程序错误）→ 弹窗告警后退出，不进入事件循环 |
| `_init_config() -> ConfigManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化配置模块 |
| `_init_event_bus() -> EventBus` | 🔒 私有 | `ApplicationBootstrap` | 初始化事件总线 |
| `_init_monitor(...) -> Monitor` | 🔒 私有 | `ApplicationBootstrap` | 初始化日志监控 |
| `_init_state_manager(...) -> StateManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化状态管理 |
| `_init_connection(...) -> ConnectionManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化设备连接 |
| `_init_recognizer(...) -> Recognizer` | 🔒 私有 | `ApplicationBootstrap` | 初始化图像识别 |
| `_init_anti_detect(...) -> AntiDetect` | 🔒 私有 | `ApplicationBootstrap` | 初始化防封策略 |
| `_init_executor(...) -> Executor` | 🔒 私有 | `ApplicationBootstrap` | 初始化执行器 |
| `_init_scheduler(...) -> Scheduler` | 🔒 私有 | `ApplicationBootstrap` | 初始化时间调度 |
| `_init_task_engine(...) -> None` | 🔒 私有 | `ApplicationBootstrap` | 注册全部任务 |
| `_init_account_manager(...) -> AccountManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化账号管理（第5层，先于运行控制） |
| `_init_run_controller(...) -> RunController` | 🔒 私有 | `ApplicationBootstrap` | 初始化运行控制（第6层，依赖账号管理已就绪） |
| `_register_signal_handlers() -> None` | 🔒 私有 | `ApplicationBootstrap` | 注册 SIGINT/SIGTERM 信号处理器，捕获后调用 shutdown() 优雅关闭 |
| `_init_ui(...) -> MainWindow` | 🔒 私有 | `ApplicationBootstrap` | 初始化并显示 UI |

### 5.3 核心流程

**启动流程**：
```
main.py → start()
  → initialize() 按6层顺序初始化所有模块
  → self_check() 启动自检（ADB/素材/配置/依赖）
  → 发布 preflight_complete 事件
  → _register_signal_handlers() 注册 SIGINT/SIGTERM
  → 显示主窗口
  → 进入 Qt 事件循环
```

**关闭流程**：
```
用户关闭窗口 / SIGINT / SIGTERM
  → shutdown()
  → 停止 09-运行控制中心（stop → 设置停止标志 → 等待三线程退出）
  → 保存 05-时间调度模块 状态（task_state.json 原子写盘）
  → 01-设备连接模块 断开连接（disconnect()）
  → 06-配置管理中心.stop_watcher() 停止热重载线程
  → 08-事件通信总线.stop()（设置 _stop_event → join 分发线程 timeout=3）
  → 关闭 12-日志监控中心（停止异步日志工作线程）
  → 清空模块字典
  → 退出事件循环 → 进程退出
```

### 5.4 关键设计

- **构造函数注入**：所有模块的依赖通过构造函数传入，不依赖全局变量
- **初始化顺序**：严格按照依赖层级排序，下层先初始化
- **关闭有序**：与初始化顺序相反，保证资源正确释放

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `start()` | `main.py`（程序入口） | 初始化所有模块并启动 UI |
| `shutdown()` | **11-用户界面模块**（窗口关闭） / 系统信号 | 优雅关闭程序 |
| `get(name)` | 已初始化的任意模块 | 获取其他模块实例引用 |

### 6.2 对外部模块的调用

启动引导是**创建者**，它调用全部模块的构造函数创建实例。它依赖以下模块的构造函数签名来正确注入依赖：

| 被调用方 | 调用方式 | 说明 |
| **08-事件通信总线** | 发布事件 | 发布 `app_started`（启动完成）、`app_stopping`（关闭开始）、`preflight_complete`（自检完成） |
| **06-配置管理中心** | new + 调用 | 创建 ConfigManager 实例，调用 load() |
| **08-事件通信总线** | new | 创建全局单例 EventBus |
| **12-日志监控中心** | new + 调用 | 创建 Monitor 实例 |
| **07-运行时状态管理** | new | 创建 StateManager 实例，注入 EventBus |
| **10-参数桥接模块** | new | 创建 ParamBridge 实例 |
| **01-设备连接模块** | new + 调用 | 创建 ConnectionManager 实例 |
| **02-图像识别模块** | new | 创建 Recognizer 实例 |
| **03-防封策略模块** | new | 创建 AntiDetect 实例 |
| **14-执行器模块** | new | 创建 Executor 实例 |
| **05-时间调度模块** | new + 调用 | 创建 Scheduler 实例，加载 task_state.json |
| **04-任务执行引擎** | 调用 | 调用注册方法注册全部任务 |
| **13-任务文件管理** | new | 创建 TaskManager 实例 |
| **15-账号管理模块** | new | 创建 AccountManager 实例（先于 09 初始化） |
| **09-运行控制中心** | new | 创建 RunController 实例（注入全部依赖，含已就绪的 AccountManager） |
| **11-用户界面模块** | new + 调用 | 创建 MainWindow 实例，调用 show() |
```
