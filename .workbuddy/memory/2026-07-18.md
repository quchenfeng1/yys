### 修复 pythonw 启动崩溃（v0.2.1）
- 用户反馈：脚本启动失败
- 根因：core/logger.py 第37行 `_logger.add(sys.stderr, ...)` 在 pythonw.exe（无控制台）模式下崩溃，因为此时 sys.stderr 是 None，loguru 不接受 None 作为日志 sink
- crash.log 记录错误：`TypeError: Cannot log to objects of type 'NoneType'`
- 修复：setup_logger() 中加判断 `if sys.stderr is not None:` 才添加控制台 sink，pythonw 模式下日志只写文件
- 验证：pythonw.exe 运行 main.py 正常进入 GUI 事件循环，日志正常写入文件，无新 crash.log
- 教训：使用 pythonw.exe（GUI无控制台模式）时，sys.stdout/sys.stderr 均为 None，任何日志库的 console sink 都必须做空值判断

  2. **is_running() 逐字符遍历bug**：`for line in result.stdout` 对字符串是逐字符遍历而非逐行，导致进程检测永远失败（明明MuMu在运行却报"未运行"）
  3. **get_screen_size() 未优先Override size**：wm size 输出有 Physical(720x1280)+Override(1280x720) 两行，原代码返回第一行Physical，导致分辨率识别错误
  4. **MuMu默认端口过时**：原配置 mumu:7555，MuMu12实际为16384
- MuMu连接修复方案：
  - emulator.py 新增 find_adb_path()：自动检测模拟器自带 adb.exe（MuMu在 nx_main\adb.exe），用 _test_adb() 实际运行 version 命令验证可用性，避开损坏的系统adb
  - emulator.py ensure_running() 开头自动调用 find_adb_path() 更新 adb_client.adb_path
  - 修复 is_running()：改为 `output_lower = result.stdout.lower()` 整体匹配
  - 修复 get_screen_size()：优先返回 Override size，无才用 Physical size
  - MuMu默认端口改为16384；安装路径检测更新为 nx_main\MuMuNxMain.exe
  - global.yaml adb.path 指向 MuMu 自带 adb
