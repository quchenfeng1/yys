# 04-任务模块（Task Module）

> **类型**：核心运行层  ｜  **对应说明书**：BaseTask 9.1 + DungeonTask 6.4 + 第六部分  ｜  **对应用户模块**：#2 任务模块

---

## 一、目的与作用

**一句话定位**：将任务拆解为"特化模块+通用模块"的组合，通过任务步骤图（DAG）描述执行流程，支持顺序/条件分支/循环/错误恢复。

**核心职责**：
1. **任务步骤化**：每个任务由多个TaskStep（步骤）组成，步骤分特化和通用
2. **步骤组合**：特化模块（副本独有操作）+ 通用模块（战斗/结算/返回等复用操作）
3. **步骤图引擎**：用有向图描述步骤间关系，支持顺序/分支/循环/跳转
4. **错误恢复**：步骤失败时走error_return分支（返回大厅→跳过任务），不崩溃
5. **自动注册**：任务文件放入tasks/目录即自动发现注册，无需改代码

**设计原则**：
- **组合优于继承**：任务不是一个大类，而是多个步骤的组合
- **通用模块复用**：战斗循环、结算领奖、返回庭院等通用步骤全项目共享
- **特化模块最小化**：每个副本只写自己独有的界面操作（入口、选层等）
- **步骤图声明式**：流程用图描述，而非代码里的if/for嵌套

### 3.2 TaskStep接口设计

```python
class TaskStep:
    """任务步骤基类。特化模块和通用模块都继承此类。"""

    name: str = ""           # 步骤名（调试用）
    is_generic: bool = False # 是否通用模块（True=可复用）

    def execute(self, context: TaskContext) -> StepResult:
        """执行步骤。返回StepResult，步骤图据此决定下一步。"""

class StepResult:
    """步骤执行结果。"""
    status: str       # "success" / "fail" / "skip" / "retry"
    next_step: str = None  # 指定下一步（覆盖默认顺序，用于条件分支）
    data: dict = None      # 输出数据（传给后续步骤）
    message: str = ""      # 日志消息

class TaskContext:
    """步骤间共享的上下文。"""
    task_config: dict       # 任务配置
    executor: Executor      # 操作执行器
    recognizer: Recognizer  # 识图引擎
    team_manager: TeamManager
    state: dict             # 临时状态（步骤间传参）
```

### 3.3 任务步骤图引擎

```python
class TaskGraph:
    """任务步骤图。用有向图描述步骤间关系。"""

    def __init__(self):
        self._steps: dict[str, TaskStep] = {}  # 步骤名→步骤实例
        self._edges: dict[str, list] = {}      # 步骤名→[后续步骤名列表]
        self._entry: str = ""                   # 入口步骤

    def add_step(self, name: str, step: TaskStep):
        """添加步骤"""

    def add_edge(self, from_step: str, to_step: str, condition=None):
        """添加边（可带条件函数，用于分支）"""

    def set_entry(self, name: str):
        """设置入口步骤"""

    def run(self, context: TaskContext) -> bool:
        """执行步骤图。从入口开始，按StepResult.next_step或默认边遍历。"""
        current = self._entry
        while current:
            step = self._steps[current]
            result = step.execute(context)
            # 发布步骤完成事件（供UI更新进度）
            event_bus.publish("step_done", step=current, result=result)
            if result.status == "fail":
                # 失败走error分支
                current = self._get_error_branch(current)
            elif result.next_step:
                # 显式指定下一步（条件分支）
                current = result.next_step
            else:
                # 默认顺序
                current = self._edges[current][0] if self._edges.get(current) else None
        return True
```

### 3.4 步骤图声明示例（御魂副本）

```python
class YuhunTask(DungeonTask):
    name = "yuhun"
    display_name = "御魂副本"

    def build_graph(self) -> TaskGraph:
        g = TaskGraph()
        g.add_step("enter", EnterYuhun())
        g.add_step("check_stamina", CheckStamina())
        g.add_step("pre_team", PreCheckTeam())
        g.add_step("select_team", SelectTeam())
        g.add_step("battle", BattleLoop(times=self.config["times"]))
        g.add_step("claim", ClaimReward())
        g.add_step("return", ReturnHall())
        g.add_step("error", ErrorReturn())

        g.set_entry("enter")
        g.add_edge("enter", "check_stamina")
        g.add_edge("check_stamina", "pre_team", condition=lambda r: r.status=="success")
        g.add_edge("check_stamina", "return", condition=lambda r: r.status=="skip")  # 体力不足跳过
        g.add_edge("pre_team", "select_team")
        g.add_edge("select_team", "battle")
        g.add_edge("battle", "claim")
        g.add_edge("claim", "return")
        # 错误分支：任意步骤失败→error
        for step in ["enter","pre_team","select_team","battle","claim"]:
            g.add_edge(step, "error", condition=lambda r: r.status=="fail")
        return g
```

### 3.5 通用模块示例（BattleLoop）

```python
class BattleLoop(TaskStep):
    """通用战斗循环。等待战斗结束→检测胜负→结算。可循环N次。"""
    is_generic = True

    def __init__(self, times: int = 1):
        self._times = times

    def execute(self, ctx: TaskContext) -> StepResult:
        for i in range(self._times):
            # 等待战斗结束
            result = ctx.executor.wait_any(
                ["common/battle/victory", "common/battle/defeat"],
                timeout=180
            )
            if not result:
                return StepResult(status="fail", message=f"第{i+1}轮战斗超时")
            name, match = result
            if "defeat" in name:
                return StepResult(status="fail", message=f"第{i+1}轮战斗失败")
            # 结算点击
            ctx.executor.click_image("common/battle/confirm_settle")
            ctx.executor.random_sleep(1, 2)
            if i < self._times - 1:
                # 非最后一轮，点击再次挑战
                ctx.executor.click_image("common/battle/challenge_again")
        return StepResult(status="success", message=f"完成{self._times}轮战斗")
```

## 五、关键设计决策

1. **步骤图优于线性流程**：DAG支持条件分支（体力不足跳过）、循环（战斗N次）、错误恢复（失败走error分支）
2. **通用模块中粒度**：BattleLoop/ClaimReward/ReturnHall为中粒度，兼顾复用性与灵活性
3. **StepResult驱动流转**：步骤返回结果含next_step字段，可实现"根据输出值判断走哪条路"
4. **TaskContext传参**：步骤间通过context.state传参，避免全局变量
5. **自动注册保留**：任务文件放入tasks/目录即自动发现，与说明书9.2一致
6. **兼容说明书接口**：BaseTask的execute()内部调用TaskGraph.run()，对外接口不变

## 六、进一步增强（v2.0）

### 6.1 步骤超时机制

每个 TaskStep 可配置 timeout，超时自动转 fail，避免卡死：

```python
class TaskStep:
    timeout: float = 120.0   # 默认120秒超时
    on_timeout: str = "fail" # "fail" / "retry" / "skip"

class TaskGraph:
    def run(self, context):
        current = self._entry
        while current:
            step = self._steps[current]
            # 超时检测：在子线程中执行步骤，主线程计时
            result = self._execute_with_timeout(step, context, step.timeout)
            if result.status == "timeout":
                if step.on_timeout == "retry":
                    result = self._retry_step(step, context)
                elif step.on_timeout == "skip":
                    result = StepResult(status="skip", message="超时跳过")
                else:
                    result = StepResult(status="fail", message="步骤超时")
            ...
```

### 6.2 步骤重试机制

可配置 retry_count，失败自动重试，重试间隔由安全模块控制：

```python
class TaskStep:
    retry_count: int = 0         # 默认不重试
    retry_delay: float = 2.0     # 重试间隔（秒，会加安全随机抖动）

class TaskGraph:
    def _execute_step(self, step, context) -> StepResult:
        for attempt in range(step.retry_count + 1):
            result = step.execute(context)
            if result.status == "success":
                return result
            if attempt < step.retry_count:
                monitor.warning(f"步骤{step.name}第{attempt+1}次失败，重试中...",
                               task=context.task_name, step=step.name)
                sleep(anti_detect.random_delay(step.retry_delay))
        return result  # 全部重试失败
```

### 6.3 步骤回滚（cleanup）

失败时执行可选的 cleanup 回调（如关闭已打开的弹窗）：

```python
class TaskStep:
    cleanup: callable = None   # 可选的清理函数

    def execute(self, context) -> StepResult:
        try:
            return self._do_execute(context)
        except Exception as e:
            if self.cleanup:
                monitor.info(f"执行清理: {self.name}", step=self.name)
                self.cleanup(context)
            raise

# 示例：进入副本步骤的cleanup
class EnterYuhun(TaskStep):
    def cleanup(self, ctx):
        """如果进入御魂界面后失败，先返回庭院再走error分支"""
        if ctx.recognizer.exists("scenes/courtyard/marker") == False:
            ctx.executor.click_image("common/nav/back_btn")
```

### 6.4 中断检查点

步骤执行中定期检查 stop 信号，支持优雅中断（不等待整个步骤完成）：

```python
class TaskContext:
    _stop_event: threading.Event  # 停止信号

    def check_interrupt(self) -> bool:
        """步骤执行中定期调用，检查是否被要求停止"""
        return self._stop_event.is_set()

# 长循环步骤（如BattleLoop）中插入检查点：
class BattleLoop(TaskStep):
    def execute(self, ctx: TaskContext) -> StepResult:
        for i in range(self._times):
            if ctx.check_interrupt():
                return StepResult(status="skip", message="用户中断")
            # ... 战斗逻辑
```

### 6.5 步骤并行执行

支持 parallel 节点，多个无依赖步骤可并行执行（如等待+检测）：

```python
class TaskGraph:
    def add_parallel(self, name: str, steps: list[TaskStep], merge: str = "all_success"):
        """添加并行节点。
        - merge="all_success": 全部成功才算成功
        - merge="any_success": 任一成功即成功
        - merge="first_result": 取第一个返回的结果
        """

# 示例：等待加载完成时，同时检测多个可能的场景
g.add_parallel("wait_scene", [
    WaitScene("courtyard"),
    WaitScene("battle"),
    WaitScene("explore"),
], merge="first_result")
```

### 6.6 步骤执行追踪

每个步骤的执行自动记录到监控模块，便于事后分析：

```python
class TaskGraph:
    def _execute_step(self, step, context):
        start = time.time()
        monitor.debug(f"开始执行步骤: {step.name}", task=context.task_name, step=step.name)
        result = step.execute(context)
        duration = time.time() - start
        monitor.record_step(step.name, result.status, duration)
        monitor.debug(f"步骤完成: {step.name} → {result.status} ({duration:.1f}s)",
                     task=context.task_name, step=step.name)
        return result
```
