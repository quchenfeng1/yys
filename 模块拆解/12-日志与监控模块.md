# 12-日志与监控模块（Monitor Module）★新增

> **类型**：支撑服务层  ｜  **对应说明书**：Logger 5.6 升级  ｜  **对应用户模块**：无（新增）

---

## 一、目的与作用

**一句话定位**：可观测性中心。统一管理结构化日志、运行指标、异常截图和运行报告，为调试、监控和优化提供数据支撑。

**为什么需要这个模块**：

现有 `core/logger.py` 只是简单的文本日志输出（loguru），缺少：

| 缺失能力 | 痛点 |
|----------|------|
| 结构化记录 | 日志只有文本，无法按模块/任务/步骤筛选检索 |
| 运行指标 | 不知道每个任务执行了多少次、成功率多少、平均耗时多少 |
| 异常截图 | 出错时没有自动保存现场截图，事后无法排查 |
| 运行报告 | 缺少每日/每周总结，不知道脚本整体运行情况 |
| 日志事件化 | UI日志面板需要实时获取日志，目前靠轮询或直接耦合 |

如果这些能力散落在各模块中实现，会导致日志逻辑侵入业务代码，且各模块日志格式不一致。

**核心职责**：
1. **结构化日志**：每条日志带模块/级别/任务/步骤/时间戳/标签，可按维度筛选
2. **运行指标收集**：自动统计各任务执行次数/成功率/平均耗时/总耗时
3. **异常自动截图**：出错时自动截图+保存上下文（任务/步骤/配置），便于排查
4. **运行报告**：每日/每周自动生成运行总结
5. **日志事件化**：日志通过事件总线发布，UI日志面板订阅显示

**设计原则**：
- **非侵入式**：其他模块只需调用 `monitor.log()` / `monitor.record_task()`，不感知日志内部实现
- **结构化优先**：所有日志和指标都是结构化数据（JSON），文本输出只是其中一种渲染
- **异步写入**：日志写入不阻塞业务线程，通过队列异步落盘
- **可配置级别**：调试时开DEBUG级全量记录，生产时开INFO级精简输出

### 3.2 核心接口设计

```python
class Monitor:
    """日志与监控中心。统一管理日志、指标、截图、报告。"""

    def __init__(self, config, event_bus):
        self._config = config
        self._bus = event_bus
        self._logger = setup_logger(config)       # loguru底层
        self._metrics = MetricsCollector()        # 指标收集
        self._snapshot = SnapshotManager(config)  # 异常截图
        self._report = ReportGenerator(config)    # 报告生成

    # === 结构化日志 ===
    def log(self, level: str, message: str, *,
            module: str = "", task: str = "", step: str = "", tags: list = None):
        """记录结构化日志。
        - level: DEBUG/INFO/WARNING/ERROR/CRITICAL
        - module: 来源模块名（如"connection"/"scheduler"/"task:yuhun"）
        - task: 当前任务名（可选）
        - step: 当前步骤名（可选）
        - tags: 自定义标签列表（如["battle","victory"]）
        日志同时：①写入文件（结构化JSON）②通过事件总线发布供UI显示
        """
        entry = LogEntry(
            timestamp=datetime.now(),
            level=level, message=message,
            module=module, task=task, step=step, tags=tags or []
        )
        # 1. 写入文件（loguru渲染）
        self._logger.log(level, f"[{module}] {message}")
        # 2. 结构化存储（JSON文件，供检索）
        self._write_structured(entry)
        # 3. 通过事件总线发布（UI日志面板订阅）
        self._bus.publish("log_record", **entry.to_dict())

    # === 便捷方法 ===
    def debug(self, msg, **kw): self.log("DEBUG", msg, **kw)
    def info(self, msg, **kw): self.log("INFO", msg, **kw)
    def warning(self, msg, **kw): self.log("WARNING", msg, **kw)
    def error(self, msg, **kw): self.log("ERROR", msg, **kw)

    # === 运行指标 ===
    def record_task_start(self, task_name: str):
        """记录任务开始（运行控制调用）"""

    def record_task_done(self, task_name: str, success: bool, duration: float):
        """记录任务完成（运行控制调用）"""

    def get_metrics(self, task_name: str = None) -> dict:
        """获取任务运行指标
        返回: {执行次数, 成功次数, 失败次数, 成功率, 平均耗时, 总耗时}
        """

    def get_all_metrics(self) -> dict:
        """获取全部任务指标"""

    # === 异常截图 ===
    def capture_on_error(self, task_name: str, step_name: str, error: Exception,
                         screenshot: np.ndarray = None):
        """异常时自动截图+保存上下文。
        保存内容：截图PNG + 上下文JSON（任务/步骤/错误信息/配置/时间）
        存放路径：logs/snapshots/YYYY-MM-DD/{task}_{step}_{timestamp}.png
        """

    # === 运行报告 ===
    def generate_daily_report(self, date=None) -> str:
        """生成每日运行报告（Markdown格式）。
        内容：执行任务列表/成功失败统计/耗时分布/异常记录/截图索引
        """

    def generate_weekly_report(self, week_end=None) -> str:
        """生成每周运行报告"""

    # === 日志检索 ===
    def query_logs(self, *, level=None, module=None, task=None,
                   start_time=None, end_time=None, keyword=None) -> list:
        """按条件检索结构化日志"""
```

### 3.3 LogEntry数据结构

```python
@dataclass
class LogEntry:
    """结构化日志条目。"""
    timestamp: datetime    # 时间戳
    level: str             # DEBUG/INFO/WARNING/ERROR/CRITICAL
    message: str           # 日志消息
    module: str            # 来源模块
    task: str              # 当前任务（可选）
    step: str              # 当前步骤（可选）
    tags: list             # 自定义标签

    def to_dict(self) -> dict:
        return {
            "timestamp": self.timestamp.isoformat(),
            "level": self.level,
            "message": self.message,
            "module": self.module,
            "task": self.task,
            "step": self.step,
            "tags": self.tags,
        }
```

### 3.4 运行指标收集器

```python
class MetricsCollector:
    """运行指标收集与统计。"""

    def __init__(self):
        self._task_stats: dict[str, TaskStats] = {}  # 任务名→统计

    def record_start(self, task_name: str):
        if task_name not in self._task_stats:
            self._task_stats[task_name] = TaskStats(task_name)
        self._task_stats[task_name].record_start()

    def record_done(self, task_name: str, success: bool, duration: float):
        self._task_stats[task_name].record_done(success, duration)

    def get(self, task_name: str) -> dict:
        return self._task_stats[task_name].summary()

    def get_all(self) -> dict:
        return {name: stats.summary() for name, stats in self._task_stats.items()}

@dataclass
class TaskStats:
    """单个任务的运行统计。"""
    name: str
    total_runs: int = 0          # 总执行次数
    success_count: int = 0       # 成功次数
    fail_count: int = 0          # 失败次数
    total_duration: float = 0.0  # 总耗时（秒）
    durations: list = None       # 每次耗时列表（用于计算分布）
    last_run: datetime = None    # 最后执行时间
    errors: list = None          # 最近N条错误记录

    @property
    def success_rate(self) -> float:
        return self.success_count / self.total_runs if self.total_runs > 0 else 0

    @property
    def avg_duration(self) -> float:
        return self.total_duration / self.total_runs if self.total_runs > 0 else 0

    def summary(self) -> dict:
        return {
            "name": self.name,
            "total_runs": self.total_runs,
            "success": self.success_count,
            "fail": self.fail_count,
            "success_rate": f"{self.success_rate:.1%}",
            "avg_duration": f"{self.avg_duration:.1f}s",
            "total_duration": f"{self.total_duration:.0f}s",
            "last_run": self.last_run.isoformat() if self.last_run else None,
        }
```

### 3.5 异常截图管理器

```python
class SnapshotManager:
    """异常时自动截图+上下文保存。"""

    def __init__(self, config):
        self._snap_dir = config.get("global.run.snapshot_dir", "logs/snapshots")

    def capture(self, task_name: str, step_name: str, error: Exception,
                screenshot: np.ndarray = None, context: dict = None):
        """保存异常截图和上下文。
        - 截图保存为PNG
        - 上下文保存为JSON（任务/步骤/错误/配置/调用栈）
        - 文件名: {task}_{step}_{HHMMSS}.png
        """
        timestamp = datetime.now()
        filename = f"{task_name}_{step_name}_{timestamp:%H%M%S}"
        # 保存截图
        if screenshot is not None:
            cv2.imwrite(f"{self._snap_dir}/{timestamp:%Y-%m-%d}/{filename}.png", screenshot)
        # 保存上下文
        ctx = {
            "timestamp": timestamp.isoformat(),
            "task": task_name,
            "step": step_name,
            "error": str(error),
            "error_type": type(error).__name__,
            "traceback": traceback.format_exc(),
            "context": context or {},
        }
        with open(f"{self._snap_dir}/{timestamp:%Y-%m-%d}/{filename}.json", "w") as f:
            json.dump(ctx, f, ensure_ascii=False, indent=2)
```

### 3.6 运行报告生成器

```python
class ReportGenerator:
    """生成每日/每周运行报告。"""

    def daily_report(self, date=None, metrics=None, logs=None) -> str:
        """生成每日运行报告（Markdown）。
        内容包括：
        - 执行任务列表（含成功/失败/耗时）
        - 整体统计（总任务数/成功率/总耗时）
        - 异常记录（失败任务的错误信息+截图索引）
        - 建议优化项（如成功率低/耗时异常的任务）
        """
        date = date or datetime.now().date()
        lines = [
            f"# 运行报告 - {date}",
            "",
            "## 任务执行统计",
            "| 任务 | 执行次数 | 成功 | 失败 | 成功率 | 平均耗时 |",
            "|------|----------|------|------|--------|----------|",
        ]
        for name, stats in (metrics or {}).items():
            lines.append(f"| {name} | {stats['total_runs']} | {stats['success']} | "
                        f"{stats['fail']} | {stats['success_rate']} | {stats['avg_duration']} |")
        # ... 异常记录、建议优化项
        return "\n".join(lines)
```

## 四、与其他模块的交互

| 交互方 | 方式 | 说明 |
|--------|------|------|
| 所有模块 | 被调用 | 各模块调monitor.log()记录日志，调record_task_*记录指标 |
| 运行控制 | 被调用 | 任务开始/完成时调record_task_start/done |
| 任务模块 | 被调用 | 步骤执行时传task/step参数记录日志 |
| 事件总线 | 发布事件 | 发布log_record事件供UI订阅 |
| UI日志面板 | 订阅事件 | 订阅log_record事件实时显示日志 |
| UI监控面板 | 调用 | 调get_metrics()显示运行指标 |
| 连接模块 | 被调用 | 截图异常时传screenshot给capture_on_error |
| 配置模块 | 读配置 | 读取日志级别/截图开关/保留天数 |

## 五、日志文件体系

```
logs/
├── app.log                   ← 文本日志（loguru渲染，人类可读）
├── structured.jsonl          ← 结构化日志（JSON Lines，机器可读）
├── metrics.json              ← 运行指标快照（定期保存）
├── snapshots/                ← 异常截图归档
│   └── 2026-07-19/
│       ├── yuhun_battle_loop_143052.png    ← 异常截图
│       └── yuhun_battle_loop_143052.json   ← 上下文
└── reports/                  ← 运行报告
    ├── daily/
    │   └── 2026-07-19.md     ← 每日报告
    └── weekly/
        └── 2026-W29.md       ← 每周报告
```

**日志保留策略**：
- 文本日志：保留7天，按天滚动
- 结构化日志：保留30天，按天滚动
- 异常截图：保留30天，自动清理过期
- 运行报告：永久保留
- 指标快照：保留90天

## 七、关键设计决策

1. **结构化优先**：所有日志和指标都是结构化数据，文本输出只是渲染之一
2. **非侵入式**：其他模块只需调monitor.log()，不感知日志内部实现
3. **异步写入**：日志通过队列异步落盘，不阻塞业务线程
4. **日志事件化**：日志通过事件总线发布，UI订阅显示，不直接耦合
5. **异常截图自动化**：出错时自动截图+保存上下文，无需手动操作
6. **运行报告**：每日/每周自动生成，帮助用户了解脚本运行状况
7. **保留策略**：不同数据不同保留期，自动清理过期文件
8. **loguru保留**：底层仍用loguru（成熟稳定），Monitor在其上封装结构化能力
