## 一、目的与作用

**一句话定位**：模块间通信枢纽。采用发布-订阅模式，模块间不直接持有对方引用，通过事件总线间接通信，实现真正的解耦。

**为什么需要这个模块**：

如果没有事件总线，模块间需要直接调用：

```
用户点"停止" → UI直接调用RunController.stop()
             → RunController直接调用Scheduler.pause()
             → RunController直接调用当前Task.abort()
             → RunController直接调用Connection.disconnect()
```

这导致：UI必须持有RunController引用，RunController必须持有Scheduler+Task+Connection引用，形成网状依赖。增删模块时需要修改所有相关模块的代码。

**有了事件总线后**：

```
用户点"停止" → UI发布事件 "stop_requested"
             → RunController订阅了"stop_requested" → 执行stop逻辑
             → Scheduler订阅了"stop_requested" → 暂停调度
             → Task订阅了"stop_requested" → 中止当前步骤
             → Connection订阅了"stop_requested" → 断开连接
```

发布者不关心谁订阅，订阅者不关心谁发布。增删模块时只需增删订阅，不改现有代码。

**核心职责**：
1. **事件发布**：publish(event_name, **data) 发布事件
2. **事件订阅**：subscribe(event_name, handler) 订阅事件
3. **事件过滤**：支持按条件过滤（只处理满足条件的事件）
4. **线程安全**：跨线程发布/订阅（UI线程与工作线程通信）
5. **事件历史**：可选记录事件历史（调试用）

**设计原则**：
- **发布者不阻塞**：publish立即返回，handler在订阅者线程异步执行
- **松耦合**：发布者和订阅者互不感知
- **事件命名规范**：past_tense事件名（如task_done而非do_task）

## 三、实现思路

### 3.1 模块结构

```
core/
├── event_bus.py          ← 事件总线主入口
└── events.py             ← 事件名常量定义（新增）
```

### 3.2 核心接口设计

```python
class EventBus:
    """发布-订阅事件总线。线程安全，跨线程通信。"""

    def publish(self, event_name: str, **data):
        """发布事件。立即返回，handler异步执行。"""

    def subscribe(self, event_name: str, handler: callable, filter=None):
        """订阅事件。
        - handler: 事件处理回调函数，接收**data
        - filter: 可选过滤函数，返回True才执行handler
        返回订阅ID（用于取消订阅）
        """

    def unsubscribe(self, subscription_id: str):
        """取消订阅"""

    def clear(self):
        """清空所有订阅（测试用）"""


# 全局单例
event_bus = EventBus()
```

### 3.3 线程安全实现

```python
class EventBus:
    def __init__(self):
        self._subscribers: dict[str, list] = {}  # event_name → [(handler, filter)]
        self._lock = threading.Lock()
        self._queue = queue.Queue()  # 事件队列，工作线程消费

    def publish(self, event_name: str, **data):
        event = Event(name=event_name, data=data, timestamp=datetime.now())
        self._queue.put(event)  # 入队，不阻塞发布者

    def _dispatch_loop(self):
        """工作线程：从队列取事件，分发给订阅者"""
        while self._running:
            event = self._queue.get()
            with self._lock:
                handlers = self._subscribers.get(event.name, [])
            for handler, filter_func in handlers:
                if filter_func is None or filter_func(event):
                    try:
                        handler(**event.data)
                    except Exception as e:
                        logger.error(f"事件处理器异常: {e}")
```

### 3.5 使用示例

```python
# UI发布停止事件
def on_stop_button_clicked(self):
    event_bus.publish(Events.STOP_REQUESTED)

# RunController订阅停止事件
class RunController:
    def __init__(self):
        event_bus.subscribe(Events.STOP_REQUESTED, self._on_stop_requested)

    def _on_stop_requested(self):
        self._state = "stopping"
        # 通知当前任务收尾...
        event_bus.publish(Events.RUN_STOPPED)

# UI订阅运行状态变化
class StatusPanel:
    def __init__(self):
        event_bus.subscribe(Events.STATE_CHANGED,
            handler=self._on_state_changed,
            filter=lambda e: e.data.get("key") == "run_status")

    def _on_state_changed(self, key, old_value, new_value):
        if new_value == "running":
            self.status_label.setText("运行中")
        elif new_value == "paused":
            self.status_label.setText("已暂停")
```

## 五、关键设计决策

1. **发布-订阅模式**：发布者和订阅者互不感知，增删模块不改现有代码
2. **异步分发**：publish入队立即返回，handler在工作线程执行，不阻塞发布者
3. **线程安全**：Lock保护订阅者列表，Queue实现跨线程通信（UI线程↔工作线程）
4. **事件过滤**：subscribe支持filter参数，订阅者可只处理关心的事件
5. **事件名常量**：Events类统一管理事件名，避免拼写错误
6. **异常隔离**：单个handler异常不影响其他handler执行
7. **全局单例**：event_bus作为全局单例，所有模块共享同一个实例

## 六、进一步增强（v2.0）

### 6.1 事件溯源（Event Sourcing）

可选记录全部事件历史，支持调试时回放事件序列排查问题：

```python
class EventBus:
    def __init__(self, enable_history=False, max_history=10000):
        self._history: list[Event] = [] if enable_history else None
        self._max_history = max_history

    def publish(self, event_name: str, **data):
        event = Event(name=event_name, data=data, timestamp=datetime.now())
        if self._history is not None:
            self._history.append(event)
            if len(self._history) > self._max_history:
                self._history.pop(0)  # 超出上限丢弃最旧的
        self._queue.put(event)

    def replay(self, start_time=None, end_time=None, event_names=None):
        """回放指定时间段/事件类型的历史事件（调试用）"""
        for event in self._history:
            if start_time and event.timestamp < start_time:
                continue
            if end_time and event.timestamp > end_time:
                continue
            if event_names and event.name not in event_names:
                continue
            yield event

    def export_history(self, output_path: str):
        """导出事件历史为JSON文件（供离线分析）"""
```

### 6.2 事件优先级

系统级事件（connection_lost/run_limit_reached）高优先级插队处理：

```python
class Event:
    name: str
    data: dict
    timestamp: datetime
    priority: int = 0   # 0=普通, 1=高优先级（插队）

class EventBus:
    def __init__(self):
        self._queue = queue.PriorityQueue()  # 改用优先级队列

    def publish(self, event_name: str, priority: int = 0, **data):
        event = Event(name=event_name, data=data, timestamp=datetime.now(), priority=priority)
        # PriorityQueue按priority排序，高优先级先出队
        self._queue.put((-priority, sequence, event))  # 负号=高优先级先出

# 高优先级事件定义
class Events:
    # 系统级事件（高优先级，插队处理）
    CONNECTION_LOST = ("connection_lost", 1)      # 连接断开
    RUN_LIMIT_REACHED = ("run_limit_reached", 1)  # 运行上限
    STOP_REQUESTED = ("stop_requested", 1)        # 用户停止
    # 普通事件（默认优先级0）
    TASK_DONE = ("task_done", 0)
    STEP_DONE = ("step_done", 0)
```

### 6.3 事件去重

短时间内重复事件自动合并，防止事件风暴（如连续多次connection_lost）：

```python
class EventBus:
    def __init__(self, dedup_window: float = 5.0):
        self._dedup_window = dedup_window  # 5秒内相同事件去重
        self._recent_events: dict[str, datetime] = {}  # 事件名→最后发布时间

    def publish(self, event_name: str, **data):
        # 去重检查
        last_time = self._recent_events.get(event_name)
        if last_time and (datetime.now() - last_time).total_seconds() < self._dedup_window:
            # 短时间内重复，跳过（或合并计数）
            monitor.debug(f"事件去重: {event_name}")
            return
        self._recent_events[event_name] = datetime.now()
        # ... 正常发布
```

### 6.4 事件死信队列

处理失败的事件进入死信队列，避免反复重试阻塞正常事件：

```python
class EventBus:
    def _dispatch_loop(self):
        while self._running:
            event = self._queue.get()
            handlers = self._subscribers.get(event.name, [])
            for handler, filter_func in handlers:
                try:
                    if filter_func is None or filter_func(event):
                        handler(**event.data)
                except Exception as e:
                    # 处理失败→进入死信队列
                    self._dead_letter.append((event, handler, e))
                    monitor.error(f"事件处理器异常: {event.name} - {e}",
                                 module="event_bus", tags=["dead_letter"])

    def get_dead_letters(self) -> list:
        """获取死信队列（调试用）"""
        return self._dead_letter
```
