> **文档性质**：基于12模块解耦方案的主程序骨架设计  ｜  **版本**：v2.0（新增日志监控模块装配）

## 一、程序启动流程

```
main.py 启动
  │
  ├─[1] 初始化基础设施
  │   ├─ 创建事件总线 EventBus（全局单例，支持事件溯源/优先级/去重）
  │   ├─ 创建状态管理器 StateManager
  │   ├─ 创建配置管理器 ConfigManager（加载所有yaml/json，支持三级分层覆盖）
  │   ├─ 创建日志监控器 Monitor（结构化日志+指标+截图+报告）★v2.0新增
  │   └─ 配置迁移检查（自动迁移旧版配置）
  │
  ├─[2] 初始化核心服务
  │   ├─ 创建连接管理器 ConnectionManager（含质量监控+连接池预热）
  │   ├─ 创建识图引擎 Recognizer（加载assets/素材索引）
  │   ├─ 创建安全引擎 AntiDetect（含操作审计+行为多样性+节奏控制）
  │   ├─ 创建操作执行器 Executor（注入Recognizer+AntiDetect+Connection）
  │   ├─ 创建阵容管理器 TeamManager
  │   ├─ 创建账号管理器 AccountManager
  │   └─ 创建调度器 Scheduler（加载task_state.json）
  │
  ├─[3] 初始化任务体系
  │   ├─ task_registry.discover_tasks()（扫描tasks/四子目录）
  │   ├─ 向Scheduler注册所有任务（repeat/priority）
  │   └─ 为每个任务构建TaskGraph（步骤图）
  │
  ├─[4] 初始化运行控制
  │   ├─ 创建 RunController（注入Scheduler+Connection+Config+Monitor）
  │   ├─ 创建 CircuitBreaker 熔断器（注入RunController）
  │   └─ RunController订阅事件总线控制信号+异常恢复策略
  │
  ├─[5] 初始化UI
  │   ├─ 创建 QApplication
  │   ├─ 创建 ParamBridge（传参模块，注入Config+StateManager+EventBus）
  │   ├─ 创建 MainWindow（三栏布局）
  │   ├─ 各UI子面板通过ParamBridge绑定配置和状态
  │   └─ 订阅事件总线刷新UI
  │
  ├─[6] 启动心跳检测
  │   └─ ConnectionManager.start_heartbeat()
  │
  └─[7] 进入Qt事件循环
      └─ app.exec_()  ← 等待用户操作
```

## 二、依赖注入与装配

主程序通过**依赖注入**装配各模块，避免模块间硬编码依赖：

```python
# main.py
def main():
    # === 基础设施 ===
    bus = EventBus(enable_history=True)       # 全局单例，开启事件溯源
    state = StateManager(bus)
    config = ConfigManager()
    config.load_all()                          # 含配置版本迁移
    monitor = Monitor(config, bus)             # 日志监控 ★v2.0
    monitor.info("脚本启动", module="main")

    # === 核心服务 ===
    connection = ConnectionManager(config, monitor)
    recognizer = Recognizer(connection, config)
    anti_detect = AntiDetect(config, state, monitor)  # 含审计+多样性
    executor = Executor(recognizer, anti_detect, connection, monitor)
    team_mgr = TeamManager(executor, config)
    account_mgr = AccountManager(config, connection)
    scheduler = Scheduler(config, state, bus, monitor)

    # === 任务体系 ===
    registry = TaskRegistry()
    registry.discover()                     # 扫描tasks/目录
    for name, task in registry.all_tasks():
        scheduler.register_task(name, task.repeat, task.priority)
        task.bind(executor, recognizer, team_mgr)  # 注入依赖

    # === 运行控制 ===
    controller = RunController(scheduler, connection, config, state,
                              registry, bus, monitor)  # 含熔断+异常恢复

    # === UI ===
    app = QApplication(sys.argv)
    bridge = ParamBridge(config, state, scheduler, bus, monitor)
    window = MainWindow(bridge)
    window.show()

    # === 启动 ===
    # 预热多开连接
    if account_mgr.has_sub_accounts():
        connection.preconnect(account_mgr.get_all_device_ids())
    connection.start_heartbeat()
    monitor.info("初始化完成，等待用户操作", module="main")
    sys.exit(app.exec_())
```

## 三、模块装配关系图

```
main.py 装配顺序（依赖方向↓）：

Layer 1 (无依赖):
  EventBus ← 全局单例（+事件溯源/优先级/去重）
  StateManager ← EventBus
  ConfigManager ← (读文件，+三级分层覆盖/配置迁移)
  Monitor ← ConfigManager, EventBus  ★v2.0

Layer 2 (依赖Layer1):
  ConnectionManager ← ConfigManager, Monitor（+质量监控/连接池预热）
  Recognizer ← ConnectionManager, ConfigManager
  AntiDetect ← ConfigManager, StateManager, Monitor（+审计/多样性/节奏控制）

Layer 3 (依赖Layer2):
  Executor ← Recognizer, AntiDetect, Connection, Monitor  ★核心注入点
  TeamManager ← Executor, ConfigManager
  AccountManager ← ConfigManager, ConnectionManager
  Scheduler ← ConfigManager, StateManager, EventBus, Monitor

Layer 4 (依赖Layer3):
  TaskRegistry ← Executor, Recognizer, TeamManager (任务绑定依赖)
  RunController ← Scheduler, Connection, Config, State, Registry, EventBus, Monitor
                  (+CircuitBreaker熔断器+异常恢复策略)

Layer 5 (依赖Layer4):
  ParamBridge ← Config, State, Scheduler, EventBus, Monitor
  MainWindow ← ParamBridge
```

**关键注入点**：Executor 同时持有 Recognizer + AntiDetect + Connection，是安全策略的注入位置。任务步骤通过TaskContext获取Executor，不直接持有底层模块。

## 四、运行时数据流

### 4.1 用户点击"启动"的完整流程

```
1. 用户点击启动按钮
2. UI ControlBar → ParamBridge.run_bridge → event_bus.publish("start_requested")
3. RunController订阅了"start_requested" → _on_start()
4. RunController._start_run():
   ├─ 检查运行允许性（防封号上限、连接状态）
   ├─ ConnectionManager.connect() → 连接模拟器
   ├─ Scheduler.load_state() → 恢复task_state.json
   ├─ StateManager.set_state("run_status", "running")
   │   → event_bus.publish("state_changed", key="run_status", ...)
   │   → UI StatusBar订阅 → 刷新显示"运行中"
   ├─ event_bus.publish("run_started") → UI订阅 → 按钮状态切换
   └─ 启动工作线程 _run_loop()
5. _run_loop():
   ├─ 熔断检查（CircuitBreaker）
   ├─ Scheduler.get_next_task() → "yuhun"
   ├─ Monitor.record_task_start("yuhun")  ← 记录指标
   ├─ StateManager.set_state("current_task", "yuhun") → UI刷新
   ├─ event_bus.publish("task_started", task_name="yuhun") → UI刷新
   ├─ task.execute() → TaskGraph.run():
   │   ├─ EnterYuhun.execute(timeout=60) → StepResult(success)  ← 步骤超时保护
   │   │   → event_bus.publish("step_done") → UI刷新进度
   │   │   → Monitor.record_step("enter", "success", 2.3s)  ← 记录步骤指标
   │   ├─ PreCheckTeam.execute() → StepResult(success)
   │   ├─ BattleLoop.execute(times=30) → 循环30轮
   │   │   每轮: Executor.click_image() → Recognizer.find() → AntiDetect.offset() → Connection.click()
   │   │         → AntiDetect.record_operation() → OperationAudit.record()  ← 操作审计
   │   └─ ...
   ├─ Monitor.record_task_done("yuhun", success=True, duration=180s)  ← 记录指标
   ├─ Scheduler.mark_done("yuhun", success=True) → 推进next_run_time → save_state()
   ├─ CircuitBreaker.record_success()  ← 重置熔断计数
   ├─ event_bus.publish("task_done") → UI刷新
   └─ 继续取下一个任务...
6. _cleanup():
   ├─ Monitor.generate_daily_report()  ← 生成运行报告
   ├─ event_bus.publish("run_summary", summary=...)  ← 通知UI
   └─ Scheduler.save_state() + Connection.disconnect()
```

### 4.2 连接断开的处理流程

```
1. HeartbeatMonitor检测到断线
2. ConnectionManager → event_bus.publish("connection_lost")
3. RunController订阅 → 暂停调度循环（设state=paused）
4. StateManager.set_state("connection_status", "disconnected") → UI标红
5. UI StatusBar订阅 → 显示"连接断开"
6. ConnectionManager自动重连（退避1s→2s→4s...）
7. 重连成功 → event_bus.publish("connection_restored")
8. RunController订阅 → 恢复调度循环
9. UI StatusBar → 显示"已连接"
```
