# 10-传参模块（Parameter Bridge Module）

> **类型**：桥梁表现层  ｜  **对应说明书**：（UI↔程序绑定，新形式化层）  ｜  **对应用户模块**：#3 传参模块

---

## 一、目的与作用

**一句话定位**：UI与程序之间的数据桥梁。内部拆分为"配置数据模型层"（定义参数结构）和"UI数据绑定层"（控件↔配置双向同步），实现UI改→配置改→程序读到新值，程序状态变→UI显示更新。

**核心职责**：
1. **参数体系定义**：定义每个任务/模块需要的参数schema（数据模型层）
2. **UI数据绑定**：UI控件与配置数据的双向绑定（绑定层）
3. **参数聚合**：一个任务需要多组参数（定时+阵容+副本），传参模块负责聚合
4. **校验传递**：UI输入的参数校验后传给程序，非法值拦截在UI层

**为什么需要这个模块**：

没有传参模块时，UI直接操作程序逻辑：
- UI按钮直接调用 `scheduler.start()`
- UI输入框直接写 `config.set(...)`
- 程序状态变化需要UI主动轮询刷新

这导致：UI与程序紧耦合，改UI逻辑要动程序代码，改程序接口要动UI代码。

有了传参模块后：
- UI只与传参模块交互（发信号/读绑定数据）
- 传参模块与配置模块/运行控制交互（读写配置/发送控制信号）
- 程序状态变化通过事件总线→传参模块→UI自动刷新

**设计原则**：
- **UI不碰逻辑**：UI控件只与传参模块的数据绑定交互，不直接调用程序模块
- **双向绑定**：UI改→配置改（用户编辑），配置改→UI更新（程序运行态变化）
- **参数聚合**：一个"运行传参"聚合了启停信号+账号选择+任务范围，一次传给程序

## 二、内部拆分

### 2.1 配置数据模型层

定义"一个任务/模块需要哪些参数"的schema：

```python
class TaskParamSchema:
    """任务参数模型。定义一个任务需要的全部参数。"""

    @staticmethod
    def get_schema(task_name: str) -> dict:
        """返回任务的参数schema
        例:
        {
            "enabled": {"type": "bool", "label": "启用", "default": False},
            "priority": {"type": "int", "label": "优先级", "default": 10, "min":1, "max":99},
            "repeat": {"type": "repeat_rule", "label": "执行规则", "default": {...}},
            "next_run_time": {"type": "datetime", "label": "下次执行时间", "readonly": False},
            "times": {"type": "int", "label": "挑战次数", "default": 30},
            "team_id": {"type": "team_select", "label": "阵容预设", "options": [...]},
        }
        """
```

### 2.2 UI数据绑定层

实现控件与配置的双向同步：

```python
class UIBinding:
    """UI控件与配置数据的双向绑定。"""

    def bind_checkbox(self, checkbox: QCheckBox, config_key: str):
        """复选框 ↔ 配置bool值
        - 用户勾选 → config.set(key, True)
        - 配置变更 → checkbox.setChecked(新值)
        """

    def bind_spinbox(self, spinbox: QSpinBox, config_key: str, min_val=None, max_val=None):
        """数字输入框 ↔ 配置int值"""

    def bind_datetime(self, widget, config_key: str):
        """时间选择器 ↔ 配置datetime值"""

    def bind_repeat_editor(self, widget, config_key: str):
        """执行规则编辑器 ↔ 配置repeat字段"""

    def bind_label(self, label: QLabel, state_key: str):
        """标签 ↔ 状态管理器（只读，自动刷新）
        - state_manager.set_state(key, value) → label.setText(新值)
        """
```

## 三、参数模块分类

用户提到"这些需要从外部传入的参数也可以分为几个模块"。传参模块按功能分为：

| 传参子模块 | 绑定UI区域 | 传入程序的数据 | 对应配置 |
|-----------|-----------|---------------|----------|
| **运行传参** | 启动/停止/暂停按钮 | 启停信号 | — |
| **连接传参** | 模拟器连接配置 | ADB路径/端口/设备ID | global.yaml → adb |
| **账号传参** | 账号管理面板 | 主号区服/多开切换 | accounts.yaml |
| **任务优先级传参** | 任务优先级配置 | 各任务priority值 | tasks.yaml |
| **时间规则传参** | 执行规则编辑器 | 各任务repeat字段 | tasks.yaml |
| **阵容传参** | 阵容预设管理 | team_id预设配置 | coords/teams/*.json |
| **防封号传参** | 防封号参数面板 | 安全强度参数 | global.yaml → anti_detect |
| **小号传参** | 小号设置面板 | 小号端口/副本/阵容 | accounts.yaml → sub_accounts |

## 四、实现思路

### 4.1 模块结构

```
ui/
├── param_bridge/
│   ├── __init__.py
│   ├── schemas.py         ← 配置数据模型层（参数schema定义）
│   ├── ui_binding.py      ← UI数据绑定层（控件↔配置双向同步）
│   ├── run_bridge.py      ← 运行传参（启停信号桥接）
│   ├── task_bridge.py     ← 任务参数传参（优先级/规则/阵容）
│   ├── account_bridge.py  ← 账号传参
│   └── config_bridge.py   ← 通用配置传参（连接/防封号/日志）
```

### 4.2 运行传参示例

```python
class RunBridge:
    """运行传参。UI启停按钮 ↔ 运行控制模块，通过事件总线。"""

    def bind_start_button(self, button: QPushButton):
        """启动按钮 → 发布start_requested事件"""
        button.clicked.connect(lambda: event_bus.publish(Events.START_REQUESTED))

    def bind_stop_button(self, button: QPushButton):
        """停止按钮 → 发布stop_requested事件"""
        button.clicked.connect(lambda: event_bus.publish(Events.STOP_REQUESTED))

    def bind_pause_button(self, button: QPushButton):
        """暂停按钮 → 发布pause_requested事件"""
        button.clicked.connect(lambda: event_bus.publish(Events.PAUSE_REQUESTED))

    def bind_status_label(self, label: QLabel):
        """状态标签 ← 订阅run_status状态变化"""
        event_bus.subscribe(Events.STATE_CHANGED,
            handler=lambda key, old_value, new_value:
                label.setText({"running":"运行中","paused":"已暂停",
                               "stopped":"已停止","stopping":"停止中"}.get(new_value, new_value))
                if key == StateKeys.RUN_STATUS else None,
            filter=lambda e: e.data.get("key") == StateKeys.RUN_STATUS)
```

### 4.3 时间规则传参示例

```python
class TaskBridge:
    """任务参数传参。UI任务行 ↔ 配置 + 定时模块。"""

    def bind_task_row(self, task_name: str, row_widget):
        """绑定任务行的所有控件"""
        config = self._config_manager

        # 启用开关
        self._binding.bind_checkbox(
            row_widget.enabled_checkbox,
            f"tasks.{task_name}.enabled"
        )
        # 优先级
        self._binding.bind_spinbox(
            row_widget.priority_spinbox,
            f"tasks.{task_name}.priority",
            min_val=1, max_val=99
        )
        # 执行规则编辑器
        self._binding.bind_repeat_editor(
            row_widget.repeat_editor,
            f"tasks.{task_name}.repeat"
        )
        # 下次执行时间（可编辑）
        self._binding.bind_datetime(
            row_widget.next_run_edit,
            f"runtime.task_state.{task_name}.next_run_time"
        )
        # 倒计时显示（只读，自动刷新）
        self._binding.bind_label(
            row_widget.countdown_label,
            f"runtime.task_state.{task_name}.next_run_time"  # 计算倒计时
        )

    def bind_skip_button(self, task_name: str, button: QPushButton):
        """跳过本次按钮 → 调scheduler.update_next_run推进"""
        button.clicked.connect(lambda: self._scheduler.update_next_run(
            task_name, self._calc_next_period(task_name)
        ))
```

## 五、与其他模块的交互

| 交互方 | 方式 | 说明 |
|--------|------|------|
| UI模块 | 双向 | UI控件通过传参模块绑定配置和状态 |
| 配置模块 | 调用 | 读get()/写set()配置数据 |
| 状态管理 | 订阅 | 订阅state_changed刷新UI只读显示 |
| 事件总线 | 发布/订阅 | 发布控制信号，订阅状态变化 |
| 定时模块 | 调用 | UI修改next_run_time时调update_next_run |
| 运行控制 | 间接 | 通过事件总线传递启停信号 |

## 六、关键设计决策

1. **UI不碰逻辑**：UI控件只与传参模块交互，不直接调用程序模块
2. **内部拆分**：配置数据模型层（定义schema）+ UI数据绑定层（双向同步），职责清晰
3. **参数模块化**：按功能分运行/连接/账号/任务/阵容/防封号/小号等传参子模块
4. **双向绑定**：用户编辑→配置更新；程序状态变→UI自动刷新
5. **事件驱动刷新**：UI只读显示（倒计时/状态）通过订阅事件自动刷新，不轮询
6. **校验在UI层**：非法值在绑定层拦截，不传到程序

## 六、进一步增强（v2.0）

### 6.1 参数变更回滚

用户修改配置后提供"撤销"能力，避免误操作后无法恢复：

```python
class UIBinding:
    def __init__(self):
        self._undo_stack: list[tuple] = []  # (config_key, old_value, new_value)

    def set_config(self, key: str, value):
        old = config.get(key)
        self._undo_stack.append((key, old, value))
        config.set(key, value)

    def undo(self):
        """撤销上一次配置修改"""
        if self._undo_stack:
            key, old, new = self._undo_stack.pop()
            config.set(key, old)
            monitor.info(f"撤销配置修改: {key} {new}→{old}", module="param_bridge")

    def can_undo(self) -> bool:
        return len(self._undo_stack) > 0
```

### 6.2 批量参数编辑

支持批量编辑多个任务的同类参数（如一次性修改所有日常任务的执行时间）：

```python
class TaskBridge:
    def batch_set(self, task_names: list, key: str, value):
        """批量修改多个任务的同一参数"""
        for name in task_names:
            config.set(f"tasks.*.{name}.{key}", value)
        monitor.info(f"批量修改{len(task_names)}个任务的{key}={value}",
                    module="param_bridge", tags=["batch"])
```

### 6.3 参数预设

常用参数组合保存为预设，一键应用（如"快速刷取模式"=关闭安全+减少延迟+增加次数）：

```python
class ParamPreset:
    """参数预设管理。保存/加载常用参数组合。"""

    def save_preset(self, name: str, params: dict):
        """保存当前参数组合为预设"""
        config.set(f"presets.{name}", params)

    def apply_preset(self, name: str):
        """应用预设"""
        params = config.get(f"presets.{name}")
        if params:
            for key, value in params.items():
                config.set(key, value)
            monitor.info(f"应用参数预设: {name}", module="param_bridge")

    def list_presets(self) -> list[str]:
        """列出所有预设"""
        return list(config.get("presets", {}).keys())
```
