# 05-时间调度模块（Time Scheduling Module）

> **类型**：核心运行层  ｜  **对应说明书**：Scheduler 5.9  ｜  **对应用户模块**：#1 定时模块

---

## 一、目的与作用

**一句话定位**：时间调度引擎。根据每个任务的执行规则和 next_run_time，提供**批量到期查询**能力，供运行控制中心的队列填充线程使用。

**与运行控制中心的职责拆分**：
- **运行控制中心**：生命周期管理——维护任务队列、驱动执行
- **时间调度模块**：纯调度——只回答"哪些任务已到期"

**核心职责**：
1. **时间规则管理**：解析每个任务的执行规则（7种类型）
2. **next_run_time 机制**：到期判据（当前时间 ≥ next_run_time + 时间窗口 + 活动有效期）
3. **批量到期查询**：返回当前所有到期任务列表，供队列填充线程入队
4. **执行推进**：执行成功后按规则推进 next_run_time，失败不推进
5. **状态持久化**：task_state.json 原子写盘，重启恢复
6. **次数控制**：times / max_daily / max_total / cooldown / today_count
7. **活动有效期**：支持任务仅在指定日期范围内执行（如活动期间）
8. **定时启停**：支持设置全局运行时段（如 8:00~23:00），超出时段自动暂停/停止
8. **每日时间窗口**：支持任务仅在每天特定时段内执行（如仅14-18点可做）

**设计原则**：
- **纯调度职责**：只回答"哪些任务已到期"，不关心队列和执行状态
- **失败不推进**：临时失败不推进 next_run_time，保持到期可重试
- **持久化优先**：每次状态变更立即原子写盘，重启不丢失

## 三、运行逻辑

### 3.1 到期判据（三重条件）

任务可执行的条件同时满足以下三项：

1. **时间已到**：当前时间 ≥ `next_run_time`
2. **在每日时间窗口内**：当前时间在 `window` 范围内（如 `["14:00", "18:00"]`）。未设置则全天可执行
3. **在活动有效期内**：当前日期在 `active_range` 范围内（如 `["2026-07-20", "2026-08-05"]`）。未设置则永久有效

三项全部满足才算到期，缺一不可。

### 3.2 日程表生成（build_schedule）

`build_schedule()` 是核心调度接口，由 ScriptWorker（运行控制）调度循环调用：

```
检查每日重置
  → 扫描所有启用任务
  → 对每个任务：
      is_due() 判断是否到期（next_run_time + 时间范围 + 活动日期）
      check_times_limit() 检查次数上限
  → 过滤掉未到期 / 达上限的任务
  → 按时 priority 升序 → 同优先级按 category 顺序排序
  → 发布 SCHEDULE_UPDATED 事件到 UI
  → 返回排序后的日程列表
```

返回列表中的每项包含：`name`, `priority`, `category`, `next_run` 等信息。

`get_next_task()` 内部调用 `build_schedule()`，返回第一个到期任务名（`Optional[str]`）。

### 3.3 八种执行规则

| 规则类型 | 说明 | 推进规则 | 配合使用 |
|---------|------|---------|---------|
| **daily** | 每日指定时间范围 | 推进到次日 time_start | time_start / time_end / max_daily |
| **weekly** | 指定星期几 | 推进到下周匹配的星期几 | weekdays / time_start / time_end |
| **monthly_start** | 每月1号 00:00 | 推进到下月1号 | max_daily |
| **interval_days** | 每N天 | 推进 N 天后 | time_start / max_total |
| **interval_hours** | 每N小时 | 推进 N 小时后 | max_daily |
| **once** | 单次执行 | 完成后标记不再调度 | at（ISO时间） |
| **expire_at** | 外部上报失效时间 | 不自动推进 | — |
| **special** | 活动限定 | 同 daily | window.date_start / window.date_end |

### 3.4 推进规则

执行成功后按规则推进 next_run_time。失败时添加递增冷却（5→10→15...最多60分钟）。
成功后 `fail_streak` 归零。

### 3.5 活动时间范围

- **daily/weekly**：`time_start` / `time_end` 限制每日执行时段
- **special**：`window.date_start` / `window.date_end` 限制活动日期范围
- 两者可同时设置，取交集

示例：
- `active_range = ["2026-07-20", "2026-08-05"]`（夏境巡游活动）
- `window = ["14:00", "18:00"]`（仅每天下午开启）
- `repeat = "interval_hours", interval = 2`（每2小时可做一次）

→ 任务仅在 7月20日~8月5日 的 14:00-18:00 之间，每2小时可执行一次。超出活动日期或不在时段内均不可执行。

### 3.6 多任务冲突处理

同一时段多个任务同时到期时，按优先级从高到低依次执行，低优先级任务自动排入后续队列。

## 四、重点功能

### 4.1 纯调度解耦

定时模块只负责任务调度计算，不涉及运行生命周期。运行控制模块驱动调度循环，定时模块提供数据查询。各自的职责边界清晰。

### 4.2 失败不推进

任务执行失败不会推进 next_run_time，保持到期状态可供下次重试。防止因临时故障跳过了每日任务。

### 4.3 原子持久化

每次状态变更写临时文件 → 原子替换原文件，崩溃不损坏已有数据。重启后从 task_state.json 恢复所有任务的 next_run_time 和今日计数。

### 4.4 活动有效期（active_range）

每个任务可设置 `active_range` 指定执行日期范围，如 `["2026-07-20", "2026-08-05"]`。超出有效期的任务自动跳过，不参与到期查询。适合限时活动场景：活动期间自动执行，活动结束自动停止。

### 4.5 每日时间窗口（window）

每个任务可设置 `window` 指定每日可执行时段，如 `["14:00", "18:00"]`。不在时段内的任务即使 `next_run_time` 已到也不执行。适合仅特定时段开放的活动。

### 4.6 活动日历导入

支持导入游戏活动日历，自动为限时活动创建/更新任务配置：

- `import_calendar(events)` 接收活动事件列表，每个事件包含：名称、开始日期、结束日期、每日窗口、任务类型
- 自动将活动期内的任务 `active_range` 设为活动日期范围
- 活动结束后自动移除或禁用对应任务
- 日历数据可通过 UI 手动导入或从预设文件加载

### 4.7 每日重置

凌晨 00:00 自动重置所有任务的 today_count，与阴阳师游戏重置时间保持一致。

## 五、实现思路

### 5.1 模块结构

```
core/
├── scheduler.py          ← 调度引擎主入口 Scheduler
├── repeat_rule.py        ← RepeatRule 执行规则定义与推进逻辑
├── task_state.py         ← TaskState 执行记录持久化
└── schedule.py           ← 日程表生成与排序
```

### 5.2 核心方法定义

**Scheduler（调度引擎主入口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `load_tasks_from_config() -> None` | 🔓 公开 | `Scheduler` | 从 tasks.yaml 加载所有任务并注册 |
| `load_state() -> None` | 🔓 公开 | `Scheduler` | 从 task_state.json 恢复执行记录 |
| `save_state() -> None` | 🔓 公开 | `Scheduler` | 原子写盘保存状态 |
| `build_schedule() -> list[dict]` | 🔓 公开 | `Scheduler` | 生成完整日程表（排序+过滤），发布 SCHEDULE_UPDATED |
| `get_next_task() -> Optional[str]` | 🔓 公开 | `Scheduler` | 获取下一个到期任务名（内部调用 build_schedule） |
| `get_all_tasks() -> list[dict]` | 🔓 公开 | `Scheduler` | 获取所有已注册任务（供 UI 展示） |
| `mark_done(task_name, success) -> None` | 🔓 公开 | `Scheduler` | 标记任务完成，成功推进 next_run_time，失败添加冷却 |
| `is_due(task_name, now=None) -> bool` | 🔓 公开 | `Scheduler` | 判断任务是否到期（next_run_time + 时间范围 + 日期范围） |
| `check_times_limit(task_name) -> bool` | 🔓 公开 | `Scheduler` | 检查任务是否未达次数上限 |
| `update_next_run(task_name, next_run_time) -> None` | 🔓 公开 | `Scheduler` | 手动设置 next_run_time |
| `get_next_run_time(task_name) -> Optional[datetime]` | 🔓 公开 | `Scheduler` | 查询任务的 next_run_time |
| `reset_daily_counters() -> None` | 🔓 公开 | `Scheduler` | 每日00:00重置 today_count |
| `import_calendar(events) -> None` | 🔓 公开 | `Scheduler` | 导入游戏活动日历，自动更新任务 active_range |

**RepeatRule（执行规则）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `next_after(from_time) -> datetime` | 🔓 公开 | `RepeatRule` | 根据规则类型，计算 from_time 之后的下次执行时间 |
| `is_expired(now) -> bool` | 🔓 公开 | `RepeatRule` | once 类型是否已完成 |

### 5.3 核心流程

**get_next_task 调用链路**：
```
填充线程调 get_next_task()
  → 内部调用 build_schedule()
  → 遍历 _tasks 所有启用任务
  → 对每个任务：
      is_due() 三重判据：
        → now ≥ next_run_time？
        → now 在 window 内？（未设 window 则通过）
        → now 在 active_range 内？（未设 active_range 则通过）
      check_times_limit() → today_count < max_daily
  → 过滤掉未到期 / 超出 window / 超出 active_range / 达上限的任务
  → 按 priority 升序 → 同优先级按 category（daily > permanent > special > event）
  → 发布 SCHEDULE_UPDATED 事件到 UI
  → 返回排序后的日程列表中的第一个任务名（Optional[str]）
```

**mark_done 推进链路**：
```
执行线程调 mark_done(name, success=True)
  → 根据任务的 RepeatRule 类型计算下一次执行时间：
      once → 标记 completed，不再调度
      daily → 次日 at_time
      weekly → 下周匹配的 weekday 的 at_time
      monthly → 下月匹配的 month_day 的 at_time
      interval_days → N 天后 at_time
      interval_hours → now + N 小时
      expire_at → 不推进，等待 report_expire()
  → 更新 _next_run[name]
  → 自增 _today_count[name]
  → 调用 save_state() 持久化

mark_done(name, success=False)
  → 不推进 _next_run[name]（保持原到期状态）
  → 调用 save_state() 持久化
```

**is_due 判据链路**：
```
is_due(name)
  → 获取任务的 next_run_time
  → 条件一：now ≥ next_run_time？→ 否则返回 False
  → 条件二：任务有 window？→ now 在 [window_start, window_end] 内？→ 否则返回 False
  → 条件三：任务有 active_range？→ now 在 [active_start, active_end] 内？→ 否则返回 False
  → 全部通过 → 返回 True
```

### 5.4 关键设计

- **next_run_time 核心判据**：解决"做过不再重复做"的问题，重启不丢失
- **三重判据**：next_run_time + window + active_range，精确控制"何时可做"+"何时段允许"+"活动期间才可做"
- **window 每日时间窗口**：限制任务仅在每天特定时段可执行，适合限时活动
- **active_range 活动有效期**：限制任务仅在指定日期范围内执行，活动结束自动停止
- **失败不推进**：临时失败不推进 next_run_time，保持到期可重试
- **原子持久化**：写临时文件 → 替换原文件，崩溃不损坏已有数据
- **每日重置**：凌晨00:00自动重置所有任务的 today_count
