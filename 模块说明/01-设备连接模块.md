# 01-设备连接模块（Device Connection Module）

> **类型**：核心运行层  ｜  **对应说明书**：ADBClient 5.1 + EmulatorManager  ｜  **对应用户模块**：#8 连接模块

---

## 一、目的与作用

**一句话定位**：封装模拟器ADB连接与底层设备操作，对上层完全屏蔽ADB命令细节，统一连接错误的抛出口。是整套系统最底层的"手和眼"。

**核心职责**：
1. **连接管理**：建立/断开/检测ADB连接，支持多模拟器多开（每个账号绑定独立端口）
2. **设备操作**：截图、点击、滑动、按键——最底层的硬件操作
3. **状态监控**：心跳检测连接是否存活，断线时通过事件总线广播
4. **自动重连**：断线后按退避策略尝试恢复连接
5. **错误出口**：所有连接相关异常统一从此模块抛出

**设计原则**：
- 最底层的执行器，不包含任何业务逻辑
- 截图返回原始图像数据，不做识别（识别归识图模块）
- 点击只接受坐标参数，不做防封号偏移（防封号归安全模块）
- 严格只读模拟器设置，禁止修改模拟器系统配置

## 三、运行逻辑

### 3.1 连接生命周期

```
建立连接：检测ADB路径 → 连接设备 → 验证连通性 → 获取屏幕信息 → 记录活动设备
                                                    失败 → 抛出连接异常

断开连接：停止心跳 → 断开ADB会话 → 清理设备池 → 更新连接状态

切换设备：保存当前设备上下文 → 从连接池获取目标设备 → 切换活动设备引用
                                              无目标 → 新建连接
```

### 3.2 心跳检测

后台线程定期（默认30秒）执行连通性检查。检测到断线时：发布 `connection_lost` 事件 → 按退避策略尝试重连（1s→2s→4s→8s→16s，最多5次）→ 重连成功发布 `connection_restored` 事件，失败发布 `connection_error` 事件。

### 3.3 多开切换

维护多设备连接池，AccountManager 切换账号时调用切换设备接口，从池中取出该账号绑定的模拟器连接。连接池支持预热，可在启动时提前建立所有账号的连接，切换时瞬间完成。

### 3.4 连接质量监控

记录每次截图/点击/滑动的响应延迟，保留最近100次历史数据。平均延迟超过2秒时通过事件总线告警。综合延迟、成功率、心跳等指标计算连接健康度（0-100分），低于50分时主动触发重连。

## 四、重点功能

### 4.1 统一错误出口

所有连接异常（ADB未找到、设备离线、连接超时、命令执行失败等）统一封装为 DeviceConnectError，上层模块只需捕获此异常即可处理所有连接问题。

### 4.2 自动重连与退避

断线后自动尝试重连，每次间隔递增（1s→2s→4s→8s→16s），最多5次。重连期间通过事件总线通知各模块，运行控制模块可据此暂停调度。

### 4.3 截图优化

使用 `adb exec-out screencap -p` 直接输出二进制流，避免文件IO开销，减少截图延迟。

### 4.4 连接池预热

多开场景下提前建立所有账号的连接，账号切换时无需等待。预热在 AccountManager 初始化时触发。

## 五、实现思路

### 5.1 模块结构

```
device/
├── connection.py        ← ConnectionManager 连接模块主入口
├── adb_client.py        ← ADB底层操作（命令封装）
├── emulator.py          ← 模拟器管理（路径检测、端口管理）
└── heartbeat.py         ← HeartbeatMonitor 心跳检测子模块
```

### 5.2 核心方法定义

**ConnectionManager（连接模块主入口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `connect(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | 建立连接，未指定则连接默认设备 |
| `disconnect(device_id) -> None` | 🔓 公开 | `ConnectionManager` | 断开指定设备连接 |
| `is_connected(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | 检测连接状态 |
| `switch_device(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | 切换操作目标设备（多开账号切换时调用） |
| `screenshot() -> np.ndarray` | 🔓 公开 | `ConnectionManager` | 截图，返回 OpenCV 格式图像 |
| `click(x, y) -> None` | 🔓 公开 | `ConnectionManager` | 坐标点击（仅坐标，不含防封号偏移） |
| `swipe(x1,y1,x2,y2,duration) -> None` | 🔓 公开 | `ConnectionManager` | 滑动操作 |
| `input_key(key) -> None` | 🔓 公开 | `ConnectionManager` | 模拟按键输入（如 KEYCODE_BACK） |
| `get_screen_size() -> tuple` | 🔓 公开 | `ConnectionManager` | 获取屏幕分辨率（只读） |
| `launch_app(package, activity) -> bool` | 🔓 公开 | `ConnectionManager` | 启动 App |
| `is_app_foreground(package) -> bool` | 🔓 公开 | `ConnectionManager` | App 是否在前台 |
| `start_heartbeat(interval) -> None` | 🔓 公开 | `ConnectionManager` | 启动心跳检测线程 |
| `stop_heartbeat() -> None` | 🔓 公开 | `ConnectionManager` | 停止心跳检测 |
| `reconnect(device_id) -> bool` | 🔓 公开 | `ConnectionManager` | 尝试重连（按退避策略） |

**HeartbeatMonitor（心跳检测）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `start(interval) -> None` | 🔓 公开 | `HeartbeatMonitor` | 启动心跳检测线程 |
| `stop() -> None` | 🔓 公开 | `HeartbeatMonitor` | 停止心跳检测 |

### 5.3 核心流程

**截图流程**：
```
screenshot()
  → 委托当前 ADBClient
  → 执行 adb exec-out screencap -p（二进制流输出）
  → 解析为 OpenCV 图像（numpy 数组）
  → 记录本次截图延迟到 _quality_records
  → 返回图像数据
```

**点击流程**：
```
click(x, y)
  → 委托当前 ADBClient
  → 执行 adb shell input tap x y
  → 记录本次点击延迟到 _quality_records
  → 返回
```

**连接检测流程**：
```
心跳线程定期执行（默认30秒）
  → 执行连通性检测命令
  → 成功 → 等待下一周期
  → 失败 → 发布 connection_lost 事件
        → 执行退避重连（1s→2s→4s→8s→16s，最多5次）
        → 成功 → 发布 connection_restored 事件
        → 失败 → 发布 connection_error 事件
```

### 5.4 关键设计

- **只读模拟器**：严格遵守用户权限边界，禁止 wm size/density 等写操作
- **ADB 路径自动检测**：MuMu 自带 adb 优先，找不到则 fallback 到系统 PATH
- **截图优化**：使用 `adb exec-out screencap -p` 直接输出二进制流，避免文件 IO
- **异常统一出口**：所有连接错误抛 DeviceConnectError，上层统一捕获
- **心跳退避重连**：断线后按指数退避重试
