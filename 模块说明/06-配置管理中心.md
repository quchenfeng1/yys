# 06-配置管理中心（Configuration Center）

> **类型**：支撑服务层  ｜  **对应说明书**：ConfigManager 5.5  ｜  **对应用户模块**：#5 配置模块

---

## 一、目的与作用

**一句话定位**：配置数据中心。统一加载/管理/持久化所有 YAML/JSON 配置，提供点分路径读写接口，不涉及任何运行逻辑判断。

**核心职责**：
1. **配置加载**：启动时加载 global.yaml / tasks.yaml / accounts.yaml / coords/*.json
2. **统一访问**：提供点分路径读写接口，所有模块统一经由本模块访问配置
3. **持久化**：配置变更后立即原子写盘，重启不丢失
4. **热重载**：支持重新读取配置文件，外部修改后同步
5. **校验**：配置值类型/范围校验，非法值告警但不阻断

**设计原则**：
- **纯数据，不判断**：只读写数据，不做业务判断（那归运行控制模块）
- **单一数据源**：所有模块统一经此模块读取配置，避免不一致
- **原子持久化**：写临时文件 → 替换原文件，避免写盘中断损坏

## 三、运行逻辑

### 3.1 配置加载流程

```
启动时 → 按顺序加载各配置文件
  → 检查版本号，执行自动迁移（如有）
  → 校验配置合法性（类型/范围检查）
  → 建立点分路径索引
  → 初始化文件监听器（热重载）
  → 就绪
```

### 3.2 配置访问流程

```
调用 get("global.adb.port")
  → 检查点分路径索引缓存（O(1) 查找）
      ├── 命中 → 直接返回缓存值
      └── 未命中 → 从内存配置 _cache 中逐层查找
           → 将结果写入索引缓存
           → 返回对应值或 default
```
  → 支持三级覆盖：task级 > account级 > global级
```

### 3.3 配置持久化流程

```
调用 set("tasks.yuhun.priority", 5)
  → 更新内存配置
  → 定位所属配置文件（tasks.yaml）
  → 写临时文件 → os.replace 替换原文件
  → 发布 config_changed 事件
```

### 3.4 三级分层覆盖

配置支持三级覆盖（优先级从高到低）：
1. **task级**：`tasks.{category}.{task}.{key}` — 单个任务专属配置
2. **account级**：`accounts.{account}.{key}` — 某个账号专属配置
3. **global级**：`global.{key}` — 全局默认配置

读取时自动按优先级查找，取最先匹配到的值。

## 四、重点功能

### 4.1 点分路径访问

统一使用点分路径访问所有配置，如 `global.adb.port`、`tasks.permanent.yuhun.priority`。不再需要直接操作 yaml/json 数据结构。

### 4.2 任务配置自动合并

`get_task_config(task_name)` 将 tasks.yaml（编排配置）和 coords/{name}.json（坐标配置）合并返回，一次调用获取完整配置。

### 4.3 热重载

配置文件被外部修改后自动重新加载，无需重启程序。也可手动调用 reload() 同步。

### 4.4 配置版本迁移

配置文件带版本号，程序升级后自动检测版本差异并执行迁移，兼容历史配置文件格式。

### 4.5 配置导入导出

支持将全套配置打包为 zip 备份，或从备份恢复。可选择覆盖模式或仅补充模式。

### 4.6 配置变更审计

每次 `set()` 操作自动记录审计日志：

| 审计字段 | 说明 |
|---------|------|
| `timestamp` | 变更时间 |
| `key_path` | 被修改的配置路径 |
| `old_value` | 修改前的值 |
| `new_value` | 修改后的值 |
| `source` | 变更来源（UI/任务/模块名） |

审计日志通过 **12-日志监控中心** 持久化存储，支持按时间/路径/来源检索。用于问题排查和变更回溯。

### 4.7 全局运行时配置

以下全局配置项由 **09-运行控制中心** 读取，控制脚本的运行行为：

| 配置路径 | 类型 | 说明 | 示例 |
|---------|------|------|------|
| `global.run_window` | `list[str]` | 每日运行时段，空则不限制 | `["08:00", "23:00"]` |
| `global.scheduled_start` | `str \| null` | 定时启动时间 | `"06:00"` |
| `global.scheduled_stop` | `str \| null` | 定时停止时间 | `"23:00"` |
| `global.notification` | `dict` | 通知方式配置 | `{desktop: true, sound: false, webhook: null}` |
| `global.teaming` | `dict` | 组队配置（等待超时、重试次数等） | `{wait_timeout: 30, max_retries: 3}` |

## 五、实现思路

### 5.1 模块结构

```
core/
├── config_manager.py     ← 配置管理主入口
└── config_schema.py      ← 配置 Schema 定义与校验
```

### 5.2 核心方法定义

**ConfigManager（配置管理中心）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `get(key_path, default) -> Any` | 🔓 公开 | `ConfigManager` | 点分路径读取配置值 |
| `set(key_path, value) -> None` | 🔓 公开 | `ConfigManager` | 设置配置值并原子持久化 |
| `get_section(section) -> dict` | 🔓 公开 | `ConfigManager` | 读取整个配置段 |
| `get_task_config(name) -> dict` | 🔓 公开 | `ConfigManager` | 读取完整任务配置（合并编排+坐标） |
| `get_coords(scene) -> dict` | 🔓 公开 | `ConfigManager` | 读取场景坐标 |
| `reload() -> None` | 🔓 公开 | `ConfigManager` | 手动热重载所有配置 |
| `load() -> None` | 🔓 公开 | `ConfigManager` | 加载并解析全部配置文件（初始化时调用） |
| `validate() -> list[str]` | 🔓 公开 | `ConfigManager` | 校验所有配置，返回错误列表 |
| `export_config(path) -> None` | 🔓 公开 | `ConfigManager` | 导出全套配置为 zip 备份 |
| `import_config(path) -> None` | 🔓 公开 | `ConfigManager` | 从 zip 备份恢复配置 |

### 5.3 核心流程

**配置加载流程**：
```
启动 → 按序加载 global.yaml / tasks.yaml / accounts.yaml / coords/*.json
  → 检查 _version，执行自动迁移（如有）
  → validate() 校验合法性（类型/范围检查）
  → 建立点分路径索引到 _cache
  → 启动 _watcher 文件监听线程
  → 就绪
```

**配置读取流程**：
```
get("global.adb.port")
  → 解析点分路径 ["global", "adb", "port"]
  → 从 _cache 中逐层查找
  → 找到则返回对应值，未找到返回 default
  → 支持三级覆盖：task级 > account级 > global级
```

**配置写入流程**：
```
set("tasks.yuhun.priority", 5)
  → 更新 _cache 内存配置
  → 定位所属配置文件（tasks.yaml）
  → 写临时文件 → os.replace 替换原文件
  → 发布 config_changed 事件到事件总线
```

### 5.4 关键设计

- **纯数据职责**：只读写，不判断业务逻辑
- **原子写盘**：写临时文件 → os.replace 替换，崩溃不损坏
- **校验可选**：validate() 返回错误列表，非法配置只告警不阻断
- **三级覆盖**：task级 > account级 > global级，自动按优先级查找
