# 14-日程表视图模块（Schedule View Module）★v2.4 从 05-定时模块 拆出

> **类型**：桥梁表现层（UI 面板）  ｜  **对应说明书**：11.3.1  ｜  **对应模块**：从 05-定时模块 + 11-UI模块 拆出

---

## 一、目的与作用

**一句话定位**：Scheduler 日程表数据的可视化呈现。从 05-定时模块（Scheduler）获取数据，通过 11-UI模块 的任务队列面板（TaskQueuePanel）展示。

**为什么拆出**：

原 05-定时模块（Scheduler）既负责"计算何时执行哪个任务"又隐含"日程表的生成与排序"。v2.4 将日程表的**可视化管理**职责明确拆出：

| 职责 | 归属 |
|------|------|
| RepeatRule 规则定义 | 05-定时模块 |
| next_run_time 计算与推进 | 05-定时模块 |
| 日程表生成（过滤+排序） | 05-定时模块 → `build_schedule()` |
| 日程表数据存储 | 07-状态管理模块 → `SCHEDULE_QUEUE` |
| **日程表可视化展示** | **14-日程表视图模块** → `TaskQueuePanel` |

---

## 二、数据流

```
Scheduler.build_schedule()
  → 过滤启用任务 + is_due() + check_times_limit()
  → 按 priority → default_order 排序
  → 返回 [{name, priority, category, next_run}, ...]
  → StateManager.set_state("schedule_queue", queue)
  → EventBus.publish("schedule_updated", queue=...)
  → TaskQueuePanel._on_schedule_updated()
  → 重建当前任务卡片 + 队列小方块
```

| 属性 | 大卡片 (compact=False) | 小卡片 (compact=True) |

### 3.3 刷新机制

```
事件: schedule_updated → 重建队列卡片
事件: task_started    → 更新当前任务为大卡片
事件: task_done       → 清除当前卡片 + 刷新队列
```
