# 模块设计书规范

> 本文档定义项目中所有模块说明文件的统一格式、内容要求和编写规范。所有模块设计书必须遵循本规范。

---

## 一、文件命名规范

### 1.1 命名格式

```
{序号}-{模块名称}.md
```

| 要素 | 规则 | 示例 |
|------|------|------|
| 序号 | 两位数字，按逻辑依赖排序 | `01`、`02`、`13` |
| 模块名称 | 4~8个中文字，精准描述功能 | `设备连接模块`、`运行控制中心` |
| 后缀 | `.md` | — |

## 二、文件结构规范

每个模块设计书必须包含以下 **6个章节**，顺序固定。

### 2.1 章节总览

```
# {序号}-{模块名称}（{英文名称}）

> **类型**：{层类型} ｜ **对应说明书**：{参考章节} ｜ **说明**：{一句话定位}

---

## 一、目的与作用

## 二、模块属性与依赖

## 三、运行逻辑

## 四、重点功能

## 五、实现思路

## 六、使用方法（模块间交互）
```

### 2.2 章节内容要求

#### 一、目的与作用

| 子要素 | 必填 | 内容 |
|--------|------|------|
| **一句话定位** | ✅ | 用一句话概括模块的核心职责（50字内） |
| **核心职责** | ✅ | 5~10条，以编号列表列出 |
| **设计原则** | ✅ | 4~8条，以列表列出，每条是一个设计决策 |

#### 二、模块属性与依赖

必须包含三个子节：

**1. 依赖注入（外部模块引用）** — 若模块不依赖其他模块则填"无"
```
| 属性名 | 类型 | 作用域 | 作用 |
|--------|------|--------|------|
| `_xxx` | `XxxModule` | 🔒 私有 | 说明用途 |
```
- 作用域标记：🔒 私有（仅模块内部使用）

**2. 对外暴露属性（其他模块可读取）**
```
| 属性名 | 类型 | 作用域 | 说明 |
|--------|------|--------|------|
| `xxx` | `str` | 📖 只读对外 | 说明用途 |
```
- 作用域标记：📖 只读对外（其他模块可通过状态管理或接口读取）
- 列表只包含被其他模块引用的属性，纯内部属性不在此列

**3. 内部私有属性**
```
| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_xxx` | `类型` | 说明用途 |
```
- 按功能分组列出（如：线程同步原语、队列数据结构、线程引用、状态计数）
- 所有属性名以 `_` 开头，表示私有

#### 三、运行逻辑

描述模块的核心运行流程。要求：

- 用 **自然语言 + 流程图（ASCII或Mermaid）** 描述
- 关键路径用步骤编号 `1. 2. 3. ...` 清晰列出
- 涉及状态转换的必须画状态机
- 涉及多线程的必须说明线程间的协作方式
- **异常恢复流程也必须用步骤编号列出**，不能仅用表格描述
- 如果有异常/边界情况，在最后用"关键规则"列出

#### 四、重点功能

列出该模块最核心的 3~6 个功能亮点。每个功能用一段话说明：

```
### 4.1 {功能名称}

{功能说明}。{解决了什么问题}。{有什么优势}。
```

#### 五、实现思路

包含三个子节：

**1. 模块结构**
```
{项目目录}/
├── {文件名}.py       ← {作用说明}
├── {文件名}.py       ← {作用说明}
└── {文件名}.py       ← {作用说明}
```

**2. 核心方法定义**

从程序实现角度列出所有主要方法。按类分组：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `method(args) -> ReturnType` | 🔓 公开/🔒 私有/🔒 保护 | `ClassName` | 说明用途 |

- 可见性标记：🔓 公开（public）/ 🔒 私有（private）/ 🔒 保护（protected）

**3. 核心流程**

用步骤编号列出模块的关键执行链路：启动链路、运行链路、停止链路（若适用）。

**4. 关键设计**

列出 3~6 条关键设计决策，每条一句话。

#### 六、使用方法（模块间交互）

**1. 外部提供的调用接口**

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `接收 xxx 事件` | `模块名` | 说明 |

**2. 对外部模块的调用**

| 被调用方 | 调用方式 | 说明 |
|---------|---------|------|
| **模块名** | 调用/订阅/读写 | 说明 |

## 三、属性与类型规范

### 3.1 类型标注

所有属性必须标注类型。支持的类型：

| 类型 | 示例 | 说明 |
|------|------|------|
| 基础类型 | `str`、`int`、`float`、`bool` | Python 标准类型 |
| 枚举 | `RunState`、`TaskStatus` | 自定义枚举 |
| 容器 | `list[str]`、`dict[str, Any]`、`set[str]` | 泛型标注 |
| 可选 | `str \| None`、`datetime \| None` | 可为 null 的字段 |
| 模块引用 | `Scheduler`、`EventBus` | 其他模块的类名 |
| 线程原语 | `Event`、`Lock`、`Thread` | 不带包路径，用简单类名 |
| 数据结构 | `deque[TaskInfo]` | 带泛型参数 |
| 回调 | `callable` | 函数引用 |

> ⚠️ **类型名规则**：使用简单类名，**不带包路径**。如 `Event` 而非 `threading.Event`，`Lock` 而非 `threading.Lock`。包路径是代码实现细节，设计书中无需体现。

### 3.2 作用域标记

| 标记 | 含义 | 说明 |
|------|------|------|
| 🔓 公开 | 对外公开的方法或属性 | 其他模块可直接调用 |
| 🔒 私有 | 模块内部使用 | 其他模块不可直接访问 |
| 🔒 保护 | 子类可访问 | 仅在继承体系中使用 |
| 📖 只读对外 | 其他模块可读取但不可修改 | 通过属性访问器或状态管理读取 |

### 3.3 命名规范

| 类别 | 规范 | 示例 |
|------|------|------|
| 公有方法 | `snake_case` | `get_due_tasks()` |
| 私有方法 | `_snake_case` | `_filler_loop()` |
| 公有属性 | `snake_case` | `run_status` |
| 私有属性 | `_snake_case` | `_fifo_queue` |
| 类名 | `PascalCase` | `TaskGraph`、`RunController` |
| 枚举值 | `SCREAMING_SNAKE_CASE` | `SUCCESS`、`FAIL` |
| 常量 | `SCREAMING_SNAKE_CASE` | `DEFAULT_TIMEOUT` |

## 四、内容规范

### 4.1 禁止内容

- ❌ **禁止出现 Python 代码块**（\`\`\`python）。设计书是设计文档，不是代码实现。用自然语言、表格、流程图代替
- ❌ **禁止出现文件行号引用**（如 "Lines 45-60 omitted"）
- ❌ **禁止出现实现细节的 API 名称**（如 `threading.Event`、`os.replace`）。用概念描述代替：如"停止信号"、"原子写盘"

### 4.2 推荐内容

- ✅ **表格**：属性定义、方法定义、接口列表
- ✅ **ASCII 流程图**：多线程协作、执行链路
- ✅ **编号列表**：步骤流程、关键规则
- ✅ **对比表格**：职责拆分、状态转换

### 4.3 设计原则检查清单

每个模块设计书在完成后应检查：

- [ ] 章节结构是否完整（6个章节）
- [ ] 是否包含了"依赖注入"子节（即使为空）
- [ ] 对外暴露属性是否标注了作用域
- [ ] 运行逻辑是否包含流程图或步骤编号
- [ ] 核心方法是否标注了可见性
- [ ] 无 Python 代码块
- [ ] 文件名是否符合 `{序号}-{名称}.md` 格式

## 五、模块间交互规范

### 5.1 通信方式

模块间通信只能通过以下三种方式：

| 方式 | 适用场景 | 示例 |
|------|---------|------|
| **直接调用** | 明确的数据请求 | 填充线程调 `scheduler.get_due_tasks()` |
| **事件总线** | 解耦通知 | UI 发布 `stop_requested`，运行控制中心订阅 |
| **状态管理** | 共享状态读写 | 运行控制中心写 `run_status`，UI 读取展示 |

### 5.2 分层调用方向

```
桥梁表现层（UI / 参数桥接 / 用户界面）
    ↕ 事件总线 + 传参模块
支撑服务层（配置 / 状态 / 事件 / 运行控制 / 日志）
    ↕ 直接调用
核心运行层（连接 / 识别 / 防封 / 任务 / 定时）
```

- **上层可以调用下层**，但下层不能调用上层
- **同层之间通过事件总线通信**，避免直引用
- **支撑服务层**是整个系统的枢纽，连接表现层和核心运行层
