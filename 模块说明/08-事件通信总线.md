# 08-事件通信总线（Event Communication Bus）

> **类型**：支撑服务层  ｜  **对应说明书**：（新概念）  ｜  **说明**：解耦新增，模块间通信枢纽

---

## 一、目的与作用

**一句话定位**：模块间通信枢纽。采用发布-订阅模式，模块间不直接持有对方引用，通过事件总线间接通信，实现真正的解耦。

**为什么需要这个模块**：

没有事件总线时，模块间是网状直接调用（如 UI → RunController → Scheduler → Task → Connection），增删模块需修改所有相关代码。

有了事件总线后，发布者不关心谁订阅，订阅者不关心谁发布。增删模块只需增删订阅，不改现有代码。

```
用户点"停止" → UI 发布 "stop_requested"
  → RunController 订阅后执行停止逻辑
  → Scheduler 订阅后暂停调度
  → Task 订阅后中止当前步骤
  → Connection 订阅后断开连接
```

**核心职责**：
1. **事件发布**：发布事件，不关心谁在处理
2. **事件订阅**：订阅事件，支持按条件过滤
3. **线程安全**：跨线程发布/订阅（UI线程与工作线程通信）
4. **事件历史**：可选记录事件历史，便于调试

**设计原则**：
- **发布者不阻塞**：publish 立即返回，handler 异步执行
- **松耦合**：发布者和订阅者互不感知
- **事件命名规范**：过去式命名（如 task_done 而非 do_task）

## 三、运行逻辑

### 3.1 发布-订阅流程

**订阅**：`subscribe(event_name, handler, filter?)` → 将 handler 注册到 event_name 的订阅者列表 → 返回订阅 ID（用于取消订阅）。

**发布**：`publish(event_name, **data)` → 封装事件对象（含名称、数据、时间戳）→ 放入异步队列 → 立即返回。

**分发**：工作线程从队列取出事件 → 查找该事件的所有订阅者 → 依次执行 handler → filter 返回 False 的跳过 → 单个 handler 异常不影响其他。

### 3.2 线程安全

通过线程锁保护订阅者注册表的并发访问。发布操作使用异步队列，发布者线程不阻塞，订阅者 handler 在工作线程中顺序执行。

### 3.3 事件命名规范

事件名采用过去式，统一格式如 `stop_requested`、`run_started`、`task_done`、`connection_lost`。通过 Events 常量类统一管理，避免字符串拼写错误。

## 四、重点功能

### 4.1 完全解耦

模块间通过事件通信，不持有对方引用。发布者不知道谁在处理事件，订阅者不知道谁发布了事件。新增功能只需新增订阅，无需修改现有代码。

### 4.2 条件过滤

订阅时传入 filter 函数，只有满足条件的事件才触发 handler。避免订阅者收到无关事件后自行判断。

### 4.3 事件历史

可开启事件历史记录，记录所有发布的事件（含时间戳和数据），便于调试时追溯"发生了什么"。

## 五、实现思路

### 5.1 模块结构

```
core/
├── event_bus.py          ← 事件总线主入口
└── events.py             ← 事件名常量定义
```

### 5.2 核心方法定义

**EventBus（事件总线）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `publish(name, **data) -> None` | 🔓 公开 | `EventBus` | 发布事件，放入异步队列后立即返回 |
| `subscribe(name, handler, filter) -> str` | 🔓 公开 | `EventBus` | 订阅事件，返回订阅 ID（用于取消） |
| `unsubscribe(sub_id) -> None` | 🔓 公开 | `EventBus` | 按订阅 ID 取消订阅 |
| `clear() -> None` | 🔓 公开 | `EventBus` | 清空所有订阅（测试/重置用） |
| `start() -> None` | 🔓 公开 | `EventBus` | 启动分发工作线程 |
| `stop() -> None` | 🔓 公开 | `EventBus` | 停止分发工作线程 |

### 5.3 核心流程

**事件发布与分发流程**：
```
任意模块.publish("stop_requested")
  → EventBus 封装 Event 对象（名称+数据+时间戳）
  → 放入 _queue（异步队列，立即返回）
  → _dispatch_thread 从队列取出 Event
  → 查找 _subscribers["stop_requested"]
  → 遍历 handler，filter 返回 False 的跳过
  → 依次执行 handler，异常隔离不中断循环
```

**订阅注册流程**：
```
任意模块.subscribe("state_changed", handler, filter?)
  → EventBus 加锁 _lock
  → 追加到 _subscribers["state_changed"] 列表
  → 生成唯一订阅 ID 返回
  → 解锁
```

### 5.4 关键设计

- **异步队列**：publish 入队立即返回，工作线程异步分发，不阻塞发布者
- **异常隔离**：单个 handler 异常不影响其他订阅者
- **线程安全**：Lock 保护订阅者列表，Queue 实现跨线程通信（UI 线程 ↔ 工作线程）
- **条件过滤**：subscribe 支持 filter 参数，订阅者可只处理关心的事件
- **事件名常量**：Events 类统一管理事件名，避免拼写错误
- **全局单例**：整个程序共享一个 EventBus 实例

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `publish(event_name, **data)` | 所有模块 | 发布事件，异步分发 |
| `subscribe(event_name, handler, filter)` | 所有模块 | 订阅事件，返回订阅 ID |
| `unsubscribe(subscription_id)` | 任意模块 | 取消订阅 |
| `clear()` | 测试/重置 | 清空所有订阅 |

### 6.3 使用方式

各模块在初始化时通过 `event_bus.subscribe()` 订阅关心的事件，在适当的时候通过 `event_bus.publish()` 发布事件。全局单例 `event_bus` 在程序启动时创建，各模块直接引用。
