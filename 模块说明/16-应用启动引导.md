# 16-应用启动引导（Application Bootstrap）

> **类型**：入口层  ｜  **对应说明书**：main.py ｜  **说明**：新增，定义模块初始化顺序、依赖注入、启动与关闭流程

---

## 一、目的与作用

**一句话定位**：应用程序的入口与组装器。按照正确的依赖顺序初始化所有模块，建立模块间的引用关系，启动 UI，处理优雅关闭。

**为什么需要这个模块**：

目前 13 个模块各自有独立的设计，但缺少一个"总装图"：

- 各模块的初始化顺序是什么？（配置模块必须在其他模块之前初始化）
- 模块间的依赖引用如何注入？（构造函数传递？全局单例？）
- 启动时先加载配置还是先连接设备？
- 关闭时先断开连接还是先保存状态？

应用启动引导模块回答这些问题，是整个程序的**总装蓝图**。

**核心职责**：
1. **初始化顺序编排**：按依赖关系依次初始化所有模块
2. **依赖注入**：将已初始化的模块引用传递给依赖方
3. **启动入口**：初始化完成后显示 UI，进入事件循环
4. **优雅关闭**：接收关闭信号 → 停止运行 → 保存状态 → 断开连接 → 退出
5. **单例管理**：确保每个模块只有一个实例（全局单例）

**设计原则**：
- **依赖顺序明确**：先初始化被依赖方，再初始化依赖方
- **全局单例**：每个模块只有一个实例，通过启动引导统一创建和持有
- **关闭有序**：关闭顺序与初始化顺序相反，保证资源正确释放

## 二、模块属性与依赖

### 2.1 依赖注入（外部模块引用）

启动引导模块不依赖其他业务模块，它是**创建者**而非**使用者**。它持有所有模块的单例引用。

| 属性名 | 类型 | 作用域 | 作用 |
|--------|------|--------|------|
| `_modules` | `dict[str, object]` | 🔒 私有 | 已初始化的模块实例字典，按名称索引 |

### 2.2 对外暴露属性

| 属性名 | 类型 | 作用域 | 说明 |
|--------|------|--------|------|
| `modules` | `dict[str, object]` | 📖 只读对外 | 所有已初始化模块的单例字典，供其他模块按需获取引用 |

### 2.3 内部私有属性

| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_init_order` | `list[str]` | 模块初始化顺序列表 |
| `_shutdown_hooks` | `list[callable]` | 关闭时需执行的回调列表 |

## 三、运行逻辑

### 3.1 模块初始化顺序

依赖关系决定了严格的初始化顺序：

```
第1层：基础设施（无依赖）
  ① 配置管理中心（ConfigManager） — 其他模块依赖它读取配置
  ② 事件通信总线（EventBus） — 其他模块依赖它通信

第2层：基础服务（依赖配置+事件）
  ③ 日志监控中心（Monitor） — 启动日志系统
  ④ 运行时状态管理（StateManager）
  ⑤ 参数桥接模块（ParamBridge）

第3层：核心功能（依赖2层）
  ⑥ 设备连接模块（ConnectionManager）
  ⑦ 图像识别模块（Recognizer）
  ⑧ 防封策略模块（AntiDetect）

第4层：业务编排（依赖3层）
  ⑨ 执行器模块（Executor） — 依赖 ⑥⑦⑧
  ⑩ 时间调度模块（Scheduler）
  ⑪ 任务执行引擎（TaskRegistry + BaseTask）
  ⑫ 任务文件管理（TaskManager）

第5层：运行控制（依赖4层）
  ⑬ 运行控制中心（RunController） — 依赖 ⑩⑪ + 其他

第6层：账号与界面（依赖5层）
  ⑭ 账号管理模块（AccountManager）
  ⑮ 用户界面模块（MainWindow）
```

### 3.2 启动流程

```
main.py 入口
  → 1. 创建 ApplicationBootstrap 实例
  → 2. 按初始化顺序依次创建各模块实例：

      初始化配置管理中心
        → 加载所有配置文件（global.yaml / tasks.yaml / accounts.yaml）
        → 完成配置校验

      初始化事件通信总线
        → 创建全局单例 EventBus

      初始化日志监控中心
        → 传入配置和事件总线
        → 启动日志系统

      初始化运行时状态管理
        → 传入事件总线
        → 设置初始状态（run_status = stopped）

      初始化参数桥接模块
        → 传入配置、状态、事件总线

      初始化设备连接模块
        → 传入配置、事件总线、状态管理
        → 检测 ADB 路径

      初始化图像识别模块
        → 传入配置
        → 加载素材索引

      初始化防封策略模块
        → 传入配置、状态管理

      初始化执行器模块
        → 传入识图、防封、连接、监控

      初始化时间调度模块
        → 传入配置、状态管理、事件总线
        → 加载 task_state.json

      初始化任务执行引擎
        → 扫描 tasks/ 目录 → 自动注册全部任务

      初始化任务文件管理
        → 准备任务文件 CRUD 能力

      初始化运行控制中心
        → 传入调度、任务注册、连接、配置、状态、事件、监控

      初始化账号管理模块
        → 传入配置、连接、状态、事件

      初始化用户界面模块
        → 传入参数桥接
        → 显示主窗口

  → 3. 进入 Qt 事件循环（app.exec_()）
```

### 3.3 关闭流程

```
用户关闭窗口 / 系统关闭信号
  → 1. 停止运行控制中心（停止双线程、清空队列）
  → 2. 保存调度状态（task_state.json 原子写盘）
  → 3. 断开设备连接
  → 4. 关闭日志系统
  → 5. 退出事件循环
  → 6. 进程退出
```

### 3.4 依赖注入方式

所有模块采用**构造函数注入**：每个模块在创建时将其依赖的模块实例通过构造函数传入，而非在模块内部自行创建或查找。注入顺序严格按照初始化顺序：先初始化的模块实例作为参数传入后初始化的模块。

## 四、重点功能

### 4.1 依赖顺序自动推导

按照"被依赖方先初始化"的原则编排顺序。底层模块（配置、事件）最先初始化，上层模块（UI）最后初始化。

### 4.2 全局单例管理

启动引导创建并持有所有模块实例，通过 `modules` 字典对外提供。任何模块需要获取其他模块引用时，通过启动引导获取，避免重复创建。

### 4.3 优雅关闭

关闭顺序与初始化顺序相反。先停止运行控制中心 → 保存调度状态 → 断开连接 → 退出。保证资源正确释放，状态不丢失。

## 五、实现思路

### 5.1 模块结构

```
core/
└── bootstrap.py          ← 应用启动引导（初始化编排 + 依赖注入 + 关闭管理）

项目根目录/
└── main.py               ← 程序入口，调用 bootstrap.start()
```

### 5.2 核心方法定义

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `start() -> None` | 🔓 公开 | `ApplicationBootstrap` | 按顺序初始化所有模块，启动 UI |
| `shutdown() -> None` | 🔓 公开 | `ApplicationBootstrap` | 优雅关闭：停止运行→保存→断连→退出 |
| `get(module_name) -> object` | 🔓 公开 | `ApplicationBootstrap` | 按名称获取已初始化的模块实例 |
| `_init_config() -> ConfigManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化配置模块 |
| `_init_event_bus() -> EventBus` | 🔒 私有 | `ApplicationBootstrap` | 初始化事件总线 |
| `_init_monitor(...) -> Monitor` | 🔒 私有 | `ApplicationBootstrap` | 初始化日志监控 |
| `_init_state_manager(...) -> StateManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化状态管理 |
| `_init_connection(...) -> ConnectionManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化设备连接 |
| `_init_recognizer(...) -> Recognizer` | 🔒 私有 | `ApplicationBootstrap` | 初始化图像识别 |
| `_init_anti_detect(...) -> AntiDetect` | 🔒 私有 | `ApplicationBootstrap` | 初始化防封策略 |
| `_init_executor(...) -> Executor` | 🔒 私有 | `ApplicationBootstrap` | 初始化执行器 |
| `_init_scheduler(...) -> Scheduler` | 🔒 私有 | `ApplicationBootstrap` | 初始化时间调度 |
| `_init_task_engine(...) -> None` | 🔒 私有 | `ApplicationBootstrap` | 注册全部任务 |
| `_init_run_controller(...) -> RunController` | 🔒 私有 | `ApplicationBootstrap` | 初始化运行控制 |
| `_init_account_manager(...) -> AccountManager` | 🔒 私有 | `ApplicationBootstrap` | 初始化账号管理 |
| `_init_ui(...) -> MainWindow` | 🔒 私有 | `ApplicationBootstrap` | 初始化并显示 UI |

### 5.3 核心流程

**启动流程**：
```
main.py → start()
  → initialize() 按6层顺序初始化所有模块
  → 显示主窗口
  → 进入 Qt 事件循环
```

**关闭流程**：
```
用户关闭窗口 / SIGINT / SIGTERM
  → shutdown()
  → 停止 09-运行控制中心（停止双线程、清空队列）
  → 保存 05-时间调度模块 状态（task_state.json 原子写盘）
  → 01-设备连接模块 断开连接
  → 关闭 12-日志监控中心
  → 退出事件循环 → 进程退出
```

### 5.4 关键设计

- **构造函数注入**：所有模块的依赖通过构造函数传入，不依赖全局变量
- **初始化顺序**：严格按照依赖层级排序，下层先初始化
- **关闭有序**：与初始化顺序相反，保证资源正确释放

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `start()` | `main.py`（程序入口） | 初始化所有模块并启动 UI |
| `shutdown()` | **11-用户界面模块**（窗口关闭） / 系统信号 | 优雅关闭程序 |
| `get(name)` | 已初始化的任意模块 | 获取其他模块实例引用 |

### 6.2 对外部模块的调用

启动引导是**创建者**，它调用全部模块的构造函数创建实例。它依赖以下模块的构造函数签名来正确注入依赖：

| 被调用方 | 调用方式 | 说明 |
|---------|---------|------|
| **06-配置管理中心** | new + 调用 | 创建 ConfigManager 实例，调用 load() |
| **08-事件通信总线** | new | 创建全局单例 EventBus |
| **12-日志监控中心** | new + 调用 | 创建 Monitor 实例 |
| **07-运行时状态管理** | new | 创建 StateManager 实例，注入 EventBus |
| **10-参数桥接模块** | new | 创建 ParamBridge 实例 |
| **01-设备连接模块** | new + 调用 | 创建 ConnectionManager 实例 |
| **02-图像识别模块** | new | 创建 Recognizer 实例 |
| **03-防封策略模块** | new | 创建 AntiDetect 实例 |
| **14-执行器模块** | new | 创建 Executor 实例 |
| **05-时间调度模块** | new + 调用 | 创建 Scheduler 实例，加载 task_state.json |
| **04-任务执行引擎** | 调用 | 调用注册方法注册全部任务 |
| **13-任务文件管理** | new | 创建 TaskManager 实例 |
| **09-运行控制中心** | new | 创建 RunController 实例（注入全部依赖） |
| **15-账号管理模块** | new | 创建 AccountManager 实例 |
| **11-用户界面模块** | new + 调用 | 创建 MainWindow 实例，调用 show() |
    main()
```
