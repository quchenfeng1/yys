## 一、目的与作用

**一句话定位**：全局状态管理中心。集中管理脚本运行时所有跨模块共享的状态，通过事件总线广播状态变化。

**为什么需要这个模块**：

脚本运行中有大量全局状态需要被多个模块共享：
- 当前操作账号（主号/小号1/小号2）
- 当前连接的模拟器设备ID
- 当前游戏场景（庭院/战斗中/探索中）
- 运行状态（运行中/暂停/停止/错误恢复中）
- 当前执行的任务名和步骤
- 今日已运行时长/操作次数

如果这些状态散落在各模块内部，会导致：
1. 模块间互相查询状态时紧耦合
2. 状态不一致风险（A模块改了状态，B模块不知道）
3. UI难以获取全局状态做统一展示

**核心职责**：
1. **状态集中存储**：所有全局状态存于StateManager，单一数据源
2. **读写接口**：提供get_state(key) / set_state(key, value)
3. **变化广播**：状态变更时通过事件总线自动广播，订阅者自动收到
4. **状态快照**：可导出当前全部状态快照（调试/日志用）

**设计原则**：
- **单一数据源**：全局状态只在StateManager中维护，其他模块不缓存
- **变化即广播**：set_state自动发事件，订阅者无需轮询
- **只管运行时状态**：配置数据归配置模块，持久化执行记录归定时模块，StateManager只管"当前运行态"

## 二、实现思路

### 3.1 模块结构

```
core/
├── state_manager.py      ← 状态管理主入口
└── state_schema.py       ← 状态键名规范（新增）
```

### 3.2 核心接口设计

```python
class StateManager:
    """全局状态管理中心。"""

    def get_state(self, key: str, default=None) -> Any:
        """读取状态值
        例: get_state("current_account") → "main"
            get_state("run_status") → "running"
            get_state("current_scene") → "courtyard"
        """

    def set_state(self, key: str, value: Any):
        """设置状态值，并自动通过事件总线广播变化
        例: set_state("run_status", "paused")
            → 自动发布 event: state_changed(key="run_status", old="running", new="paused")
        """

    def get_snapshot(self) -> dict:
        """获取全部状态快照（调试/日志/UI刷新用）"""

    def reset(self):
        """重置所有状态为初始值（脚本重启时）"""

    def subscribe(self, key: str, callback):
        """订阅特定状态的变化（便捷方法，内部走事件总线）"""
```

### 3.3 状态键名规范

```python
class StateKeys:
    # === 运行状态 ===
    RUN_STATUS = "run_status"          # "running" / "paused" / "stopped" / "error"
    RUN_START_TIME = "run_start_time"  # 本次运行开始时刻
    TODAY_RUN_DURATION = "today_run_duration"  # 今日累计运行秒数

    # === 账号状态 ===
    CURRENT_ACCOUNT = "current_account"  # "main" / "sub1" / "sub2"
    ACCOUNT_ROLE = "account_role"        # "main" / "sub"

    # === 连接状态 ===
    CONNECTION_STATUS = "connection_status"  # "connected" / "disconnected" / "reconnecting"
    ACTIVE_DEVICE_ID = "active_device_id"   # "127.0.0.1:16384"

    # === 场景状态 ===
    CURRENT_SCENE = "current_scene"  # "courtyard" / "battle" / "explore" / "loading"

    # === 任务执行状态 ===
    CURRENT_TASK = "current_task"          # 当前执行的任务名
    CURRENT_STEP = "current_step"          # 当前执行的步骤名
    TASK_PROGRESS = "task_progress"        # 进度 "3/30"
    SCHEDULE_QUEUE = "schedule_queue"      # 当前日程队列（任务名列表）

    # === 安全状态 ===
    TODAY_OPERATION_COUNT = "today_operation_count"  # 今日操作次数
    RUN_LIMIT_REACHED = "run_limit_reached"          # 是否到上限
```

### 3.4 状态变化广播机制

```python
class StateManager:
    def set_state(self, key: str, value: Any):
        old_value = self._states.get(key)
        self._states[key] = value
        if old_value != value:
            # 通过事件总线广播状态变化
            event_bus.publish("state_changed",
                              key=key,
                              old_value=old_value,
                              new_value=value)

# 其他模块订阅状态变化：
state_manager.subscribe(StateKeys.RUN_STATUS, lambda new: ...)
# 等价于：
event_bus.subscribe("state_changed",
    filter=lambda e: e.key == StateKeys.RUN_STATUS,
    handler=lambda e: ...)
```

## 四、与其他模块的交互

| 交互方 | 方式 | 说明 |
|--------|------|------|
| 所有模块 | 被调用 | 各模块读写全局状态都经StateManager |
| 事件总线 | 发布事件 | set_state时自动发布state_changed事件 |
| UI模块 | 订阅事件 | UI订阅state_changed刷新状态展示区 |
| 运行控制 | 读写 | 读写run_status（running/paused/stopped） |
| 连接模块 | 读写 | 读写connection_status、active_device_id |
| AccountManager | 读写 | 读写current_account、account_role |
| 任务模块 | 读写 | 读写current_task、current_step、task_progress |
| 安全模块 | 读写 | 读写today_operation_count、run_limit_reached |
| 定时模块 | 读写 | 读写schedule_queue（当前日程表） |

## 五、关键设计决策

1. **单一数据源**：全局状态只在StateManager维护，其他模块不自行缓存，避免不一致
2. **变化即广播**：set_state自动发事件，订阅者无需轮询检查
3. **只管运行时态**：配置归配置模块，持久化执行记录归定时模块，StateManager只管"当前运行态"
4. **键名规范**：StateKeys常量类统一管理键名，避免拼写错误
5. **快照导出**：get_snapshot()方便调试和UI展示
6. **非持久化**：运行时状态不写盘（重启即重置），持久化数据归各自的模块（定时模块写task_state.json）

## 六、进一步增强（v2.0）

### 6.1 状态历史记录

可选记录关键状态的变化历史，便于调试"为什么任务没执行"等问题：

```python
class StateManager:
    def __init__(self, enable_history=False):
        self._history: dict[str, list] = {} if enable_history else None  # key→[(timestamp, value)]

    def set_state(self, key: str, value: Any):
        old_value = self._states.get(key)
        self._states[key] = value
        if self._history is not None and old_value != value:
            self._history.setdefault(key, []).append((datetime.now(), value))
        if old_value != value:
            event_bus.publish("state_changed", key=key, old_value=old_value, new_value=value)

    def get_history(self, key: str, limit=20) -> list:
        """获取状态变化历史（调试用）"""
        return (self._history or {}).get(key, [])[-limit:]
```

### 6.2 状态校验

设置状态时自动校验值的有效性，防止非法状态：

```python
class StateManager:
    VALIDATORS = {
        "run_status": lambda v: v in ("running", "paused", "stopped", "stopping", "error"),
        "connection_status": lambda v: v in ("connected", "disconnected", "reconnecting"),
        "current_account": lambda v: v in ("main", "sub1", "sub2"),
    }

    def set_state(self, key: str, value: Any):
        validator = self.VALIDATORS.get(key)
        if validator and not validator(value):
            monitor.warning(f"非法状态值: {key}={value}", module="state_manager")
            return  # 拒绝设置
        # ... 正常设置
```

### 6.3 状态快照自动保存

定时保存状态快照到内存（非磁盘），用于异常恢复时还原上下文：

```python
class StateManager:
    def snapshot(self) -> dict:
        """导出当前全部状态快照"""
        return dict(self._states)

    def restore(self, snapshot: dict):
        """从快照恢复状态（异常恢复时用）"""
        self._states = dict(snapshot)
        event_bus.publish("state_restored", keys=list(snapshot.keys()))
```
