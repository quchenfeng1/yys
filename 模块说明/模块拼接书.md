## 三、任务队列搭建阶段

### 3.1 用户点击"启动"后的完整链路

```
用户点击 UI 的"启动"按钮
  │
  ▼
11-用户界面模块.MainWindow._on_start()
  │  创建 ScriptWorker（QThread 子类），注入 Scheduler，调用 worker.start()
  ▼
ScriptWorker._execute()（独立线程）
  │
  ├── Step1: 加载配置 → 初始化 Scheduler → load_tasks_from_config() → build_schedule()
  │     └── 发布 schedule_updated 事件 → UI 刷新队列展示
  │
  ├── Step2: 连接模拟器（ensure_running + stop_check）
  │
  ├── Step3-7: 分辨率检查 → 启动App → 素材加载 → 初始化识别器/执行器
  │
  ├── Step8: 登录流程（LoginFlow）
  │     ├── 成功 → 进入 _run_schedule_loop()
  │     └── 失败 → 停止
  │
  └── _run_schedule_loop() ← 持续调度循环
```

### 3.2 调度循环：单线程优先队列

每轮扫描到期任务 → 按 priority 插入队列 → FIFO 执行：

```
_run_schedule_loop():
  │
  └── while not is_stopped():
        │
        ├── ① 调 scheduler.build_schedule()
        │       → 扫描所有启用 + 到期 + 未达上限的任务
        │       → 按 priority 升序 → 同 priority 按 category 顺序排序
        │       → 发布 SCHEDULE_UPDATED 事件 → UI 刷新队列卡片
        │
        ├── ② 合并到任务队列 _task_queue（list）：
        │       → 遍历 build_schedule() 返回的到期任务列表
        │       → 已在队列中的跳过，新任务按 priority 插入对应位置
        │       → 队列内始终保持 priority 排序
        │
        ├── ③ if _task_queue 为空:
        │       sleep(5); continue  ← 无任务，休眠
        │
        ├── ④ task = _task_queue.pop(0)  ← 队首出队（FIFO）
        │
        ├── ⑤ 发布 TASK_STARTED 事件 → UI 更新当前任务卡片
        │
        ├── ⑥ 执行任务：
        │       动态导入 tasks/{cat}/{task_name}.py
        │       → 查找 TaskStep 子类 → 创建 TaskContext → step.execute(ctx)
        │
        ├── ⑦ scheduler.mark_done(task_name, success)
        │       → success=True: 推进 next_run_time
        │       → success=False: 递增冷却 5→10→15...→60分钟
        │
        ├── ⑧ 发布 TASK_DONE 事件 → UI 清除当前任务 + 刷新队列
        │
        └── ⑨ 回到①（新一轮扫描会补充新到期任务）
```

### 3.3 队列管理特性

| 操作 | 实现 |
|------|------|
| **新任务入队** | 每轮扫描自动发现到期任务，按 priority 插入队列 |
| **按优先级排序** | 入队时按 priority 插入对应位置，队列始终保持有序 |
| **FIFO 执行** | `pop(0)` 队首出队，先入先执行 |
| **取消任务** | `[t for t in queue if t.name != target]` 直接删除 |
| **跳过当前** | `mark_done(task, success=True)` 推进 next_run |
| **清空队列** | `_task_queue.clear()` |
| **去重** | 入队前检查 `task["name"]` 是否已在队列中 |

### 3.4 队列状态示意图

```
┌─────────────────────────────────────────────────────┐
│                运行中（running）                       │
│                                                       │
│  调度循环（每轮扫描）                                  │
│  ─────────────────────                                │
│  ① build_schedule() ──→ 05-时间调度模块               │
│  ② 新任务按 priority 插入队列                          │
│                          ┌──────────────────────┐    │
│                          │  优先队列（list）      │    │
│                          │  ┌─────┬─────┬─────┐ │    │
│                          │  │ 签到 │ 御魂 │ 觉醒 │ │    │
│                          │  │ P5  │ P10 │ P10 │ │    │
│                          │  └─────┴─────┴─────┘ │    │
│                          │  pop(0) → FIFO 出队    │    │
│                          └──────────────────────┘    │
│                              │                        │
│  ③ 出队 → 动态导入 → 执行 → mark_done → 回到①         │
└─────────────────────────────────────────────────────┘
```

## 四、任务执行阶段

### 4.1 单次任务执行全链路

```
队列出队 → task_name = "home_scan"
  │
  ├── 1. 发布 TASK_STARTED 事件
  │     └── UI TaskQueuePanel 收到 → 显示当前任务卡片
  │
  ├── 2. 动态导入任务模块
  │     importlib.import_module(f"tasks.special.{task_name}")
  │     → 遍历模块类 → 找 is_generic=False 的 TaskStep 子类
  │
  ├── 3. 构造 TaskContext
  │     ├── task_config    ← 06-配置管理中心.get_task_config(task_name)
  │     ├── executor       ← 14-执行器模块
  │     ├── recognizer     ← 02-图像识别模块
  │     └── log            ← ScriptWorker.log（输出到 UI 终端）
  │
  ├── 4. step.execute(context) → StepResult
  │     │
  │     │  进入任务逻辑（以 home_scan 为例）：
  │     │  ┌──────────────────────────────────────┐
  │     │  │ 调用 OpenBottomMenu.execute()：       │
  │     │  │                                      │
  │     │  │ ① recognizer.find("主界面/识别-个人名片")│
  │     │  │    → 未找到 → StepResult.fail         │
  │     │  │                                      │
  │     │  │ ② executor.click_if_exists(           │
  │     │  │      "主界面/按钮-打开底部菜单")        │
  │     │  │                                      │
  │     │  │ ③ recognizer.find("主界面/识别-个人名片")│
  │     │  │    + recognizer.find("主界面/按钮-式神录")│
  │     │  │    → 两者都在 → StepResult.success    │
  │     │  └──────────────────────────────────────┘
  │     │
  │     └── 返回 StepResult
  │
  ├── 5. 判断 result.status
  │     ├── "success" → scheduler.mark_done(task_name, success=True)
  │     ├── "fail"    → scheduler.mark_done(task_name, success=False)
  │     │                 → 递增冷却后重新入队
  │     └── "skip"    → scheduler.mark_done(task_name, success=True)
  │
  ├── 6. 发布 TASK_DONE 事件
  │     └── UI 清除当前任务 + 刷新队列
  │
  └── 7. 回到调度循环①
```

### 4.2 步骤内的执行器调用细节

任务步骤通过 `context.executor` 调用 **14-执行器模块**：

```
以 OpenBottomMenu 中的"点击底部菜单按钮"为例：

context.executor.click_if_exists("主界面/按钮-打开底部菜单")
  │
  ├── 1. 调 02-图像识别模块.find("主界面/按钮-打开底部菜单")
  │     → 找到 → MatchResult(center, confidence)
  │     → 未找到 → 返回 False
  │
  ├── 2. 调 03-防封策略模块.random_offset(center_x, center_y)
  │     → 返回安全坐标 (cx, cy)
  │
  ├── 3. 调 03-防封策略模块.check_run_limit()
  │     → 超限抛出 AntiBanRiskError
  │
  ├── 4. 调 01-设备连接模块.click(cx, cy)
  │     → 执行 ADB shell input tap
  │
  ├── 5. 调 03-防封策略模块.sleep(base=0.8, jitter=0.5)
  │     → 随机延迟模拟人类操作
  │
  ├── 6. 调 03-防封策略模块.record_action() → 计数
  │
  └── 7. 调 03-防封策略模块.maybe_long_pause() → 概率走神
```

## 五、停止阶段

### 5.1 停止链路

```
用户点击 UI 的"停止"按钮
  │
  ▼
11-用户界面模块.MainWindow._on_stop()
  │  worker.stop() → _stop_flag = True
  │  control_bar.set_idle()
  ▼
ScriptWorker._run_schedule_loop()
  │  while 循环检测 is_stopped() → True → 退出循环
  │
  ├── 1. scheduler.save_state()
  │     └── 持久化 next_run_time / today_count 到 task_state.json
  │
  ├── 2. 发布 RUN_STOPPED 事件
  │     └── UI 状态栏更新为"已停止"
  │
  └── 3. finished_signal.emit → MainWindow._on_finished()
        └── 恢复控制栏按钮状态
```

### 5.2 队列中的未执行任务

停止时队列中剩余的任务**保留在 task_state.json 中**（next_run_time 未推进），下次启动时自动重新进入队列。

## 六、完整模块调用关系矩阵

### 6.1 各运行时阶段涉及的模块

| 阶段 | 涉及模块 | 说明 |
|------|---------|------|
| **启动** | 06, 08, 12, 07, 11, 13, 05 | UI 初始化 → Scheduler 加载 |
| **待命** | 11(UI), 08(事件) | 等待用户点击启动 |
| **初始化** | 06, 01, 02, 03, 14, 05 | ScriptWorker Step1~Step7 |
| **登录** | 14, 02, 01, 03 | LoginFlow 执行 |
| **调度循环** | 05, 04, 14, 02, 03, 01, 08 | _run_schedule_loop 循环 |
| **停止** | 05, 08 | save_state + 发布事件 |
| **日常重置** | 05 | 每日00:00重置 today_count |

### 6.2 核心数据流

```
配置数据流：
  06-配置管理中心 ← YAML/JSON 文件
    → 所有模块读取配置

事件数据流：
  任意模块 → 发布事件 → 08-事件通信总线 → 分发给订阅者

状态数据流：
  任意模块 → set_state() → 07-运行时状态管理 → 发布 state_changed
    → UI 订阅 → 自动刷新展示

操作数据流：
  04-任务步骤 → context.executor.click_image()
    → 14-执行器模块 → 02-图像识别(find)
                    → 03-防封策略(random_offset)
                    → 01-设备连接(click)
    → 返回结果给任务步骤
```
