# 14-执行器模块（Executor Module）

> **类型**：核心运行层  ｜  **对应说明书**：5.3 ｜  **说明**：从03-防封策略模块拆出，独立为操作执行桥接层

---

## 一、目的与作用

**一句话定位**：高层操作执行桥接层。封装"识图→安全偏移→设备操作"的完整链路，为任务步骤提供 `click_image()`、`wait_any()` 等语义化操作接口。

**为什么拆出**：

原 03-防封策略模块 中 Executor 仅作为"安全注入点"描述，但实际 `core/executor.py` 代码承担了更多职责：

- 协调识图模块获取坐标
- 调用防封模块生成安全参数
- 委托连接模块执行设备操作
- 提供任务步骤可直接调用的高层 API

将其拆为独立模块，职责更清晰。

**核心职责**：
1. **操作链路编排**：按"识图 → 安全偏移 → 执行"顺序协调三个底层模块
2. **高层操作接口**：提供 `click_image()`、`wait_any()`、`ensure_scene()` 等语义化方法
3. **超时与重试封装**：操作超时自动重试，重试间隔由安全模块控制
4. **全链路记录**：每次操作记录识别结果、安全参数、执行耗时到监控模块
5. **异常转换**：将底层异常（DeviceConnectError、RecognizeError）转换为操作结果

**设计原则**：
- **桥接而非控制**：Executor 不包含业务逻辑，只负责编排调用顺序
- **接口语义化**：对外暴露 `click_image("common/battle/challenge_btn")` 而非 `click(x, y)`
- **可替换底层**：替换识图算法或连接方式不影响 Executor 的上层调用方

## 三、运行逻辑

### 3.1 操作执行链路

每次高层操作（如 `click_image`）的内部流程：

```
调用 click_image("common/battle/challenge_btn")
  → 1. 调 recognizer.find("common/battle/challenge_btn") → 得到原始坐标 (x, y)
  → 2. 未找到 → 返回 False（调用方处理）
  → 3. 调 anti_detect.random_offset(x, y) → 得到安全偏移后坐标 (safe_x, safe_y)
  → 4. 调 anti_detect.human_move_path(起点, safe_x, safe_y) → 得到轨迹点列表
  → 5. 调 anti_detect.maybe_long_pause() → 判断是否走神
  → 6. 走神 → 调 anti_detect.get_pause_duration() → 等待随机时长
  → 7. 逐点移动 → 最后调 connection.click(safe_x, safe_y)
  → 8. 记录耗时和结果到 _monitor
  → 9. 返回 True
```

### 3.2 等待机制

`wait_any(template_names, timeout, interval)`：

```
1. 记录开始时间
2. 循环：
   a. 调 connection.screenshot() 获取当前截图
   b. 遍历 template_names，对每个调 recognizer.find()
   c. 找到任意一个 → 返回 (模板名, MatchResult)
   d. 未找到 → 调 anti_detect.random_delay(interval) 等待
   e. 检查是否超时 → 超时返回 None
```

### 3.3 场景确保

`ensure_scene(template_name, timeout)` — 确保当前处于指定场景，不在则等待：

```
1. 调 recognizer.wait(template_name, timeout=timeout)
2. 找到 → 返回 True
3. 超时未找到 → 返回 False（调用方走错误恢复）
```

## 四、重点功能

### 4.1 一键操作链路

`click_image(template)` 一次调用完成"识图→偏移→轨迹→走神检查→点击→记录"全链路。任务步骤无需关心底层细节。

### 4.2 语义化接口

| 接口 | 说明 | 替代的原始操作 |
|------|------|--------------|
| `click_image(name)` | 找到图片并点击 | `find + offset + click` |
| `wait_any(names)` | 等待多个目标任一出现 | 轮询截图+识别 |
| `ensure_scene(name)` | 确保在某个场景 | 循环 wait |
| `random_sleep(a, b)` | 随机等待一段时间 | `sleep(random.uniform)` |

### 4.3 全链路可观测

每次操作自动记录：原始坐标、安全偏移后坐标、操作耗时、识别置信度、是否走神。数据写入监控模块，可用于事后审计和操作模式分析。

## 五、实现思路

### 5.1 模块结构

```
core/
└── executor.py       ← 执行器主入口（单文件，约200行）
```

### 5.2 核心方法定义

**Executor**（单类，约200行）：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `click_image(name, region, timeout) -> bool` | 🔓 公开 | `Executor` | 识图→偏移→点击全链路，返回是否成功 |
| `click_position(x, y) -> None` | 🔓 公开 | `Executor` | 直接点击坐标（已含安全偏移），不经过识图 |
| `wait_any(names, timeout, interval) -> tuple \| None` | 🔓 公开 | `Executor` | 等待多个模板中任一出现 |
| `ensure_scene(name, timeout) -> bool` | 🔓 公开 | `Executor` | 确保当前场景为目标场景 |
| `random_sleep(min_s, max_s) -> None` | 🔓 公开 | `Executor` | 随机等待一段时间 |
| `swipe(x1,y1,x2,y2,duration) -> None` | 🔓 公开 | `Executor` | 滑动操作（含安全微调） |
| `get_last_operation() -> dict \| None` | 🔓 公开 | `Executor` | 获取上一次操作详情 |

### 5.3 核心流程

**click_image 完整链路**：
```
click_image(template_name)
  → find 获取坐标 → 未找到返回 False
  → random_offset 安全偏移
  → human_move_path 生成轨迹
  → maybe_long_pause 走神判断
  → connection.click 执行
  → 记录耗时和结果到 _monitor
  → 返回 True
```

**wait_any 等待链路**：
```
wait_any(names, timeout, interval)
  → 记录开始时间
  → 循环：
      截图 → 遍历识别 names
      找到任一 → 返回 (模板名, 坐标)
      未找到 → random_delay 等待
      超时 → 返回 None
```

### 5.4 关键设计

- **桥接模式**：Executor 本身不含业务逻辑，只编排三个底层模块的调用顺序
- **全链路记录**：每次操作记录完整上下文，便于问题排查
- **安全透明**：调用方无需关心安全处理，Executor 自动注入防封偏移和走神
- **接口语义化**：`click_image("btn_name")` 替代 `find→offset→click` 三步操作
