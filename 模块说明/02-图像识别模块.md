# 02-图像识别模块（Image Recognition Module）

> **类型**：核心运行层  ｜  **对应说明书**：Recognizer 5.2  ｜  **对应用户模块**：#6 识图控制模块

---

## 一、目的与作用

**一句话定位**：在截图中定位目标图片，返回匹配位置与置信度。纯识别引擎，不涉及任何操作和安全处理，是系统的"眼睛"。

**核心职责**：
1. **模板匹配**：在截图中查找目标模板图，返回位置+置信度
2. **素材管理**：加载 assets/ 四层分类目录的全部图片，建立内存索引
3. **区域限定**：支持限定搜索范围，加速识别减少误匹配
4. **等待机制**：轮询等待目标出现，支持超时和多个模板同时等待
5. **OCR文字定位**：识别界面文字位置，应对动态背景界面

**设计原则**：
- **纯粹性**：只做"看"，不做"做"（点击归执行模块，安全归安全模块）
- **无副作用**：识别过程不修改任何状态，纯函数式调用
- **可独立测试**：给图片+模板→返回结果，不依赖设备连接

| 属性名 | 类型 | 作用域 | 说明 |
|--------|------|--------|------|
| `match_result` | `MatchResult` | 📖 只读对外 | 匹配结果：模板名、中心坐标、左上角坐标、区域大小、置信度 |

### 2.3 内部私有属性

| 属性名 | 类型 | 作用 |
|--------|------|------|
| `_asset_cache` | `dict[str, np.ndarray]` | 素材缓存：name → 灰度图，启动时全量加载 |
| `_result_cache` | `dict[str, tuple[float, MatchResult]]` | 识别结果缓存：短时间重复识别，默认 TTL 1秒 |

## 三、运行逻辑

### 3.1 识别流程

```
接收识别请求（模板名 + 可选区域 + 阈值）
  → 检查结果缓存（TTL内命中则直接返回）
  → 检查截图缓存（同一帧内多次识别复用截图）
      ├── _screenshot_cache 有效且未过期 → 直接使用
      └── 无效/过期 → 从连接模块获取新截图
           → 更新 _screenshot_cache + _last_frame_time
  → 灰度化处理（默认）
  → 执行模板匹配（cv2.matchTemplate）
  → 解析匹配结果，取最高置信度
  → 记录本次识别耗时
  → 返回 MatchResult（坐标 + 置信度）
```

> 截图缓存机制：在一次任务步骤执行期间（通常 0.5~2 秒），所有 `find()` 调用共享同一帧截图，避免重复 ADB 请求。当前步骤完成后由 14-执行器模块 清空缓存。

### 3.2 等待机制

`wait(template_name, timeout, interval)`：每隔 interval 秒截图识别一次，直到目标出现或超时返回 None。`wait_any(template_names, timeout)`：同时等待多个模板中任意一个出现，返回最先匹配到的结果。

### 3.3 素材索引

启动时递归扫描 assets/ 下全部 PNG 文件，按相对路径（如 `common/battle/challenge_btn`）建立索引，统一转为灰度图缓存到内存。运行时查找直接从内存读取，避免磁盘 IO。

### 3.4 OCR定位

当模板匹配无法应对动态背景界面时，使用 OCR 识别文字位置。作为模板匹配的补充方案，速度较慢但适应性更强。

---

## 四、重点功能

### 4.1 模板匹配 + OCR 双引擎

静态界面用 OpenCV 模板匹配（快速高效），动态背景界面用 OCR 定位文字（适应变化）。两者互补，覆盖所有识别场景。

### 4.2 多尺度匹配

渲染有缩放偏差时，尝试 0.95/1.0/1.05 三个尺度的模板匹配，取置信度最高的结果，提升鲁棒性。

### 4.3 识别缓存

短时间内对同一模板的重复识别结果缓存（默认1秒），避免轮询等待时的重复计算开销。

### 4.4 区域限定

通过 region 参数限定搜索范围，既加速识别又减少误匹配。

## 五、实现思路

### 5.1 模块结构

```
core/
├── recognizer.py        ← Recognizer 识图主引擎（模板匹配）
└── ocr_locator.py       ← OcrLocator OCR文字定位子模块（预留）
```

### 5.2 核心方法定义

**Recognizer（识图主引擎）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `find(name, region, threshold) -> MatchResult \| None` | 🔓 公开 | `Recognizer` | 查找单个模板，返回最佳匹配或 None |
| `find_all(name, region, threshold) -> list[MatchResult]` | 🔓 公开 | `Recognizer` | 查找所有匹配位置 |
| `exists(name, threshold) -> bool` | 🔓 公开 | `Recognizer` | 判断目标是否存在 |
| `wait(name, timeout, interval) -> MatchResult \| None` | 🔓 公开 | `Recognizer` | 等待模板出现，超时返回 None |
| `wait_any(names, timeout) -> tuple[str, MatchResult] \| None` | 🔓 公开 | `Recognizer` | 等待多个模板中任一出现 |
| `reload() -> None` | 🔓 公开 | `Recognizer` | 重新加载素材（素材更新后调用） |
| `suggest_template(screenshot) -> str` | 🔓 公开 | `Recognizer` | 将截图与已知模板对比，建议最匹配的模板名（用于未知场景自动收藏） |

**OcrLocator（OCR文字定位，预留）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `locate_text(text, region) -> tuple \| None` | 🔓 公开 | `OcrLocator` | 识别文字位置，返回中心坐标或 None |
| `locate_any(texts, region) -> tuple[str, tuple] \| None` | 🔓 公开 | `OcrLocator` | 多个候选文字，返回首个匹配 |

> 注：素材索引功能已内联到 `Recognizer._load_templates()` 中，`AssetIndex` 独立类已取消。
| `reload() -> None` | 🔓 公开 | `AssetIndex` | 重新扫描加载 |

### 5.3 核心流程

**识别流程**：
```
find(name, region, threshold)
  → 检查 _result_cache 是否有未过期的缓存结果
  → 有 → 直接返回缓存
  → 无 → 调 _connection.screenshot() 获取当前截图
       → 灰度化处理
       → 在截图中执行模板匹配（cv2.matchTemplate）
       → 按 threshold 筛选，取最高置信度匹配
       → 记录耗时到 _latency_records
       → 写入 _result_cache（TTL=1秒）
       → 返回 MatchResult
```

**等待流程**：
```
wait(name, timeout, interval)
  → 记录开始时间
  → 循环：
      调 find(name) → 找到则返回结果
      未找到 → sleep(interval)
      检查是否超时 → 超时返回 None
```

### 5.4 关键设计

- **灰度优先**：默认转灰度匹配提速，颜色敏感场景可开启彩色模式
- **PIL 读取兼容中文路径**：保留 `_imread_unicode()` 方案处理中文路径
- **索引名=相对路径**：`common/battle/challenge_btn` 对应 `assets/common/battle/challenge_btn.png`
- **无状态设计**：识别过程不修改任何外部状态，纯函数式调用，便于测试

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

| 调用接口 | 调用方 | 说明 |
|---------|--------|------|
| `find(template_name)` | **14-执行器模块** / 任务步骤 | 查找单个模板，返回最佳匹配 |
| `exists(template_name)` | 任务步骤 | 判断目标是否存在（快速检查） |
| `wait(template_name)` | 任务步骤 | 等待目标出现（带超时） |
| `wait_any(template_names)` | 任务步骤 / **14-执行器模块** | 多个目标等待任一出现 |
| `locate_text(text)` | 任务步骤 | OCR文字定位 |

### 6.2 对外部模块的调用

| 被调用方 | 调用方式 | 说明 |
|---------|---------|------|
| **01-设备连接模块** | 调用 | 调 `screenshot()` 获取当前截图 |
| **06-配置管理中心** | 读配置 | 读取识别阈值、素材目录配置 |
| **12-日志监控中心** | 记录 | 记录识别耗时和性能数据 |

### 6.3 执行链路示意

```
任务步骤 → 14-执行器模块.click_image("btn")
  ① 02-图像识别模块.find("btn") → 得到原始坐标
  ② 03-防封策略模块.random_offset(坐标) → 得到安全偏移后坐标
  ③ 01-设备连接模块.click(安全坐标) → 执行点击
  ④ 14-执行器模块 记录结果到 12-日志监控中心
```

识图模块只做①，不直接参与②和③，保持职责纯粹。
