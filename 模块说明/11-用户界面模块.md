# 11-用户界面模块（User Interface Module）

> **类型**：桥梁表现层  ｜  **对应说明书**：第十一部分界面与菜单结构  ｜  **对应用户模块**：#4 UI模块

---

## 一、目的与作用

**一句话定位**：用户界面。分解为菜单树、任务列表、日志终端、状态展示等子模块，通过传参模块与程序逻辑交互，UI 自身不含任何业务逻辑。

**核心职责**：
1. **界面展示**：三栏布局（左菜单 / 中任务列表 / 右日志终端），展示配置、任务、日志、状态
2. **用户交互**：接收用户操作（点击/输入/勾选），通过传参模块传递给程序
3. **状态刷新**：订阅事件总线，自动刷新运行状态、任务进度、连接状态
4. **内置终端**：捕获 stdout/stderr 实时显示，替代外部命令行黑窗口
5. **素材管理**：可视化增删改查 assets/ 目录的图片素材

**设计原则**：
- **UI零逻辑**：UI只负责展示和接收输入，所有逻辑通过传参模块交给程序
- **事件驱动刷新**：订阅事件自动更新，不主动轮询程序状态
- **子模块独立**：每个 UI 区域是独立 Widget，可单独开发测试替换
- **菜单与目录对应**：菜单分类与 tasks/ 子目录一一对应，自动生成

## 三、运行逻辑

### 3.1 事件驱动刷新机制

UI 子模块不主动轮询程序状态，而是通过事件总线订阅相关事件自动更新：

- **运行状态变化**：订阅 state_changed(run_status) → 更新状态显示文字和颜色
- **任务执行**：订阅 task_started / task_done / step_done → 更新当前任务和步骤显示
- **连接状态**：订阅 connection_lost / connection_restored → 更新连接图标
- **日程更新**：订阅 schedule_updated → 刷新任务队列卡片
- **日志记录**：订阅 log_record → 追加到日志流显示

### 3.2 任务队列展示（TaskQueuePanel）

中间面板的任务队列卡片组件，将定时模块的日程表数据可视化：

**数据流**：`定时模块 build_schedule()` → 过滤+排序 → 存入状态管理 → 发布 `schedule_updated` 事件 → 本面板订阅并重建卡片。

**刷新机制**：

| 触发事件 | 响应行为 |
|---------|---------|
| `schedule_updated` | 重建整个队列卡片列表 |
| `task_started` | 更新当前任务为大卡片（含进度条），队列中移除该任务 |
| `task_done` | 清除当前任务卡片，刷新队列 |

**卡片设计**：

| 属性 | 大卡片（当前任务） | 小卡片（队列任务） |
|------|-------------------|------------------|
| 尺寸 | 自适应宽 × 90px | 120 × 70px |
| 内容 | 名称 + 优先级徽章 + 状态 + 进度条 | 名称 + 优先级 + 预计时间 |
| 交互 | 展示当前执行进度 | 点击可跳转详情（预留） |

**优先级色阶**：P1(红) → P2(橙) → P3(黄) → P5(绿) → P10(蓝,默认) → P20(紫) → P99(灰)

### 3.3 内置终端

日志面板的双标签设计：日志标签页展示结构化日志流（带级别筛选/清除/导出），终端标签页以只读方式实时显示 stdout/stderr 输出。采用暗色背景，自动着色（INFO=绿 / WARNING=橙 / ERROR=红 / DEBUG=灰）。

### 3.4 图片素材管理

可视化面板管理 assets/ 目录下的素材图片：
- 左侧 9 个场景分区列表，显示各分区图片数量
- 右侧缩略图 + 名称 + 备注 + 尺寸
- 支持添加（从本地选择PNG自动复制到分区）、编辑备注、预览、删除

### 3.5 任务列表自动生成

任务列表面板自动扫描 tasks/ 的四类子目录，为每个任务生成一行配置控件（启用开关、优先级、执行规则编辑器、倒计时），新增任务无需修改 UI 代码。

## 四、重点功能

### 4.1 UI零逻辑

UI 只负责展示和接收输入，不包含任何业务逻辑。所有程序交互通过传参模块中转，UI 不直接调用连接/识图/安全/任务/定时/运行控制等核心模块。

### 4.2 三栏布局

左栏菜单树 + 弹出配置面板，中栏控制栏 + 任务列表 + 队列卡片，右栏日志 + 终端。底部状态栏展示全局运行状况。与现有 GUI 布局一致。

### 4.3 事件驱动

UI 通过订阅事件自动刷新，不轮询程序状态，性能开销小，响应及时。

### 4.4 子模块独立

每个 UI 面板是独立 Widget，可单独开发、测试、替换。新增面板不影响现有布局。

## 五、实现思路

### 5.1 模块结构

```
ui/
├── main_window.py            ← 主窗口（三栏布局）
├── param_bridge/             ← 传参模块
├── panels/                   ← 各UI子面板（18个子面板）
└── widgets/                  ← 可复用UI组件
    ├── task_row.py           ← 任务行组件
    ├── repeat_editor.py      ← 执行规则编辑器
    ├── countdown_label.py    ← 倒计时标签
    └── team_editor.py        ← 阵容编辑器
```

### 5.2 核心方法定义

UI 模块不提供程序调用接口，只通过事件总线被动接收事件刷新界面。

**MainWindow（主窗口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `init_ui() -> None` | 🔓 公开 | `MainWindow` | 初始化三栏布局和所有子面板 |
| `refresh_task_list() -> None` | 🔓 公开 | `MainWindow` | 扫描 tasks/ 目录刷新任务列表 |
| `show() -> None` | 🔓 公开 | `MainWindow` | 显示主窗口并启动事件循环 |

### 5.3 核心流程

**事件驱动刷新流程**：
```
程序模块发布事件（如 task_started）
  → 08-事件通信总线 分发事件
  → UI 订阅的 handler 被调用
  → 更新对应控件显示（当前任务卡片、进度条等）
  → 无需轮询
```

**用户操作流程**：
```
用户点击"启动"按钮
  → 调用 10-参数桥接模块.request_start()
  → 参数桥接模块发布 start_requested 事件
  → 09-运行控制中心 订阅后执行启动逻辑
  → UI 不直接调用任何核心模块
```

### 5.4 关键设计

- **传参模块桥梁**：UI 不直接碰配置/状态/事件，全经传参模块中转
- **事件驱动刷新**：订阅事件自动更新，不轮询程序状态
- **复用组件**：TaskRow / RepeatEditor / CountdownLabel 等抽到 widgets/ 复用
- **子模块独立**：每个 UI 面板是独立 Widget，可单独开发测试替换

## 六、使用方法（模块间交互）

### 6.1 外部提供的调用接口

UI 模块不对外提供程序调用接口。其他模块通过事件总线发布事件，UI 订阅后自动刷新界面。

### 6.2 对外部模块的调用

| 被调用方 | 调用方式 | 说明 |
|---------|---------|------|
| **10-参数桥接模块** | 调用 | 绑定控件 / 发启停信号 / 修改配置 |
| **08-事件通信总线** | 订阅 | 订阅 task_started / state_changed / log_record 等事件刷新 UI |
| **04-任务执行引擎** | 读（间接） | 通过任务注册表扫描 tasks/ 目录获取已注册任务列表 |
| **13-任务文件管理** | 调用 | 新建任务时调 `new_task()`、删除时调 `delete_task()`、打开文件时调 `open_file()` |
