# 10-参数桥接模块（Parameter Bridge Module）

> **类型**：桥梁表现层  ｜  **对应说明书**：（UI↔程序绑定，新形式化层）  ｜  **对应用户模块**：#3 传参模块

---

## 一、目的与作用

**一句话定位**：UI与程序之间的数据桥梁。内部拆分为"配置数据模型层"（定义参数结构）和"UI数据绑定层"（控件↔配置双向同步），实现 UI 改 → 配置改 → 程序读到新值，程序状态变 → UI 自动更新。

**为什么需要这个模块**：

没有传参模块时，UI 直接操作程序逻辑（按钮调 scheduler.start()、输入框写 config.set()），导致 UI 与程序紧耦合。有了传参模块后，UI 只与传参模块交互，传参模块再与配置模块/运行控制/事件总线交互，UI 和程序完全解耦。

**核心职责**：
1. **参数体系定义**：定义每个任务/模块需要哪些参数的 schema
2. **UI数据绑定**：UI控件与配置数据的双向同步
3. **参数聚合**：一个任务需要多组参数（定时+阵容+副本），负责聚合
4. **校验拦截**：UI输入的参数校验后传给程序，非法值拦截在 UI 层

**设计原则**：
- **UI不碰逻辑**：UI控件只与传参模块交互，不直接调用程序模块
- **双向绑定**：用户编辑 → 配置更新；程序状态变 → UI 自动刷新
- **参数聚合**：一个"运行传参"聚合了启停信号+账号选择+任务范围

## 二、模块属性与依赖

### 2.1 依赖注入（外部模块引用）

| 属性名 | 类型 | 作用域 | 作用 |

| 属性名 | 类型 | 作用域 | 说明 |

## 三、运行逻辑

### 3.1 双向绑定流程

**用户修改控件**：用户勾选/输入/选择 → UIBinding 检测变化 → 写入配置模块 set() → 配置持久化 → 发布 config_changed 事件 → 程序读取到新值。

**程序状态变化**：程序模块更新状态 → set_state() → 发布 state_changed 事件 → UIBinding 收到事件 → 自动更新控件显示。

### 3.2 运行传参流程

UI 启停按钮 → RunBridge 桥接 → 通过事件总线发布控制信号（start_requested / stop_requested / pause_requested）→ 运行控制模块订阅并执行。

### 3.3 任务参数传参流程

UI 任务行控件（启用开关/优先级/规则编辑器）→ TaskBridge 桥接 → 通过 UIBinding 写入配置模块 → 定时模块读取配置进行调度。

### 3.4 校验拦截

所有 UI 输入的参数在绑定层进行类型/范围校验，非法值弹出提示并不提交，确保脏数据不进入程序。

---

## 四、重点功能

### 4.1 UI零逻辑

UI 控件只与传参模块的数据绑定交互，不直接调用任何程序模块。改 UI 布局不影响程序逻辑，改程序接口不影响 UI 代码。

### 4.2 双向数据绑定

用户编辑控件 → 自动写配置并持久化；程序状态变化 → 自动更新控件显示。无需手动同步。

### 4.3 参数变更回滚

支持撤销上一次配置修改，避免误操作后无法恢复。

### 4.4 批量参数编辑

支持批量修改多个任务的同类参数（如一次性修改所有日常任务的执行时间），提升配置效率。

## 五、实现思路

### 5.1 模块结构

```
ui/
├── param_bridge/
│   ├── schemas.py         ← 配置数据模型层（参数 schema 定义）
│   ├── ui_binding.py      ← UI数据绑定层（控件↔配置双向同步）
│   ├── run_bridge.py      ← 运行传参（启停信号桥接）
│   ├── task_bridge.py     ← 任务参数传参（优先级/规则/阵容）
│   ├── account_bridge.py  ← 账号传参
│   └── config_bridge.py   ← 通用配置传参（连接/防封号/日志）
```

### 5.2 核心方法定义

**RunBridge（运行传参桥接）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `request_start() -> None` | 🔓 公开 | `RunBridge` | 发布 start_requested 事件（用户点启动） |
| `request_stop() -> None` | 🔓 公开 | `RunBridge` | 发布 stop_requested 事件（用户点停止） |
| `request_pause() -> None` | 🔓 公开 | `RunBridge` | 发布 pause_requested 事件（用户点暂停） |
| `request_resume() -> None` | 🔓 公开 | `RunBridge` | 发布 resume_requested 事件（用户点恢复） |

**TaskBridge（任务参数传参桥接）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `update_priority(name, value) -> None` | 🔓 公开 | `TaskBridge` | 修改任务优先级，写入配置 |
| `update_repeat(name, rule) -> None` | 🔓 公开 | `TaskBridge` | 修改任务执行规则，写入配置 |
| `update_next_run(name, time) -> None` | 🔓 公开 | `TaskBridge` | 手动设置任务的 next_run_time |
| `batch_update(names, key, value) -> None` | 🔓 公开 | `TaskBridge` | 批量修改多个任务的同一参数 |

**UIBinding（UI 数据绑定层）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `bind(widget, config_path) -> None` | 🔓 公开 | `UIBinding` | 将 UI 控件绑定到指定配置路径 |
| `bind_state(widget, state_key) -> None` | 🔓 公开 | `UIBinding` | 将 UI 控件绑定到指定状态键（只读显示） |
| `unbind(widget) -> None` | 🔓 公开 | `UIBinding` | 解绑控件 |
| `undo() -> None` | 🔓 公开 | `UIBinding` | 撤销上一次配置修改 |

### 5.3 核心流程

**用户修改控件流程**：
```
用户勾选/输入/选择
  → UIBinding 检测变化
  → 校验类型/范围（非法值提示不提交）
  → 写入配置模块 set()
  → 配置持久化
  → 发布 config_changed 事件
  → 程序读取到新值
```

**运行传参流程**：
```
用户点"启动"按钮
  → RunBridge.request_start()
  → 发布 start_requested 事件到事件总线
  → 09-运行控制中心 订阅后执行启动逻辑
```

**程序状态→UI刷新流程**：
```
程序模块更新状态 → set_state()
  → 发布 state_changed 事件
  → UIBinding 收到事件
  → 自动更新对应控件显示
```

### 5.4 关键设计

- **UI不碰逻辑**：UI 只与传参模块交互，不直接调用程序
- **事件驱动刷新**：只读显示（倒计时/状态）通过订阅事件自动刷新，不轮询
- **校验在UI层**：非法值在绑定层拦截，不传到程序
- **双向绑定**：用户编辑 → 配置更新；程序状态变 → UI 自动刷新
