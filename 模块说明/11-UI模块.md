# 11-UI模块（UI Module）

> **类型**：桥梁表现层  ｜  **对应说明书**：第十一部分界面与菜单结构  ｜  **对应用户模块**：#4 UI模块

---

## 一、目的与作用

**一句话定位**：用户界面。分解为日志、菜单、任务配置、任务列表、状态展示等子模块，通过传参模块与程序逻辑交互，UI自身不含任何业务逻辑。

**核心职责**：
1. **界面展示**：三栏布局（左菜单/中任务列表/右日志+终端），展示配置、任务、日志、终端输出、状态
2. **用户交互**：接收用户操作（点击/输入/勾选），通过传参模块传递给程序
3. **状态刷新**：订阅事件总线，自动刷新运行状态、任务进度、连接状态
4. **内置终端**：捕获 stdout/stderr 实时显示，替代外部命令行黑窗口
5. **子模块化**：每个UI区域独立成子模块，可独立开发、测试、替换

**设计原则**：
- **UI零逻辑**：UI只负责展示和接收输入，所有逻辑通过传参模块交给程序
- **事件驱动刷新**：UI订阅事件自动更新，不主动轮询程序状态
- **子模块独立**：每个UI区域是独立的Widget，可单独开发测试
- **菜单与目录对应**：菜单分类与tasks/子目录一一对应，自动生成

### 2.1 内置终端（★ v2.1 新增）

**设计动机**：原架构中 Python 的 print() 输出和异常 traceback 会弹出外部 PowerShell/CMD 黑窗，不仅体验差，而且日志与程序输出分离不便于排查。v2.1 将日志面板升级为双标签组合面板：

```
┌──────────────────────────┐
│ [ 📋 日志 ] [ 🖥 终端 ]  │  ← QTabWidget
├──────────────────────────┤
│                          │
│  切换标签查看不同内容     │
│                          │
│  日志：结构化日志流       │
│  终端：stdout/stderr     │
│         实时输出（只读）  │
└──────────────────────────┘
```

**核心特性**：
- **终端只读**：用户不可编辑，不可输入命令，纯输出展示
- **自动着色**：[INFO]=绿色 [WARNING]=橙色 [ERROR]=红色 [DEBUG]=灰色
- **实时重定向**：通过 `OutputRedirector` 替换 `sys.stdout/stderr`，所有 `print()` 和异常 traceback 实时显示
- **深色主题**：终端采用 VS Code 风格暗色背景（#1E1E1E），与日志浅色背景形成对比
- **程序退出时自动卸载**：恢复原始 stdout/stderr，不影响后续输出

**实现文件**：`ui/panels/log_panel.py`（约 270 行）
- `OutputRedirector`：stdout/stderr 重定向器
- `TerminalWidget`：内置只读终端控件
- `LogStreamWidget`：结构化日志流控件
- `LogPanel`：QTabWidget 组合面板（日志+终端）

### 2.2 任务队列展示面板（★ v2.2 新增 — 从 Scheduler + UI 中拆出的独立模块）

**设计动机**：Scheduler（05-定时模块）生成日程表数据（队列列表），StateManager 存储队列状态，EventBus 广播 `schedule_updated` 事件——但缺少一个**可视化模块**将这些数据呈现为直观的任务队列。v2.2 将这一职责从 Scheduler/UI 中拆出，形成独立的「任务队列展示面板」。

**拆出依据**：该模块横跨 Scheduler（数据源）和 UI（展示层），需同时订阅 `schedule_updated`、`task_started`、`task_done` 三个事件，且拥有独立的卡片式布局逻辑。放在 Scheduler 中会污染纯调度逻辑，放在主窗口会膨胀 UI 代码——拆为独立模块职责最清晰。

**核心职责**：
1. **当前任务展示**：大卡片 + 进度条，显示正在执行的任务名称、优先级徽章、进度（如 15/30）
2. **任务队列展示**：小方块卡片，水平流式排列，按优先级从上到下，每个卡片显示任务名、优先级、预计执行时间
3. **实时刷新**：订阅事件总线，任务开始时高亮当前卡片，完成时移除，队列自动前移
4. **卡片交互**：点击队列卡片可跳转任务详情（预留）

**数据流**：

```
Scheduler.get_all_tasks()
  → 过滤 (enabled=true + status=due + 未达上限)
  → 按 priority 排序
  → 构建队列列表
  → event_bus.publish("schedule_updated")
  → TaskQueuePanel._on_schedule_updated()
  → _rebuild_queue() → 生成小方块卡片

RunController 执行任务
  → event_bus.publish("task_started", task_name="yuhun")
  → TaskQueuePanel._on_task_started()
  → _rebuild_current() → 生成大卡片 + 进度条
  → 队列中移除已开始的任务
```

**实现文件**：`ui/panels/task_queue_panel.py`（~300 行）
- `QueueTheme`：颜色主题（优先级色阶、状态色、卡片样式）
- `TaskCard`：卡片组件（大卡片=current，小卡片=compact）
- `TaskQueuePanel`：主面板（当前任务区 + 队列滚动区）

**位置**：中间面板，全局控制栏正下方、任务列表上方。

### 2.3 图片配置面板（★ v2.3 新增 — 可视化素材管理）

**设计动机**：v2.2 之前素材管理依赖手动操作文件系统和 `IMAGE_MAP` 映射表，用户需要在 `所需图片/` 文件夹和 `assets/` 目录之间手动搬运。v2.3 提供完整的可视化面板，直接在 UI 中完成素材的增删改查和预览。

**核心职责**：
1. **分区浏览**：左侧 9 个场景分区列表，显示各分区图片数量
2. **图片列表**：右侧显示当前分区的图片缩略图 + 名称 + 备注 + 尺寸
3. **添加图片**：从本地文件选择 PNG，自动复制到对应分区并生成元数据
4. **编辑备注**：修改图片的用途说明，可移动到其他分区
5. **预览**：双击图片以真实尺寸查看
6. **删除**：删除图片文件和元数据

**实现文件**：`ui/panels/image_manager_panel.py`（~280 行）
- `SectionListPanel`：左侧分区列表
- `ImageListPanel`：右侧图片列表 + 操作按钮
- `ImageManagerPanel`：主面板容器

**数据源**：`core/image_manager.py` — 管理 assets/ 下的 9 个分区目录和 `.image_meta.json` 元数据。

### 3.2 主窗口布局

```python
class MainWindow(QMainWindow):
    """主窗口。三栏QSplitter布局，子面板按需加载。"""

    def __init__(self):
        # 三栏布局
        splitter = QSplitter(Qt.Horizontal)
        splitter.addWidget(self._left_panel)    # 左：菜单树+弹出面板
        splitter.addWidget(self._center_panel)  # 中：控制栏+任务列表
        splitter.addWidget(self._right_panel)   # 右：日志
        self.setCentralWidget(splitter)

        # 底部状态栏
        self.statusBar().addWidget(self._status_bar)

        # 初始化传参模块绑定
        self._param_bridge = ParamBridge()
        self._init_bindings()

    def _init_bindings(self):
        """通过传参模块绑定所有UI控件"""
        # 运行控制按钮
        self._param_bridge.run_bridge.bind_start_button(self.control_bar.start_btn)
        self._param_bridge.run_bridge.bind_stop_button(self.control_bar.stop_btn)
        self._param_bridge.run_bridge.bind_pause_button(self.control_bar.pause_btn)
        # 任务列表
        for task_name, row in self.task_list.rows.items():
            self._param_bridge.task_bridge.bind_task_row(task_name, row)
        # ...
```

### 3.3 事件驱动刷新

UI子模块通过事件总线订阅状态变化，自动刷新：

```python
class StatusBar:
    """底部状态展示栏。订阅事件自动刷新。"""

    def __init__(self):
        # 运行状态
        event_bus.subscribe(Events.STATE_CHANGED,
            handler=self._on_run_status_changed,
            filter=lambda e: e.data.get("key") == StateKeys.RUN_STATUS)
        # 连接状态
        event_bus.subscribe(Events.CONNECTION_LOST, self._on_connection_lost)
        event_bus.subscribe(Events.CONNECTION_RESTORED, self._on_connection_restored)
        # 当前任务
        event_bus.subscribe(Events.TASK_STARTED, self._on_task_started)
        event_bus.subscribe(Events.TASK_DONE, self._on_task_done)
        # 步骤进度
        event_bus.subscribe(Events.STEP_DONE, self._on_step_done)

    def _on_run_status_changed(self, key, old_value, new_value):
        self.run_status_label.setText(
            {"running":"运行中","paused":"已暂停","stopped":"已停止"}.get(new_value, new_value)
        )

    def _on_task_started(self, task_name):
        self.current_task_label.setText(f"正在执行: {task_name}")

    def _on_step_done(self, step_name, result):
        self.progress_label.setText(f"步骤: {step_name} → {result.status}")
```

class TaskListPanel:
    """任务列表面板。自动扫描tasks/目录生成，无需改UI代码。"""

    def refresh(self):
        """扫描tasks/四子目录，生成任务行"""
        for category in ["daily", "permanent", "event", "special"]:
            tasks = task_registry.list_by_category(category)
            for task in tasks:

                self._param_bridge.task_bridge.bind_task_row(task.name, row)
                self.add_row(category, row)

## 四、与其他模块的交互

| 交互方 | 方式 | 说明 |
|--------|------|------|
| 传参模块 | 双向 | 所有UI控件通过传参模块绑定配置和状态 |
| 事件总线 | 订阅 | 订阅事件自动刷新UI（状态/进度/日志） |
| 任务注册表 | 读 | 扫描tasks/目录生成任务列表 |
| 配置模块 | 间接 | 通过传参模块读写配置 |
| 状态管理 | 间接 | 通过传参模块订阅状态变化 |

**关键**：UI模块**不直接**调用连接/识图/安全/任务/定时/运行控制等核心模块。所有交互都经传参模块或事件总线。

## 五、关键设计决策

1. **UI零逻辑**：UI只展示和接收输入，业务逻辑全在程序侧
2. **子模块独立**：每个面板是独立Widget，可单独开发和测试
3. **事件驱动刷新**：订阅事件自动更新，不轮询程序状态
4. **菜单自动生成**：任务列表扫描tasks/目录生成，新增任务无需改UI
5. **三栏布局保留**：左菜单/中任务/右日志，与v0.5现有GUI一致
6. **复用组件**：TaskRow/RepeatEditor/CountdownLabel等可复用组件抽到widgets/
7. **传参模块桥梁**：UI不直接碰配置/状态/事件，全经传参模块中转
8. **运行监控面板**：v2.0新增，展示运行指标/异常截图/运行报告，帮助用户了解脚本运行状况
9. **日志导出**：日志面板新增导出功能，一键打包日志+截图+指标，方便反馈问题
