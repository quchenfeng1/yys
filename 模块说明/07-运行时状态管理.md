# 07-运行时状态管理（Runtime State Management）

> **类型**：支撑服务层  ｜  **对应说明书**：（新概念）  ｜  **说明**：解耦新增，统一管理运行时全局状态

---

## 一、目的与作用

**一句话定位**：全局状态管理中心。集中管理脚本运行时所有跨模块共享的状态，通过事件总线广播状态变化，避免模块间紧耦合查询。

**为什么需要这个模块**：

脚本运行中有大量全局状态需要被多个模块共享——当前账号、连接设备、游戏场景、运行状态、执行任务、今日统计等。如果这些状态散落在各模块内部，会导致：
1. **紧耦合**：模块间互相查询状态时需持有对方引用
2. **不一致**：A模块改了状态，B模块不知道
3. **UI难以展示**：UI需要轮询各模块获取状态

**核心职责**：
1. **状态集中存储**：所有全局状态单一数据源
2. **读写接口**：get_state(key) / set_state(key, value)
3. **变化广播**：状态变更时通过事件总线自动通知订阅者
4. **状态快照**：导出当前全部状态快照，用于调试和 UI 刷新

**设计原则**：
- **单一数据源**：全局状态只在此维护，其他模块不自行缓存
- **变化即广播**：set_state 自动发事件，订阅者无需轮询
- **只管运行时态**：配置归配置模块，持久化记录归定时模块，本模块只管理"当前运行态"

## 三、运行逻辑

### 3.1 状态读写流程

**写状态**：`set_state(key, value)` → 校验值有效性 → 对比旧值 → 更新内存 → 若有变化则发布 `state_changed` 事件（含 key、old_value、new_value）。

**读状态**：`get_state(key, default)` → 从内存字典中查找 → 找到返回值，未找到返回 default。

### 3.2 变化广播机制

每次 set_state 检测到值有变化时，自动通过事件总线发布 `state_changed` 事件。订阅者可针对性订阅特定 key 的变化，无需轮询检查。

### 3.3 状态校验

设置状态时自动校验值的有效性，拒绝非法状态值（如将 run_status 设为不存在的值会被拒绝并告警）。

### 3.4 状态快照

`get_snapshot()` 返回当前全部状态的字典副本，可用于：
- 写入日志方便调试
- UI 整体刷新展示
- 异常恢复时保存上下文

### 3.5 状态历史（可选）

可启用历史记录功能，记录关键状态的每次变更（含时间戳），便于事后排查"为什么任务没执行"等问题。

## 四、重点功能

### 4.1 单一数据源

所有全局状态集中管理，其他模块不自行缓存副本，从根本上避免状态不一致问题。

### 4.2 自动广播

状态变化即推送，订阅者实时感知，无需轮询、无需持有发布者引用。

### 4.3 非持久化

运行时状态不写磁盘（重启即重置），与持久化数据分离。需要持久化的数据由对应模块自行管理（如定时模块写 task_state.json）。

### 4.4 快照导出

一键获取全局状态全貌，便于调试、日志记录和 UI 刷新。

## 五、实现思路

### 5.1 模块结构

```
core/
├── state_manager.py      ← StateManager 状态管理主入口
└── state_schema.py       ← StateKeys 状态键名规范常量
```

### 5.2 核心方法定义

**StateManager（状态管理主入口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `get_state(key, default) -> Any` | 🔓 公开 | `StateManager` | 读取任意全局状态值 |
| `set_state(key, value) -> None` | 🔓 公开 | `StateManager` | 更新状态，校验后自动广播 state_changed 事件 |
| `get_snapshot() -> dict` | 🔓 公开 | `StateManager` | 获取全部状态的字典快照 |
| `reset() -> None` | 🔓 公开 | `StateManager` | 重置所有状态为初始值（脚本重启时） |
| `subscribe(key, callback) -> None` | 🔓 公开 | `StateManager` | 订阅特定状态的变化（便捷封装） |

### 5.3 核心流程

**写状态流程**：
```
set_state(key, value)
  → 检查 key 是否有校验器
  → 有 → 调校验器判断值是否合法
        → 不合法 → 记录告警，拒绝设置
  → 读取旧值 old_value = _state[key]
  → 对比 old_value != value
  → 无变化 → 直接返回
  → 有变化 → 更新 _state[key] = value
           → 记录到 _history（如启用）
           → 发布 state_changed(key, old_value, new_value) 到事件总线
```

**读状态流程**：
```
get_state(key, default=None)
  → 在 _state 字典中查找 key
  → 找到 → 返回 _state[key]
  → 未找到 → 返回 default
```

### 5.4 关键设计

- **键名规范**：通过 `StateKeys` 常量类统一管理键名，避免拼写错误
- **变化即广播**：`set_state` 自动发布 `state_changed` 事件，订阅者无需轮询
- **校验可选**：关键状态设置校验器，非法值拒绝设置并告警
- **快照导出**：`get_snapshot()` 方便调试和 UI 刷新
- **非持久化**：运行时状态不写盘（重启即重置），持久化数据归各自模块
