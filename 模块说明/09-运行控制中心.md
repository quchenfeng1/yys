# 09-运行控制中心（Run Control Center）v3.0

> **类型**：核心运行层 ｜  **对应说明书**：5.9 ｜  **说明**：ScriptWorker 驱动持续调度循环

---

## 一、目的与作用

**一句话定位**：脚本生命周期管理。ScriptWorker 线程完成初始化（连接→登录）后进入持续调度循环，由 Scheduler 驱动任务执行。

**核心职责**：
1. **初始化流程**：加载配置→连接模拟器→启动App→初始化识别器→登录
2. **持续调度循环**：`_run_schedule_loop()` 循环获取到期任务并执行
3. **任务动态加载**：`importlib.import_module` 动态导入任务模块并执行
4. **停止控制**：`is_stopped()` 检查停止标志，循环中每步检查
5. **失败冷却**：任务失败后 Scheduler 添加递增冷却，防止无限重试
6. **事件发布**：发布 `TASK_STARTED`/`TASK_DONE` 到 UI，发布 `SCHEDULE_UPDATED` 到 UI

**设计原则**：
- **单线程循环**：一个 `while not is_stopped()` 循环驱动所有调度
- **停止即终止**：用户停止操作立即生效，循环退出
- **Scheduler 驱动**：任务到期判断和推进完全由 Scheduler 负责
- **动态导入**：任务模块按需加载，无需预注册

## 三、运行逻辑

### 3.1 整体流程

```
MainWindow 点击启动
  → ScriptWorker.start()（新线程）
    → _execute()
      Step1: 加载配置 → 初始化/复用 Scheduler → build_schedule()
      Step2: 连接模拟器（ensure_running + stop_check）
      Step3-7: 分辨率检查 → 启动App → 素材加载 → 初始化识别器/执行器
      Step8: 登录流程（LoginFlow）
        → 成功 → _run_schedule_loop()
        → 失败 → 停止
```

### 3.2 调度循环

```python
while not self.is_stopped():
    1. scheduler.build_schedule()       # 刷新日程 → 发布 SCHEDULE_UPDATED
    2. task_name = scheduler.get_next_task()
       if not task_name: sleep(5); continue
    3. event_bus.publish(TASK_STARTED)
    4. 动态导入 tasks/{cat}/{task_name}.py
       查找 TaskStep 子类 → 创建 TaskContext(
           task_name, task_config=config.get_task_config(name),  # ← 注入任务专属配置
           executor, recognizer, log
       ) → step.execute(ctx)
    5. scheduler.mark_done(task_name, success)
    6. event_bus.publish(TASK_DONE)
```

### 3.3 停止流程

```
用户点停止
  → _on_stop() → worker.stop()
    → _stop_flag = True
    → 循环检查 is_stopped() → 退出
    → scheduler.save_state()
    → finished_signal
```

### 3.4 异常处理

| 场景 | 行为 |
|------|------|
| 任务执行异常 | 捕获 → 记录日志 → `mark_done(success=False)` → 递增冷却 |
| 调度循环异常 | 捕获 → 递增错误计数 → 连续10次自动停止 |
| 连接失败 | `ensure_running` 内 `stop_check` 中断 → 停止 |

## 四、重点功能

### 4.1 持续调度循环

登录成功后不退出，进入 `_run_schedule_loop()` 无限循环。每轮迭代刷新日程表、获取到期任务、执行、推进 next_run_time。无到期任务时休眠 5 秒，避免 CPU 空转。解决了"脚本执行一次就停止"的问题，实现了长期无人值守运行。

### 4.2 任务动态加载

通过 `importlib.import_module(f"tasks.{cat}.{task_name}")` 按需加载任务模块，无需预先注册。遍历模块中的类，通过 `issubclass(obj, TaskStep)` 和 `is_generic=False` 自动识别任务类。解决了任务文件与调度器的解耦问题，新增任务只需放文件+配置 YAML。

### 4.3 失败递增冷却

任务失败后不立即重试，而是将 `next_run_time` 推进 5→10→15...→60 分钟。避免死循环反复执行失败任务，同时保留自动恢复能力。成功执行后 `fail_streak` 归零。

### 4.4 外部调度器复用

MainWindow 启动时已初始化 Scheduler 并发布初始日程到 UI。ScriptWorker 可复用该实例（通过 `scheduler` 参数注入），避免重复加载配置和状态不一致。

## 五、实现思路

### 5.1 模块结构

```
ui/
└── script_worker.py          ← ScriptWorker（QThread 子类），运行控制主实现

core/
├── scheduler.py              ← Scheduler（被 ScriptWorker 调用）
├── repeat_rule.py            ← RepeatRule（Scheduler 内部使用）
└── task_state.py             ← TaskStateStore（Scheduler 内部使用）
```

### 5.2 核心方法定义

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `run() -> None` | 🔓 公开 | `ScriptWorker` | QThread 入口，调用 `_execute()` |
| `stop() -> None` | 🔓 公开 | `ScriptWorker` | 设置停止标志 |
| `is_stopped() -> bool` | 🔓 公开 | `ScriptWorker` | 检查停止标志（线程安全） |
| `_execute() -> None` | 🔒 私有 | `ScriptWorker` | Step1→Step8 初始化 + 调度循环 |
| `_run_schedule_loop() -> None` | 🔒 私有 | `ScriptWorker` | 持续调度循环 |
| `log(msg, level) -> None` | 🔒 私有 | `ScriptWorker` | 发送日志到 UI 终端 |

### 5.3 核心流程

**启动链路**：
1. MainWindow._on_start() 创建 ScriptWorker 实例
2. 注入 Scheduler（复用已有实例）
3. worker.start() → QThread 启动 → run() → _execute()

**运行链路**：
1. Step1~Step8 顺序执行初始化
2. 登录成功后进入 _run_schedule_loop()
3. 循环：build_schedule → get_next_task → 动态导入 → 执行 → mark_done

**停止链路**：
1. 用户点击停止 → worker.stop()
2. _stop_flag = True
3. 循环检查到停止 → 退出循环
4. save_state() → finished_signal

### 5.4 关键设计

- **QThread 子类**：ScriptWorker 继承 QThread，通过 pyqtSignal 与主线程 UI 通信
- **线程安全停止**：`_stop_flag` 由 `QMutex` 保护，循环中每步检查
- **动态导入**：任务不预注册，通过 `importlib` 按名加载，与 `TaskManager` 文件扫描解耦
- **Scheduler 注入**：支持外部复用 Scheduler 实例，避免重复加载配置
