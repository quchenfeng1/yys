# 12-日志监控中心（Logging & Monitoring Center）

> **类型**：支撑服务层  ｜  **对应说明书**：Logger 5.6 升级  ｜  **说明**：新增，统一管理可观测性能力

---

## 一、目的与作用

**一句话定位**：可观测性中心。统一管理结构化日志、运行指标、异常截图和运行报告，为调试、监控和优化提供数据支撑。

**为什么需要这个模块**：

现有日志只是简单文本输出，缺少结构化记录、运行指标统计、异常自动截图、运行报告生成等能力。如果这些能力散落在各模块中实现，会导致日志逻辑侵入业务代码，格式不一致。

**核心职责**：
1. **结构化日志**：每条日志带模块/级别/任务/步骤/标签，可按维度筛选检索
2. **运行指标收集**：自动统计各任务执行次数/成功率/平均耗时/总耗时
3. **异常自动截图**：出错时自动截图并保存上下文（任务/步骤/配置/调用栈）
4. **运行报告**：每日/每周自动生成运行总结（Markdown格式）
5. **日志事件化**：日志通过事件总线发布，UI日志面板订阅显示

**设计原则**：
- **非侵入式**：其他模块只需简单调用，不感知日志内部实现
- **结构化优先**：所有日志和指标都是结构化数据，文本输出只是其中一种渲染
- **异步写入**：日志写入不阻塞业务线程，通过队列异步落盘
- **可配置级别**：调试时全量记录，生产时精简输出

## 三、运行逻辑

### 3.1 结构化日志流程

```
调用 log(level, message, module, task, step, tags)
  → 封装为 LogEntry（含时间戳/级别/消息/模块/任务/步骤/标签）
  → 写入文本日志文件（loguru渲染）
  → 写入结构化日志文件（JSON格式，供检索）
  → 通过事件总线发布 log_record 事件（UI日志面板订阅）
  → 返回
```

### 3.2 运行指标收集流程

```
运行控制模块调用 record_task_start(task_name)
  → 记录任务开始时间

运行控制模块调用 record_task_done(task_name, success, duration)
  → 更新该任务的执行次数、成功/失败计数、总耗时
  → 更新最后执行时间
  → 失败时记录错误信息

查询：get_metrics(task_name) → 返回单个任务统计
      get_all_metrics() → 返回全部任务统计
```

每个任务的统计指标：总执行次数、成功次数、失败次数、成功率、平均耗时、总耗时、最后执行时间。

### 3.3 异常截图流程

```
捕获到异常 → 调用 capture_on_error(task, step, error, screenshot)
  → 生成文件名 {task}_{step}_{时间戳}
  → 保存截图 PNG 到 logs/snapshots/{日期}/
  → 保存上下文 JSON（任务/步骤/错误信息/调用栈/时间）
  → 记录错误日志
```

### 3.4 运行报告生成

`generate_daily_report()`：汇总当日所有任务的执行情况、成功率、耗时分布、异常记录、截图索引。
`generate_weekly_report()`：按周汇总，包含趋势分析。

## 四、重点功能

### 4.1 结构化日志

每条日志携带模块、任务、步骤、标签等多维信息，可按任意维度筛选检索。文本和 JSON 双格式写入，兼顾可读性和可检索性。

### 4.2 运行指标自动统计

无需手动记录，运行控制模块每次任务执行时自动上报数据，自动统计各任务的执行次数、成功率、耗时等关键指标。

### 4.3 异常截图自动保存

出错时自动截取现场画面并保存上下文信息，事后可回溯异常现场。截图和上下文按日期归档，UI 查看器可直接浏览。

### 4.4 日志事件化

日志通过事件总线实时推送给 UI 日志面板，无需轮询，无额外延迟。

## 五、实现思路

### 5.1 模块结构

```
core/
├── monitor.py               ← 监控主入口 Monitor
├── metrics_collector.py     ← 运行指标收集器
├── snapshot_manager.py      ← 异常截图管理器
├── report_generator.py      ← 运行报告生成器
└── logger.py                ← 底层日志引擎（保留loguru）
```

### 5.2 核心方法定义

**Monitor（监控主入口）**：

| 方法签名 | 可见性 | 所属类 | 作用 |
|---------|--------|--------|------|
| `log(level, msg, module, task, step, tags) -> None` | 🔓 公开 | `Monitor` | 记录结构化日志 |
| `info(msg, ...) -> None` | 🔓 公开 | `Monitor` | 便捷 INFO 级别日志 |
| `warning(msg, ...) -> None` | 🔓 公开 | `Monitor` | 便捷 WARNING 级别日志 |
| `error(msg, ...) -> None` | 🔓 公开 | `Monitor` | 便捷 ERROR 级别日志 |
| `debug(msg, ...) -> None` | 🔓 公开 | `Monitor` | 便捷 DEBUG 级别日志 |
| `record_task_start(name) -> None` | 🔓 公开 | `Monitor` | 记录任务开始时间 |
| `record_task_done(name, success, duration) -> None` | 🔓 公开 | `Monitor` | 记录任务完成统计 |
| `get_metrics(name) -> dict` | 🔓 公开 | `Monitor` | 查询单个任务指标 |
| `get_all_metrics() -> dict` | 🔓 公开 | `Monitor` | 查询全部任务指标 |
| `capture_on_error(task, step, error) -> None` | 🔓 公开 | `Monitor` | 异常截图并保存上下文 |
| `generate_daily_report() -> str` | 🔓 公开 | `Monitor` | 生成当日运行报告（Markdown） |
| `generate_weekly_report() -> str` | 🔓 公开 | `Monitor` | 生成本周运行报告（Markdown） |
| `query_logs(level, module, task, time_range) -> list` | 🔓 公开 | `Monitor` | 检索历史日志 |

### 5.3 核心流程

**结构化日志流程**：
```
调用 log(level, msg, module, task, step, tags)
  → 封装为 LogEntry（含时间戳/级别/消息/模块/任务/步骤/标签）
  → 写入文本日志文件（loguru 渲染）
  → 写入结构化日志文件（JSON 格式，供检索）
  → 发布 log_record 事件到事件总线（UI 日志面板订阅）
  → 返回
```

**运行指标收集流程**：
```
record_task_start(name) → 记录任务开始时间
record_task_done(name, success, duration)
  → 更新 _task_stats[name] 的执行次数、成功/失败计数、总耗时
  → 失败时记录错误信息
```

### 5.4 关键设计

- **非侵入式**：其他模块只需调用 monitor.log() / monitor.record_task()，不感知内部实现
- **异步写入**：日志通过队列异步写入，不阻塞业务线程
- **日志检索**：支持按级别/模块/任务/时间/关键词检索历史日志
- **日志事件化**：通过事件总线推送日志，UI 订阅后实时显示
