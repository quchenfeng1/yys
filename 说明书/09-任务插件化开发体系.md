## 第九部分 任务插件化开发体系

### 9.0 体系总览 ★

**核心理念：配置驱动 + 自动发现 + 标准契约**。目标是让新增任意模块（副本 / 日常 / 特殊）成本最低化，遵循统一"三步法"：

```
① 截图素材 → ② 填配置 → ③ 写任务类（或用脚手架自动生成）
```

**扩展能力矩阵**：

| 扩展场景 | 是否需写代码 | 是否需改核心 | 标准耗时 |
|----------|--------------|--------------|----------|
| 替换界面图（版本更新） | 否 | 否 | 约 10 分钟 |
| 新增常驻任务 | 少量 | 否 | 20-30 分钟 |
| 新增日常任务 | 少量 | 否 | 20-30 分钟 |
| 新增特殊机制副本 | 中等 | 否 | 30-60 分钟 |
| 修改入口 / 流程顺序 | 否（改配置） | 否 | 约 5 分钟 |

### 9.1 任务接口契约规范 ★

所有任务继承统一基类，遵守接口契约。基类提供模板方法，子类按需覆写钩子。

**BaseTask 完整接口**：

```python
class BaseTask:
    # ===== 类属性（子类必须定义）=====
    name: str               # 任务唯一标识，与素材目录、配置文件同名
    display_name: str       # UI 显示名
    category: str           # 分类: "daily" / "dungeon" / "special"

    # ===== 可选类属性（有默认值）=====
    priority: int = 0       # 优先级（数字小先执行）
    time_window: str = None # 时间窗 "17:00-22:00"，None 表示任意时间
    valid_until: str = None # 有效期，过期自动禁用（活动任务用）

    # ===== 生命周期钩子（子类按需覆写）=====
    def pre_check(self) -> bool:
        """前置检查：体力/次数/时间/有效期。返回 False 跳过本任务。"""
    def setup(self) -> bool:
        """前置准备：导航到目标场景、切换阵容。"""
    def run(self) -> bool:
        """核心执行逻辑（必须实现）。"""
    def teardown(self) -> bool:
        """收尾：回庭院、关弹窗。默认实现为回主页。"""
    def post_check(self) -> bool:
        """后置校验：确认任务完成。"""
    def on_error(self, error: Exception) -> bool:
        """异常处理：返回 True 表示已恢复，False 放弃本任务。"""

    # ===== 模板方法（请勿覆写）=====
    def execute(self) -> bool:
        """统一执行流程: pre_check → setup → run → teardown → post_check"""
```

**契约要点**：
- `name` 必须与 `assets/tasks/{category}/{name}/` 素材目录、`config/coords/{name}.json` 配置文件同名，形成**三者绑定**。其中 `category` 为任务分类（daily/permanent/event/special）。
- 通用素材（战斗按钮、UI元素等）放 `assets/common/`，多任务共享，不参与三者绑定。
- `run()` 是唯一必须实现的钩子，其余有默认实现（默认通过 / 空操作）。
- `execute()` 是模板方法，**子类不要覆写**，保证所有任务执行流程统一、可监控、可异常恢复。
- 任何设备操作必须通过 `self.executor` 调用，**禁止直接调 ADB**（防封号守门）。
- `DungeonTask` / `SpecialTask` 在此基础上扩展副本专用钩子（enter / select_floor / start_battle 等），见 [06-游戏流程模块](06-游戏流程模块.md) 6.4（DungeonTask）与 6.6（SpecialTask）节。

### 9.2 自动注册机制 ★

**无需手动改 `__init__.py`**。调度器启动时自动扫描任务目录，发现并注册所有任务类：

```python
# tasks/registry.py
def discover_tasks() -> dict[str, BaseTask]:
    """扫描 tasks/daily、tasks/permanent、tasks/event、tasks/special 四个目录，
       导入所有模块，收集 BaseTask 子类，按 name 建立注册表。"""
    tasks = {}
    for pkg in ["daily", "permanent", "event", "special"]:
        for module in import_all_modules(f"tasks.{pkg}"):
            for cls in iter_subclasses(module, BaseTask):
                if getattr(cls, "name", None):
                    tasks[cls.name] = cls()
    return tasks
```

**注册规则**：
- 任务类只要放在对应目录、继承 BaseTask 并定义 `name`，即被自动发现注册。
- `category` 由所在目录隐式决定（daily→daily，permanent→permanent，event→event，special→special）。
- 同名冲突时记录警告，后注册者覆盖。
- **删除任务文件即等于卸载**，无需清理注册代码。

### 9.3 任务脚手架工具 ★

`tools/task_generator.py` 一键生成新任务全套文件，消除重复劳动：

```bash
# 生成一个常驻任务
python tools/task_generator.py new --type dungeon --name yuling --display "御灵"

# 生成一个日常任务
python tools/task_generator.py new --type daily --name sign_in --display "每日签到"

# 生成一个特殊副本
python tools/task_generator.py new --type special --name true_orochi --display "真八岐大蛇"
```

**脚手架自动生成清单**：
1. `tasks/{type}s/{name}.py` — 任务类模板（含注释骨架，各钩子已列出待填充）
2. `config/coords/{name}.json` — 配置模板（含 entry_path、times 等默认字段）
3. `assets/tasks/{category}/{name}/` — 素材目录（含 README 说明需要哪些截图）
4. 自动在 `config/tasks.yaml` 追加启用项（默认 `enabled: false`）

生成后开发者只需：**填截图 → 填配置 → 实现 `run()` 核心逻辑**。

### 9.4 扩展场景一：新增日常任务（SOP）

日常任务（daily 类）继承 `BaseTask`，纯领奖无战斗，最简结构：

1. **生成骨架**：`python tools/task_generator.py new --type daily --name sign_in --display "每日签到"`
2. **截图素材**：签到按钮、领取确认等，存入 `assets/tasks/daily/sign_in/`。
3. **填配置** `config/coords/sign_in.json`：
   ```json
   { "entry_path": ["courtyard/icon_sign_in"], "loop": false }
   ```
4. **配置执行规则（repeat）**（重要）：在 `tasks.yaml` 的 `daily` 段加 `repeat` 字段，选择执行方式：
   - **绝大多数日常任务用 `daily`**：`repeat: {type: "daily", at_time: "00:00", times: 1}`（成功后锁到次日 00:00，当天不重复）。
   - 每周一次的任务用 `weekly`：`repeat: {type: "weekly", weekdays: [1], at_time: "00:00", times: 1}`。
   - 间隔型任务（如好友寄养）用 `interval_hours`：`repeat: {type: "interval_hours", hours: 6, times: 1}`（hours 可在 UI 改）。
   - 依赖失效时间的（如结界卡）用 `expire_at`：`repeat: {type: "expire_at", times: 1}`，并在 `run()` 内识图识别失效时间后调 `self.report_expire(...)` 上报。
5. **实现 `run()`**：通常就是"点入口→点领取→关弹窗"几行 `self.executor.click_image(...)`；若是 expire_at 型，执行末尾调 `self.report_expire(失效时间)`。
6. **启用**：tasks.yaml 设 `enabled: true` 并设 `priority`。

日常任务通常代码量最小，10-20 行即可完成；无阵容、无战斗。配好 repeat 后，脚本会自动在执行成功后推进 next_run_time 并持久化，重启不重复。**所有 repeat 参数与 next_run_time 均可在 UI 查看修改。**

### 9.5 扩展场景二：新增常驻任务（SOP）

常驻副本（permanent 类）继承 `DungeonTask`，有战斗逻辑。以"御灵"为例：

1. **生成骨架**：
   ```bash
   python tools/task_generator.py new --type permanent --name yuling --display "御灵"
   ```
   自动生成任务类、配置模板、素材目录，并在 tasks.yaml 注册（默认禁用）。
2. **截图素材**：存入 `assets/tasks/permanent/yuling/`：`entry.png`、`floor_select.png`、`challenge_btn.png`，复用 `common/battle/victory.png` 等。
3. **填副本配置** `config/coords/yuling.json`（含阵容引用与次数）：
   ```json
   {
     "entry_path": ["courtyard/icon_explore", "explore/btn_yuling"],
     "floor": 3,
     "times": 10,
     "max_daily": 100,
     "team_id": "yuling_team",
     "ensure_team_before_enter": true,
     "lock_team_after_select": true
   }
   ```
4. **配置阵容预设** `config/coords/teams/yuling_team.json`：复用已有预设（如 `yuhun_speed`）则改 `team_id` 即可；否则按 [07-资源与配置管理](07-资源与配置管理.md) 7.2 阵容御魂配置规范 新建，并在 `assets/teams/yuling_team/` 放 `marker.png`（阵容标记图）与选阵容分步图。
5. **配置执行规则（repeat）**（重要）：常驻副本也必须配 `repeat`，精确控制何时刷几次：
   ```yaml
   - name: "yuling"
     enabled: true
     priority: 10
     repeat: {type: "weekly", weekdays: [6,7], at_time: "10:00", times: 10, max_daily: 30}
   ```
   - 可按每日/每周/每月/隔N天/隔N小时/单次/依赖失效时间七种方式配置。
   - `times` 是单次调度刷的次数（如御灵刷 10 次），`max_daily` 是每日累计上限。
   - 若无特定时间偏好，可配 `daily` + at_time，或直接在 UI 用执行规则编辑器可视化设置。
6. **实现钩子** `tasks/permanent/yuling.py`：填充 `enter()`、`select_floor()` 等核心逻辑；阵容环节（`ensure_team`/`select_team`/`lock_team`）由基类默认调用 TeamManager，一般无需重写。
7. **启用并测试**：tasks.yaml 设 `enabled: true`，UI 单步执行先验阵容调整再验副本循环。

**无需改动**核心识别、操作、防封号代码。**repeat 与 next_run_time 均可在 UI 查看修改并持久化。**

### 9.6 扩展场景三：新增活动任务（SOP）

限时活动（event 类）继承 `EventTask`，带有效期，规则多变：

1. **生成骨架**：`python tools/task_generator.py new --type event --name event_summer --display "夏日活动"`
2. **截图素材**：活动入口 banner、各步骤界面，存入 `assets/tasks/event/event_summer/`。
3. **填配置** `config/coords/event_summer.json`（含有效期）：
   ```json
   {
     "valid_from": "2026-07-20",
     "valid_until": "2026-08-10",
     "entry_path": ["scenes/courtyard/icon_event_banner"],
     "steps_image": ["tasks/event/event_summer/step1", "tasks/event/event_summer/step2", "tasks/event/event_summer/challenge"],
     "has_battle": true,
     "team_id": "event_team"
   }
   ```
4. **实现 `run()`**：按 `steps_image` 顺序点击；有战斗则复用 DungeonTask 的战斗/结算逻辑。
5. **启用**：tasks.yaml `event` 段加项并设 `valid_until`；过期后调度器自动跳过，无需手动删配置。

**复用技巧**：同类活动下次开放时，复制配置改 `valid_until` 与入口图即可快速接入。

### 9.7 扩展场景四：新增特殊任务（SOP）

特殊任务（special 类）继承 `SpecialTask`，固定流程但执行方式特殊。以"真八岐大蛇"为例：

1. **生成骨架**：`--type special --name true_orochi --display "真八岐大蛇"`
2. **截图素材**：按特殊流程节点截图（多阶段界面）。
3. **填配置**：含特殊字段（`phases`、`team_id`、`team_per_phase`）：
   ```json
   {
     "entry_path": ["courtyard/icon_explore", "explore/btn_true_orochi"],
     "phases": ["phase1_setup", "phase2_battle", "phase3_settle"],
     "team_id": "orochi_team",
     "team_per_phase": {"phase2_battle": "orochi_battle_team"},
     "ensure_team_before_enter": true
   }
   ```
4. **配置阵容预设**：多层副本用 `team_per_phase` 为各阶段指定不同 `team_id`，TeamManager 会在对应阶段前自动 `ensure_team` 切换阵容。无此需求则只用单一 `team_id`（同 9.5 第 4 步方式新建或复用预设）。
5. **实现钩子**：`setup()`（含阵容准备）、`execute_steps()`（分阶段执行，阶段间 TeamManager 自动切阵容）、`teardown()`（退出）。
6. **测试**：因流程复杂，建议每个阶段单独"单步执行"验证；先验证阵容切换，再验证战斗循环。

**关键**：复杂流程拆分为独立子函数，每个子函数可独立测试；组队类需区分司机/乘客模式。

### 9.8 替换界面图（版本更新后）

1. 在新版本模拟器中按 1280×720 截图
2. 用图像编辑器裁剪出按钮/图标最小区域
3. 命名为原素材同名文件，覆盖 `assets/对应子目录/`
4. 运行 `python tools/asset_helper.py --check` 校验所有素材能否被识别
5. 失败的素材重新截取调整，直至全部通过

### 9.9 修改副本入口路径

仅需修改对应 `config/coords/{副本}.json` 的 `entry_path` 数组，按导航顺序填入素材名，无需改代码。

### 9.10 调整防封号强度

修改 `config/global.yaml` 的 `anti_detect` 段：
- 提高安全性：增大 `click_offset_radius`、`delay_jitter`、`long_pause_prob`
- 提升效率（风险增加）：减小上述值
