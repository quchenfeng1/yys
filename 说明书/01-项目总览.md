## 第一部分 项目总览

### 1.1 项目目标

开发一套基于**图像识别**的《阴阳师》手游自动化脚本，运行于 PC 端，通过连接安卓模拟器（或安卓真机）实现以下完整流程：

```
启动模拟器 → 启动阴阳师 → 登录流程 → 进入主界面
        → 调度循环（Scheduler 持续检查到期任务 → 执行 → 推进 next_run）→ 手动停止
```

### 1.3 模块分类体系（v2.0）

v2.4 将系统拆分为 **14 个模块**，按三大层次组织：

```
┌──────────────────────────────────────────────────────────┐
│              桥梁表现层（Bridge / Presentation）            │
│         传参模块(10)  ·  UI模块(11)                        │
│         用户操作↔程序逻辑的桥梁，事件驱动刷新               │
├──────────────────────────────────────────────────────────┤
│              支撑服务层（Support Services）                 │
│  配置(6) · 状态(7) · 事件总线(8) · 运行控制(9) · 日志(12)  │
│  为运行层提供数据、通信、生命周期管理、可观测性              │
├──────────────────────────────────────────────────────────┤
│              核心运行层（Core Runtime）                     │
│  连接(1) · 识图(2) · 安全(3) · 任务(4) · 定时(5)          │
│  连设备→看屏幕→安全操作→执行任务→按时调度                   │
└──────────────────────────────────────────────────────────┘
```

> 详细解耦思路见 `模块说明/模块解耦思路.md`，主程序设计见 `模块说明/主程序设计思路.md`。

### 1.4 设计原则

1. **配置驱动，素材分离**：所有界面图、按钮坐标、副本入口均存放于外部素材目录与配置文件，版本更新时只需替换图片/改配置，无需改代码。
2. **模块解耦，事件驱动**：12 个模块通过事件总线（发布-订阅）松耦合通信，模块间不直接持有对方引用。增删模块只增删订阅，不改现有代码。
3. **防封优先，安全第一**：任何点击操作必须经过防封号处理（随机偏移、随机延迟、自然轨迹），杜绝机械式精确点击。安全策略覆盖全操作链路（点击/滑动/等待/节奏）。
4. **纯调度与运行控制分离**：定时模块只管"何时执行哪个任务"，运行控制模块管"启动/暂停/停止生命周期"，职责正交、互不干扰。
5. **任务步骤图（DAG）**：每个任务由多个 TaskStep（特化模块+通用模块）组合，用有向图描述步骤间关系（顺序/分支/循环/跳转），通用模块（战斗/结算/返回）全项目复用。
6. **UI 零逻辑**：UI 只负责展示和接收输入，所有业务逻辑通过传参模块交给程序。UI 订阅事件总线自动刷新，不主动轮询。
7. **单一数据源**：全局运行时状态集中于 StateManager，配置数据集中于 ConfigManager，各模块不自行缓存，避免不一致。
8. **可观测**：结构化日志（按模块/任务/步骤/标签检索）、运行指标自动统计、异常自动截图、每日/每周运行报告。
