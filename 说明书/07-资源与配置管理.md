## 第七部分 资源与配置管理

### 7.1 图片素材管理（★ v2.3 重构）

v2.3 将素材从"按任务类型分"重构为**按游戏场景分区**，与游戏本身的界面逻辑一致。

**分区体系（9个场景）**：

| 分区 | 目录 | 内容 |
|------|------|------|
| 主界面 | `assets/主界面/` | 庭院标志、探索/町中/签到等入口按钮 |
| 探索 | `assets/探索/` | 探索地图、御魂/觉醒/秘闻/章节等副本入口 |
| 召唤 | `assets/召唤/` | 召唤按钮、十连、跳过动画 |
| 商城 | `assets/商城/` | 商城入口、购买按钮、免费礼包 |
| 战斗 | `assets/战斗/` | 挑战按钮、胜利/失败标志、准备按钮 |
| 阴阳寮 | `assets/阴阳寮/` | 寮入口、结界突破、道馆、麒麟 |
| 活动 | `assets/活动/` | 限时活动 Banner、入口、兑换 |
| 通用 | `assets/通用/` | 跨场景通用按钮（关闭/确认/返回） |
| 阵容 | `assets/阵容/` | 阵容验证图、选阵容分步图 |

**设计优势**：
- **多任务共用一张图**：御魂副本和觉醒副本都在「探索」分区，共用同一个"探索入口"图片
- **直观查找**：按游戏场景分区，知道按钮在哪个场景就能找到
- **可视化管理**：UI 中「图片配置」菜单提供完整的 CRUD + 预览功能

**元数据文件**：`assets/.image_meta.json` — 记录每张图片的备注、尺寸、添加时间、被哪些任务引用。

### 7.2 图片管理器（core/image_manager.py）★ v2.3 新增

**核心接口**：

```python
class ImageManager:
    def get_sections(self) -> list        # 获取所有分区及图片数量
    def get_images(self, section) -> list # 获取指定分区的图片列表
    def add_image(source, section, note)  # 添加图片（从外部复制进来）
    def update_note(filename, note)       # 修改备注
    def delete_image(filename)            # 删除图片
    def get_image_path(filename)          # 获取路径（预览用）
    def get_recognizer_index()            # 生成给 Recognizer 的索引
```

**目录结构**：所有识别图片统一存放于 `assets/`，采用四层分类：

| 层级 | 目录 | 用途 | 示例 |
|------|------|------|------|
| 第一层 | `common/` | 公共素材（跨任务复用） | `common/battle/challenge_btn.png` |
| 第一层 | `scenes/` | 场景标志图（判断当前场景） | `scenes/login/enter_game.png` |
| 第一层 | `tasks/` | 任务专属素材（按任务类型分） | `tasks/permanent/yuhun/entry.png` |
| 第一层 | `teams/` | 阵容御魂预设 | `teams/yuhun_speed/marker.png` |

**命名规范**：全小写，下划线分词。素材索引名 = 相对 assets/ 的路径（去掉 .png），用 `/` 分隔。
- 示例：`common/battle/challenge_btn`、`scenes/courtyard/main`、`tasks/permanent/yuhun/entry`
- 代码中引用素材时使用完整索引名

**截图要求**：
- 分辨率：1280×720（与模拟器一致）
- 格式：PNG（无损）
- 内容：只截取按钮/图标的最小有效区域，避免包含过多背景
- 标志图：每个场景至少一张"标志性全屏图"用于场景判断

**素材入库流程**：
1. 用户将原始模拟器截图放入 `所需图片/` 暂存区
2. 脚本启动时按 `IMAGE_MAP` 映射自动归入 `assets/` 对应子目录（或手动归档）
3. 运行 `python tools/asset_helper.py --check` 校验素材有效性
4. 无需改代码，重启脚本即可生效

**素材更新流程**（版本更新后）：
1. 在模拟器中截取新版界面图，放入 `所需图片/`
2. 裁剪出对应按钮/图标区域
3. 替换 `assets/对应子目录/同名文件.png`
4. 运行 `tools/asset_helper.py --check` 校验
5. 无需改代码，重启脚本即可生效

### 7.2 配置文件格式

**全局配置（config/global.yaml）**：

```yaml
adb:
  path: "C:/Program Files/Netease/MuMu/nx_main/adb.exe"  # MuMu 自带 adb（默认）
  port: 16384             # 模拟器 ADB 端口（MuMu 默认 16384）
  device_id: "127.0.0.1:16384"

screen:
  width: 1280
  height: 720
  dpi: 240

app:
  package: "com.netease.onmyoji.wyzymnqsd_cps"
  activity: "com.netease.onmyoji.Launcher"

recognize:
  threshold: 0.8          # 默认匹配阈值
  grayscale: true         # 灰度匹配
  method: "template"      # template / feature

anti_detect:
  click_offset_radius: 12 # 点击随机偏移半径(像素)
  delay_jitter: 0.6       # 延迟抖动系数
  long_pause_prob: 0.05   # 长暂停触发概率
  max_daily_runtime: 8    # 每日最大运行时长(小时)
  max_daily_actions: 2000 # 每日最大操作次数
  min_interval: 0.8       # 最小操作间隔(秒)

run:
  mode: "background"      # background / foreground
  log_level: "INFO"
  screenshot_on_error: true
```

每个阵容预设独立存为 `config/coords/teams/<team_id>.json`，副本配置通过 `team_id` 字段引用。一套预设可被多个副本复用。


**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `team_id` | string | 预设唯一标识，副本配置以此引用 |
| `shikigami` | array | 出战式神编队（5个位置），含技能预设 |
| `mitama_presets` | array | 御魂装配方案，每条指定式神、套装、属性位、副属性倾向 |
| `lock_after_select` | bool | 对局内选阵容后是否锁定（锁定后重复刷取不再选阵容） |
| `adjust_outside_first` | bool | 进本前是否对局外调整（阵容已匹配则跳过） |
| `verify_image` | string | 当前阵容校验标记图（识别此图判断是否已装备该预设） |
| `select_steps_image` | array | 对局内选阵容的分步识别图（滑动/点击指引） |

**素材目录**：`assets/teams/<team_id>/` 存放该预设的 marker、选阵容分步图、御魂装配相关截图。新增预设时同步建立此目录。

**预设复用规则**：多个副本可引用同一 `team_id`（如御魂、觉醒、业原火共用 `yuhun_speed`）。修改预设一处，所有引用副本同步生效，无需逐副本改配置。

**账号管理配置（config/accounts.yaml）★ v1.7新增**：

集中管理主号与最多2个小号的账号信息、区服、多开端口绑定、小号副本配置。完整格式与字段说明见 [第十二部分 12.6 账号配置文件格式](12-账号管理与多开体系.md#126-账号配置文件格式configaccountsyaml-)。要点：
- 主号配置 `main_account`（唯一），含可切换区服列表 `servers_available`。
- 小号配置 `sub_accounts`（数组，最多2个），每个小号含独立 `adb_port` / `device_id` 与 `dungeon_tasks` 副本配置。
- 小号的 `dungeon_tasks` 复用主号的副本定义文件，仅参数（times / team_id / enabled / repeat）独立。
- UI 修改后立即持久化到此文件。

### 7.3 版本更新维护策略

当游戏版本更新导致界面变化时，**维护成本最小化**是核心设计目标：

| 变更类型 | 维护方式 | 是否需改代码 |
|----------|----------|--------------|
| 按钮图标变化 | 替换 `assets/` 对应 PNG | 否 |
| 按钮位置变化 | 模板匹配自动定位，无需改坐标 | 否 |
| 新增副本入口 | 新增素材图 + 配置项 | 否（仅需配置） |
| 流程顺序变化 | 修改 `config/coords/*.json` 的 steps | 否 |
| 新增日常任务 | 新建任务文件 + 注册 + 配置 | 是（少量代码） |
| 识别阈值调整 | 修改 `global.yaml` | 否 |
