**层次职责**：

| 层次 | 模块 | 职责 |
|------|------|------|
| **核心运行层** | 01连接 → 02识图 → 03安全 → 04任务 → 05定时 | "连设备→看屏幕→安全操作→执行任务→按时调度"的主链路 |
| **支撑服务层** | 06配置·07状态·08事件·09运行控制·12日志监控 | 为核心层提供数据、状态、通信、生命周期管理、可观测性 |

### 3.2 模块调用关系（事件驱动）

v2.0 采用**事件总线 + 依赖注入**的松耦合架构。模块间不直接持有对方引用，而是通过事件总线间接通信：

```
用户点击"启动"
  │
  ▼
UI ControlBar ──发布──▶ event_bus.publish("start_requested")
  │                         │
  │              ┌──────────┼──────────┐
  │              ▼          ▼          ▼
  │        RunController  Scheduler  Monitor
  │        (启动调度循环)  (暂停调度)  (记录启动)
  │              │
  │    ┌─────────┼─────────┐
  │    ▼         ▼         ▼
  │  Scheduler  StateMgr  Connection
  │  .get_next  .set_state  .connect()
  │  _task()   ("running")
  │    │
  │    ▼
  │  TaskGraph.run() ──▶ TaskStep.execute()
  │    │                    │
  │    │              ┌─────┼─────┐
  │    │              ▼     ▼     ▼
  │    │        Recognizer AntiDetect Connection
  │    │        .find()    .offset()  .click()
  │    │
  │    ▼
  │  event_bus.publish("task_done")
  │    │
  │    ▼
  │  UI StatusBar ──订阅──▶ 自动刷新显示
```

**关键约束**：
- 任务模块只能调用核心运行层（Recognizer/AntiDetect/Connection 通过 Executor 注入），**禁止直接调用设备层**。
- 模块间通过事件总线松耦合通信，发布者不关心谁订阅，订阅者不关心谁发布。
- UI 模块不直接调用任何核心模块，所有交互经传参模块（ParamBridge）中转。
- 安全策略通过 Executor 注入：识图返回原始坐标 → 安全模块加偏移 → 连接模块执行点击。

### 3.3 依赖注入装配顺序

主程序 `main.py` 按依赖关系自底向上装配各模块（详见 `模块说明/主程序设计思路.md`）：

```
Layer 1 (无依赖):
  EventBus → StateManager → ConfigManager → Monitor

Layer 2 (依赖Layer1):
  ConnectionManager → Recognizer → AntiDetect

Layer 3 (依赖Layer2):
  Executor ★ ← Recognizer + AntiDetect + Connection
  TeamManager ← Executor
  AccountManager ← ConfigManager + ConnectionManager
  Scheduler ← ConfigManager + StateManager + EventBus + Monitor

Layer 4 (依赖Layer3):
  TaskRegistry ← Executor + Recognizer + TeamManager
  RunController ← Scheduler + Connection + Config + State + Registry + EventBus + Monitor

Layer 5 (依赖Layer4):
  ParamBridge ← Config + State + Scheduler + EventBus + Monitor
  MainWindow ← ParamBridge
```

### 3.4 数据流（单次识别-点击循环，v2.0安全注入版）

```
1. 任务步骤执行 Executor.click_image("challenge_btn")
   ↓
2. Executor 调用 Recognizer.find("challenge_btn") → 原始坐标 (637, 598)
   ↓
3. Executor 调用 AntiDetect.random_offset(637, 598) → 安全坐标 (641, 602)
   ↓
4. Executor 调用 AntiDetect.human_move_path(当前位置, (641,602)) → 贝塞尔轨迹
   ↓
5. Executor 调用 Connection.click(641, 602) → ADB 执行点击
   ↓
6. AntiDetect.record_operation() → 累计今日操作次数
   ↓
7. Monitor.record_step() → 结构化日志 + 指标统计
   ↓
8. 返回 StepResult 给任务步骤图，决定下一步
```

### 3.5 事件总线通信（关键事件流）

事件总线（EventBus）是 v2.0 架构的核心通信枢纽。以下是关键事件流（详见 `模块说明/08-事件总线模块.md`）：

**运行控制事件**：
| 事件 | 发布者 | 订阅者 |
|------|--------|--------|
| `start_requested` | UI 启动按钮 | RunController |
| `stop_requested` | UI 停止按钮 | RunController, Scheduler, TaskGraph, Connection |
| `run_started` / `run_stopped` | RunController | UI, StateManager, Monitor |
| `run_limit_reached` | AntiDetect | RunController, UI |

**连接事件**：
| 事件 | 发布者 | 订阅者 |
|------|--------|--------|
| `connection_lost` / `connection_restored` | ConnectionManager | RunController, UI, StateManager |

**任务事件**：
| 事件 | 发布者 | 订阅者 |
|------|--------|--------|
| `task_started` / `task_done` | RunController | UI, StateManager, Scheduler, Monitor |
| `step_done` | TaskGraph | UI, Monitor |
| `task_skipped` | Scheduler | UI, Monitor |

**状态事件**：
| 事件 | 发布者 | 订阅者 |
|------|--------|--------|
| `state_changed` | StateManager | UI, 相关模块 |
| `config_changed` | ConfigManager | 相关模块 |
| `account_switched` | AccountManager | Connection, StateManager |

### 3.6 运行状态机

RunController 维护的运行生命周期状态机（详见 `模块说明/09-运行控制模块.md`）：

```
                    start_requested
    stopped ──────────────────────► running
       ▲                               │
       │                               │ pause_requested
       │                               ▼
       │                           paused
       │                               │
       │                               │ start_requested（恢复）
       │                               ▼
       │                            running
       │                               │
       │ stop_requested                │
       │                               ▼
       │                           stopping
       │                     （等当前步骤完成）
       │                               │
       └───────────────────────────────┘
                       │
           error ──────┘（异常时）
```
