## 第三部分 整体架构设计

### 3.1 分层架构

脚本采用**五层架构**，自下而上层层封装，上层不感知底层细节：

```
┌─────────────────────────────────────────────────────┐
│                   UI 层 (UI Layer)                    │
│         PyQt5 控制面板：任务勾选、参数设置、启停        │
├─────────────────────────────────────────────────────┤
│                任务调度层 (Task Layer)                 │
│   调度引擎 / 日常 / 常驻 / 活动 / 特殊 / 登录流程      │
├─────────────────────────────────────────────────────┤
│              核心服务层 (Core Layer)                   │
│ 识别│执行│防封号│配置│阵容御魂│调度引擎│账号管理│日志  │
├─────────────────────────────────────────────────────┤
│                设备层 (Device Layer)                   │
│        ADB 连接 │ 截图 │ 点击 │ 滑动 │ 按键           │
├─────────────────────────────────────────────────────┤
│              基础设施层 (Infra Layer)                  │
│        素材资源 │ 配置文件 │ 日志文件 │ 截图存档        │
└─────────────────────────────────────────────────────┘
```

### 3.2 模块调用关系

```
UI层 ──触发──▶ 任务调度层 ──调用──▶ 核心服务层
                                      │
                          ┌───────────┼───────────┐
                          ▼           ▼           ▼
                      图像识别     操作执行     配置管理
                          │           │
                          ▼           ▼
                       设备层（ADB截图/点击）
                          │
                          ▼
                      模拟器/真机
```

**关键约束**：
- 任务层只能调用核心服务层，**禁止直接调用设备层**（所有设备操作必须经操作执行模块，从而强制经过防封号处理）。
- 核心服务层之间可互相调用，但操作执行模块调用图像识别时需注意避免循环依赖。
- UI 层与任务层通过事件/信号解耦，UI 不阻塞任务执行。

### 3.3 数据流（单次识别-点击循环）

```
1. 任务层发起"点击某按钮"请求（传入图片名/坐标）
   ↓
2. 操作执行模块 → 防封号引擎（计算随机偏移、延迟）
   ↓
3. 设备层截图 → 图像识别模块（模板匹配定位）
   ↓
4. 防封号引擎生成最终点击坐标（含随机抖动）
   ↓
5. 设备层执行点击（带自然移动轨迹）
   ↓
6. 日志模块记录（坐标、置信度、耗时）
   ↓
7. 返回结果给任务层
```
