## 第十一部分 界面与菜单结构

UI 采用 PyQt5，v2.0 采用**事件驱动刷新 + 传参模块桥接**架构。UI 只负责展示和接收输入，所有业务逻辑通过传参模块（ParamBridge）交给程序，UI 订阅事件总线自动刷新状态。

> 详细 UI 设计见 `模块说明/UI设计思路.md` 和 `模块说明/11-UI模块.md`。

### 11.2 脚本配置（全局设置）

| 子菜单 | 暴露的配置项 | 对应配置文件 |
|--------|--------------|--------------|
| 模拟器连接 | ADB 路径、端口、设备 ID、分辨率 | global.yaml → adb / screen |
| **账号管理** ★ v1.7 | 主号昵称、当前目标区服（可多区切换）、可切换区服列表 | accounts.yaml → main_account |
| **任务优先级** ★ | default_order 大类顺序、**精确到每个单独任务的 priority 值**（可在配置中逐任务设置） | tasks.yaml → default_order + 各任务 priority |
| **默认调度参数** ★ | 每日重置时刻 reset_at（默认 00:00，阴阳师重置时间）、新任务默认执行规则模板 | global.yaml → schedule |
| 防封号参数 | 点击偏移半径、延迟抖动、走神概率、每日时长/操作上限 | global.yaml → anti_detect |
| **运行时段** ★ | 脚本全天运行（无全局时段限制），**任务的执行时间由各任务的时间规则(repeat)控制**；仅保留每日运行时长/操作次数上限作为安全阀 | global.yaml → run |
| 阵容御魂预设管理 | 预设列表（新增/编辑/删除）、查看式神编队与御魂方案 | config/coords/teams/*.json |
| 日志与截图 | 日志级别、异常截图开关、日志保留天数 | global.yaml → run |

> 这些是"需要暴露出来方便调整"的部分。核心识别阈值（recognize 段）也可在此暴露给高级用户微调。**所有设置修改后立即持久化到对应配置文件，确保下次启动不丢失。**
>
> **任务优先级说明** ★：优先级归入配置菜单下管理，用户可在配置中精确到每个单独任务设置 priority 值（数字越小越优先）。同时可调整 default_order 控制同优先级任务的大类执行顺序。每个任务的优先级也可在任务控制面板的任务行中快捷调整。

**四类任务列表**（每类一个可折叠面板，菜单分类与 `tasks/` 子目录一一对应）：

| 面板 | 对应目录 | 每个任务可调项 |
|------|----------|----------------|
| 日常任务 | tasks/daily/ | 启用开关、优先级、**执行规则(repeat)**、**下次执行时间(next_run_time)** |
| 常驻任务 | tasks/permanent/ | 启用开关、优先级、**执行规则(repeat)**、挑战次数(times)、每日上限、阵容(team_id)、**下次执行时间** |
| 活动任务 | tasks/event/ | 启用开关、有效期(valid_from/until)、**执行规则(repeat)**、进度显示 |
| 特殊任务 | tasks/special/ | 启用开关、优先级、**执行规则(repeat)**、**下次执行时间** |

> **所有任务都可在 UI 查看并修改执行规则与下次执行时间**，修改后立即写入 tasks.yaml 与 task_state.json，长期保存。

**任务列表行为**：
- 列表自动从 `tasks/` 各子目录扫描生成（自动注册），新增任务文件后刷新即出现，**无需改 UI 代码**。
- 每个任务行显示：名称、启用开关、优先级、执行规则摘要、**下次执行时间（距下次还剩 XX 小时 YY 分）**、当前状态（待执行/进行中/已完成/已跳过/等待中）。
  - "等待中"表示 `now < next_run_time`，行尾显示倒计时（如寄养 21:00 可执行，当前 18:00 则显示"3 小时后可执行"）。
  - "已完成"表示 once/daily 任务当日已成功，行尾显示下次重置时间。
- 点击任务行展开详细参数面板：
  - **执行规则编辑器**：可视化选择执行方式（每日/每周/每月/隔N天/隔N小时/单次/依赖失效时间）、设置执行时刻、周几、次数等，无需手写 YAML。
  - **下次执行时间**：可直接输入或用时间选择器修改，保存后调度器立即按新时间调度（可"提前到现在"立即执行，或"推迟"跳过当前轮次）。
  - 其他参数：阵容(team_id)、入口路径、副本层数等。
  - 所有修改保存到 tasks.yaml（执行规则）与 task_state.json（next_run_time）。
- 提供"单步执行"按钮，便于调试单个任务（忽略 next_run_time 限制强制执行一次）。
- 提供"跳过本次"按钮：把该任务 next_run_time 推进到下一周期（daily 推到次日、interval_hours 加一个间隔、weekly 推到下个匹配日），用于用户主动跳过。

### 11.4 小号设置（多开配置）★ v1.7新增

**定位**：与"脚本配置"、"任务控制"同级别的一级菜单，专门管理小号（多开账号）的独立配置。小号**只需配合主号刷副本**，不执行日常/活动/特殊任务，因此独立成菜单，不与主号任务混在一起。

**小号设置面板**（每个小号一个可折叠面板，最多2个）：

| 配置项 | 说明 | 对应配置 |
|--------|------|----------|
| 启用开关 | 是否启用该小号 | accounts.yaml → sub_accounts[].enabled |
| 昵称 | 小号备注名 | accounts.yaml → sub_accounts[].nickname |
| 区服 | 小号所在区服（固定，不像主号可多区切换） | accounts.yaml → sub_accounts[].server |
| **模拟器端口** ★ | 小号绑定的独立模拟器 ADB 端口（多开核心） | accounts.yaml → sub_accounts[].adb_port |
| 设备 ID | ADB 设备标识（如 127.0.0.1:16416） | accounts.yaml → sub_accounts[].device_id |
| **副本配置** ★ | 小号要刷的副本列表，每个副本可独立设置：启用开关、挑战次数(times)、阵容(team_id)、执行规则(repeat) | accounts.yaml → sub_accounts[].dungeon_tasks |

**小号副本配置说明**：
- 小号的副本配置**复用主号的副本代码文件**（tasks/permanent/），仅参数独立。
- 小号可刷与主号相同或不同的副本，次数和阵容均可不同。
- 小号的阵容预设（team_id）可引用与主号相同的预设，也可引用小号专属预设（在 config/coords/teams/ 中新建）。
- 小号副本的执行规则（repeat）独立配置，不受主号调度影响。

> 小号的详细体系设计见 [第十二部分 账号管理与多开体系](12-账号管理与多开体系.md)。小号配置的完整格式见 [12.6 账号配置文件格式](12-账号管理与多开体系.md#126-账号配置文件格式configaccountsyaml-)。

### 11.6 UI 架构演进（v2.0）★

#### 11.6.1 传参模块（ParamBridge）—— UI 与程序的桥梁

v2.0 新增传参模块（`模块说明/10-传参模块.md`），位于 `ui/param_bridge/`，内部拆分为两层：

| 子层 | 职责 | 文件 |
|------|------|------|
| **配置数据模型层** | 定义每个任务/模块的参数 schema（类型/范围/默认值） | `schemas.py` |
| **UI 数据绑定层** | 控件 ↔ 配置的双向同步（UI改→配置改→程序读新值） | `ui_binding.py` |

**传参子模块分类**：

| 传参子模块 | 绑定 UI 区域 | 传入程序的数据 |
|-----------|-------------|---------------|
| `run_bridge.py` | 启动/停止/暂停按钮 | 启停信号（通过事件总线发布） |
| `task_bridge.py` | 任务列表面板 | 各任务 enabled/priority/repeat/next_run_time |
| `config_bridge.py` | 模拟器连接/防封号/日志面板 | global.yaml 配置项 |
| `account_bridge.py` | 账号管理面板 | accounts.yaml 配置项 |

**关键原则**：UI 不直接调用任何核心模块（Scheduler/Connection/Executor 等），所有交互经 ParamBridge 中转。

#### 11.6.2 事件驱动刷新

v2.0 UI 完全采用事件驱动：UI 面板订阅事件总线（`module拆解/08-事件总线模块.md`），状态变化时自动刷新，无需主动轮询。

| UI 组件 | 订阅事件 | 刷新行为 |
|---------|----------|----------|
| 状态栏（StatusBar） | `state_changed` | 自动显示运行状态/连接状态/当前账号/操作计数 |
| 控制栏（ControlBar） | `run_started` / `run_stopped` | 按钮状态切换（启动变灰色、停止变亮） |
| 任务列表 | `task_started` / `task_done` / `step_done` | 更新任务行状态、进度显示 |
| 日志面板（LogPanel） | `log_record` | 实时追加日志条目 |
| 倒计时标签 | `state_changed` (next_run_time) | 自动更新"距下次执行还剩 XX" |

### 11.7 内置终端面板（★ v2.1 新增）

#### 11.7.1 设计动机

原架构中，Python 脚本的 `print()` 输出和异常 `traceback` 会弹出外部 PowerShell/CMD 命令行黑窗口。这带来三个问题：
1. **体验割裂**：用户需要在 GUI 窗口和命令行窗口之间切换
2. **日志分散**：程序日志在 GUI 右侧，print 输出在黑窗口，排查问题需两边对照
3. **不美观**：黑窗口与 PyQt5 GUI 风格不协调

v2.1 将右侧日志面板升级为**双标签组合面板**，新增「终端」标签作为内置只读终端，彻底替代外部命令行窗口。

#### 11.7.2 终端特性

| 特性 | 说明 |
|------|------|
| **只读不可编辑** | 终端纯输出，用户无法输入命令或修改内容 |
| **stdout/stderr 重定向** | 通过 `OutputRedirector` 替换 `sys.stdout`/`sys.stderr`，所有 `print()` 和异常实时显示 |
| **自动着色** | `[INFO]=绿色` `[WARNING]=橙色` `[ERROR]=红色` `[DEBUG]=灰色` `[STEP]=蓝色` |
| **深色主题** | VS Code 风格暗色背景（#1E1E1E，#D4D4D4 文字），与日志浅色背景对比 |
| **清屏按钮** | 一键清除终端内容 |
| **自动卸载** | 程序退出时恢复原始 stdout/stderr，不影响后续输出 |
| **行数上限** | 最多保留 10000 行，超出自动丢弃旧行，防止内存溢出 |

#### 11.7.3 实现架构

```
右侧面板 LogPanel (QWidget)
  └── QTabWidget
       ├── Tab 0: 「📋 日志」→ LogStreamWidget
       │     ├── 筛选栏（级别 + 模块）
       │     ├── QPlainTextEdit（结构化日志流，浅色背景）
       │     └── [清除] [导出] 按钮
       │
       └── Tab 1: 「🖥 终端」→ TerminalWidget
             ├── 信息栏（"终端就绪 — 实时输出（只读）"）
             ├── QPlainTextEdit（只读，深色背景，等宽字体）
             └── [清屏] 按钮
```

**关键类**：
- `OutputRedirector(QObject)`：替换 `sys.stdout/stderr`，通过 Qt 信号线程安全地发送输出到终端
- `TerminalWidget(QWidget)`：内置只读终端控件
- `LogStreamWidget(QWidget)`：结构化日志流控件
- `LogPanel(QWidget)`：QTabWidget 组合容器

**生命周期**：
1. UI 启动 → `LogPanel.start()` → 订阅 `log_record` 事件 + 安装 OutputRedirector
2. 运行中 → 所有 print() / 异常自动显示在终端标签；结构化日志显示在日志标签
3. UI 关闭 → `LogPanel.shutdown()` → 卸载 OutputRedirector，恢复原始 stdout/stderr

#### 11.7.4 与外部命令行的对比

| | 外部命令行（旧） | 内置终端（v2.1 新） |
|------|-----------------|---------------------|
| 窗口 | 独立 PowerShell 黑窗 | GUI 内嵌标签页 |
| 交互 | 可输入命令（不需要） | 只读，不可输入 |
| 样式 | 系统默认 | VS Code 暗色主题 |
| 与日志关系 | 分离，需对照查看 | 同一面板，点击标签切换 |
| 输出着色 | 无 | 按级别自动着色 |
| 用户体验 | 割裂 | 统一 GUI 内 |
