## 第十二部分 账号管理与多开体系 ★

> v1.7 新增。本部分定义多区切换、多开协作、小号配置的完整体系。核心服务实现见 [05-核心模块详解](05-核心模块详解.md) 5.10 账号管理与多开模块。

### 12.1 账号体系总览

脚本支持**最多3个账号**：1个主号 + 最多2个小号，各自角色定位不同：

| 角色 | 数量上限 | 任务范围 | 说明 |
|------|----------|----------|------|
| **主号（main）** | 1 个（必须） | 全部：日常 + 常驻副本 + 活动 + 特殊 | 执行所有任务类型，是脚本的主要操作对象 |
| **小号（sub）** | 0~2 个 | **仅常驻副本刷取**（permanent 类） | 配合主号刷副本（如组队副号位），**不执行日常、活动、特殊任务** |

**核心约束**：
- 小号**只配合主号刷副本**，不独立执行日常领奖等任务，减少小号行为特征、降低风控。
- 每个账号绑定**独立模拟器实例**（独立 ADB 端口与设备 ID），实现真多开。
- 小号的副本配置独立于主号——小号可刷与主号不同（或相同）的副本，各自配置次数与阵容。
- 主号与小号共享同一套 `assets/` 素材库和 `config/coords/` 坐标配置（界面元素相同），仅任务编排和账号信息独立。

### 12.2 多区切换机制

**场景**：用户在多个区服有账号，需在脚本中切换目标账号/区服。

**设计**：
- 每个账号配置中包含 `server`（区服名称）字段。
- **主号多区切换**：主号可配置多个区服，在"账号管理"页面选择当前目标区服。切换区服后，登录流程（6.1）在选区环节自动选择配置的区服。
- **小号固定区服**：小号的区服在配置中固定（小号通常与主号不同区或同区不同号）。
- 区服切换通过登录流程的"选区"节点实现，不需要额外的模块——AccountManager 提供当前账号的 server 信息，LoginFlow 读取后执行选区操作。

### 12.3 多开控制与设备绑定

**多开方式**：每个账号绑定一个独立的模拟器实例（窗口），通过 ADB 端口区分。

```
主号  →  模拟器实例 A（ADB 127.0.0.1:16384）
小号1 →  模拟器实例 B（ADB 127.0.0.1:16416）
小号2 →  模拟器实例 C（ADB 127.0.0.1:16448）
```

**设备切换**：AccountManager 的 `switch_account(account_id)` 方法将当前操作的 ADB 设备切换到目标账号绑定的设备。调度器在执行小号任务前自动切换到小号设备，执行完毕后切回主号设备。

**ADBClient 适配**：底层 ADBClient（5.1）支持多设备——通过 `-s <device_id>` 参数指定目标设备。AccountManager 维护"账号 → 设备 ID"的映射，操作执行模块从 AccountManager 获取当前活跃设备 ID 后传给 ADBClient。

### 12.4 小号任务范围与配置

**任务范围过滤**：调度器（5.9）在生成日程表时，对每个账号调用 `AccountManager.get_task_scope(account_id)`：
- 主号：返回全部启用任务（daily + permanent + event + special）。
- 小号：**仅返回 permanent 类任务**中该小号配置的副本子集。

**小号副本配置**：每个小号在 `accounts.yaml` 中配置自己的 `dungeon_tasks` 列表，指定该小号要刷哪些副本、各自次数与阵容：

```yaml
sub_accounts:
  - account_id: "sub1"
    dungeon_tasks:
      - name: "yuhun"           # 复用主号的副本定义，但可配不同参数
        enabled: true
        times: 20                # 小号刷 20 次（可与主号不同）
        team_id: "yuhun_sub1"   # 小号可用不同阵容预设
      - name: "jiejie_tupo"
        enabled: false           # 小号可不刷结界突破
```

> 小号的副本任务**复用主号的 tasks/permanent/ 代码文件**，仅参数（次数、阵容、启用与否）独立配置。无需为小号单独开发副本代码。

### 12.5 主号与小号的协作流程

**独立刷取模式**（默认）：主号和小号各自独立刷副本，调度器按日程表在多设备间切换操作。

**组队协作模式**（组队副本场景）：当主号执行组队副本（如 `team_dungeon`）时：
1. 调度器检测到该副本需要副号配合（副本配置中 `need_sub_account: true`）。
2. AccountManager 切换到小号设备 → 小号进入副本作为乘客/副号。
3. 切换回主号设备 → 主号作为司机创建房间/开战。
4. 战斗中小号自动战斗（auto_battle），主号控制节奏。
5. 结算后两个账号各自领取奖励。

> 组队协作的具体识图与操作流程在对应副本任务代码中实现，AccountManager 只负责"在正确的时间切换到正确的设备"。

### 12.6 账号配置文件格式（config/accounts.yaml）★

```yaml
# 主号配置
main_account:
  account_id: "main"
  role: "main"
  nickname: "主号"
  server: "春樱共斗"              # 当前目标区服
  servers_available:              # 主号可切换的区服列表
    - "春樱共斗"
    - "秋风忆梦"
  adb_port: 16384
  device_id: "127.0.0.1:16384"
  enabled: true

# 小号配置（最多2个）
sub_accounts:
  - account_id: "sub1"
    role: "sub"
    nickname: "小号1"
    server: "春樱共斗"
    adb_port: 16416              # 独立模拟器端口
    device_id: "127.0.0.1:16416"
    enabled: true
    dungeon_tasks:                # 小号仅刷副本，不执行日常/活动/特殊
      - name: "yuhun"
        enabled: true
        times: 20
        team_id: "yuhun_sub1"
        repeat: {type: "daily", at_time: "14:00", times: 20}
      - name: "jiejie_tupo"
        enabled: false
        repeat: {type: "daily", at_time: "08:00", times: 6}

  - account_id: "sub2"
    role: "sub"
    nickname: "小号2"
    server: "秋风忆梦"
    adb_port: 16448
    device_id: "127.0.0.1:16448"
    enabled: false                # 未启用
    dungeon_tasks: []
```

**字段说明**：

| 字段 | 适用 | 说明 |
|------|------|------|
| `account_id` | 全部 | 唯一标识，调度器与 UI 以此引用 |
| `role` | 全部 | `"main"`（主号）/ `"sub"`（小号） |
| `nickname` | 全部 | 备注名，UI 显示用 |
| `server` | 全部 | 当前目标区服 |
| `servers_available` | 主号 | 主号可切换的区服列表（多区切换） |
| `adb_port` | 全部 | 绑定的模拟器 ADB 端口（多开独立） |
| `device_id` | 全部 | ADB 设备标识 |
| `enabled` | 全部 | 是否启用该账号 |
| `dungeon_tasks` | 小号 | 小号可执行的副本列表及参数（主号复用 tasks.yaml） |

### 12.7 与其他模块的集成关系

```
AccountManager（账号管理）
    │
    ├──▶ Scheduler（调度器）
    │     └─ 生成日程表时按账号过滤任务范围
    │     └─ 执行小号任务前 switch_account 切换设备
    │
    ├──▶ ADBClient（设备层）
    │     └─ 从 AccountManager 获取当前活跃 device_id
    │     └─ 多设备操作通过 -s 参数指定目标
    │
    ├──▶ LoginFlow（登录流程）
    │     └─ 读取当前账号的 server 执行选区
    │
    ├──▶ TeamManager（阵容管理）
    │     └─ 小号副本可用独立 team_id 预设
    │
    └──▶ UI（界面层）
          └─ 账号管理页面：设置主号区服、新增/删除小号
          └─ 小号设置页面：配置小号副本参数
```

> AccountManager 是"当前操作上下文"的提供者——所有需要知道"现在在操作哪个账号、哪台设备"的模块，都从 AccountManager 获取，而非各自硬编码。
