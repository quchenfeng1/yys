### 5.1 连接模块（device/connection.py）[01-连接]

**定位**：核心运行层第1模块。封装模拟器ADB连接与底层设备操作，统一连接异常的抛出口。v2.0 新增心跳检测、自动重连、多开设备管理。

**对应解耦文档**：`模块说明/01-连接模块.md`

**核心接口**：

```python
class ConnectionManager:
    """连接模块统一入口。管理多设备连接，提供设备操作（v2.0 增强版）。"""

    def connect(self, device_id: str = None) -> bool
    def disconnect(self, device_id: str = None)
    def is_connected(self, device_id: str = None) -> bool
    def get_active_device(self) -> ADBClient
    def switch_device(self, device_id: str) -> bool     # ★v2.0 多开切换

    # === 设备操作（委托给当前ADBClient）===
    def screenshot(self) -> np.ndarray
    def click(self, x: int, y: int)                     # 仅坐标，不含防封
    def swipe(self, x1, y1, x2, y2, duration)
    def input_key(self, key: str)
    def get_screen_size(self) -> tuple                  # 只读，不修改模拟器设置

    # === App管理 ===
    def launch_app(self, package: str, activity: str = None) -> bool
    def is_app_running(self, package: str) -> bool
    def is_app_foreground(self, package: str) -> bool

    # === 状态监控（★v2.0新增）===
    def start_heartbeat(self, interval: float = 30)
    def stop_heartbeat(self)
    def reconnect(self, device_id: str = None) -> bool  # 退避重连1s→2s→4s→8s→16s

    # === 连接质量监控（★v2.0新增）===
    def get_quality(self) -> dict                        # 各操作平均/最大延迟
```

**关键设计决策（v2.0）**：
- 心跳退避重连：断线后按指数退避（1s→2s→4s→8s→16s）最多5次自动重试，失败通过事件总线广播 `connection_lost`。
- 只读模拟器：严格遵守用户权限边界，禁止 `wm size`/`density` 等写操作。
- 连接质量监控：记录截图/点击/滑动各操作的响应延迟，平均延迟>2s时通过 Monitor 告警。
- 多开设备映射：维护 `device_id → ADBClient` 映射表，AccountManager 切换账号时调 `switch_device`。

### 5.2 识图控制模块（core/recognizer.py）[02-识图]

**定位**：核心运行层第2模块。纯识别引擎——在截图中定位目标图片，返回匹配位置与置信度。**不做操作、不做安全处理**，保持纯粹可独立测试。

**对应解耦文档**：`模块说明/02-识图控制模块.md`

**核心接口**：

```python
class Recognizer:
    """识图引擎。纯识别，不操作，不防封（v2.0 增强版）。"""

    def find(self, template_name: str, region=None, threshold=0.8,
             multi_scale: bool = False) -> MatchResult | None  # ★v2.0 多尺度
    def find_all(self, template_name: str, region=None, threshold=0.8) -> list[MatchResult]
    def exists(self, template_name: str, threshold=0.8) -> bool
    def wait(self, template_name: str, timeout=10, interval=0.5) -> MatchResult | None
    def wait_any(self, template_names: list, timeout=10) -> tuple[str, MatchResult] | None
    def reload(self)

class OcrLocator:                                          # ★v2.0 OCR子模块
    def locate_text(self, text: str, region=None) -> tuple | None
    def locate_any(self, texts: list, region=None) -> tuple[str, tuple] | None

class AssetIndex:                                          # ★v2.0 素材索引
    def load_all(self)                                     # 递归扫描assets/预加载
    def get(self, name: str) -> np.ndarray | None
    def reload(self)
```

**识别策略（v2.0 增强）**：
- 主用模板匹配（`TM_CCOEFF_NORMED`）+ 灰度优先 + 区域限定。
- **多尺度匹配** ★v2.0：`multi_scale=True` 时尝试 0.95/1.0/1.05 三个缩放，应对渲染偏差。
- **OCR文字定位** ★v2.0：动态界面（背景变化的按钮）用 OCR 识别文字位置兜底。
- **识图结果缓存** ★v2.0：短时间内同一模板缓存1秒，避免重复计算。
- **性能监控** ★v2.0：自动记录每次识图耗时，超过阈值时 Monitor 告警。

**关键**：识图模块不直接调用安全模块。识图返回原始坐标，安全策略由 Executor 在中间层注入。

### 5.6 任务模块（tasks/）[04-任务]★ v2.0 核心重构

**定位**：核心运行层第4模块。v2.0 从"继承体系"升级为**任务步骤图（DAG）架构**——每个任务由多个 TaskStep（特化模块+通用模块）组合，用有向图描述步骤间关系（顺序/条件分支/循环/跳转）。

**对应解耦文档**：`模块说明/04-任务模块.md`

**核心概念**：

| 概念 | 说明 |
|------|------|
| **TaskStep** | 任务步骤基类。特化模块和通用模块都继承此类，实现 `execute(context) → StepResult` |
| **TaskGraph** | 任务步骤图引擎。用有向图描述步骤间关系，支持顺序/分支/循环/跳转 |
| **StepResult** | 步骤执行结果：status(success/fail/skip/retry) + next_step + data |
| **TaskContext** | 步骤间共享上下文：task_config / executor / recognizer / team_manager / state |
| **通用模块** | 全项目复用的步骤：BattleLoop / ClaimReward / ReturnHall / PreCheckTeam / SelectTeam / ErrorReturn / CheckStamina / ClosePopup |
| **特化模块** | 每个副本独有的步骤：EnterYuhun / EnterAwaken / SignInEntry / EnterTrueOrochi 等 |

**步骤图示例（御魂副本）**：

```python
class YuhunTask(DungeonTask):
    def build_graph(self) -> TaskGraph:
        g = TaskGraph()
        g.add_step("enter", EnterYuhun())           # 特化：进入御魂
        g.add_step("check_stamina", CheckStamina())  # 通用：体力检查
        g.add_step("pre_team", PreCheckTeam())       # 通用：阵容检查
        g.add_step("select_team", SelectTeam())      # 通用：选阵容
        g.add_step("battle", BattleLoop(times=30))   # 通用：战斗循环×30
        g.add_step("claim", ClaimReward())           # 通用：结算领奖
        g.add_step("return", ReturnHall())           # 通用：返回庭院
        g.add_step("error", ErrorReturn())           # 通用：错误恢复

        g.set_entry("enter")
        g.add_edge("enter", "check_stamina")
        g.add_edge("check_stamina", "pre_team", condition=lambda r: r.status=="success")
        g.add_edge("check_stamina", "return", condition=lambda r: r.status=="skip")
        g.add_edge("pre_team", "select_team")
        g.add_edge("select_team", "battle")
        g.add_edge("battle", "claim")
        g.add_edge("claim", "return")
        for s in ["enter","pre_team","select_team","battle","claim"]:
            g.add_edge(s, "error", condition=lambda r: r.status=="fail")
        return g
```

**v2.0 关键设计**：
- **组合优于继承**：任务不是一个大类，而是多个步骤的有向图组合。新增副本时主要写特化步骤，通用步骤零成本复用。
- **错误自动恢复**：任意步骤失败走 error 分支（返回大厅→跳过任务），不崩溃。
- **步骤超时保护** ★v2.0：每个步骤可设 `timeout`，超时自动返回 fail。
- **自动注册**：任务文件放入 `tasks/` 目录即自动发现注册，无需改任何注册代码。

> 任务体系的其他方面（BaseTask 基类、任务分类、自动注册、脚手架工具）保持 v1.7 设计不变，详见 [第九部分](09-任务插件化开发体系.md)。

### 5.7 状态管理模块（core/state_manager.py）[07-状态]★ v2.0 新增

**定位**：支撑服务层第7模块。全局运行时状态集中管理中心——所有跨模块共享的状态存于此处，状态变化通过事件总线自动广播。

**对应解耦文档**：`模块说明/07-状态管理模块.md`

**为什么需要**：脚本运行中有大量全局状态（运行状态、当前账号、连接状态、当前场景、当前任务/步骤、操作计数）。如果散落在各模块内部，会导致模块间互相查询时紧耦合，且状态不一致风险高。

**核心接口**：

```python
class StateManager:
    def get_state(self, key: str, default=None) -> Any
    def set_state(self, key: str, value: Any)         # 自动通过事件总线广播变化
    def get_snapshot(self) -> dict                    # 全部状态快照（调试/UI用）
    def reset(self)                                    # 重置为初始值
    def subscribe(self, key: str, callback)            # 便捷订阅方法
```

**关键状态键名**（StateKeys）：

| 键名 | 类型 | 示例值 |
|------|------|--------|
| `run_status` | str | "running" / "paused" / "stopped" / "error" |
| `current_account` | str | "main" / "sub1" / "sub2" |
| `connection_status` | str | "connected" / "disconnected" / "reconnecting" |
| `active_device_id` | str | "127.0.0.1:16384" |
| `current_scene` | str | "courtyard" / "battle" / "explore" |
| `current_task` | str | "yuhun" |
| `current_step` | str | "battle_loop" |
| `today_operation_count` | int | 456 |
| `run_limit_reached` | bool | false |

**关键设计**：
- **单一数据源**：全局状态只在 StateManager 维护，其他模块不自行缓存。
- **变化即广播**：`set_state` 自动发布 `state_changed` 事件，UI 和其他模块无需轮询。
- **只管运行时态**：配置归 ConfigManager，持久化执行记录归 Scheduler，StateManager 只管"当前运行态"。
- **非持久化**：运行时状态不写盘（重启即重置）。

### 5.8 事件总线模块（core/event_bus.py）[08-事件]★ v2.0 新增

**定位**：支撑服务层第8模块。模块间松耦合通信枢纽——发布-订阅模式，模块间不直接持有对方引用，通过事件总线间接通信。

**对应解耦文档**：`模块说明/08-事件总线模块.md`

**为什么需要**：如果没有事件总线，UI 点"停止"需要直接持有 RunController/Scheduler/Task/Connection 的引用，形成网状依赖。有了事件总线后，UI 只发布 `stop_requested` 事件，各模块自行订阅处理——发布者不关心谁订阅，订阅者不关心谁发布。

**核心接口**：

```python
class EventBus:
    def publish(self, event_name: str, **data)           # 发布事件，立即返回
    def subscribe(self, event_name: str, handler, filter=None) -> str  # 订阅，返回ID
    def unsubscribe(self, subscription_id: str)
    def clear()

event_bus = EventBus()  # 全局单例
```

**核心事件清单**（详见 `模块说明/08-事件总线模块.md` 2.1-2.5 完整清单）：

| 类别 | 关键事件 | 发布者 → 订阅者 |
|------|----------|----------------|
| 运行控制 | `start_requested` / `stop_requested` | UI → RunController, Scheduler, TaskGraph |
| 运行控制 | `run_started` / `run_paused` / `run_stopped` | RunController → UI, StateManager |
| 连接 | `connection_lost` / `connection_restored` | ConnectionManager → RunController, UI |
| 任务 | `task_started` / `task_done` / `step_done` | RunController → UI, Scheduler, Monitor |
| 调度 | `schedule_updated` / `task_due` | Scheduler → UI, RunController |
| 状态 | `state_changed` / `config_changed` | StateManager/ConfigManager → UI, 相关模块 |

**关键设计**：
- **线程安全**：工作线程消费事件队列，`publish` 不阻塞发布者。
- **事件命名规范**：past_tense（如 `task_done` 而非 `do_task`）。
- **事件过滤**：`subscribe` 支持 filter 函数，只处理满足条件的事件。
- **事件溯源** ★v2.0：可选记录事件历史，调试"为什么任务没执行"时回溯事件链。

### 5.9 运行控制模块（core/run_controller.py）[09-运行控制]★ v2.1 强制停止

**定位**：支撑服务层第9模块。程序运行生命周期管理——接收 UI 启停信号、检查运行允许性、驱动调度循环。**v2.1：停止 = 立即强制终止，不等步骤完成。**

**v2.1 核心变更**：
- **停止行为**：从"优雅停止（等步骤完成）"改为"强制停止（立即终止线程）"
- **实现方式**：`threading.Event` 信号检查 + Windows `TerminateThread` API 兜底
- **任务隔离**：每个任务在独立子线程执行，`force_stop()` 精确终止任务线程

**对应解耦文档**：`模块说明/09-运行控制模块.md`

**简化状态机（v2.1）**：

```
                    start_requested
    stopped ──────────────────────► running
       ▲        stop_requested        │
       │◄─────────────────────────  paused
       │   (从任意非stopped状态        │
       │    立即 force_stop() )        │
       └──────────────────────────────┘
```

**核心接口**：

```python
class RunController:
    def force_stop(self)       # ★ v2.1：立即强制终止所有线程
    def _force_kill_thread(t)  # ★ v2.1：Windows TerminateThread API

    # 强制停止流程：_stop_event.set() → TerminateThread(task_thread)
    #             → TerminateThread(run_thread) → _cleanup_after_stop()
    #             → 发布 run_stopped → UI 瞬间恢复
```

**调度循环（_run_loop）**：
```
while running:
  1. 检查运行允许性（防封号上限/连接状态）
  2. 优雅停止检查（stopping 态等当前任务完成）
  3. scheduler.get_next_task() → 取下一个到期任务
  4. 执行任务 → 发布 task_started → task.execute() → 发布 task_done
  5. scheduler.mark_done(task, success) → 推进 next_run_time
  6. 继续取下一个任务...
```

**LogEntry 结构化日志**：

```python
@dataclass
class LogEntry:
    timestamp: datetime    # 时间戳
    level: str             # DEBUG/INFO/WARNING/ERROR/CRITICAL
    message: str           # 日志消息
    module: str            # 来源模块（如 "task:yuhun"）
    task: str              # 当前任务
    step: str              # 当前步骤
    tags: list             # 自定义标签（如 ["battle","victory"]）
```

**关键设计**：
- **非侵入式**：其他模块只需调 `monitor.info()` / `monitor.record_task_start()`，不感知日志内部实现。
- **异步写入**：日志写入不阻塞业务线程，通过队列异步落盘。
- **三层输出**：每条日志同时输出到文件（loguru渲染）、结构化JSON、事件总线（UI实时显示）。
- **异常截图**：出错时自动截图+保存上下文 JSON，存放 `logs/snapshots/YYYY-MM-DD/{task}_{step}_{timestamp}.png`。
- **日志导出** ★v2.0：一键打包日志+截图+指标为 zip，方便反馈问题。
