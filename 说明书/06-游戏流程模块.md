## 第六部分 游戏流程模块

### 6.1 登录流程模块（tasks/login_flow.py）

**目标**：从模拟器启动阴阳师开始，到稳定进入庭院主界面。

**流程节点**（每个节点对应一张或多张识别素材）：

```
[1] 启动阴阳师 App
    └─ 识别: app_icon.png / 通过 ADB am start 启动
[2] 开屏动画 / 健康游戏公告
    └─ 识别: splash_skip.png / health_notice_confirm.png
    └─ 等待加载，识别到"开始游戏"或"进入游戏"按钮
[3] 公告弹窗关闭
    └─ 识别: announcement_close.png（可多次出现，循环关闭）
[4] 选号界面（如需切换账号）
    └─ 识别: select_account.png / switch_account.png
    └─ 输入账号密码（配置中预设，走 input_text）
[5] 选区界面
    └─ 识别: select_server.png
    └─ 匹配目标区服名（OCR 或模板匹配区服按钮）
    └─ 点击"开始游戏"
[6] 加载进入
    └─ 等待庭院主界面出现（识别 courtyard_main.png 作为完成标志）
[7] 关闭可能的弹窗（签到、活动、奖励领取）
    └─ 循环关闭直到无弹窗
```

**容错设计**：
- 每个节点设置超时（默认 30s），超时则截图存档并重试。
- 支持断点续登：若已在游戏内则跳过登录流程。
- 登录失败超过 3 次则停止并告警，避免反复尝试触发风控。

**配置示例（config/coords/login.json）**：

```json
{
  "app_package": "com.netease.onmyoji.wyzymnqsd_cps",
  "app_activity": "com.netease.onmyoji.Launcher",
  "enter_game": {
    "reference_image": "所需图片/MuMu-20260719-020905-471.png",
    "target_text": "进入游戏",
    "auto_detect": true,
    "fixed_region": {
      "enabled": false,
      "x": 0, "y": 0, "width": 0, "height": 0
    },
    "loop": {
      "interval": 1.0,
      "max_clicks": 30,
      "timeout": 60
    },
    "courtyard_check": {
      "enabled": false,
      "image": "scenes/courtyard/main"
    }
  },
  "account": {
    "auto_login": false,
    "username": "",
    "password": ""
  }
}
```

**登录流程说明**（v1.6 更新）：
- 放弃6张必传识图素材，改为 **OCR 识别"进入游戏"位置 → 循环点击固定区域** 方案。
- 启动 App 后，首次运行时用 RapidOCR 从参考图识别"进入游戏"文字位置并保存；后续直接使用保存的固定坐标。
- 每隔约 1 秒点击一次"进入游戏"区域，直到进入主界面（或达到 max_clicks / timeout）。
- 进入主界面判断：若 `courtyard_check.enabled=true` 且有 `scenes/courtyard/main` 素材，则模板匹配检测；否则按点击次数/超时退出。

### 6.2 主界面导航模块

**职责**：在庭院、町中、探索等大界面间导航，提供"回到庭院"等公共方法。

**核心方法**：

```python
class Navigator:
    def go_home(self) -> bool              # 回到庭院（反复点返回/主页）
    def open_explore(self) -> bool         # 进入探索地图
    def open_town(self) -> bool            # 进入町中
    def open_menu(self) -> bool            # 打开菜单
    def close_all_popups(self) -> bool     # 关闭所有弹窗
    def current_scene(self) -> str         # 识别当前所处场景
```

**场景识别**：维护一组"场景标志图"，通过匹配判断当前在哪个界面，用于异常恢复。

### 6.3 日常任务模块（tasks/daily/）

纯领奖类任务，**不涉及副本战斗**：点击入口 → 领取 → 关弹窗。

**BaseTask 基类**（所有任务类的根基类，日常/常驻/活动/特殊均继承自它）：

```python
class BaseTask:
    name: str                       # 任务名（与目录、配置文件三者绑定）
    category: str                   # 任务分类：daily / permanent / event / special
    task_type: str                  # 任务类型：battle(战斗任务) / event_task(事件任务)
    enabled: bool = True            # 是否启用
    priority: int = 0               # 优先级（数字越小越优先，见 5.9）
    repeat: RepeatRule = None        # 执行规则（见 5.9），所有任务必配，决定 next_run_time 推进
    config: dict                    # 任务配置

    def pre_check(self) -> bool     # 前置检查（体力、次数、时间窗口）
    def run(self) -> bool           # 执行任务（子类实现）
    def post_check(self) -> bool    # 后置检查
    def execute(self) -> bool       # 模板方法：pre_check → run → post_check
```

**已规划的日常任务**（tasks/daily/）：

**task_type 说明**：
- `"battle"` = 战斗任务：执行前需切换阵容，配置包含阵容预设
- `"event_task"` = 事件任务：纯时间驱动，配置仅含循环时间和次数
- 每个任务文件通过模块级变量 `task_type = "battle"` 或 `task_type = "event_task"` 声明

| 任务 | 文件 | 说明 | 典型 repeat |
|------|------|------|-------------|
| 每日签到 | sign_in.py | 每日签到、领取签到奖励 | daily 00:00 ×1 |
| 奖励领取 | daily_rewards.py | 邮件、任务奖励、成就领取 | daily 00:00 ×1 |
| 商城购买 | shop_buy.py | 每日免费/限购商品自动购买 | daily 00:00 ×1 |
| 每周分享 | weekly_share.py | 每周分享得奖励 | weekly 周一 |
| 阴阳寮签到 | luntra_sign.py | 寮每日签到 | daily 全天 |

> 日常任务代码量最小，通常 10-20 行；无阵容、无战斗，不调用 TeamManager。

### 6.4 常驻任务模块（tasks/permanent/）

常驻副本，**有明确副本战斗逻辑**，需配置挑战次数（times）与执行规则（repeat）。继承 `DungeonTask`（继承自 `BaseTask`）。涵盖御魂、觉醒、契灵、结界突破、道馆等长期开放、规则稳定的战斗玩法。

**DungeonTask 基类**：

```python
class DungeonTask(BaseTask):
    # —— 阵容环节（调用 TeamManager 核心服务）——
    def pre_check_team(self) -> bool  # 检测当前阵容是否匹配目标预设，不匹配则需调整
    def ensure_team(self) -> bool     # 对局外调整阵容+御魂（委托 TeamManager.ensure_team）
    # —— 副本流程 ——
    def enter(self) -> bool           # 进入副本（导航到入口并点击）
    def select_floor(self) -> bool    # 选择层数
    def select_team(self) -> bool     # 对局内选阵容（委托 TeamManager.select_team_in_battle）
    def lock_team(self) -> bool       # 锁定阵容（委托 TeamManager.lock_team，仅首次）
    def start_battle(self) -> bool    # 点击挑战
    def wait_battle_end(self) -> bool # 等待战斗结束（识别胜利/失败）
    def settle(self) -> bool          # 结算（点确认、领奖励）
    def loop(self, times: int)        # 循环挑战：首次走完整流程，后续跳过选阵容（已锁定）
```

**常驻任务执行流程**（execute 模板方法编排）：

```
任务触发
  │
  ├─[1] pre_check_team    检测当前阵容是否匹配目标预设
  │      └─ 不匹配 → ensure_team（对局外调整阵容+御魂，回到庭院）
  │      └─ 匹配   → 跳过调整
  ├─[2] enter             第一次进入副本（导航到入口）
  ├─[3] select_floor      选择层数
  ├─[4] select_team       对局内选择目标阵容预设
  ├─[5] lock_team         锁定阵容（lock_after_select=true 时）
  ├─[6] start_battle      点击挑战
  ├─[7] wait_battle_end   等待战斗结束
  ├─[8] settle            结算领奖
  └─[9] loop              重复 [6][7][8]（已锁定，不再选阵容）
                         达到 times 次后退出副本
```

> **关键**：阵容调整（阶段一）与选阵容（阶段二）分离。`ensure_team` 在进入副本前的庭院完成；`select_team + lock_team` 仅在**首次**进入副本时执行一次，锁定后重复刷取直接走挑战→结算循环，既符合游戏机制又减少操作量、降低风控风险。
>
> **阵容检查强制性** ★：每个战斗任务首次进入战斗前**必须**执行 `pre_check_team`，不匹配则强制 `ensure_team` 调整。锁定与否由副本配置的 `lock_team_after_select` 字段决定（见 [05-核心模块详解](05-核心模块详解.md) 5.8 阵容检查的强制性）。

### 6.5 活动任务模块（tasks/event/）

限时活动，**规则多变、可能战斗也可能仅领奖**。因活动有有效期，单独成类，避免过期后仍被执行。继承 `EventTask`（继承自 `BaseTask`）。

**EventTask 基类**：

```python
class EventTask(BaseTask):
    """限时活动基类，带有效期管理"""
    valid_from: str = None      # 生效日期
    valid_until: str = None     # 失效日期，过期自动禁用
    def is_active(self, today=None) -> bool   # 判断活动是否在有效期内
    def run(self) -> bool                      # 活动逻辑（战斗/领奖，自定义）
    # execute() 模板方法: is_active 检查 → run
```

**设计要点**：
- **有效期管理**：`valid_until` 到期后调度器自动跳过，无需手动删配置；活动结束后任务文件保留，下次同类活动复用骨架。
- **规则配置驱动**：活动入口、步骤、奖励领取点全部走配置（`steps_image`），换活动只改配置不改代码。
- **杂逻辑兼容**：有的活动仅领奖（同日常），有的需战斗（同常驻），EventTask 不强制流程，由 `run()` 自定义。

**活动配置示例（config/coords/event_xxx.json）**：

```json
{
  "valid_from": "2026-07-20",
  "valid_until": "2026-08-10",
  "entry_path": ["scenes/courtyard/icon_event_banner"],
  "steps_image": ["tasks/event/event_xxx/step1", "tasks/event/event_xxx/step2", "tasks/event/event_xxx/challenge"],
  "has_battle": true,
  "team_id": "event_team",
  "auto_disable_after_expire": true
}
```

> 活动更新频繁时，只需复制一个现有活动配置改 `valid_until`/入口图/步骤图即可快速接入新活动。

### 6.6 特殊任务模块（tasks/special/）

**固定流程但执行方式特殊**的任务：可能需要先识别任务状态再决定动作，或机制与常驻副本差异大。继承 `SpecialTask`（继承自 `BaseTask`），步骤自定义。

**SpecialTask 基类**：

```python
class SpecialTask(BaseTask):
    """特殊任务基类，步骤自定义，比 DungeonTask 更灵活"""
    def setup(self) -> bool          # 前置准备（识别任务状态、进入特殊场景、切换阵容）
    def execute_steps(self) -> bool  # 自定义多步骤执行（核心逻辑）
    def teardown(self) -> bool       # 收尾（退出场景、回庭院）
    # execute() 模板方法: setup → execute_steps → teardown
```

**特殊任务设计原则**：
- **不强求套用标准流程**：自定义步骤序列，复杂流程拆分为独立子函数，每个子函数可单独测试。
- **角色模式切换**：组队类任务区分"司机模式"与"乘客模式"（配置项切换），共用一套代码。
- **场景导航复用**：进入阴阳寮、町中等场景统一调用 Navigator，保证路径一致。
